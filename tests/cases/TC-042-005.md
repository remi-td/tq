## Test Suite B: API Compatibility - `ParsedStatement` Struct

### TS42-A01: `ParsedStatement` struct fields are unchanged (AC-12)

This is validated at compile time: if the struct changed its public fields, all existing code using those fields would fail to compile, and `cargo test` would not produce any test results.

**Implicit validation via TS42-R01:** If `cargo test` compiles and runs, the `ParsedStatement` struct is API-compatible.

**Explicit code inspection check:**

The `ParsedStatement` struct must retain these exact public fields:
- `pub sql: String`
- `pub statement_number: usize`
- `pub start_line: usize`

And these methods:
- `pub fn new(sql: String, statement_number: usize, start_line: usize) -> Self`
- `pub fn preview(&self, max_len: usize) -> String`

**Inspection command:**
```bash
grep -A 10 "pub struct ParsedStatement" src/sql/parser.rs
```

Expected output (order of fields may vary):
```
pub struct ParsedStatement {
    pub sql: String,
    pub statement_number: usize,
    pub start_line: usize,
}
```

## Test Suite D: Existing Parser Test Verification (AC-10)

The following existing tests from `src/sql/parser.rs` must continue to pass after the rewrite. They verify backwards compatibility for the simple cases that worked before:

| Existing Test Name | Validates | Expected Behavior After Rewrite |
|--------------------|-----------|----------------------------------|
| `test_parse_single_statement` | Single statement without semicolon | Unchanged: 1 statement |
| `test_parse_single_statement_with_semicolon` | Single statement with trailing `;` | Unchanged: 1 statement, sql trimmed |
| `test_parse_multiple_statements` | Three inline statements | Unchanged: 3 statements |
| `test_parse_multiline_statements` | Multi-line with line tracking | Unchanged: 3 statements, correct start_line |
| `test_parse_empty_input` | Empty string | Unchanged: 0 statements |
| `test_parse_whitespace_only` | Whitespace only | Unchanged: 0 statements |
| `test_parse_empty_statements_skipped` | `SELECT 1;;; SELECT 2;` | Unchanged: 2 statements |
| `test_parse_statement_with_newlines` | Multi-line SELECT | Unchanged: 1 statement |
| `test_parse_trailing_semicolons` | `SELECT 1;;;` | Unchanged: 1 statement |
| `test_parse_leading_whitespace` | Leading whitespace | Unchanged: 2 statements |
| `test_statement_preview_short` | Short preview | Unchanged |
| `test_statement_preview_long` | Truncated preview with `...` | Unchanged |
| `test_statement_preview_normalizes_whitespace` | Whitespace normalization | Unchanged |
| `test_has_multiple_statements` | Basic cases | Unchanged |
| `test_has_multiple_statements_empty` | Empty input | Unchanged |
| `test_line_tracking_accuracy` | Line numbers | Unchanged |
| `test_windows_line_endings` | `\r\n` handling | Unchanged |

**Tests that CHANGE behavior (architect must update the test assertions):**

| Existing Test Name | Old Behavior | New Expected Behavior | Reason |
|--------------------|-------------|----------------------|--------|
| `test_parse_preserves_comments` | Comments INCLUDED in sql field | Comments STRIPPED from sql field | REQ-PARSE-009: line comments are stripped |
| `test_parse_multiline_comment` | Block comment INCLUDED in sql field | Block comment STRIPPED from sql field | REQ-PARSE-010: block comments are stripped |
| `test_parse_complex_script` | Comments appear in statement sql | Comments stripped; statement count/content may differ | REQ-PARSE-009, REQ-PARSE-010 |

Note: `test_parse_complex_script` currently asserts:
```rust
assert!(statements[0].sql.contains("CREATE TABLE")); // still passes
```
But the test also expects the first statement to contain the `-- Setup script` comment. After the rewrite, the comment should be stripped. The architect must update this test's assertion for the `sql` field of comments-adjacent statements.

**Run command:**
```bash
cargo test --lib sql::parser
```

All listed tests must show `ok` status.
