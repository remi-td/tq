# TC-042-004: Combined Scenarios (All 3 Bugs Together)

**Test ID:** TC-042-004
**Feature:** SQL Parser - Combined Quote/Comment/Multi-line Handling
**Priority:** P0 - Critical
**Test Type:** Unit + Integration
**Sprint:** 42
**Created:** 2026-03-21
**Requirement References:** REQ-PARSE-001 through REQ-PARSE-015, AC-1 through AC-12
**GitHub Issues:** #28, #29, #30

---

## Objective

Verify that all three parser fixes work together in realistic, combined SQL scripts where quoted strings, multi-line statements, and comment blocks all appear in the same input. Also verify the `has_multiple_statements()` utility function, the `ParsedStatement.preview()` method, and end-to-end CLI `--file` wiring for the error path (no database required).

## Background

Real-world SQL scripts routinely mix all three constructs simultaneously. For example, a migration script may include:
- A multi-line `INSERT` with string values containing semicolons
- Block comments explaining sections
- Line comments on individual lines
- Mix of single-line and multi-line statements

The parser must handle all of these correctly when they appear together, not just in isolation. These combination tests verify that the state-machine transitions between states are correct (e.g., entering a block comment while accumulating a multi-line statement, then exiting and continuing that statement).

### TS42-U21: Combined script - all three bugs together

```rust
#[test]
fn test_combined_all_three_bugs() {
    // This is the definitive combined test addressing bugs #28, #29, and #30
    // simultaneously in a realistic SQL script
    let sql = r#"
-- Script header: combined bug test
/* Block comment with semicolons; that must not split; anything */

-- Create table (multi-line DDL)
CREATE TABLE test_combined (
    id     INTEGER,
    note   VARCHAR(200)
);

-- Insert with semicolon in string value (bug #28)
INSERT INTO test_combined
VALUES (1, 'step 1; step 2; done');

-- Insert with escaped quote and semicolons (bugs #28 + #29 combined)
INSERT INTO test_combined
VALUES (2, 'it''s fine; really');

/* Query section */
SELECT
    id,
    note
FROM test_combined
WHERE note LIKE '%step%';

-- Cleanup
DROP TABLE test_combined;
"#;
    let statements = parse_statements(sql).expect("parse should succeed");

    // Total: CREATE, INSERT, INSERT, SELECT, DROP = 5 statements
    // (comment-only segments and blank lines are discarded)
    assert_eq!(
        statements.len(), 5,
        "expected 5 statements, got {}; statements: {:?}",
        statements.len(),
        statements.iter().map(|s| &s.sql).collect::<Vec<_>>()
    );

    // Statement 1: CREATE TABLE
    assert!(statements[0].sql.contains("CREATE TABLE test_combined"));
    assert_eq!(statements[0].statement_number, 1);

    // Statement 2: INSERT with semicolon in string (bug #28)
    assert!(statements[1].sql.contains("INSERT INTO test_combined"));
    assert!(
        statements[1].sql.contains("'step 1; step 2; done'"),
        "string with semicolons must be preserved intact"
    );
    assert_eq!(statements[1].statement_number, 2);

    // Statement 3: INSERT with escaped quote + semicolons (bugs #28 + #29)
    assert!(statements[2].sql.contains("INSERT INTO test_combined"));
    assert!(
        statements[2].sql.contains("'it''s fine; really'"),
        "escaped quote + semicolons in string must be preserved"
    );
    assert_eq!(statements[2].statement_number, 3);

    // Statement 4: SELECT (multi-line, bug #29)
    assert!(statements[3].sql.contains("SELECT"));
    assert!(statements[3].sql.contains("FROM test_combined"));
    assert_eq!(statements[3].statement_number, 4);

    // Statement 5: DROP TABLE
    assert!(statements[4].sql.contains("DROP TABLE test_combined"));
    assert_eq!(statements[4].statement_number, 5);

    // All comments must be stripped from all statements
    for stmt in &statements {
        assert!(
            !stmt.sql.contains("-- "),
            "line comment must not appear in statement {}: {}",
            stmt.statement_number, stmt.sql
        );
        assert!(
            !stmt.sql.contains("/*"),
            "block comment must not appear in statement {}: {}",
            stmt.statement_number, stmt.sql
        );
    }
}
```

**Expected Result:** Exactly 5 statements; all comment text stripped; string contents with semicolons and escaped quotes preserved.

### TS42-U28: Complex script with line numbers verified end-to-end

```rust
#[test]
fn test_complex_script_line_numbers_end_to_end() {
    // Verify start_line accuracy through a realistic multi-statement script
    // with comments interspersed
    let sql = concat!(
        "-- Line 1: comment\n",              // line 1
        "SELECT 1;\n",                        // line 2: stmt 1 starts line 2
        "-- Line 3: comment\n",              // line 3
        "/*\n",                               // line 4: block comment start
        " * Line 5\n",                        // line 5
        " */\n",                              // line 6: block comment end
        "SELECT 2;\n",                        // line 7: stmt 2 starts line 7
        "SELECT\n",                           // line 8: stmt 3 starts line 8
        "    3\n",                            // line 9
        "FROM dual;",                         // line 10
    );
    let statements = parse_statements(sql).expect("parse should succeed");
    assert_eq!(statements.len(), 3);
    assert_eq!(statements[0].start_line, 2, "stmt 1 starts line 2");
    assert_eq!(statements[1].start_line, 7, "stmt 2 starts line 7");
    assert_eq!(statements[2].start_line, 8, "stmt 3 starts line 8");
}
```

**Expected Result:** 3 statements with start_line values of 2, 7, and 8.

## Integration Test Cases (No Database Required)

These tests run the `tq` CLI binary directly via `std::process::Command` and validate the `--file` execution path. They do NOT require a live database because they test error paths that fail before connecting.

### TS42-I01: Parse error in `--file` is reported with line number

```rust
// Location: tests/integration_tests.rs
#[test]
fn test_file_with_parse_error_reports_line_number() {
    use std::io::Write;

    // Write a SQL file with an unterminated string
    let dir = std::env::temp_dir();
    let file_path = dir.join("tq_test_parse_error.sql");
    let sql_content = "SELECT 1;\nSELECT 'unterminated\n";
    std::fs::write(&file_path, sql_content).expect("failed to write test file");

    // Run tq query --file <path>; expect it to fail with a parse error
    // No TQ_LOGON needed - parse error occurs before connection attempt
    let output = std::process::Command::new(env!("CARGO_BIN_EXE_tq"))
        .args(["query", "--file", file_path.to_str().unwrap()])
        .output()
        .expect("failed to run tq");

    // Clean up
    let _ = std::fs::remove_file(&file_path);

    // Must fail (non-zero exit)
    assert!(
        !output.status.success(),
        "tq must fail when SQL file has a parse error"
    );

    // Error message must mention the line number
    let stderr = String::from_utf8_lossy(&output.stderr);
    let stdout = String::from_utf8_lossy(&output.stdout);
    let combined = format!("{stderr}{stdout}");
    assert!(
        combined.contains("2") || combined.to_lowercase().contains("unterminated"),
        "error output must mention line 2 or describe the parse error: {combined}"
    );
}
```

**Expected Result:** Non-zero exit code; error output mentions the problematic line number.
