# Test Case TC061: Result Paging - Pager Shows Position Indicator

## Purpose

Verify that the pager displays a clear status line showing current position, total size, percentage, and available commands.

## Prerequisites

- tq REPL mode active
- Pager enabled
- Query with 100+ rows and 10+ columns

## Test Procedure

### Step 1: Activate pager

```sql
tq> SELECT TOP 100 * FROM DBC.TablesV;
```

### Step 2: Verify status line at initial view

**Expected status line elements:**
- Current line range: "Lines 1-25"
- Total lines: "of 100"
- Percentage: "(0%)" or "0%"
- Help text: "j/k=scroll, q=quit" or similar

Example: `Lines 1-25 of 100 (0%) | j/k=scroll, q=quit`

### Step 3: Navigate and verify status updates

Press 'j' 10 times

**Expected:**
- Status updates to show new line range
- Percentage updates
- Example: "Lines 11-35 of 100 (11%)"

Press 'l' 3 times (if horizontal scroll active)

**Expected:**
- Status shows column position too
- Example: "Lines 11-35 of 100 (11%) | Cols 4-10 of 15"

### Step 4: Verify percentage calculation

Navigate to middle of results (line 50)

**Expected:**
- Percentage around 50%
- Example: "Lines 50-75 of 100 (50%)"

Navigate to end

**Expected:**
- Percentage around 100%
- Example: "Lines 76-100 of 100 (100%)"

### Step 5: Verify help text visibility

Check status line includes help text:
- [ ] Navigation keys mentioned (j/k or arrows)
- [ ] Exit key mentioned (q or Esc)
- [ ] Concise (fits in terminal width with position info)

## Verification

**Status Line Components:**
- [ ] Current line range visible
- [ ] Total line count visible
- [ ] Percentage indicator visible
- [ ] Column info (if horizontal scroll active)
- [ ] Help text present and clear
- [ ] Updates in real-time on navigation

**Status Line Format:**
- [ ] Appears at bottom of terminal (last line)
- [ ] Distinct visual style (inverse video, color, or separator)
- [ ] Doesn't overlap with data
- [ ] Readable and not truncated

**Accuracy:**
- [ ] Line ranges are correct
- [ ] Percentage calculation is accurate
- [ ] Updates immediately on scroll

## Expected Results

**Status Line Example (Vertical Only):**
```
Lines 25-50 of 200 (25%) | j/k=scroll, PageUp/PageDown=page, q=quit
```

**Status Line Example (Vertical + Horizontal):**
```
Lines 25-50 of 200, Cols 5-12 of 16 (25%) | hjkl/arrows=scroll, q=quit
```

**Visual Placement:**
```
╭─────────────┬──────────────┬─────────────╮
│ DatabaseName ┆ TableName    ┆ TableKind   │
├╌╌╌╌╌╌╌╌╌╌╌╌╌┼╌╌╌╌╌╌╌╌╌╌╌╌╌╌┼╌╌╌╌╌╌╌╌╌╌╌╌╌┤
│ DBC         ┆ Columns      ┆ V           │
...
Lines 1-24 of 100 (0%) | j/k=scroll, q=quit  ← Status line
```

## Pass/Fail Criteria

**PASS:**
- Status line is visible at bottom
- Shows current position accurately
- Shows total size
- Shows percentage
- Includes concise help text
- Updates on every navigation action

**FAIL:**
- No status line visible
- Status line missing key information
- Position info is incorrect
- Percentage wrong
- Doesn't update on navigation
- Status line overlaps with data

## Notes

Status line is critical for user orientation:
- Where am I in the results?
- How much more data is there?
- What keys can I use?

From src/commands/repl/pager.rs (exists but not used):
```rust
pub fn status_line(&self) -> String {
    format!("Lines {}-{} of {} ({:.0}%)",
        self.start_row + 1,
        min(self.start_row + self.visible_rows, self.total_rows),
        self.total_rows,
        self.percentage())
}
```

The fix must integrate this status line generation into the pager rendering.
