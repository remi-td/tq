# Test Case TC077: Table Display - Wide Terminal Handling (120 cols)

## Purpose

Verify that table display correctly utilizes wider terminal space (120 columns) to show more columns while maintaining readability.

## Scope

**Testing:**
- Terminal width detection (120 columns)
- More columns visible than 80-col terminal
- Still truncates if >10 columns
- "(+n cols)" indicator adjusts correctly
- Layout remains clean and readable

**Not Testing:**
- 80-column terminal (TC076)
- Very wide terminals (TC078, TC079)
- Batch mode (TC080)

## Prerequisites

- tq binary with Sprint 11 fixes
- Terminal set to 120 columns
- Same test query as TC076 (10+ columns)

## Pass/Fail Criteria

**PASS:**
- Shows more columns than 80-col terminal
- Fits within 120 columns
- "(+n cols)" count is accurate
- Readability maintained
- Width utilized effectively (not overly conservative)

**FAIL:**
- Same number of columns as 80-col terminal (width ignored)
- Exceeds 120 columns (width detection broken)
- Columns too narrow to read (over-cramming)
- Layout quality degraded
- Excessive padding returns

## Notes

**Dynamic Width Handling:**

The implementation should:
1. Detect terminal width
2. Calculate how many columns fit
3. Show maximum readable columns within width
4. Not use fixed column count

**Column Width Calculation:**

Each column needs minimum width:
- Header length + 2 (padding)
- OR max data length + 2
- OR minimum 8 characters (readability)

Don't cram columns if too narrow.

**120 Columns Common:**

Many developers use 120-column terminals:
- Modern monitors are wide
- More code/data visible
- Standard in many IDEs
- Good real-world test case
