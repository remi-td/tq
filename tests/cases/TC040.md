## Purpose

Verify that /logon supports all Teradata authentication mechanisms (TD2, LDAP, KRB5, TDNEGO) when switching connections.

## Scope

This test validates:
- TD2 authentication in /logon
- LDAP authentication in /logon
- KRB5 authentication in /logon
- TDNEGO authentication in /logon
- Authentication mechanism display in connection info
- Error messages specific to auth failures

## Prerequisites

- tq binary built in release mode
- Access to databases configured for different auth mechanisms
- Valid credentials for each auth type
- REPL mode functional

## Test Procedure

### Step 1: Test TD2 authentication (default)
```sql
tq> /logon user:pass@host:1025/db
# OR explicitly:
tq> /logon user:pass@host:1025/db?logmech=TD2
```

### Step 2: Verify TD2 connection
```sql
tq[db]> /logon
```

**Expected behavior:**
- Shows Authentication: TD2

### Step 3: Test LDAP authentication
```sql
tq[db]> /logon user:pass@host:1025/db?logmech=LDAP
```

### Step 4: Verify LDAP connection
```sql
tq[db]> /logon
```

**Expected behavior:**
- Shows Authentication: LDAP

### Step 5: Test KRB5 authentication (if available)
```sql
tq[db]> /logon user:pass@host:1025/db?logmech=KRB5
```

### Step 6: Verify KRB5 connection
```sql
tq[db]> /logon
```

**Expected behavior:**
- Shows Authentication: KRB5

### Step 7: Test TDNEGO authentication (if available)
```sql
tq[db]> /logon user:pass@host:1025/db?logmech=TDNEGO
```

### Step 8: Test invalid authentication mechanism
```sql
tq[db]> /logon user:pass@host:1025/db?logmech=INVALID
```

**Expected behavior:**
- Error: Unknown authentication mechanism
- Old connection preserved

## Pass/Fail Criteria

**PASS if:**
- All available auth mechanisms work
- Authentication method displayed correctly
- Invalid auth mechanism caught with error
- Old connection preserved on auth failure
- Clear error messages
- No crashes

**FAIL if:**
- Any auth mechanism fails unexpectedly
- Auth method not shown or incorrect
- Invalid mechanism not caught
- Crashes or hangs

## Notes

- Not all environments have all auth mechanisms configured
- Skip unavailable auth types with note in results
- TD2 most common (default)
- LDAP second most common in enterprises
- KRB5 and TDNEGO less common but important
- Auth mechanism should be clearly shown in /logon output
