# Test Case TC063: Result Paging - /pager on and /pager off Metacommands

## Purpose

Verify that the `/pager on` and `/pager off` metacommands enable and disable result paging correctly, and that the setting persists across queries within the same session.

## Prerequisites

- tq REPL mode active
- Live Teradata database connection

## Test Procedure

### Step 1: Check default pager state

```sql
tq> /help
```

Look for pager status in help or banner. Default should be "enabled" (per specifications).

### Step 2: Verify pager works by default

```sql
tq> SELECT TOP 100 * FROM DBC.TablesV;
```

**Expected:**
- Pager activates (interactive paging)
- Can navigate with j/k
- Exit with q

### Step 3: Disable pager

```sql
tq> /pager off
```

**Expected:**
- Confirmation message: "Pager disabled" or similar
- No error

### Step 4: Verify pager is disabled

```sql
tq> SELECT TOP 100 * FROM DBC.TablesV;
```

**Expected:**
- All results dump to terminal immediately
- NO paging (results scroll past)
- Output completes without user interaction
- Returns to prompt immediately

### Step 5: Re-enable pager

```sql
tq> /pager on
```

**Expected:**
- Confirmation message: "Pager enabled"
- No error

### Step 6: Verify pager is re-enabled

```sql
tq> SELECT TOP 100 * FROM DBC.TablesV;
```

**Expected:**
- Pager activates again
- Interactive paging works
- Can navigate and exit

### Step 7: Test persistence across queries

```sql
tq> /pager off
tq> SELECT 1 AS test1;
tq> SELECT TOP 10 * FROM DBC.DatabasesV;
tq> SELECT TOP 100 * FROM DBC.TablesV;
```

**Expected:**
- All three queries output without paging
- Setting persists across multiple queries

### Step 8: Test invalid commands

```sql
tq> /pager
tq> /pager invalid
tq> /pager ON (uppercase)
```

**Expected:**
- Clear error messages for invalid usage
- Help text showing correct syntax: `/pager on|off`
- Case-insensitive is acceptable: ON = on

## Verification

**Metacommand Recognition:**
- [ ] `/pager on` recognized
- [ ] `/pager off` recognized
- [ ] Commands execute without error

**State Management:**
- [ ] Pager enabled by default (or as configured)
- [ ] `/pager off` disables paging
- [ ] `/pager on` enables paging
- [ ] Setting persists across queries
- [ ] Setting is per-session (doesn't affect other sessions)

**Behavior Changes:**
- [ ] When enabled: large results trigger paging
- [ ] When disabled: all results dump immediately
- [ ] No paging for small results regardless of setting

**User Feedback:**
- [ ] Confirmation message on state change
- [ ] Clear error messages for invalid syntax
- [ ] Help text shows usage

## Expected Results

**Session Flow:**
```
tq> /pager on
Pager enabled

tq> SELECT TOP 100 * FROM DBC.TablesV;
[Pager activates, interactive mode]

tq> /pager off
Pager disabled

tq> SELECT TOP 100 * FROM DBC.TablesV;
[All results dump immediately, no paging]

tq> /pager on
Pager enabled
```

## Pass/Fail Criteria

**PASS:**
- `/pager on` enables paging
- `/pager off` disables paging
- Setting persists across queries
- Confirmation messages shown
- Behavior changes as expected

**FAIL:**
- Metacommands not recognized
- `/pager off` has no effect (paging still occurs) ← LIKELY CURRENT BUG
- Setting doesn't persist
- Crashes or errors on valid commands
- No feedback to user

## Notes

From sprint-8-root-cause-analysis.md:
> "The `/pager on|off` metacommand sets this value, but nothing ever reads it to conditionally enable paging."

State is tracked in `src/commands/repl/state.rs`:
```rust
pub fn set_pager(&mut self, enabled: bool) {
    self.pager_enabled = enabled;
}

pub fn is_pager_enabled(&self) -> bool {
    self.pager_enabled
}
```

But `is_pager_enabled()` is never called in executor. The fix must:
1. Check `state.is_pager_enabled()` before deciding to page
2. Respect the setting (don't page if disabled)
3. Implement paging if enabled and results are large

**Default State:**

Per specifications, pager should be enabled by default. This can be configured in state initialization:
```rust
pub fn new() -> Self {
    Self {
        pager_enabled: true,  // Default to enabled
        ...
    }
}
```
