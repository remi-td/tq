# TC-044-002: Driver Resolution Error Message Lists All Searched Paths

**Sprint:** 44
**Feature:** Runtime Driver Library Resolution (Issue #31)
**Acceptance Criteria:** AC-3
**Type:** Unit Test
**Requires DB:** No
**Requires Binary:** No

---

## Objective

Verify that when the Teradata driver library cannot be found in any candidate directory, the resulting `TqError::DriverLoad` error message includes all searched paths. Users must be able to see which directories were tried so they can diagnose the problem.

## Preconditions

- `resolve_driver_candidates` function exists (see TC-044-001)
- `DatabaseClient::new()` or a dedicated path resolution entry point accepts injectable `exe_path`
- A temp directory can be used as a fake "exe dir" that does not contain the library

## Test Scenarios

### Scenario 1: Error when all candidates fail

**Setup:**
- `exe_path` pointing to a temp dir (no library present)
- `flag = Some("/nonexistent/custom")` (directory does not exist)
- `env_var = None`
- `cwd` fallback also has no library

**Action:** Call the driver resolution with library loading (or simulate the error path by calling the function that produces the `DriverLoad` error)

**Expected:** Error message contains all three searched paths:
- The exe-relative path
- `/nonexistent/custom`
- `.` (cwd fallback)

**Assert:**
```
let err_msg = format!("{}", the_error);
assert!(err_msg.contains("/nonexistent/custom") || err_msg.contains("custom"));
// Exe dir path should appear
// CWD fallback should appear
```

### Scenario 2: Error message format is human-readable

**Setup:** Single candidate (exe dir only, no library present)

**Expected:** Error message is human-readable, mentions "searched" or "tried" or lists the path clearly

**Assert:** Error message is not just a raw OS error; it contains actionable context

### Scenario 3: Error via user_message() is actionable

**Setup:** Any failing driver resolution

**Expected:** `TqError::DriverLoad.user_message()` contains:
- The searched paths
- A suggestion to use `--driver-lib-dir`
- A note about ensuring the teradatasql library is present

**Assert:** Existing `user_message()` in `error.rs` for `DriverLoad` variant covers AC-3 message requirements

## Implementation Notes

The key design question: does the error from a failing `DatabaseClient::new()` list ALL searched paths, or just the final one that failed?

The implementation should collect all candidates first, attempt each, and on total failure produce an error that lists the full search list. This could be implemented as:

```rust
fn load_driver_from_candidates(candidates: &[PathBuf]) -> Result<()> {
    let mut errors = Vec::new();
    for candidate in candidates {
        match teradatarustapi::load_driver(candidate.to_str().unwrap_or(".")) {
            Ok(_) => return Ok(()),
            Err(e) => errors.push((candidate.clone(), e)),
        }
    }
    // All failed - produce error listing all searched paths
    let searched: Vec<String> = candidates.iter()
        .map(|p| p.display().to_string())
        .collect();
    Err(TqError::DriverLoad {
        path: searched.join(", "),
        message: format!("Library not found in any of: {}", searched.join(", ")),
    })
}
```

## Test Code Sketch

```rust
#[test]
fn test_driver_error_lists_searched_paths() {
    // Create a DatabaseClient::new() with a custom flag path pointing to /nonexistent
    // Since the library won't load in test env, we expect a DriverLoad error
    // The error message must contain the searched paths.
    // This test validates the error message, not driver loading.
    let config = ConnectionConfig { /* ... mock values ... */ };
    let result = DatabaseClient::new_with_exe_path(
        config,
        Some("/nonexistent/custom"),  // driver_lib_dir flag
        Path::new("/tmp/fake-exe"),   // injected exe path
    );
    assert!(result.is_err());
    let err_msg = format!("{}", result.unwrap_err());
    // The error should mention the searched paths
    assert!(
        err_msg.contains("/tmp/fake-exe") || err_msg.contains("fake-exe")
        || err_msg.contains("/nonexistent"),
        "Error message should list searched paths, got: {}", err_msg
    );
}
```

## Pass Criteria

- Error from failed driver resolution lists all candidate paths that were searched
- Error message is human-readable, not a raw OS error code
- `user_message()` includes `--driver-lib-dir` suggestion
