# TC101: TC097 Migration Validation (Sprint 68)

**Sprint:** 68
**Feature:** Objective 1 — Migrate TC097-A..H to `spawn_tq_repl_tiered` + `Stage::Query`
**Component:** `tests/interactive_tests.rs`
**Test Type:** Structural check (grep, no DB) + Interactive PTY execution (`#[ignore]`, live DB required)
**Related Strategy:** `tests/strategy/sprint-68-strategy.md` — Objective 1
**Specification:** `docs/sprints/sprint-68-planning.md` → Objective 1 Acceptance Criteria

---

## Overview

TC097 defined 8 interactive watch tests (A..H) that have timed out silently in Sprints 65, 66, and
67. The Sprint 66 tiered PTY harness (`spawn_tq_repl_tiered`, `TqPty`, `Stage::*`) was built
specifically to produce observable PTY dump evidence on timeout instead of a silent `ExpectTimeout`.
Sprint 68 migrates all 8 tests to that harness.

This test case covers two validation layers:

1. **TC101-code-check (structural):** Confirm by grep that the migration actually happened — all 8
   test functions use `TqPty` / `spawn_tq_repl_tiered` + `expect_stage(Stage::...)` and the two
   hardcoded `set_expect_timeout` overrides are removed.

2. **TC101-A..H (execution):** Run the 8 migrated tests with `--ignored`. PASS means either the
   test passes outright, or it times out and produces a PTY dump file at
   `tests/results/sprint-66/<test_name>.pty.log` with non-zero byte count. Silent
   `ExpectTimeout` without a dump file is NOT acceptable.

## Migration Pattern Reference

Each migrated test follows this structure (documented here for the architect's implementation):

**Before (legacy pattern):**
```rust
#[test]
#[ignore]
fn test_sessions_watch_q_exits() {
    let mut p = spawn_tq_repl();
    p.expect("Connected to").expect("Failed to connect");
    std::thread::sleep(Duration::from_secs(1));
    p.send_line("/sessions --watch --interval 1").expect("send watch command");
    std::thread::sleep(Duration::from_secs(2));
    // ... test body
    p.expect(expectrl::Regex("tq>|tq >")).expect("REPL prompt must return");
}
```

**After (tiered harness pattern):**
```rust
#[test]
#[ignore]
fn test_sessions_watch_q_exits() {
    let mut p = spawn_tq_repl_tiered("test_sessions_watch_q_exits");
    p.expect_stage(Stage::Connect, "Connected to")
        .expect("connect stage: failed to see 'Connected to'");
    std::thread::sleep(Duration::from_secs(1));
    p.session_mut().send_line("/sessions --watch --interval 1")
        .expect("send /sessions --watch");
    std::thread::sleep(Duration::from_secs(2));
    // ... test body using p.session_mut() for sends
    p.expect_stage(Stage::Prompt, expectrl::Regex("tq>|tq >"))
        .expect("prompt stage: REPL prompt must reappear");
}
```

**TC101-H specifically:** The two calls to `p.set_expect_timeout(Some(Duration::from_secs(30)))`
at the former lines 3554 and 3561 must be deleted. The `TqPty` wrapper manages timeout budgets
through `expect_stage`; direct `set_expect_timeout` overrides bypass the harness.
