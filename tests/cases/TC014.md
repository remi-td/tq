## Purpose

Verify that tq returns correct exit codes for various success and failure scenarios following UNIX conventions.

## Scope

This test validates:
- Exit code 0 for success
- Exit code 1 for runtime errors
- Exit code 2 for usage errors
- Consistency across commands

## Prerequisites

- tq binary is built and available
- `.env` file configured with valid connection credentials for success scenarios
- Valid and invalid test scenarios

## Test Procedure

### Step 1: Success scenarios (exit code 0)
```bash
# Successful ping (using credentials from .env file)
tq ping > /dev/null 2>&1
echo "Ping: $?"

# Successful query
tq query "SELECT 1" > /dev/null 2>&1
echo "Query: $?"

# Help
tq --help > /dev/null 2>&1
echo "Help: $?"

# Version
tq --version > /dev/null 2>&1
echo "Version: $?"
```

### Step 2: Usage errors (exit code 2)
```bash
# Invalid flag
tq --invalid-flag ping 2> /dev/null
echo "Invalid flag: $?"

# Missing required argument
tq query 2> /dev/null
echo "Missing query: $?"

# Invalid connection string format
tq -l "invalid" ping 2> /dev/null
echo "Invalid connection string: $?"

# Invalid output format
tq query --format invalid "SELECT 1" 2> /dev/null
echo "Invalid format: $?"
```

### Step 3: Runtime errors (exit code 1)
```bash
# Connection failure
tq -l "user:pass@nonexistent:1025/db" ping 2> /dev/null
echo "Connection failure: $?"

# Query syntax error
tq query "INVALID SQL QUERY" 2> /dev/null
echo "Query syntax error: $?"

# File not found
tq query --file /nonexistent/file.sql 2> /dev/null
echo "File not found: $?"

# Permission denied for output
tq query --output /root/test.txt "SELECT 1" 2> /dev/null
echo "Permission denied: $?"
```

### Step 4: Verify shell script integration
```bash
cat > /tmp/test_exit_codes.sh << 'EOF'
#!/bin/bash
set -e  # Exit on error

# Using credentials from .env file
# This should succeed
tq query "SELECT 1" > /dev/null

echo "Script completed successfully"
EOF

chmod +x /tmp/test_exit_codes.sh
/tmp/test_exit_codes.sh
echo "Script exit code: $?"
rm /tmp/test_exit_codes.sh
```

### Step 5: Test with || operator
```bash
tq -l "invalid" ping 2> /dev/null || echo "Ping failed as expected (exit: $?)"
```

### Step 6: Test with && operator
```bash
tq ping > /dev/null 2>&1 && echo "Ping succeeded"
```

## Pass/Fail Criteria

**PASS if:**
- All successful operations return 0
- Usage errors return 2
- Runtime errors return 1
- Exit codes are consistent across commands
- Scripts can detect success/failure via exit codes
- Shell operators (&&, ||) work as expected

**FAIL if:**
- Success returns non-zero
- Errors return zero
- Exit codes are inconsistent
- Wrong exit code for error type (1 vs 2)

## Notes

- Exit codes are critical for shell scripting
- 0 = success
- 1 = general/runtime error
- 2 = usage/argument error
- 130 = interrupted (Ctrl-C) - future enhancement
- Exit codes should match documentation
- Consistent behavior across all commands
