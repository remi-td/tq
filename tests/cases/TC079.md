# Test Case TC079: Table Display - Ultra-Wide Terminal Handling (200+ cols)

## Purpose

Verify that table display handles ultra-wide terminals (200+ columns) gracefully, showing maximum useful data without degrading into unreadable extreme widths.

## Scope

**Testing:**
- Terminal width detection (200+ columns)
- Maximum reasonable columns shown
- Column width limits enforced
- Layout remains professional
- Edge case handling

**Not Testing:**
- Normal terminal widths (other TCs)
- Infinite width scenarios

## Prerequisites

- tq binary with Sprint 11 fixes
- Very wide monitor or terminal (200+ cols)
- Test query with many columns

## Test Procedure

### Setup

```bash
# Set terminal to 200+ columns
# May require ultra-wide monitor or manual terminal resize

tput cols  # Verify: 200+

./target/release/tq repl
```

### Execution Steps

**Step 1: Execute many-column query**

```sql
tq> SELECT TOP 5 * FROM DBC.TablesV;
```

**Expected outcome:**
- Shows many columns (15-20+)
- Each column still readable
- Column widths reasonable (not excessively wide)
- Professional layout maintained

**Step 2: Verify column width sanity**

Observe individual column widths:

**Expected outcome:**
- No column exceeds ~50 characters (even with space available)
- Text truncated within cells if needed
- Width limits prevent absurd layouts

**Step 3: Test with query containing fewer columns**

```sql
tq> SELECT DatabaseName, TableName FROM DBC.TablesV LIMIT 5;
```

**Expected outcome:**
- Columns size appropriately (not stretched to 200 cols)
- Dynamic width calculation based on content
- Not artificially padded to fill terminal

### Verification

**Sanity Checklist:**

- [ ] Table displays correctly
- [ ] Readable and professional
- [ ] Column widths reasonable
- [ ] No absurd stretching
- [ ] Handles edge case gracefully

### Cleanup

```bash
tq> /quit
```

## Expected Results

**Output should remain reasonable:**

- Shows many columns (15-25)
- Each column appropriately sized for content
- Not stretched artificially
- Maintains readability

## Pass/Fail Criteria

**PASS:**
- Displays correctly in ultra-wide terminal
- Column widths remain reasonable (<50 chars)
- Layout professional
- Shows maximum useful columns
- No crashes or layout corruption

**FAIL:**
- Crashes with very wide terminal
- Columns stretched to absurd widths
- Unreadable layout
- Width detection breaks

## Notes

**Edge Case Consideration:**

Ultra-wide terminals are rare but should work:
- 34" ultra-wide monitors
- Terminal spanning multiple monitors
- Unusual setups

Implementation should:
- Handle gracefully
- Not crash
- Apply reasonable limits
- Maintain readability

**Low Priority:**

Most users have 80-160 column terminals. Ultra-wide is edge case. Lower priority testing.
