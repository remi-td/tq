# TC-047-001: Bug #36 — /inspect DDL & Column Type Fix for Views

## Metadata

| Field | Value |
|-------|-------|
| **Test ID** | TC-047-001 |
| **Title** | `/inspect` on a view must show complete DDL and non-NULL column types |
| **Category** | Unit Test + Integration Test |
| **Priority** | Critical (P0) |
| **Feature** | Sprint 47 — Bug #36: /inspect DDL & Column Type Fix |
| **Test Type** | Unit (no DB) + Integration (DB required, `#[ignore]`) |
| **DB Required** | No for unit tests; Yes for integration tests |
| **Created** | 2026-03-23 |
| **Acceptance Criteria** | AC-1, AC-2, AC-3, AC-4 |

## Purpose

Verify that after the Bug #36 fix:
1. `/inspect <view>` shows complete view definition text — not truncated or garbled. The root cause is that Teradata's `SHOW VIEW` may return the DDL across multiple rows (one row per continuation segment), and the previous code may only take the first row.
2. `/inspect <view>` shows actual column types from `DBC.ColumnsV`, not `[NULL]`. The previous implementation may have used a view or query that returns NULL for ColumnType on views.
3. `/inspect <macro>` shows the full macro definition, fetched via `SHOW MACRO`.

## Acceptance Criteria Coverage

- **AC-1**: `/inspect dbc.tables` shows complete view definition text (not garbled/truncated)
- **AC-2**: `/inspect` on a view shows column types from DBC.ColumnsV (not [NULL])
- **AC-3**: `/inspect` on a macro shows full macro definition
- **AC-4**: Unit tests cover DDL retrieval for views and macros

Add the following tests to the `#[cfg(test)]` module in `src/commands/inspect.rs`:

// TC-047-001-A: Multi-row DDL concatenation — view
// Simulates SHOW VIEW returning 3 rows (Teradata splits long DDL across rows)
#[test]
fn ddl_multirow_all_rows_concatenated() {
    // Simulate what query_definition processes internally:
    // Build a Vec<String> as if extracted from result.rows
    let rows = vec![
        "CREATE VIEW \"DBC\".\"Tables\" AS".to_string(),
        " SELECT TableName, DatabaseName".to_string(),
        " FROM DBC.TVM WHERE TVMNameI = 'T'".to_string(),
    ];
    let definition = rows.join("");
    assert!(definition.contains("CREATE VIEW"), "First row must be present");
    assert!(definition.contains("FROM DBC.TVM"), "Last row must be present");
    assert!(
        !definition.is_empty(),
        "Multi-row result must not produce empty definition"
    );
}

// TC-047-001-B: NULL row filtering — rows with "[NULL]" are excluded
#[test]
fn ddl_null_rows_filtered_out() {
    // Simulate the concatenation logic skipping [NULL] values
    let raw_values = vec!["CREATE VIEW db.v AS SELECT 1".to_string(), "[NULL]".to_string()];
    let definition: String = raw_values
        .into_iter()
        .filter(|s| s != "[NULL]")
        .collect::<Vec<_>>()
        .join("");
    assert_eq!(definition, "CREATE VIEW db.v AS SELECT 1");
    assert!(!definition.contains("[NULL]"), "[NULL] rows must not appear in definition");
}

// TC-047-001-C: Empty result — SHOW VIEW returns 0 rows → empty definition (no panic)
#[test]
fn ddl_empty_result_returns_empty_string() {
    let rows: Vec<String> = vec![];
    let definition: String = rows.join("");
    assert_eq!(definition, "", "Empty result must produce empty definition");
    // No panic is the implicit assertion here
}

// TC-047-001-D: View SQL uses SHOW VIEW (not SHOW TABLE)
#[test]
fn ddl_view_sql_uses_show_view() {
    // Verify the SQL construction for views uses SHOW VIEW
    let db = "DBC";
    let obj = "Tables";
    let kind = "V";
    let sql = match kind {
        "V" => format!("SHOW VIEW \"{}\".\"{}\"", db, obj),
        "M" => format!("SHOW MACRO \"{}\".\"{}\"", db, obj),
        _ => String::new(),
    };
    assert!(sql.starts_with("SHOW VIEW"), "View DDL query must use SHOW VIEW");
    assert!(sql.contains("\"DBC\""), "Database part must be quoted");
    assert!(sql.contains("\"Tables\""), "Object part must be quoted");
}

// TC-047-001-E: Macro SQL uses SHOW MACRO (not SHOW VIEW)
#[test]
fn ddl_macro_sql_uses_show_macro() {
    let db = "mydb";
    let obj = "mymacro";
    let kind = "M";
    let sql = match kind {
        "V" => format!("SHOW VIEW \"{}\".\"{}\"", db, obj),
        "M" => format!("SHOW MACRO \"{}\".\"{}\"", db, obj),
        _ => String::new(),
    };
    assert!(sql.starts_with("SHOW MACRO"), "Macro DDL query must use SHOW MACRO");
    assert!(sql.contains("\"mydb\""), "Database part must be double-quoted");
    assert!(sql.contains("\"mymacro\""), "Object part must be double-quoted");
}

// TC-047-001-F: Unknown kind returns empty definition (tables have no SHOW DDL)
#[test]
fn ddl_table_kind_returns_empty() {
    let db = "mydb";
    let obj = "mytable";
    let kind = "T";
    let sql = match kind {
        "V" => format!("SHOW VIEW \"{}\".\"{}\"", db, obj),
        "M" => format!("SHOW MACRO \"{}\".\"{}\"", db, obj),
        _ => String::new(),
    };
    assert!(sql.is_empty(), "Table kind must return empty SQL (no SHOW statement)");
}

use std::process::Command;

fn tq_binary() -> String {
    std::env::var("TQ_BINARY").unwrap_or_else(|_| "./target/release/tq".to_string())
}

fn logon() -> String {
    std::env::var("TQ_LOGON").expect("TQ_LOGON must be set for integration tests")
}

// TC-047-001-G: View DDL not truncated (AC-1)
// dbc.tables is a well-known Teradata system view — always available
#[test]
#[ignore]
fn inspect_view_ddl_not_truncated() {
    let output = Command::new(tq_binary())
        .args(["-l", &logon(), "inspect", "dbc.tables"])
        .output()
        .expect("Failed to run tq inspect");

    let stdout = String::from_utf8_lossy(&output.stdout);

    assert!(output.status.success(), "tq inspect dbc.tables must exit 0");
    assert!(
        stdout.contains("── Definition ──") || stdout.contains("Definition"),
        "Output must contain Definition section for a view"
    );
    // The DDL must contain some SQL keywords — a truncated/garbled DDL would not
    assert!(
        stdout.contains("SELECT") || stdout.contains("CREATE") || stdout.contains("REPLACE"),
        "View definition must contain SQL keywords (not truncated/garbled)"
    );
}

// TC-047-001-H: View column types are not [NULL] (AC-2)
#[test]
#[ignore]
fn inspect_view_column_types_not_null() {
    let output = Command::new(tq_binary())
        .args(["-l", &logon(), "inspect", "dbc.columns"])
        .output()
        .expect("Failed to run tq inspect");

    let stdout = String::from_utf8_lossy(&output.stdout);

    assert!(output.status.success(), "tq inspect dbc.columns must exit 0");
    // Count the number of [NULL] occurrences in the column type column
    // In the column listing section, [NULL] should not appear as a Type value
    let columns_section_start = stdout.find("── Columns").unwrap_or(0);
    let columns_section = &stdout[columns_section_start..];
    // [NULL] appearing in the Type position (2nd column) indicates the bug
    // Heuristic: lines with [NULL] followed by whitespace suggest a type-column NULL
    let null_count = columns_section.matches("[NULL]").count();
    assert_eq!(
        null_count, 0,
        "Column types must not contain [NULL] — found {} occurrences in: {}",
        null_count, &columns_section[..200.min(columns_section.len())]
    );
}

// TC-047-001-I: JSON format does not have null column types (AC-2, JSON path)
#[test]
#[ignore]
fn inspect_view_json_column_types_not_null() {
    let output = Command::new(tq_binary())
        .args(["-l", &logon(), "inspect", "--format", "json", "dbc.columns"])
        .output()
        .expect("Failed to run tq inspect --format json");

    let stdout = String::from_utf8_lossy(&output.stdout);

    assert!(output.status.success(), "tq inspect --format json must exit 0");
    let json: serde_json::Value = serde_json::from_str(&stdout)
        .unwrap_or_else(|e| panic!("Output must be valid JSON: {}\nOutput was: {}", e, stdout));

    let columns = json["columns"].as_array()
        .expect("JSON must have 'columns' array");

    assert!(!columns.is_empty(), "columns array must not be empty for dbc.columns");

    for col in columns {
        let type_val = &col["type"];
        assert!(
            !type_val.is_null(),
            "Column 'type' must not be JSON null — found null for column: {:?}",
            col["name"]
        );
        let type_str = type_val.as_str().unwrap_or("");
        assert!(
            !type_str.contains("[NULL]"),
            "Column 'type' must not contain '[NULL]' string — got: {}",
            type_str
        );
    }
}

// TC-047-001-J: Macro full definition (AC-3) — uses a known DBC macro if available
#[test]
#[ignore]
fn inspect_macro_shows_full_definition() {
    // Note: If no macro is available in the test database, this test may be skipped.
    // Use a well-known system macro if available, or create a test macro.
    // This test is a best-effort check — if DBC has no macros, the output should
    // contain an appropriate "no definition" message, not an error.
    let output = Command::new(tq_binary())
        .args(["-l", &logon(), "inspect", "dbc.showtables"])
        .output()
        .expect("Failed to run tq inspect on a macro");

    // Either succeeds with macro definition, or gives "not found" for missing macro
    // The key assertion is: no panic, no empty output, no process crash
    assert!(
        output.status.code().is_some(),
        "tq inspect must complete (not crash) even for macros"
    );
    let stdout = String::from_utf8_lossy(&output.stdout);
    // If the macro exists, DDL should contain EXEC or similar macro syntax
    // If not found, error message should be present
    assert!(
        !stdout.is_empty(),
        "Output must not be completely empty"
    );
}
