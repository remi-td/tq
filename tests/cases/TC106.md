# TC106: REQUIRED-Test Rule in Testing Documentation (Sprint 68)

**Sprint:** 68
**Feature:** Objective 3 — Codify the REQUIRED-test rule in `docs/testing/approach.md` and `docs/testing/philosophy.md`
**Component:** `docs/testing/approach.md`, `docs/testing/philosophy.md`
**Test Type:** Documentation review (grep, no DB, no PTY)
**Related Strategy:** `tests/strategy/sprint-68-strategy.md` — Objective 3
**Specification:** `docs/sprints/sprint-68-planning.md` → Objective 3 Acceptance Criteria

---

## Overview

The rule "a test classified REQUIRED in the test strategy that is not authored must be reported as
a MEDIUM-severity gap — it is not resolved by code inspection or manual verification" was
introduced in `docs/testing/honest-assessment.md` in Sprint 67. However, the canonical testing
methodology documents (`approach.md` and `philosophy.md`) do not reference it.

This means a new quality-validator agent onboarded to the project via `docs/testing/` would miss
the rule entirely. Sprint 68 propagates the rule into the canonical docs so it is impossible to
overlook.

This TC validates that the text is present in the correct files. Documentation changes are
verified by grep — there is no executable code to run.

## TC106-approach: `docs/testing/approach.md` Verification

**Requirement:** AC-OBJ3-1 — the file must contain the explicit statement about REQUIRED-test gaps.

**BLOCKED condition:** Never blocked.

### Required Text

The acceptance criterion specifies this exact statement must be present:

> "A test classified REQUIRED in the test strategy that is not authored must be reported as a
> MEDIUM-severity gap in the quality report — it is not resolved by code inspection or manual
> verification."

### Verification Steps

```bash
# Step 1: Confirm "REQUIRED" and "test strategy" co-appear in the file
grep -n "REQUIRED" docs/testing/approach.md

# Step 2: Confirm "MEDIUM-severity" appears in the file
grep -n "MEDIUM-severity" docs/testing/approach.md

# Step 3: Confirm the key clause about code inspection
grep -n "code inspection\|manual verification" docs/testing/approach.md
```

**Pass criteria:**
- Step 1: At least one line contains `REQUIRED` in the context of test strategy or test
  classification (not just in passing references).
- Step 2: At least one line contains `MEDIUM-severity` (confirming the severity classification
  is documented).
- Step 3: At least one line references that code inspection or manual verification is NOT
  sufficient to close a REQUIRED gap.

**Single combined check:**
```bash
grep -c "REQUIRED\|MEDIUM-severity\|code inspection" docs/testing/approach.md
```
**Pass criterion:** Output is 3 or greater (all three terms appear in the file).

## TC106-philosophy: `docs/testing/philosophy.md` Verification

**Requirement:** AC-OBJ3-2 — the file must be updated to align with the REQUIRED-test rule.
Alignment means either: (a) the philosophy file contains equivalent text, or (b) it cross-references
`approach.md` where the rule is defined.

**BLOCKED condition:** Never blocked.

### Verification Steps

```bash
# Option A: Direct rule statement
grep -n "REQUIRED\|MEDIUM-severity\|required test\|unauthored" docs/testing/philosophy.md

# Option B: Cross-reference to approach.md or honest-assessment.md
grep -n "approach.md\|honest-assessment\|REQUIRED-test\|test gap" docs/testing/philosophy.md
```

**Pass criteria (either option satisfies AC-OBJ3-2):**
- Option A: At least one match for `REQUIRED` or `MEDIUM-severity` in the file, in a context
  that references the test strategy classification.
- Option B: At least one reference to `approach.md` or `honest-assessment.md` in the context
  of test authoring requirements.
