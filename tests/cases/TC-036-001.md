## Purpose

Verify that `tq help config` output includes project config section with complete information about `.tq.toml` files and displays the 5-level configuration precedence hierarchy clearly.

## Acceptance Criteria Coverage

- **AC-1**: `tq help config` includes project config section with `.tq.toml` description
- **AC-2**: `tq help config` shows 5-level precedence hierarchy (defaults → user config → project config → env vars → CLI)

## Scope

This test validates:
- Project config section exists in help text
- `.tq.toml` file is mentioned
- `.tq.toml.example` is mentioned for getting started
- 5-level precedence hierarchy is displayed
- Precedence hierarchy shows correct order: defaults → user → project → env → CLI
- Help text content is clear and comprehensive

## Prerequisites

- Rust test framework available
- `tq` binary built
- Help text generation implementation complete

## Test Procedure

### Unit Test Implementation:

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_help_config_includes_project_config_section() {
        let help_text = generate_config_help();

        // Verify project config section exists
        assert!(
            help_text.contains("PROJECT CONFIGURATION") ||
            help_text.contains("Project Config") ||
            help_text.contains(".tq.toml"),
            "Help text should include project config section"
        );

        // Verify .tq.toml is mentioned
        assert!(
            help_text.contains(".tq.toml"),
            "Help text should mention .tq.toml file"
        );
    }

    #[test]
    fn test_help_config_mentions_example_file() {
        let help_text = generate_config_help();

        // Verify .tq.toml.example is mentioned
        assert!(
            help_text.contains(".tq.toml.example"),
            "Help text should mention .tq.toml.example for getting started"
        );
    }

    #[test]
    fn test_help_config_shows_precedence_hierarchy() {
        let help_text = generate_config_help();

        // Verify precedence hierarchy section exists
        assert!(
            help_text.contains("precedence") ||
            help_text.contains("PRECEDENCE") ||
            help_text.contains("priority"),
            "Help text should include precedence hierarchy section"
        );

        // Verify all 5 levels mentioned
        let levels = vec!["default", "user", "project", "environment", "command"];
        for level in levels {
            assert!(
                help_text.to_lowercase().contains(level),
                "Help text should mention '{}' in precedence hierarchy",
                level
            );
        }
    }

    #[test]
    fn test_help_config_precedence_order() {
        let help_text = generate_config_help();

        // Find positions of each level in help text
        let text_lower = help_text.to_lowercase();

        // These should appear in order (earlier = lower precedence)
        let default_pos = text_lower.find("default").unwrap();
        let user_pos = text_lower.find("user config").unwrap_or(text_lower.find("user").unwrap());
        let project_pos = text_lower.find("project").unwrap();
        let env_pos = text_lower.find("environment").unwrap_or(text_lower.find("env var").unwrap());
        let cli_pos = text_lower.find("command").unwrap_or(text_lower.find("cli").unwrap());

        // Verify order (lower precedence appears before higher precedence)
        assert!(default_pos < project_pos, "Defaults should appear before project config");
        assert!(user_pos < project_pos, "User config should appear before project config");
        assert!(project_pos < env_pos, "Project config should appear before environment");
        assert!(env_pos < cli_pos, "Environment should appear before CLI arguments");
    }

    #[test]
    fn test_help_config_describes_project_config_discovery() {
        let help_text = generate_config_help();

        // Verify directory walking behavior is described
        assert!(
            help_text.contains("current directory") ||
            help_text.contains("walks up") ||
            help_text.contains("parent"),
            "Help text should describe how .tq.toml is discovered"
        );
    }
}
```

### Integration Test Implementation:

#[test]

    let output = Command::new(TQ_BIN)
        .args(&["help", "config"])

        .expect("Failed to execute tq help config");

    assert!(output.status.success(), "Command should succeed");

    let stdout = String::from_utf8_lossy(&output.stdout);

    assert!(
        stdout.contains("PROJECT") && stdout.contains(".tq.toml"),
        "Output should include project config section"
    );
