## Overview

Sprint 67 introduced horizontal scroll-to-match: when a search match is in a column outside the
current horizontal viewport, the pager calls `scroll_to_match_index` which adjusts `col_offset`
so the matched column is visible. This behavior was classified REQUIRED in the Sprint 67 strategy
but the test was not authored. Sprint 68 closes that gap.

The unit test creates a `Pager` with:
- 8 narrow columns (to control `visible_column_count()`)
- 5 rows where all cells are `"x"` except row 2, column 6, which contains `"TARGET"`
- A `term_width` calibrated so that `visible_column_count()` returns 3
- Initial `col_offset = 0`

After calling `submit_search("TARGET")`:
- The match is at `col = 6`, outside `[col_offset=0, col_offset+3=3)`
- `scroll_to_match_index` must set `col_offset = 6 + 1 - 3 = 4`
- Column 6 is now within `[4, 4+3=7)` — visible

## TC102-U01: `scroll_to_match_snaps_to_rightmost_column`

**Requirement:** AC-OBJ2-1 — when a search match is in a column outside the horizontal viewport,
`col_offset` advances so the matched column is in view.

**Location:** `src/commands/repl/pager.rs`, `#[cfg(test)]` module

**BLOCKED condition:** Never blocked. Pure in-memory unit test.

### Fixture Design

The test must construct a `Pager` where `visible_column_count()` reliably returns 3.
The method computes: `term_width / (max_col_width + border_chars)`.

A safe approach: 8 columns, each named `"cN"` with values `"x"` (1 char).
Column display width ≈ `max(header.len(), max_value.len()) + padding` = `max(2, 1) + 2 = 4`.
With `term_width = 14`: `14 / 4 = 3` visible columns.

The exact formula is implementation-specific. The test should:
1. Construct the pager.
2. Assert `pager.visible_column_count() == 3` before searching (guards the fixture calibration).
3. Assert `pager.col_offset == 0` before searching.
4. Call `pager.submit_search("TARGET")`.
5. Assert `pager.col_offset > 0` (scrolled right — always true if visible < 7 < 8 cols).
6. Assert that column 6 is within `[col_offset, col_offset + visible_column_count())`.

If `visible_column_count()` cannot be pinned to exactly 3 (due to border/padding details), the
test may assert `col_offset > 0` and column 6 is visible, rather than `col_offset == 4` exactly.

### Test Code

```rust
#[test]
fn scroll_to_match_snaps_to_rightmost_column() {
    use crate::db::types::Value;
    use crate::format::table::QueryResult;
    use std::collections::HashMap;

    // Build an 8-column result set.
    // All cells "x", except row index 2 (0-based), column index 6 = "TARGET".
    let col_names: Vec<String> = (0..8).map(|i| format!("c{}", i)).collect();
    let rows: Vec<Vec<Value>> = (0..5)
        .map(|r| {
            (0..8)
                .map(|c| {
                    if r == 2 && c == 6 {
                        Value::String("TARGET".to_string())
                    } else {
                        Value::String("x".to_string())
                    }
                })
                .collect()
        })
        .collect();

    let result = QueryResult {
        columns: col_names.iter().map(|n| n.as_str()).collect(),
        rows,
        // Use defaults for other fields
        ..QueryResult::default()
    };

    let config = PagerConfig {
        term_width: 14,  // Calibrated: 14 / ~4 chars-per-col ≈ 3 visible
        page_size: 10,   // All 5 rows visible
        ..PagerConfig::default()
    };

    let mut pager = Pager::new(&result, &config);

    // Pre-condition: no scroll yet
    assert_eq!(pager.col_offset, 0, "Initial col_offset must be 0");

    // The fixture calibration guard: confirm visible is small enough
    // that column 6 is initially out of view.
    let visible = pager.visible_column_count();
    assert!(
        visible <= 6,
        "visible_column_count() must be ≤ 6 for column 6 to be off-screen; got {}",
        visible
    );
    assert!(
        pager.col_offset + visible <= 6,
        "Column 6 must be initially out of viewport [0, {})",
        pager.col_offset + visible
    );

    // Execute: search triggers scroll_to_match_index
    pager.submit_search("TARGET");

    // Post-condition: col_offset advanced
    assert!(
        pager.col_offset > 0,
        "col_offset must have advanced; got {}",
        pager.col_offset
    );

    // Column 6 must now be in viewport [col_offset, col_offset + visible)
    let visible_after = pager.visible_column_count();
    assert!(
        pager.col_offset <= 6 && 6 < pager.col_offset + visible_after,
        "Column 6 must be in viewport [{}, {}); col_offset = {}",
        pager.col_offset,
        pager.col_offset + visible_after,
        pager.col_offset
    );

    // Optional exact assertion (use if visible == 3 is confirmed):
    // assert_eq!(pager.col_offset, 4, "col_offset = 6 + 1 - 3 = 4");
}
```

**Notes for implementation:**
- `Pager::new`, `PagerConfig`, `QueryResult`, and `Value` types must be importable from within the
  `#[cfg(test)]` block. Use `super::*` or the full crate path.
- If `QueryResult::default()` does not exist, construct the minimal struct directly.
- `pager.visible_column_count()` is private but accessible from `#[cfg(test)]` in the same module.
- `pager.submit_search(...)` is the public-facing test entry point that calls `scroll_to_match_index`.
- The exact assertion `col_offset == 4` is commented out; use it if the `term_width=14` fixture
  reliably yields `visible == 3`. The `col_offset > 0` + in-viewport assertion is always valid.

### Pass Criteria

1. Before search: `pager.col_offset == 0`.
2. Before search: `pager.col_offset + visible_column_count() <= 6` (column 6 is off-screen).
3. After `submit_search("TARGET")`: `pager.col_offset > 0`.
4. After search: column 6 is within `[col_offset, col_offset + visible_column_count())`.
