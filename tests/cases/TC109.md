**Components:** `src/commands/space.rs` (new), `src/commands/severity.rs` (shared with TC110)
**Test Type:** Unit (owned by `rust-teradata-architect`, colocated in `src/`) + Integration (live DB,

## Division of labor (Sprint 76 convention)

Per `CLAUDE.md`, `rust-teradata-architect` owns production code *and unit tests*;
`quality-validator` owns `tests/` (integration/interactive) and does not edit `src/`. The 13 unit
tests below (TC109-U01–U13) are implemented inside `src/commands/space.rs`'s own `#[cfg(test)] mod
tests`, per `docs/design/space-analysis.md` §Testing Strategy — several of the functions they
exercise (`parse_target`, `display_table`/`display_json`/`display_csv`/`display_markdown`) are
module-private by design, so they are not reachable from an external `tests/` binary regardless of
timing. The 14 integration tests (TC109-I01–I14) are implemented in `tests/integration_space.rs` and
spawn the built `tq` binary against the live database from `.env` (`TQ_LOGON`).

### Notes on assertion style

Because `src/commands/space.rs` did not exist yet when this file was authored (architect
implementing in parallel per the Sprint 76 execution plan), the integration assertions are
deliberately black-box: exit codes, JSON/CSV/markdown structural validity, row counts via
line-splitting, and substring presence of known table/database names — rather than exact JSON key
names or error message wording, which were not yet defined. `docs/design/space-analysis.md`'s error
example (`Error: 'dbspace' operates on databases only, but ...`) should be used to tighten
TC109-I04's assertion once the exact wording is confirmed live.

### Descoped (Phase 2 coordinator ruling)

No fuzzy-match/spelling-suggestion helper exists anywhere in `src/`. TC109-I06/I07 assert only the
project's standard not-found message; the strategy doc's original "with spelling suggestion if the
helper exists" language is resolved to "no suggestion asserted" for Sprint 76.
