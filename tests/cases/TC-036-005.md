## Purpose

Verify that `/repeat` command works correctly with all types of SQL statements: SELECT (queries), INSERT/UPDATE/DELETE (DML), and CREATE/DROP/ALTER (DDL).

## Acceptance Criteria Coverage

- **AC-10**: `/repeat` works after any SQL statement (SELECT, INSERT, DDL, etc.)

## Scope

This test validates:
- `/repeat` after SELECT query
- `/repeat` after INSERT statement
- `/repeat` after UPDATE statement
- `/repeat` after DELETE statement
- `/repeat` after CREATE TABLE (DDL)
- `/repeat` after DROP TABLE (DDL)
- `/repeat` after ALTER TABLE (DDL)
- State tracking works for all SQL types

## Prerequisites

- Rust test framework available
- `tq` binary built with REPL support
- expectrl crate for PTY testing
- Database connection available
- Test database with write permissions
- Temporary test tables can be created/dropped

## Test Procedure

### Interactive Test 1: Repeat SELECT Query

```rust
#[test]
#[ignore] // Requires database connection
fn test_repeat_select_query() {
    let mut repl = spawn_repl().expect("Failed to spawn REPL");

    // Execute SELECT query
    repl.send_line("SELECT CURRENT_DATE AS today;").unwrap();
    repl.expect("today").unwrap();

    // Repeat SELECT
    repl.send_line("/repeat").unwrap();
    repl.expect("today").unwrap();

    // Should see same date (query re-executed)
}
```

### Interactive Test 2: Repeat INSERT Statement

```rust
#[test]
#[ignore] // Requires database connection
fn test_repeat_insert_statement() {
    let mut repl = spawn_repl().expect("Failed to spawn REPL");

    // Create test table
    let table_name = format!("test_repeat_insert_{}", random_suffix());
    repl.send_line(&format!("CREATE TABLE {} (id INT, value VARCHAR(50));", table_name))
        .unwrap();
    repl.expect("created").unwrap_or_else(|_| repl.expect("OK").unwrap());

    // Execute INSERT
    repl.send_line(&format!("INSERT INTO {} VALUES (1, 'first');", table_name))
        .unwrap();
    repl.expect("1 row").unwrap_or_else(|_| repl.expect("OK").unwrap());

    // Repeat INSERT - should insert another row
    repl.send_line("/repeat").unwrap();
    repl.expect("1 row").unwrap_or_else(|_| repl.expect("OK").unwrap());

    // Verify 2 rows inserted
    repl.send_line(&format!("SELECT COUNT(*) FROM {};", table_name)).unwrap();
    repl.expect("2").unwrap();

    // Cleanup
    repl.send_line(&format!("DROP TABLE {};", table_name)).unwrap();
}
```

## Expected Results

### Interactive Test Results:
1. **SELECT**: `/repeat` re-executes query and shows results
2. **INSERT**: `/repeat` inserts another row (DML repeats successfully)
3. **UPDATE**: `/repeat` updates again (counter incremented twice)
4. **DELETE**: `/repeat` attempts deletion again (0 rows affected second time)
5. **CREATE TABLE**: `/repeat` fails with "already exists" error (expected)
6. **DROP TABLE**: `/repeat` fails with "does not exist" error (expected)
7. **ALTER TABLE**: `/repeat` fails with "already exists" error (expected)
8. **Mixed types**: `/repeat` correctly remembers last SQL regardless of type

## Pass/Fail Criteria

**PASS if:**
- All 8 interactive tests pass
- `/repeat` works with SELECT queries (DQL)
- `/repeat` works with INSERT/UPDATE/DELETE (DML)
- `/repeat` works with CREATE/DROP/ALTER (DDL)
- Last SQL tracked correctly regardless of statement type
- Idempotency not enforced (repeat executes SQL as-is, may fail)
- Error messages clear when DDL repeated (e.g., "already exists")
- No crashes or unexpected behavior
- State management works across all SQL types

**FAIL if:**
- Any interactive test fails
- `/repeat` doesn't work with specific SQL type
- Wrong SQL statement repeated
- State not tracked for certain SQL types
- Crashes or panics when repeating DDL
- Database connection errors
- Test cleanup fails (tables not dropped)
