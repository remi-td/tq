## Purpose

Validate `install.sh` for POSIX compliance, platform detection correctness, installation directory handling, and graceful error behavior. The network-dependent behaviors (GitHub API download, checksum verification, actual binary installation) are NOT testable without a live GitHub Release and are deferred.

## Acceptance Criteria Coverage

- **AC-16**: Detects Linux (x86_64, aarch64) and macOS (x86_64, aarch64) - reviewable
- **AC-17**: Downloads correct binary from latest GitHub Release - NOT LOCALLY TESTABLE
- **AC-18**: Verifies SHA256 checksum - NOT LOCALLY TESTABLE
- **AC-19**: Installs to `~/.local/bin` by default, respects `TQ_INSTALL_DIR` - reviewable + dry run
- **AC-20**: Provides clear error for unsupported platforms - reviewable
- **AC-21**: POSIX-compatible (no bashisms, works with sh/dash) - shellcheck
- **AC-22**: Usage: `curl -sSL <raw-url>/install.sh | sh` - reviewable

## Test Procedure

### Step 1: Shellcheck POSIX Compliance (PREFERRED - requires shellcheck)

```bash
shellcheck --shell=sh install.sh 2>&1
echo "Exit code: $?"
```

**Expected result:**
- Exit code: 0
- Zero warnings or errors
- BLOCKED if shellcheck is not installed

**Status:** This check is BLOCKED in the current environment (shellcheck not installed).
**Resolution needed:** `brew install shellcheck` on macOS or `apt-get install shellcheck` on Ubuntu.

### Step 2: Platform Detection Logic Review

```bash
grep -n "uname" install.sh
```

**Expected result:**
- `uname -s` used to detect OS (Linux vs Darwin)
- `uname -m` used to detect architecture (x86_64 vs aarch64/arm64)
- Both are POSIX-standard commands

```bash
grep -n "aarch64\|arm64\|x86_64" install.sh
```

**Expected result:**
- All 4 supported combinations represented:
  - Linux x86_64 → `x86_64-unknown-linux-gnu`
  - Linux aarch64 → `aarch64-unknown-linux-gnu`
  - macOS x86_64 → `x86_64-apple-darwin`
  - macOS aarch64 → `aarch64-apple-darwin`

### Step 3: Installation Directory Handling

```bash
grep -n "TQ_INSTALL_DIR\|local/bin" install.sh
```

**Expected result:**
- `TQ_INSTALL_DIR` variable referenced (for override)
- `~/.local/bin` or `$HOME/.local/bin` as default
- Logic: `INSTALL_DIR="${TQ_INSTALL_DIR:-$HOME/.local/bin}"`

### Step 4: Unsupported Platform Error

```bash
grep -n -A2 "unsupported\|not supported\|Windows\|musl" install.sh
```

**Expected result:**
- Error message for unsupported platforms (Windows, musl)
- Script exits with non-zero code on unsupported platform
- Error message is human-readable

### Step 5: Script Syntax Validation (no shellcheck fallback)

```bash
sh -n install.sh 2>&1
echo "Exit code: $?"
```

**Expected result:**
- Exit code: 0 (sh -n performs syntax check without execution)
- No syntax errors reported

### Step 6: Dry Run (no live release available)

```bash
TQ_INSTALL_DIR=/tmp/tq-test-install sh install.sh 2>&1
echo "Exit code: $?"
```

**Expected result:**
- Script executes without crashing on a syntax/logic error
- Fails gracefully (non-zero exit) because no GitHub Release exists yet
- Error message is informative (e.g., "Failed to fetch release" or GitHub API error)
- Does NOT crash with unbound variable errors or bash-specific syntax errors

### Step 7: Usage Pattern Review

```bash
head -20 install.sh
```

**Expected result:**
- Script header comments show usage: `curl -sSL <url>/install.sh | sh`
- Script uses a shebang line `#!/bin/sh` (not `#!/bin/bash`)

## Shellcheck Blocker

**IMPORTANT:** The shellcheck POSIX compliance test (AC-21) is the strongest validation for this script. Without shellcheck, we can only check:
- Basic syntax via `sh -n`
- Script structure via grep/review

This does NOT provide the same confidence as `shellcheck --shell=sh`. The coordinator must arrange for shellcheck installation before the final test report can claim AC-21 is VERIFIED.

## Notes

- Network-dependent tests (AC-17, AC-18) are deferred to end-to-end testing after first release publication
- The dry run test (Step 6) is important - it catches runtime syntax errors that static checks miss
- `sh -n` checks POSIX syntax but does not catch all bashisms (shellcheck is required for that)
