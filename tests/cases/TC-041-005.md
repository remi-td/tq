## Purpose

Verify the three Sprint 40 remediation items are correctly implemented: (1) `/p` alias documented in help text, (2) `execute`/`execute_with_params` duplication eliminated in query.rs and repl/mod.rs, (3) `LazyLock` used for regex compilation in params.rs.

Note: The regression suite (855+ tests passing) is covered by TC-041-001 which runs `cargo test`. This test focuses on the specific code changes.

## Acceptance Criteria Coverage

- **AC-23**: Resolve `/p` alias - add to spec and help text
- **AC-24**: Eliminate `execute`/`execute_with_params` duplication in query.rs
- **AC-25**: Use `LazyLock` for regex compilation in params.rs
- **AC-26**: All existing 855 tests pass (covered by TC-041-001)

## Test Procedure

### Step 1: /p Alias in Help Text (AC-23)

```bash
cd <project-root>
cargo build -q 2>&1
./target/debug/tq help params 2>&1 | grep -i "/p\b\|\\\\p\b"
```

Alternatively, check the help text file directly:

```bash
grep -rn '"/p"\|/p alias\|\\\\p' src/help/ src/ --include="*.rs" --include="*.txt" | grep -i "params\|alias"
```

**Expected result:**
- `/p` alias is mentioned in at least one of: `tq help params` output, help text files, or command registration
- The alias is visible to the user (not just internal code)

### Step 2: Execute Deduplication in query.rs (AC-24)

```bash
grep -n "fn execute" src/commands/query.rs
```

**Expected result:**
- Single `execute` function signature (not two separate functions)
- Likely accepts `Option<&ParamStore>` or similar unified parameter
- `execute_with_params` should NOT appear as a separate function

```bash
grep -n "execute_with_params\|fn execute" src/commands/query.rs
```

**Expected result:**
- Zero occurrences of `execute_with_params` as a function definition
- One unified `execute` function (accepting optional params)

### Step 3: Execute Deduplication in repl/mod.rs (AC-24)

```bash
grep -n "fn execute\|execute_with_params" src/commands/repl/mod.rs
```

**Expected result:**
- No `execute_with_params` function definition in repl/mod.rs
- Calls to query execution use a single unified function

### Step 4: LazyLock for Regex in params.rs (AC-25)

```bash
grep -n "LazyLock\|lazy_static\|Lazy\|Regex::new\|static.*Regex\|static.*RE" src/params.rs
```

**Expected result:**
- `LazyLock` present (Rust 1.80+ standard library feature)
- OR `std::sync::LazyLock` present
- `Regex::new(...)` should NOT appear in a hot path (each call compiles a new regex)
- `lazy_static!` is acceptable but `LazyLock` is preferred per AC-25

### Step 5: Compilation Cleanliness

```bash
cd <project-root>
cargo clippy -- -D warnings 2>&1
echo "Exit code: $?"
```

**Expected result:**
- Exit code: 0
- Zero warnings
- No deprecated API usage

## Pass/Fail Criteria

| Check | Pass Condition | Fail Condition |

| execute_with_params removed from query.rs (AC-24) | grep returns no function definition | Separate function still exists |
| execute_with_params removed from repl/mod.rs (AC-24) | grep returns no function definition | Separate function still exists |
