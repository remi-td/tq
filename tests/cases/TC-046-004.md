## Purpose

Verify that clap correctly parses `tq describe`, `tq list`, and `tq show-indexes` subcommands with their arguments and flags. This validates the `Command` enum variants and their argument structs exist with the correct field types — without requiring a database connection or binary execution.

## Acceptance Criteria Coverage

- **AC-8**: Unit tests for argument parsing
- **AC-6**: All new commands support `--format table|csv|json` flag (parsing side)

## Prerequisites

- `src/cli.rs` has `Describe`, `List`, `ShowIndexes` variants added to `Command` enum
- Each variant has the correct argument structs with `table`, `subcommand`, `pattern`, `format` fields as appropriate
- `cargo test --lib` compiles successfully

## Test Procedure

### Expected CLI Shape

```
tq describe <TABLE> [--format table|csv|json]
tq list databases|tables|views [PATTERN] [--format table|csv|json]
tq show-indexes <TABLE> [--format table|csv|json]
```

### Test Implementation (in `src/cli.rs` `#[cfg(test)]` module)

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use clap::Parser;

    // Helper: parse from args, discard global options, return Command variant
    fn parse_command(args: &[&str]) -> Command {
        let cli = Cli::try_parse_from(args).expect("Failed to parse CLI args");
        cli.command
    }

    // TC-046-004-A: tq describe TABLE — basic parsing
    #[test]
    fn test_describe_basic_parsing() {
        let cmd = parse_command(&["tq", "describe", "mydb.employees"]);
        match cmd {
            Command::Describe(args) => {
                assert_eq!(args.table, "mydb.employees");
            }
            other => panic!("Expected Describe, got {:?}", other),
        }
    }

    // TC-046-004-B: tq describe TABLE --format json
    #[test]
    fn test_describe_format_json() {
        let cmd = parse_command(&["tq", "describe", "--format", "json", "employees"]);
        match cmd {
            Command::Describe(args) => {
                assert_eq!(args.format, OutputFormat::Json);
            }
            other => panic!("Expected Describe, got {:?}", other),
        }
    }

    // TC-046-004-C: tq describe TABLE --format csv
    #[test]
    fn test_describe_format_csv() {
        let cmd = parse_command(&["tq", "describe", "--format", "csv", "employees"]);
        match cmd {
            Command::Describe(args) => {
                assert_eq!(args.format, OutputFormat::Csv);
            }
            other => panic!("Expected Describe, got {:?}", other),
        }
    }

    // TC-046-004-D: tq list databases
    #[test]
    fn test_list_databases() {
        let cmd = parse_command(&["tq", "list", "databases"]);
        match cmd {
            Command::List(args) => {
                assert!(matches!(args.subcommand, ListSubcommand::Databases));
            }
            other => panic!("Expected List, got {:?}", other),
        }
    }

    // TC-046-004-E: tq list tables (no pattern)
    #[test]
    fn test_list_tables_no_pattern() {
        let cmd = parse_command(&["tq", "list", "tables"]);
        match cmd {
            Command::List(args) => {
                assert!(matches!(args.subcommand, ListSubcommand::Tables));
                // Pattern should be None
                assert!(args.pattern.is_none());
            }
            other => panic!("Expected List, got {:?}", other),
        }
    }

    // TC-046-004-F: tq list tables emp* (with pattern)
    #[test]
    fn test_list_tables_with_pattern() {
        let cmd = parse_command(&["tq", "list", "tables", "emp*"]);
        match cmd {
            Command::List(args) => {
                assert!(matches!(args.subcommand, ListSubcommand::Tables));
                assert_eq!(args.pattern.as_deref(), Some("emp*"));
            }
            other => panic!("Expected List, got {:?}", other),
        }
    }

    // TC-046-004-G: tq list views
    #[test]
    fn test_list_views() {
        let cmd = parse_command(&["tq", "list", "views"]);
        match cmd {
            Command::List(args) => {
                assert!(matches!(args.subcommand, ListSubcommand::Views));
            }
            other => panic!("Expected List, got {:?}", other),
        }
    }

    // TC-046-004-H: tq show-indexes TABLE
    #[test]
    fn test_show_indexes_basic() {
        let cmd = parse_command(&["tq", "show-indexes", "mydb.employees"]);
        match cmd {
            Command::ShowIndexes(args) => {
                assert_eq!(args.table, "mydb.employees");
            }
            other => panic!("Expected ShowIndexes, got {:?}", other),
        }
    }

    // TC-046-004-I: tq show-indexes TABLE --format csv
    #[test]
    fn test_show_indexes_format_csv() {
        let cmd = parse_command(&["tq", "show-indexes", "--format", "csv", "employees"]);
        match cmd {
            Command::ShowIndexes(args) => {
                assert_eq!(args.format, OutputFormat::Csv);
            }
            other => panic!("Expected ShowIndexes, got {:?}", other),
        }
    }

    // TC-046-004-J: tq describe (no table) — must fail parsing (missing required arg)
    #[test]
    fn test_describe_no_table_fails() {
        let result = Cli::try_parse_from(["tq", "describe"]);
        assert!(result.is_err(), "Expected error for missing table argument");
    }
}
```

- `test_describe_format_csv` — PASS: format = `OutputFormat::Csv`
- `test_list_databases` — PASS: `List` with `ListSubcommand::Databases`
- `test_list_tables_no_pattern` — PASS: `ListSubcommand::Tables`, pattern = None
- `test_list_tables_with_pattern` — PASS: pattern = Some("emp*")
- `test_list_views` — PASS: `ListSubcommand::Views`
- `test_show_indexes_basic` — PASS: `ShowIndexes` with `table = "mydb.employees"`

## Pass/Fail Criteria

**PASS if:**
- All 10 tests compile and pass
- Correct variant matched for each command
- `--format` flag correctly maps to `OutputFormat` enum values
- Missing required argument correctly returns an error from clap

**FAIL if:**
- Compilation fails — indicates missing variants or argument structs in `cli.rs`
- Wrong variant is matched — indicates command name mismatch
- `--format` parsing fails — indicates missing flag or wrong enum mapping
- `test_describe_no_table_fails` panics instead of returning Err — indicates missing `required = true` on table argument

## Notes

- The exact names of fields (`table`, `pattern`, `subcommand`, `format`) and the `ListSubcommand` enum depend on the implementation by `rust-teradata-architect`. Adjust field names to match the actual implementation.
- `OutputFormat` is already defined in `src/cli.rs` as `Table`, `Json`, `Csv`. The new commands reuse this enum.
- The `#[test]` module must be inside `src/cli.rs` or import the correct structs. Since `cli.rs` is a library module, `#[cfg(test)]` tests inside it are compiled with `cargo test --lib`.
- If clap uses `#[command(subcommand)]` for `list`, the `ListSubcommand` enum test syntax will need adjustment per implementation.
