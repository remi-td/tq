## Purpose

Verify that table name completion handles error conditions gracefully without crashing the REPL or exposing sensitive information.

## Scope

This test validates:
- Permission denied to DBC.TablesV
- Network timeout during metadata query
- Connection lost during completion
- Empty result set (no tables)
- Slow database response
- Graceful error messages
- REPL continues operating after errors

## Prerequisites

- tq binary built in release mode
- Ability to simulate various error conditions (may require test setup)
- REPL mode functional

## Test Procedure

### Step 1: Test with permission denied (if possible to simulate)
```sql
# Connect to database where user lacks SELECT on DBC.TablesV
tq> SELECT * FROM <TAB>
```

**Expected behavior:**
- Warning message: "Cannot load table list (permission denied)"
- Suggestion to contact DBA
- REPL continues to work
- Can still type table names manually

### Step 2: Test with empty database (no tables)
```sql
# Connect to empty database or newly created database
tq> SELECT * FROM <TAB>
```

**Expected behavior:**
- Message: "(No tables found in current database)"
- No error, just informative message
- REPL continues working

### Step 3: Test with very slow database
```sql
# Simulate or use slow connection if available
tq> SELECT * FROM <TAB>
```

**Expected behavior:**
- Shows "Loading tables..." message
- If exceeds timeout (500ms), shows timeout warning
- Suggests trying again or typing manually
- REPL doesn't hang

### Step 4: Test metadata query failure recovery
```sql
# After Step 3 timeout, try again
tq> SELECT * FROM <TAB>
```

**Expected behavior:**
- Second attempt tries metadata query again
- Doesn't cache error state permanently
- Shows appropriate message

### Step 5: Verify REPL functionality after errors
```sql
# After any error above, execute actual query
tq> SELECT 1 AS test;
```

**Expected behavior:**
- Query executes successfully
- REPL not corrupted by metadata errors
- Exit code 0

### Step 6: Test connection lost during completion
```sql
# If possible, disconnect network during metadata query
# (This is advanced testing, may skip if not feasible)
tq> SELECT * FROM <TAB>
```

**Expected behavior:**
- Error message: "Connection lost"
- Suggests using /ping or /reconnect
- REPL shows disconnected state

## Pass/Fail Criteria

**PASS if:**
- All error conditions handled gracefully
- Clear, actionable error messages
- REPL never crashes
- Can continue using REPL after errors
- No sensitive information exposed
- Timeout prevents indefinite hanging
- Error state not permanently cached

**FAIL if:**
- REPL crashes on metadata errors
- Hangs indefinitely on slow queries
- Error messages unclear or unhelpful
- Can't use REPL after metadata failure
- Caches error state permanently

## Notes

- Error handling critical for production use
- Users will encounter slow databases, permissions issues
- Graceful degradation essential: completion unavailable but REPL works
- Some error conditions may be difficult to simulate in test environment
- Consider using mock/test database with restricted permissions
