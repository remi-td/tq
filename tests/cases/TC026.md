## Purpose

Verify that tab completion works correctly after the FROM keyword, showing available table names from the current database with proper caching and performance.

## Scope

This test validates:
- Tab completion triggers after FROM keyword
- Database metadata query executes successfully
- Table list displayed correctly
- Prefix matching filters tables appropriately
- Single match auto-completes
- Multiple matches display list
- Performance meets <500ms requirement
- Results are cached for subsequent completions

## Prerequisites

- tq binary built in release mode
- Valid Teradata connection credentials configured in .env
- Test database with multiple tables (at least 5-10 tables for meaningful testing)
- REPL mode functional
- Access to DBC.TablesV system catalog

## Test Procedure

### Step 1: Start REPL and verify basic functionality
```bash
tq repl
# Wait for prompt: tq>
```

### Step 2: Test tab completion after FROM with no prefix
```sql
tq> SELECT * FROM <TAB>
```

**Expected behavior:**
- Displays list of all tables in current database
- Shows "Loading tables..." if first time (within 500ms)
- Shows list once loaded

### Step 3: Test prefix matching with partial table name
```sql
tq> SELECT * FROM emp<TAB>
```

**Expected behavior:**
- If single match (e.g., "employees"): auto-completes to "employees"
- If multiple matches: displays matching tables (employees, employee_archive, etc.)
- Filters list based on prefix

### Step 4: Test cycling through multiple matches
```sql
tq> SELECT * FROM e<TAB>
# First Tab: shows all tables starting with 'e'
# Second Tab: cycles to first match
# Third Tab: cycles to second match
```

### Step 5: Verify caching (second completion should be instant)
```sql
tq> SELECT * FROM <TAB>
```

**Expected behavior:**
- No "Loading tables..." message
- Instant display (< 50ms perceived)
- Same table list as before

### Step 6: Test case-insensitive matching
```sql
tq> SELECT * FROM EMP<TAB>
tq> SELECT * FROM Emp<TAB>
tq> SELECT * FROM emp<TAB>
```

**Expected behavior:**
- All three should produce identical completion results
- Case preserved from user input

### Step 7: Test schema-qualified completion (if applicable)
```sql
tq> SELECT * FROM production.<TAB>
```

**Expected behavior:**
- Shows tables in production schema
- Format: schema.table_name

### Step 8: Measure performance on first Tab press
```bash
# Use script mode to measure timing
# Press Tab after FROM and note timing displayed
```

**Expected behavior:**
- Metadata query completes in < 500ms
- Shows loading indicator if > 100ms
- Never hangs or times out

## Pass/Fail Criteria

**PASS if:**
- Tab completion triggers after FROM keyword
- Table list loads from database metadata
- Prefix matching filters correctly
- Single match auto-completes
- Multiple matches display list
- Caching works (second completion is instant)
- Case-insensitive matching works
- Performance < 500ms on first Tab, < 50ms on cached
- No errors or crashes

**FAIL if:**
- Tab completion doesn't trigger after FROM
- No tables displayed
- Metadata query fails or times out
- Prefix matching incorrect
- Performance exceeds 500ms consistently
- Caching doesn't work
- Crashes or errors during completion

## Notes

- Performance will vary based on database size and network latency
- First completion includes metadata query overhead
- Cache invalidated on connection change (/logon)
- Metadata queried from DBC.TablesV
- Context detection should work with various spacing: "FROM<TAB>", "FROM <TAB>", "FROM  <TAB>"
