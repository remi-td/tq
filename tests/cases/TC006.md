## Purpose

Verify that tq correctly parses various valid connection string formats.

## Scope

This test validates:
- Full connection string parsing (user:password@host:port/database)
- Connection string without password
- Different port numbers
- Environment variable support
- --logon flag vs TQ_LOGON
- .env file support

## Prerequisites

- tq binary is built and available
- `.env` file can be temporarily modified for testing
- No actual database connection required (can test with ping and expect failure)

## Test Procedure

### Step 1: Full connection string
```bash
tq -l "testuser:testpass@testhost:1025/testdb" ping 2>&1 | head -1
```

### Step 2: Connection string without password (will fail but should parse)
```bash
tq -l "testuser@testhost:1025/testdb" ping 2>&1 | grep -i "auth\|password" || echo "Parsed successfully, failed at auth"
```

### Step 3: Different port
```bash
tq -l "user:pass@host:1026/db" ping 2>&1 | head -1
```

### Step 4: .env file configuration
```bash
# Temporarily update .env file to test file-based configuration
mv .env .env.backup 2>/dev/null || true
echo "TQ_LOGON=user:pass@host:1025/db" > .env
tq ping 2>&1 | head -1
# Restore original .env
rm .env
mv .env.backup .env 2>/dev/null || true
```

### Step 5: Environment variable (explicit export)
```bash
export TQ_LOGON="user:pass@host:1025/db"
tq ping 2>&1 | head -1
```

### Step 6: Override environment with flag
```bash
export TQ_LOGON="user1:pass1@host1:1025/db1"
tq -l "user2:pass2@host2:1026/db2" ping 2>&1 | grep "host2" && echo "Flag overrides environment"
unset TQ_LOGON
```

## Expected Results

### Step 1:
Should attempt connection to testhost:1025
Error message should reference correct host/port if unreachable

### Step 2:
Should parse connection string successfully
Should fail at authentication stage (not parsing stage)
Error about missing password, NOT about invalid format

### Step 3:
Should attempt connection to host:1026 (not default 1025)

### Step 4:
Should read connection string from .env file
Should attempt connection to host:1025

### Step 5:
Should read connection string from TQ_LOGON environment variable
Should attempt connection to host:1025

### Step 6:
Output should reference "host2" not "host1"
Confirms CLI flag takes precedence over environment variable

## Pass/Fail Criteria

**PASS if:**
- Valid connection strings are parsed without errors
- Host, port, user, database extracted correctly
- Password (when present) is handled securely
- .env file configuration works
- Environment variable works as fallback
- CLI flag overrides environment variable
- Parsing errors are clear and specific

**FAIL if:**
- Valid formats are rejected
- Components extracted incorrectly
- Precedence order is wrong
- Error messages are misleading

## Notes

- Connection string format: user:password@host:port/database
- Password is optional in connection string (can come from file)
- Port must be explicit (no default port inference)
- Case sensitivity matters for username/password
