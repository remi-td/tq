## Purpose

Verify that tq handles SQL syntax errors gracefully with clear, actionable error messages.

## Scope

This test validates:
- Syntax error detection
- Error message clarity
- Error context display
- Suggestions for corrections
- Exit code 1 for query errors

## Prerequisites

- tq binary is built and available
- `.env` file configured with valid Teradata connection credentials

## Test Procedure

### Step 1: Simple typo (SELCT instead of SELECT)
```bash
# Using credentials from .env file
tq query "SELCT * FROM table1" 2>&1
echo "Exit code: $?"
```

### Step 2: Missing FROM keyword
```bash
tq query "SELECT *" 2>&1
echo "Exit code: $?"
```

### Step 3: Unclosed quote
```bash
tq query "SELECT 'unclosed FROM table1" 2>&1
echo "Exit code: $?"
```

### Step 4: Invalid column name
```bash
tq query "SELECT nonexistent_column FROM dbc.dbcinfo" 2>&1
echo "Exit code: $?"
```

### Step 5: Nonexistent table
```bash
tq query "SELECT * FROM nonexistent_table_12345" 2>&1
echo "Exit code: $?"
```

### Step 6: Permission error
```bash
tq query "DROP TABLE important_system_table" 2>&1
echo "Exit code: $?"
```

### Step 7: Invalid function name
```bash
tq query "SELECT INVALID_FUNCTION(column) FROM dbc.dbcinfo" 2>&1
echo "Exit code: $?"
```

## Expected Results

### Step 1 Output (stderr):
```
Error: SQL syntax error

Query:
  SELCT * FROM table1
  ^^^^^

Details: Syntax error: expected SELECT but found SELCT

Suggestion: Did you mean "SELECT"?
```
Exit code: 1

### Step 2 Output (stderr):
```
Error: SQL syntax error

Query:
  SELECT *

Details: Syntax error: FROM clause required

Suggestion: Add FROM clause: SELECT * FROM table_name
```
Exit code: 1

### Step 3 Output (stderr):
```
Error: SQL syntax error

Query:
  SELECT 'unclosed FROM table1
         ^

Details: Unterminated string literal

Suggestion: Close the string with a matching quote
```
Exit code: 1

### Step 4 Output (stderr):
```
Error: Column does not exist

Query:
  SELECT nonexistent_column FROM dbc.dbcinfo
         ^^^^^^^^^^^^^^^^^^

Details: Column 'nonexistent_column' not found in table 'dbc.dbcinfo'

Suggestion: Check column name spelling or use DESCRIBE to see available columns
```
Exit code: 1

### Step 5 Output (stderr):
```
Error: Table does not exist

Query:
  SELECT * FROM nonexistent_table_12345
                ^^^^^^^^^^^^^^^^^^^^^^^

Details: Object 'nonexistent_table_12345' does not exist

Suggestions:
  - Check table name spelling
  - Verify table exists: SELECT * FROM dbc.tables WHERE tablename = 'nonexistent_table_12345'
  - Check current database
```
Exit code: 1

### Step 6 Output (stderr):
```
Error: Permission denied

Query:
  DROP TABLE important_system_table

Details: Insufficient privileges to DROP table 'important_system_table'

Action required:
  Contact your database administrator to request privileges
```
Exit code: 1

### Step 7 Output (stderr):
```
Error: Unknown function

Details: Function 'INVALID_FUNCTION' does not exist

Suggestion: Check function name or use a valid SQL function
```
Exit code: 1

## Pass/Fail Criteria

**PASS if:**
- All syntax errors are caught and reported
- Error messages are clear and specific
- Query context is shown (what went wrong where)
- Helpful suggestions are provided
- Exit code is 1 for all cases
- No stack traces in user output
- Errors written to stderr

**FAIL if:**
- Unclear error messages
- No context or suggestions
- Exit code is 0 or 2 (wrong code)
- Stack traces visible to user
- Program crashes
- Errors on stdout instead of stderr

## Notes

- Error message quality is critical for user experience
- Should distinguish between different error types
- Context helps user locate the problem
- Suggestions should be actionable
- Teradata error codes should be mapped to friendly messages
- Consider showing query with error location highlighted
- Future: syntax highlighting in error context
