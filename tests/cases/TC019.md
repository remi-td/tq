## Purpose

Verify that tq correctly reads and applies configuration from environment variables.

## Scope

This test validates:
- TQ_LOGON for connection string (via .env file or explicit export)
- TQ_LOGMECH for authentication mechanism
- TQ_FORMAT for default output format
- TQ_TIMEOUT for connection timeout
- TQ_COLOR for color output
- Precedence: CLI args > explicit env vars > .env file

## Prerequisites

- tq binary is built and available
- `.env` file for baseline configuration

## Test Procedure

### Step 1: TQ_LOGON via .env file
```bash
# Verify connection works using .env file
tq ping 2>&1 | head -1
```

### Step 2: TQ_LOGON explicit export overrides .env
```bash
# Temporarily override .env with explicit export
export TQ_LOGON="testuser:testpass@differenthost:1025/testdb"
tq ping 2>&1 | head -1
unset TQ_LOGON
```

### Step 3: TQ_LOGMECH
```bash
# Using connection from .env
export TQ_LOGMECH=LDAP
tq ping 2>&1 | head -1
unset TQ_LOGMECH
```

### Step 4: TQ_FORMAT
```bash
# Using connection from .env
export TQ_FORMAT=json
tq query "SELECT 1 AS test" | head -1
unset TQ_FORMAT
```

### Step 5: TQ_TIMEOUT
```bash
# Using connection from .env
export TQ_TIMEOUT=5s
tq -vv ping 2>&1 | grep -i timeout
unset TQ_TIMEOUT
```

### Step 6: TQ_COLOR
```bash
# Using connection from .env
export TQ_COLOR=never
tq query "SELECT 1" | od -An -tx1 | grep -q 1b || echo "No ANSI codes"
unset TQ_COLOR
```

### Step 7: CLI args override env vars (logon)
```bash
export TQ_LOGON="user1:pass1@host1:1025/db1"
tq -l "user2:pass2@host2:1026/db2" ping 2>&1 | grep -i host2
unset TQ_LOGON
```

### Step 8: CLI args override env vars (format)
```bash
# Using connection from .env
export TQ_FORMAT=json
tq query --format csv "SELECT 1" | head -1
unset TQ_FORMAT
```

### Step 9: Multiple env vars together
```bash
# Using connection from .env
export TQ_FORMAT=json
export TQ_LOGMECH=TD2
export TQ_COLOR=never
tq query "SELECT 1"
unset TQ_FORMAT TQ_LOGMECH TQ_COLOR
```

## Pass/Fail Criteria

**PASS if:**
- All documented environment variables work
- Values are correctly parsed and applied
- CLI arguments override environment variables
- Multiple environment variables can be used together
- Invalid values cause appropriate errors
- Exit codes are correct

**FAIL if:**
- Environment variables ignored
- Values not parsed correctly
- Precedence is wrong (env overrides CLI)
- Cannot use multiple env vars together
- Crashes on invalid env var values

## Notes

- Environment variables provide convenient defaults
- Useful for shell sessions and scripts
- .env file is loaded automatically from project directory
- Precedence order: CLI args > explicit env vars > .env file > config file > defaults
- Common pattern in UNIX tools
- Should validate environment variable values
- Consider documenting all env vars in --help output
- Test with: env | grep TQ_
- .env file approach is recommended for development and testing
