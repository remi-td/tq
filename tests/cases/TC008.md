## Purpose

Verify that tq supports multiple authentication mechanisms and correctly passes them to the Teradata driver.

## Scope

This test validates:
- TD2 authentication (default)
- LDAP authentication
- Kerberos (KRB5) authentication
- TDNEGO authentication
- --logmech flag functionality
- TQ_LOGMECH environment variable

## Prerequisites

- tq binary is built and available
- `.env` file configured with valid connection credentials
- Test database configured for multiple auth mechanisms
- Appropriate credentials for each mechanism

## Test Procedure

### Step 1: TD2 authentication (default)
```bash
# Using credentials from .env file
tq ping
```

### Step 2: TD2 authentication (explicit)
```bash
tq --logmech TD2 ping
```

### Step 3: LDAP authentication
```bash
tq --logmech LDAP -l "ldapuser:ldappass@testhost:1025/testdb" ping
```

### Step 4: Kerberos authentication
```bash
# Assumes valid Kerberos ticket exists
kinit testuser@REALM
tq --logmech KRB5 -l "testuser@testhost:1025/testdb" ping
```

### Step 5: TDNEGO authentication
```bash
tq --logmech TDNEGO -l "testuser:testpass@testhost:1025/testdb" ping
```

### Step 6: Environment variable
```bash
export TQ_LOGMECH=LDAP
tq -l "ldapuser:ldappass@testhost:1025/testdb" ping
```

### Step 7: Invalid mechanism
```bash
tq --logmech INVALID ping 2>&1
```

## Pass/Fail Criteria

**PASS if:**
- All authentication mechanisms can be specified
- Connections succeed with valid credentials for each mechanism
- Default is TD2 when not specified
- Environment variable works as fallback
- CLI flag overrides environment variable
- Invalid mechanisms are rejected with helpful message
- Exit codes are correct (0 for success, 2 for invalid arg)

**FAIL if:**
- Authentication mechanisms not recognized
- Default mechanism is wrong
- Precedence is incorrect
- Invalid mechanisms cause crashes
- Error messages are unclear

## Notes

- TD2 is Teradata's native authentication
- LDAP requires LDAP-enabled Teradata system
- Kerberos requires valid ticket and krb5 configuration
- TDNEGO negotiates the best available mechanism
- Not all test environments support all mechanisms
- May need to skip tests for unavailable mechanisms
