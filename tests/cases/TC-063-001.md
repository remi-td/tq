## Purpose

Verify that `render_exit_snapshot(&self, writer: &mut impl Write)` on the `Pager` struct correctly renders a static, plain-text snapshot of the current pager viewport to a generic `Write` implementor. All rendering logic — viewport selection, borders, headers, data rows, hidden-columns footer, row-count/timing footer, ANSI-free output, and `\n` line endings — is validated using `Vec<u8>` as the writer, with no live database or terminal required.

## Acceptance Criteria Coverage

- AC-2: Static table matches last pager viewport (row_offset, col_offset, page_size)
- AC-3: Hidden columns footer: "N columns hidden: col1, col2, ..."
- AC-4: "Use --format csv or --format json to see all columns" hint when columns are hidden
- AC-5: Row count and timing footer: "N row(s) in set (X.XXXs)"
- AC-6: No ANSI color codes in snapshot output
- AC-7: Same box-drawing border characters as pager (╭ ─ ┬ ╮ ├ ┼ ┤ ╰ ┴ ╯ │)
- AC-10: Unit tests exist for snapshot rendering logic

## Scope

This test validates 10 scenarios:

1. **Part A** — Basic snapshot: small result, all columns visible, row_offset=0
2. **Part B** — Horizontal scroll: col_offset > 0, hidden-columns footer lists correct names
3. **Part C** — Vertical scroll: row_offset > 0, only current page rows rendered
4. **Part D** — Both offsets: col_offset and row_offset both non-zero
5. **Part E** — Row count / timing footer: exact format "N row(s) in set (X.XXXs)"
6. **Part F** — Hidden columns footer exact format + hint line
7. **Part G** — No hidden-columns footer when all columns visible
8. **Part H** — No ANSI codes: output contains no `\x1b` (0x1B) byte
9. **Part I** — Line endings are `\n` not `\r\n`
10. **Part J** — CJK/Unicode columns render with correct visual width

## Prerequisites

### Part A: Basic Snapshot — All Columns Visible

**Test name:** `test_snapshot_basic_all_visible`

```rust
#[test]
fn test_snapshot_basic_all_visible() {
    // 3 columns, 5 rows — fits in a wide terminal
    let result = create_test_result(3, 5);
    let mut pager = create_pager_with_width(&result, 200);
    pager.row_offset = 0;
    pager.col_offset = 0;
    pager.page_size = 10; // more than 5 rows, so all rows visible

    let mut buf = Vec::new();
    pager.render_exit_snapshot(&mut buf).expect("snapshot failed");
    let output = String::from_utf8(buf).expect("invalid utf-8");

    // Top border starts with ╭
    assert!(output.starts_with('╭'), "Must start with top-left corner ╭");

    // Contains header (column names col0, col1, col2)
    assert!(output.contains("col0"), "Must contain column header col0");
    assert!(output.contains("col1"), "Must contain column header col1");
    assert!(output.contains("col2"), "Must contain column header col2");

    // Contains data rows
    assert!(output.contains("val_0_0"), "Must contain first row data");
    assert!(output.contains("val_4_2"), "Must contain last row data");

    // Bottom border somewhere before footers
    assert!(output.contains('╰'), "Must contain bottom-left corner ╰");

    // No hidden-columns footer (all visible)
    assert!(!output.contains("columns hidden"), "Must NOT show hidden columns footer when all visible");
    assert!(!output.contains("--format csv"), "Must NOT show hint when all visible");
}
```

**Expected:** Passes. Output contains top border, header, 5 data rows, bottom border, row count footer. No hidden-columns footer.

### Part D: Both Offsets Non-Zero

**Test name:** `test_snapshot_both_offsets`

```rust
#[test]
fn test_snapshot_both_offsets() {
    // 5 columns, 8 rows
    let result = create_test_result(5, 8);
    let mut pager = create_pager_with_width(&result, 200);
    pager.col_offset = 1; // skip col 0
    pager.row_offset = 2; // skip rows 0, 1
    pager.page_size = 3;  // show rows 2, 3, 4

    let mut buf = Vec::new();
    pager.render_exit_snapshot(&mut buf).expect("snapshot failed");
    let output = String::from_utf8(buf).expect("invalid utf-8");

    // col 0 absent from table, col 1 present
    assert!(!output.starts_with_column_header("col0", &output),
        "col0 must not appear in table header");
    // row 2 col 1 present
    assert!(output.contains("val_2_1"), "Row 2, col 1 must appear");
    assert!(output.contains("val_4_1"), "Row 4, col 1 must appear");
    // row 0, 5 absent
    assert!(!output.contains("val_0_1"), "Row 0 must not appear");
    assert!(!output.contains("val_5_1"), "Row 5 must not appear");
    // hidden columns footer present for col0
    assert!(output.contains("columns hidden"), "Hidden columns footer must be present");
}
```

Note: The `starts_with_column_header` assertion is a prose description. In practice, check that the header row of the table (between `╭` and `├`) does not include "col0". Implement as:

```rust
    // Extract header section (before first ├)
    if let Some(header_end) = output.find('├') {
        let header_section = &output[..header_end];
        assert!(!header_section.contains("col0"),
            "col0 must not appear in table header when col_offset=1");
        assert!(header_section.contains("col1"),
            "col1 must appear as first visible column");
    } else {
        panic!("Could not find middle border ├ in snapshot output");
    }
```

**Expected:** Passes. Table shows rows 2-4, columns 1-4 (or however many fit). Hidden-columns footer mentions col0.

### Part J: CJK/Unicode Column Names and Data

**Test name:** `test_snapshot_cjk_unicode`

```rust
#[test]
fn test_snapshot_cjk_unicode() {
    use crate::db::{ColumnMetadata, TeradataType, Value};
    use std::time::Duration;

    // Column name and value containing CJK characters (each 2 display columns wide)
    let columns = vec![
        ColumnMetadata::new("名前", TeradataType::Varchar, true),  // 4 display cols
        ColumnMetadata::new("id",  TeradataType::Integer, false),
    ];
    let rows = vec![
        vec![Value::String("田中".into()), Value::Integer(1)],  // 4 display cols
        vec![Value::String("Alice".into()), Value::Integer(2)],
    ];
    let result = QueryResult::new(columns, rows, Duration::from_millis(5));

    let mut pager = create_pager_with_width(&result, 200);
    pager.col_offset = 0;
    pager.row_offset = 0;
    pager.page_size = 10;

    let mut buf = Vec::new();
    pager.render_exit_snapshot(&mut buf).expect("snapshot failed");
    let output = String::from_utf8(buf).expect("invalid utf-8");

    // Output must contain the CJK characters (not garbled)
    assert!(output.contains("名前"), "CJK column header must appear in output");
    assert!(output.contains("田中"), "CJK cell value must appear in output");

    // Each border line must have consistent visual width (no overflow)
    for line in output.lines() {
        if line.starts_with('╭') || line.starts_with('├') || line.starts_with('╰') || line.starts_with('│') {
            let width = UnicodeWidthStr::width(line);
            assert!(
                width <= 200,
                "Line visual width {} exceeds terminal width 200: '{}'",
                width, line
            );
        }
    }
}
```

**Expected:** Passes. CJK characters appear correctly; no line overflows the terminal width.

## Notes for rust-teradata-architect

1. The `render_exit_snapshot` method must NOT call any crossterm `execute!()` macros. It writes plain text only.
2. Use `\n` for line endings (not `\r\n` which the live render methods use for raw mode).
3. The hidden-columns list covers ALL columns not in the current viewport: both left-hidden (`data.columns[..col_offset]`) and right-hidden (`data.columns[end_col..]`).
4. Timing format must use `{:.3}` (3 decimal places), consistent with the existing `render_status_bar` implementation.
5. `pad_to_display_width()` must be used for CJK-safe cell padding — not `format!("{:width$}", ...)`.
6. The method should be `pub` or `pub(crate)` so the test module (which is `mod tests` inside the same file) can call it. Since the test module uses `use super::*`, `pub(crate)` is sufficient.
