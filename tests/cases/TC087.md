# TC087: Transaction Control - Rollback on Error

**Test ID:** TC087  
**Feature:** Batch Mode Transaction Control (Sprint 23 - P1)  
**Priority:** Critical  
**Test Type:** Integration  
**Created:** 2026-01-23

## Objective

Verify `--atomic` automatically executes ROLLBACK when any statement fails.

## Requirement Coverage

- REQ-F2-04: ROLLBACK on error
- REQ-F2-05: Atomicity (all-or-nothing)

## Test Procedure

```bash
# Create test table
tq query "CREATE VOLATILE TABLE test_rollback (id INT PRIMARY KEY, val VARCHAR(50))"

# Execute batch with --atomic where middle statement fails
cat > /tmp/test_batch_fail.sql << 'SQL'
INSERT INTO test_rollback VALUES (1, 'First');
INSERT INTO test_rollback VALUES (1, 'Duplicate PK - will fail');
INSERT INTO test_rollback VALUES (2, 'Third');
SQL

tq query --file /tmp/test_batch_fail.sql --atomic -v 2>&1 || echo "Expected failure"

# Verify NO rows committed (complete rollback)
tq query "SELECT COUNT(*) FROM test_rollback"
# Expected: 0 (all rolled back)

# Clean up
tq query "DROP TABLE test_rollback"
rm -f /tmp/test_batch_fail.sql
```

## Expected Results

- ✅ First INSERT executes
- ✅ Second INSERT fails (duplicate key)
- ✅ Verbose output shows: "ROLLBACK (statement failed)"
- ✅ Count is 0 (first INSERT rolled back)
- ✅ Exit code non-zero

## Acceptance Criteria

- Complete rollback on ANY error
- First statement's changes undone
- Error message indicates rollback occurred
- Database state unchanged
