# Test Case TC064: LIMIT Hint - Query with 100+ Rows Shows Correct Teradata Syntax

## Purpose

Verify that when query results are limited to 100 rows (default limit), the hint message uses correct Teradata SQL syntax (TOP/SAMPLE) instead of MySQL/PostgreSQL LIMIT syntax.

## Scope

**Testing:**
- Hint message after truncated results (>100 rows)
- Correct Teradata SQL keyword usage
- Message clarity and actionability

**Not Testing:**
- Actual TOP/SAMPLE functionality (already works per bug report)
- Limit threshold configuration
- Different output formats

## Prerequisites

- tq REPL mode active
- Live Teradata database connection
- Table with 100+ rows available (e.g., DBC.TablesV)

## Test Procedure

### Setup

```bash
./target/release/tq
```

### Execution Steps

**Step 1: Query table with >100 rows (triggers default limit)**

```sql
tq> SELECT * FROM DBC.TablesV;
```

**Expected outcome:**
- Query executes and returns first 100 rows
- Results display in table format
- Hint message appears after results

**Step 2: Verify hint message text**

Read the hint message displayed after results.

**INCORRECT (Current Bug):**
```
Showing first 100 rows. Add LIMIT clause for different results.
```

**CORRECT (Expected After Fix):**
```
Showing first 100 rows. Use TOP N or SAMPLE N for different results.
```

**Step 3: Verify message mentions both TOP and SAMPLE**

Check that hint includes:
- [ ] "TOP N" mentioned
- [ ] "SAMPLE N" mentioned (or just "SAMPLE")
- [ ] "LIMIT" is NOT mentioned

**Step 4: Test with different query styles**

```sql
tq> SELECT DatabaseName, TableName FROM DBC.TablesV;
```

**Expected:**
- Same hint message appears
- Hint is consistent across query styles

**Step 5: Verify hint doesn't appear for small results**

```sql
tq> SELECT TOP 10 * FROM DBC.TablesV;
```

**Expected:**
- Query returns 10 rows
- NO hint message (results not limited by tq)

### Verification

**Message Content:**
- [ ] Mentions "TOP N" or "TOP"
- [ ] Mentions "SAMPLE N" or "SAMPLE"
- [ ] Does NOT mention "LIMIT"
- [ ] Clear and actionable
- [ ] Grammatically correct

**Message Placement:**
- [ ] Appears after results
- [ ] Before next prompt
- [ ] On separate line(s)
- [ ] Clearly visible

**Message Accuracy:**
- [ ] Only appears when results are limited (>100 rows)
- [ ] Doesn't appear for small result sets
- [ ] Row count "100" is accurate

## Expected Results

**Correct Hint Message (Option 1: Concise):**
```sql
tq> SELECT * FROM DBC.TablesV;
[100 rows displayed in table format]

Showing first 100 rows. Use TOP N or SAMPLE N for different results.

tq>
```

**Correct Hint Message (Option 2: With Examples):**
```sql
tq> SELECT * FROM DBC.TablesV;
[100 rows displayed]

Showing first 100 rows. Use TOP N or SAMPLE N for different results.

Examples:
  SELECT TOP 50 * FROM DBC.TablesV;
  SELECT * FROM DBC.TablesV SAMPLE 200;

tq>
```

**Key Characteristics:**
- Clear indication that results are limited
- Uses Teradata SQL keywords (TOP, SAMPLE)
- Actionable guidance for user
- Examples optional but helpful

## Pass/Fail Criteria

**PASS:**
- Hint message uses "TOP N" and "SAMPLE N"
- "LIMIT" is NOT mentioned
- Message is clear and actionable
- Appears only when results are truncated

**FAIL:**
- Message still mentions "LIMIT" ← CURRENT BUG
- Message mentions only MySQL/PostgreSQL syntax
- Message is confusing or incorrect
- Message appears when results are not truncated

## Notes

**Bug Context (from open-bugs.md):**
> "LIMIT isn't a valid Teradata SQL keyword (TOP is the equivalent keyword, SAMPLE is an alternative)"
> "For some reason using TOP or SAMPLE actually works (override the limit), which is pretty cool!"

So the functionality is correct (TOP/SAMPLE work), just the hint message is wrong.

**Root Cause (from sprint-8-root-cause-analysis.md):**

Location: `src/commands/repl/executor.rs`, lines 83-89 and 169-175

Current code:
```rust
writeln!(
    writer,
    "Showing first {} rows. Add LIMIT clause for different results.",
    default_limit
)?;
```

**Expected Fix:**

Change to:
```rust
writeln!(
    writer,
    "Showing first {} rows. Use TOP N or SAMPLE N for different results.",
    default_limit
)?;
```

This fix must be applied in TWO locations:
1. `execute_sql` function (line 87)
2. `execute_sql_with_state` function (line 173)

**Teradata Syntax Reference:**

Limiting rows in Teradata:
```sql
-- TOP: First N rows
SELECT TOP 50 * FROM table;

-- SAMPLE: Random N rows
SELECT * FROM table SAMPLE 200;
```

Not valid in Teradata:
```sql
-- LIMIT: Not supported
SELECT * FROM table LIMIT 50;  -- Syntax error
```

**Testing Tip:**

To verify TOP/SAMPLE actually work:
```sql
tq> SELECT TOP 10 * FROM DBC.TablesV;
[Should return exactly 10 rows]

tq> SELECT * FROM DBC.TablesV SAMPLE 25;
[Should return 25 random rows]
```

This confirms the hint is giving correct guidance.
