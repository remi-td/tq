## Purpose

Verify that table name completion meets performance requirements: < 500ms for metadata query, < 50ms for cached completions.

## Scope

This test validates:
- First completion (metadata query) < 500ms
- Cached completion < 50ms
- Performance consistent across multiple completions
- Large table lists handled efficiently
- No performance degradation over time

## Prerequisites

- tq binary built in release mode
- Valid Teradata connection credentials configured in .env
- Test database with representative number of tables (10-100)
- Ability to measure timing accurately
- REPL mode functional

## Test Procedure

### Step 1: Start REPL
```bash
tq repl
```

### Step 2: Measure first table completion (cold cache)
```sql
# Use external timer or REPL timing if available
tq> SELECT * FROM <TAB>
# Record time from Tab press to display
```

**Expected:** < 500ms

### Step 3: Measure cached table completion
```sql
tq> SELECT * FROM <TAB>
# Second time - cached
# Record time
```

**Expected:** < 50ms (should feel instant)

### Step 4: Measure multiple cached completions
```sql
# Repeat 10 times
tq> SELECT * FROM <TAB>
tq> SELECT * FROM <TAB>
tq> SELECT * FROM <TAB>
...
# Record average time
```

**Expected:** All < 50ms

### Step 5: Clear cache with /logon and remeasure
```sql
tq> /logon user:pass@host:1025/samedb
# Reconnect to invalidate cache
tq> SELECT * FROM <TAB>
# Should reload metadata
```

**Expected:** < 500ms (reload)

### Step 6: Test with large table list (if available)
```sql
# Connect to database with 100+ tables
tq> /logon user:pass@host:1025/large_db
tq> SELECT * FROM <TAB>
```

**Expected:** Still < 500ms even with many tables

### Step 7: Test prefix filtering performance
```sql
tq> SELECT * FROM e<TAB>
tq> SELECT * FROM em<TAB>
tq> SELECT * FROM emp<TAB>
```

**Expected:** All < 50ms (prefix filtering on cached data)

## Pass/Fail Criteria

**PASS if:**
- First completion < 500ms (95th percentile)
- Cached completion < 50ms (95th percentile)
- No performance degradation over time
- Large table lists handled within limits
- Prefix filtering instant

**FAIL if:**
- First completion > 500ms consistently
- Cached completion > 50ms
- Performance degrades over time
- Large lists cause timeout
- Prefix filtering slow

## Notes

- Use 95th percentile, not worst case
- Network latency affects first completion
- Database load affects first completion
- Cached completions should be purely local (no DB query)
- Timing precision important - use millisecond accuracy
- Run multiple times to get reliable averages
- Document test environment (network, DB specs)
