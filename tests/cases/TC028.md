## Purpose

Verify that tab completion works correctly after the UPDATE keyword, showing available table names for update statements.

## Scope

This test validates:
- Tab completion after UPDATE keyword
- Context detection for DML statements
- Prefix matching in UPDATE context
- Completion integrates with UPDATE syntax

## Prerequisites

- tq binary built in release mode
- Valid Teradata connection credentials configured in .env
- Test database with multiple tables
- REPL mode functional
- TC026 passed (basic table completion working)

## Test Procedure

### Step 1: Start REPL
```bash
tq repl
```

### Step 2: Test completion after UPDATE
```sql
tq> UPDATE <TAB>
```

### Step 3: Test prefix matching after UPDATE
```sql
tq> UPDATE emp<TAB>
```

### Step 4: Complete full UPDATE statement
```sql
tq> UPDATE employees SET salary = 50000 WHERE id = 1;
# (Don't execute - just Ctrl-C to cancel)
```

### Step 5: Test UPDATE with schema qualification
```sql
tq> UPDATE production.<TAB>
```

## Expected Results

### Step 2 Output:
```
customers    employees    orders    products    departments
```

### Step 3 Output:
```
tq> UPDATE employees
```
Auto-completes if single match

### Step 4 Output:
Completes properly, allows full statement to be typed
(Cancel with Ctrl-C to avoid actual update)

### Step 5 Output:
```
production.customers    production.employees    production.orders
```

## Notes

- UPDATE context simpler than JOIN (no aliases)
- Important for DML statement support
- Be careful not to accidentally execute UPDATE statements during testing
- Use BEGIN TRANSACTION / ROLLBACK if testing actual execution
