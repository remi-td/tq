# Test Case TC067: Batch Mode - File Input with --file Flag

## Purpose

Verify that tq can execute SQL scripts from files using the `--file` flag, supporting both absolute and relative paths.

## Scope

**Testing:**
- File path resolution (absolute and relative)
- SQL file reading and execution
- All output formats with file input
- File not found error handling
- Comments in SQL files

**Not Testing:**
- Multiple statements (covered in TC069)
- stdin input (covered in TC066, TC068)
- Transaction control (future sprint)

## Prerequisites

- tq binary built in release mode
- Valid TQ_LOGON configured
- Live Teradata database connection
- Write access to /tmp directory for test files

## Test Procedure

### Setup

```bash
# Create test SQL files
mkdir -p /tmp/tq_test

cat > /tmp/tq_test/simple.sql <<'EOF'
SELECT 1 AS test_col;
EOF

cat > /tmp/tq_test/with_comments.sql <<'EOF'
-- This is a single-line comment
SELECT 'test' AS col1;

/* This is a
   multi-line comment */
SELECT 2 AS col2;
EOF

cat > /tmp/tq_test/multiline.sql <<'EOF'
SELECT employee_id, salary
FROM DBC.EmployeesV
WHERE salary > 50000
ORDER BY salary DESC
SAMPLE 3;
EOF
```

### Execution Steps

#### Step 1: Execute simple file (absolute path)

```bash
./target/release/tq query --file /tmp/tq_test/simple.sql
```

**Expected outcome:**
- Exit code: 0
- stdout shows result (table format)
- stderr: empty
- Query executes successfully

#### Step 2: Execute file with relative path

```bash
cd /tmp/tq_test
/path/to/tq query --file simple.sql
```

**Expected outcome:**
- Exit code: 0
- Relative path resolved correctly
- Query executes successfully

#### Step 3: Execute file with comments

```bash
./target/release/tq query --file /tmp/tq_test/with_comments.sql
```

**Expected outcome:**
- Exit code: 0
- Comments handled correctly (not executed)
- Both SELECT statements execute (multiple statements - see TC069)
- Results for both queries returned

#### Step 4: Execute file with multi-line SQL

```bash
./target/release/tq query --file /tmp/tq_test/multiline.sql
```

**Expected outcome:**
- Exit code: 0
- Multi-line SQL parsed correctly
- Results returned with 3 rows (SAMPLE 3)

#### Step 5: Execute file with JSON output

```bash
./target/release/tq query --file /tmp/tq_test/simple.sql --format json
```

**Expected outcome:**
- Exit code: 0
- stdout contains valid JSON
- Format override works with file input

#### Step 6: Execute file with CSV output

```bash
./target/release/tq query --file /tmp/tq_test/simple.sql --format csv
```

**Expected outcome:**
- Exit code: 0
- stdout contains CSV with headers
- RFC 4180 compliant

#### Step 7: File not found

```bash
./target/release/tq query --file /tmp/nonexistent.sql
```

**Expected outcome:**
- Exit code: 2 (usage error)
- stderr contains clear error message:
  ```
  Error: File not found

  Could not read file: /tmp/nonexistent.sql
  Reason: No such file or directory

  Check:
    - File path is correct (relative or absolute)
    - File exists and is readable
    - Current directory: /path/to/current/dir
  ```
- stdout: empty
- Error message includes current directory for debugging

#### Step 8: File exists but not readable (permissions)

```bash
cat > /tmp/tq_test/unreadable.sql <<'EOF'
SELECT 1;
EOF
chmod 000 /tmp/tq_test/unreadable.sql

./target/release/tq query --file /tmp/tq_test/unreadable.sql
```

**Expected outcome:**
- Exit code: 2 (usage error)
- stderr contains permission error
- Clear message about file not being readable

#### Step 9: Empty file

```bash
touch /tmp/tq_test/empty.sql
./target/release/tq query --file /tmp/tq_test/empty.sql
```

**Expected outcome:**
- Exit code: 2 (usage error)
- stderr contains error about empty query
- stdout: empty

#### Step 10: File extension doesn't matter

```bash
cat > /tmp/tq_test/query.txt <<'EOF'
SELECT 'extension test' AS result;
EOF

./target/release/tq query --file /tmp/tq_test/query.txt
```

**Expected outcome:**
- Exit code: 0
- Query executes successfully
- File extension (.txt) doesn't prevent execution

### Cleanup

```bash
chmod 644 /tmp/tq_test/unreadable.sql
rm -rf /tmp/tq_test
```

## Expected Results

### Success Case (Simple File)

```bash
$ cat /tmp/test.sql
SELECT 1 AS test_col;

$ tq query --file /tmp/test.sql
┌──────────┐
│ test_col │
├──────────┤
│ 1        │
└──────────┘

$ echo $?
0
```

### Error Case (File Not Found)

```bash
$ tq query --file /tmp/nonexistent.sql
Error: File not found

Could not read file: /tmp/nonexistent.sql
Reason: No such file or directory

Check:
  - File path is correct (relative or absolute)
  - File exists and is readable
  - Current directory: /Users/user/project

$ echo $?
2
```

### Success Case with JSON

```bash
$ tq query --file /tmp/test.sql --format json
[{"test_col":1}]

$ echo $?
0
```

## Pass/Fail Criteria

**PASS:**
- File input works with absolute paths
- File input works with relative paths
- All output formats work
- Comments in SQL files handled correctly
- File not found error is clear and actionable
- Permission errors reported clearly
- Empty files rejected appropriately
- File extension doesn't affect execution
- Exit codes correct

**FAIL:**
- File not read or read incorrectly
- Path resolution broken
- Comments cause SQL errors
- Error messages unclear or missing
- Exit codes incorrect
- Crashes on missing files
- Format flags don't work with --file

## Notes

**File Reading Implementation (from sprint-10-planning.md):**
> "Use `std::fs::read_to_string()` to read file
> Path can be absolute or relative to current directory
> File extension doesn't matter (.sql, .txt, or no extension all work)"

**Comment Handling Strategy:**
> "Phase 1: Don't strip comments, let Teradata handle them
> Teradata SQL parser already handles comments correctly
> If issues arise, add comment stripping in Phase 2"

**Performance Expectation:**
- File I/O overhead: <50ms for files up to 100MB
- File reading is synchronous (blocking)
- Memory usage: entire file loaded into memory

**Path Resolution:**
- Relative paths resolved relative to current working directory
- `~` (tilde) expansion NOT supported in MVP (use absolute paths)
- Windows paths should work (C:\path\to\file.sql)
