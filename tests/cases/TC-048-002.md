# TC-048-002: JSON API Type Fixes — boolean nullable, null default, integer rows/size, database key

## Metadata

| Field | Value |
|-------|-------|
| **Test ID** | TC-048-002 |
| **Title** | JSON output uses correct types: boolean nullable, null default, integer rows/size, "database" key |
| **Category** | Unit Test (writer-injection, no DB) + Integration Test (DB required, `#[ignore]`) |
| **Priority** | Critical (P0) |
| **Feature** | Sprint 48 — Feature 2: Fix JSON API Types |
| **Test Type** | Unit (no DB) + Integration (DB required, `#[ignore]`) |
| **DB Required** | No for unit tests; Yes for integration tests |
| **Created** | 2026-03-23 |
| **Acceptance Criteria** | AC-1, AC-2, AC-3, AC-4, AC-5 |

## Purpose

Verify that after the JSON type fix:
1. `describe` JSON outputs `nullable` as a JSON boolean (`true`/`false`), not a string `"YES"`/`"NO"`.
2. `describe` JSON outputs `default` as JSON `null` when absent, not the string `"-"`.
3. `list tables` JSON outputs `estimated_rows` as a JSON integer, `size_bytes` as a JSON integer.
4. `list databases` JSON uses key `"database"` not `"name"`.

## Acceptance Criteria Coverage

- **AC-1**: describe JSON: nullable as boolean
- **AC-2**: describe JSON: default as null when absent
- **AC-3**: list tables JSON: rows and size as integers
- **AC-4**: list databases JSON: key "database" not "name"
- **AC-5**: Unit tests for all JSON type changes

```rust
// TC-048-002-A1: describe JSON nullable is boolean true (not string "YES")
#[test]
fn json_nullable_true_is_boolean() {
    // Simulate the JSON fragment that describe_json produces for a nullable column
    // After fix: nullable should be the literal `true`, not `"YES"`
    let nullable_val = true;
    let json_fragment = format!("{{\"nullable\":{}}}", nullable_val);
    assert!(
        json_fragment.contains("\"nullable\":true"),
        "nullable must be boolean true, not a string: {}",
        json_fragment
    );
    assert!(
        !json_fragment.contains("\"YES\""),
        "nullable must not be string 'YES': {}",
        json_fragment
    );
}

// TC-048-002-A3: describe JSON default is null when absent (not "-")
#[test]
fn json_default_absent_is_null() {
    // When a column has no default, the JSON must emit `"default":null`
    // not `"default":"-"` or `"default":""`
    let default_absent = Option::<String>::None;
    let json_fragment = match &default_absent {
        Some(d) => format!("{{\"default\":\"{}\"}}", d),
        None => "{\"default\":null}".to_string(),
    };
    assert!(
        json_fragment.contains("\"default\":null"),
        "absent default must produce JSON null: {}",
        json_fragment
    );
    assert!(
        !json_fragment.contains("\"-\""),
        "absent default must not produce '-': {}",
        json_fragment
    );
}

// TC-048-002-A5: describe JSON writer-injection — full column JSON round-trip
// Tests that a ColumnRow with nullable=false, no default renders correct JSON
#[test]
fn describe_json_column_writer_injection() {
    use std::io::Write;
    let mut buf: Vec<u8> = Vec::new();

    // Build the JSON fragment manually (post-fix format)
    // nullable=false (boolean), default=null (JSON null)
    let name = "emp_id";
    let col_type = "INTEGER";
    let nullable = false;   // boolean
    let default_val: Option<&str> = None;

    write!(buf, "{{\"name\":\"{}\"", name).unwrap();
    write!(buf, ",\"type\":\"{}\"", col_type).unwrap();
    write!(buf, ",\"nullable\":{}", nullable).unwrap();
    match default_val {
        Some(d) => write!(buf, ",\"default\":\"{}\"", d).unwrap(),
        None => write!(buf, ",\"default\":null").unwrap(),
    }
    write!(buf, "}}").unwrap();

    let json_str = String::from_utf8(buf).unwrap();

    // Verify JSON structure
    assert!(json_str.contains("\"nullable\":false"), "nullable must be boolean false: {}", json_str);
    assert!(json_str.contains("\"default\":null"), "absent default must be null: {}", json_str);
    assert!(!json_str.contains("\"YES\""), "no string YES: {}", json_str);
    assert!(!json_str.contains("\"NO\""), "no string NO: {}", json_str);
    assert!(!json_str.contains("\"-\""), "no dash default: {}", json_str);
}
```

## Part B — Unit Tests: list tables JSON types

### Prerequisites

- `src/commands/list.rs` updated to emit `rows_est` as integer, `size_bytes` as integer
- Note: the current field is named `rows_est` (string) and `size` (human-readable string)
- After fix: JSON must emit `"rows_est": 1000` (integer), `"size_bytes": 2621440` (integer)

### Test Implementation

Add to `#[cfg(test)] mod tests` in `src/commands/list.rs`:

```rust
// TC-048-002-B1: list tables JSON rows_est is integer (not quoted string)
#[test]
fn json_tables_rows_est_is_integer() {
    use std::io::Write;
    let mut buf: Vec<u8> = Vec::new();

    // Simulate the post-fix JSON output for a table entry
    let name = "employees";
    let kind = "TABLE";
    let rows_est: i64 = 150000;  // integer
    let size_bytes: i64 = 2621440;  // integer

    write!(buf,
        "{{\"name\":\"{}\",\"type\":\"{}\",\"rows_est\":{},\"size_bytes\":{}}}",
        name, kind, rows_est, size_bytes
    ).unwrap();

    let json_str = String::from_utf8(buf).unwrap();

    // rows_est must NOT be quoted
    assert!(
        json_str.contains("\"rows_est\":150000"),
        "rows_est must be unquoted integer: {}",
        json_str
    );
    // size_bytes must NOT be quoted
    assert!(
        json_str.contains("\"size_bytes\":2621440"),
        "size_bytes must be unquoted integer: {}",
        json_str
    );
    // Must not have quoted number
    assert!(
        !json_str.contains("\"rows_est\":\""),
        "rows_est must not be a quoted string: {}",
        json_str
    );
    assert!(
        !json_str.contains("\"size_bytes\":\""),
        "size_bytes must not be a quoted string: {}",
        json_str
    );
}
```
