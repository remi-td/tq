# Test Case TC069: Batch Mode - Multiple Statement Execution

## Purpose

Verify that tq can execute multiple SQL statements from a single file or stdin input, with proper statement separation, sequential execution, and fail-fast error handling.

## Scope

**Testing:**
- Semicolon statement separation
- Sequential statement execution
- Results display for multiple queries
- Status messages for DDL/DML
- Fail-fast behavior on error
- Statement numbering in output

**Not Testing:**
- Transaction control (future sprint)
- Continue-on-error mode (future sprint)
- Complex SQL with semicolons in strings (known limitation)

## Prerequisites

- tq binary built in release mode
- Valid TQ_LOGON configured
- Live Teradata database connection
- Permission to CREATE and DROP tables

## Test Procedure

### Setup

```bash
# Ensure database is accessible
./target/release/tq ping

# Create test SQL file with multiple statements
cat > /tmp/multi_stmt_test.sql <<'EOF'
CREATE TABLE test_multi_stmt (id INTEGER, value VARCHAR(100));

INSERT INTO test_multi_stmt VALUES (1, 'first');
INSERT INTO test_multi_stmt VALUES (2, 'second');
INSERT INTO test_multi_stmt VALUES (3, 'third');

SELECT * FROM test_multi_stmt ORDER BY id;

DROP TABLE test_multi_stmt;
EOF
```

### Execution Steps

#### Step 1: Execute multiple statements (file input)

```bash
./target/release/tq query --file /tmp/multi_stmt_test.sql
```

**Expected outcome:**
- Exit code: 0
- All 6 statements execute sequentially
- Output shows:
  ```
  Statement 1: CREATE TABLE - OK
  Statement 2: INSERT - OK (1 row affected)
  Statement 3: INSERT - OK (1 row affected)
  Statement 4: INSERT - OK (1 row affected)
  Statement 5: SELECT - 3 rows returned

  └────┴─────────┘
  ```

#### Step 3: Multiple statements with empty statements (whitespace)

```bash
cat > /tmp/empty_stmts.sql <<'EOF'

;

;;;

./target/release/tq query --file /tmp/empty_stmts.sql
```

**Expected outcome:**
- Exit code: 0
- Empty statements (whitespace-only) are skipped
- Only 3 SELECT statements execute
- No errors from empty statements

#### Step 4: Fail-fast behavior (error in middle statement)

```bash
cat > /tmp/fail_fast.sql <<'EOF'
SELECT 1 AS stmt1;
SELECT 2 AS stmt2;
INVALID SQL SYNTAX;
SELECT 4 AS stmt4;
SELECT 5 AS stmt5;
EOF

./target/release/tq query --file /tmp/fail_fast.sql
```

**Expected outcome:**
- Exit code: 1 (runtime error)
- Statements 1 and 2 execute successfully
- Statement 3 fails with SQL error
- Statements 4 and 5 NOT executed (fail-fast)
- Output:
  ```

  [results]

  Statement 2: SELECT - 1 row returned
  [results]

  Statements failed: 3 (stopped here)
  Statements remaining: 4-5

  Exit code: 1
  ```


**Expected outcome:**
- Exit code: 0

- INSERT executes

**Expected outcome:**


**Expected outcome:**
- Exit code: 0

   - [ ] Statements split on semicolon correctly
   - [ ] Empty statements skipped
   - [ ] Whitespace trimmed from each statement

   - [ ] Statements execute in file order
   - [ ] Each statement gets numbered output
   - [ ] Results displayed for queries

3. **Fail-Fast Behavior:**

## Pass/Fail Criteria

**PASS:**
- Multiple statements execute sequentially
- Semicolon separation works correctly
- Empty statements skipped
- Fail-fast on error
- Statement numbering correct (1-indexed)
- DDL/DML status messages clear
- SELECT results displayed
- All formats work
- Error context includes statement number
- Exit codes correct

**FAIL:**
- Only first statement executes
- Statement parsing broken
- Empty statements cause errors
- Execution continues after error
- Statement numbers wrong or missing
- Results not displayed
- Format flags don't work
- Unclear error messages

## Notes

**Statement Parsing Strategy (from sprint-10-planning.md):**
> "Simple semicolon splitting for MVP
> Split on `;` character
> No SQL grammar parsing (complex, error-prone)
> Known limitation: Doesn't handle `;` in strings/comments"

**Implementation Approach:**
```rust
pub fn parse_statements(sql: &str) -> Vec<String> {
    sql.split(';')
       .map(|s| s.trim())
       .filter(|s| !s.is_empty())
       .map(|s| s.to_string())
       .collect()
}
```

**Known Limitation:**
```sql
-- This will split incorrectly:
INSERT INTO messages VALUES ('Hello; World');  -- Splits at `;` inside string
```

**Mitigation:** Document limitation. Most real-world SQL doesn't have `;` in strings. Can add string-aware parsing in future sprint if needed.

**Statement Numbering:**
- User-facing numbers start at 1 (not 0)
- "Statement 1", "Statement 2", etc.
- Matches line/position in file

**Fail-Fast Philosophy (from batch-mode.md section 6.5.1):**
> "Stop on the first error
> Clear context: Show what failed and where
> Actionable messages: Suggest fixes when possible
> Exit codes: Non-zero on any failure"
