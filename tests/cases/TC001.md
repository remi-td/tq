## Purpose

Verify that the `tq ping` command successfully tests database connectivity and reports connection status and latency.

## Scope

This test validates:
- Basic ping functionality
- Connection establishment
- Latency measurement
- Success output format
- Exit code 0 on success

## Prerequisites

- tq binary is built and available in PATH or target/release
- Valid Teradata connection credentials configured
- `.env` file set up with TQ_LOGON (recommended) OR --logon flag can be used
- Database server is running and accessible

## Test Procedure

### Step 1: Setup
```bash
# Ensure .env file is configured with connection details
# The .env file should contain: TQ_LOGON=testuser:testpass@testhost:1025/testdb
# Alternatively, for testing without .env, set environment variable:
# export TQ_LOGON="testuser:testpass@testhost:1025/testdb"
```

### Step 2: Execute ping command
```bash
tq ping
```

### Step 3: Verify exit code
```bash
echo $?
```

### Step 4: Execute with explicit logon
```bash
tq -l "testuser:testpass@testhost:1025/testdb" ping
```

### Step 5: Execute with verbose output
```bash
tq -v ping
```

## Expected Results

### Step 2 Output:
```
Database connection successful (XXXms)
```
- Where XXX is the measured latency in milliseconds
- No errors on stderr
- Exit code: 0

### Step 3 Output:
```
0
```

### Step 4 Output:
Same as Step 2, confirming explicit --logon flag works

### Step 5 Output:
Should include additional verbose information:
- Connection details (host, port, database)
- Authentication mechanism
- Possibly connection timing breakdown

## Pass/Fail Criteria

**PASS if:**
- Command exits with code 0
- Output matches expected format
- Latency is displayed in milliseconds
- No errors are written to stderr
- Connection is established successfully

**FAIL if:**
- Exit code is non-zero
- Output format is incorrect
- Latency is not displayed
- Errors appear on stderr
- Connection fails when credentials are valid

## Notes

- This is the most basic connectivity test
- Latency values will vary based on network conditions
- This test requires actual database connectivity
- Alternative: Mock database connection for unit testing
