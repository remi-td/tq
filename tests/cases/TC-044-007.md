# TC-044-007: Profile Delete Confirmation - --force Bypass and Non-TTY Behavior

**Sprint:** 44
**Feature:** Profile Delete Confirmation (Sprint 43 Deferred)
**Acceptance Criteria:** AC-17, AC-18, AC-19
**Type:** Unit Test + Dependency Injection / expectrl
**Requires DB:** No
**Requires Binary:** No (unit tests); Yes (expectrl tests)

---

## Objective

Verify the three behavioral paths of `tq profile delete`:

1. `--force` bypasses confirmation in all modes (AC-19)
2. Non-TTY mode without `--force` returns an error requiring `--force` (AC-18)
3. TTY mode shows `Delete profile 'name'? [y/N]` prompt; `y` proceeds, `n` aborts (AC-17)

## Preconditions

- For unit tests: `TQ_CONFIG_DIR` redirected to temp dir
- For TTY path: either implementation accepts injectable reader, or `expectrl` is available
- Pre-existing profile in config for delete operations

## Test Scenarios

### Scenario 1: `--force` flag bypasses confirmation (AC-19)

**Type:** Unit test (existing test, verify still passes after refactor)

**Setup:** Config with profile `dev` in temp dir

**Action:** `handle_delete("dev", true)` (force=true)

**Expected:** Exit Ok(()), profile removed from config

**Assert:**
```rust
let result = handle_delete("dev", true);
assert!(result.is_ok());
let config = read_config_table().unwrap();
assert!(!config["profiles"].as_table().unwrap().contains_key("dev"));
```

### Scenario 2: Non-TTY, no `--force`, returns error (AC-18)

**Type:** Unit test (unit tests run in non-TTY environment)

**Setup:** Config with profile `dev` in temp dir

**Action:** `handle_delete("dev", false)` with no TTY available

**Expected:** Returns error mentioning `--force`

**Assert:**
```rust
let result = handle_delete("dev", false);
assert!(result.is_err());
let err_msg = format!("{}", result.unwrap_err());
assert!(err_msg.contains("--force") || err_msg.contains("force"),
    "Error must mention --force flag, got: {}", err_msg);
```

### Scenario 3: Non-TTY requires `--force` message is actionable (AC-18)

**Type:** Unit test

**Action:** Same as Scenario 2

**Additional Assert:** Error message or stderr output includes usage hint

**Assert:** Error message contains the profile name and the correct usage (`tq profile delete <name> --force`)

### Scenario 4: TTY mode - `y` input proceeds (AC-17)

**Type:** Dependency injection test (preferred) OR expectrl test (fallback)

#### 4a: Dependency injection approach

**Setup:** Config with profile `dev`

**Action:**
```rust
let result = handle_delete_interactive(
    "dev",
    false,         // force = false
    true,          // is_tty = true
    &mut "y\n".as_bytes(),  // injected reader
);
```

**Expected:** Ok(()), profile removed

**Assert:** `result.is_ok()` AND profile gone from config

#### 4b: expectrl approach (fallback)

**Setup:** Build binary, create temp config with profile `dev`

**Action:**
```rust
let mut process = expectrl::spawn(format!(
    "TQ_CONFIG_DIR={} {} profile delete dev",
    temp_dir.path().display(),
    tq_binary().display()
)).unwrap();
process.expect("Delete profile 'dev'? [y/N]").unwrap();
process.send("y\n").unwrap();
process.expect(expectrl::Eof).unwrap();
```

**Expected:** Process exits 0, profile removed from config

### Scenario 5: TTY mode - `n` input aborts (AC-17)

**Type:** Dependency injection test (preferred) OR expectrl test (fallback)

#### 5a: Dependency injection approach

**Action:**
```rust
let result = handle_delete_interactive(
    "dev",
    false,
    true,
    &mut "n\n".as_bytes(),
);
```

**Expected:** Returns error (aborted), profile still exists in config

#### 5b: expectrl approach

**Action:** Same as Scenario 4b but send `n\n` instead of `y\n`

**Expected:** Process exits non-zero, profile still in config

### Scenario 6: Prompt text matches specification (AC-17)

**Type:** Dependency injection test OR expectrl

**Action:** Capture stderr/stdout during interactive delete

**Expected:** Output contains exactly `Delete profile 'dev'? [y/N]` (or close equivalent)

**Assert:** The prompt text includes the profile name, `[y/N]` indicator

## Implementation Notes

The preferred implementation signature for testability:

```rust
// Public for testing; internal implementation
pub(crate) fn handle_delete_interactive(
    name: &str,
    force: bool,
    is_tty: bool,
    reader: &mut dyn std::io::BufRead,
) -> Result<()> {
    if force {
        // Always bypass
        return handle_delete_impl(name);
    }
    if !is_tty {
        // Non-interactive: require --force
        return Err(TqError::InvalidConfig(format!(
            "Deleting profile '{}' requires --force in non-interactive mode.\n\
             Usage: tq profile delete {} --force", name, name
        )));
    }
    // TTY: show prompt
    eprint!("Delete profile '{}'? [y/N] ", name);
    let mut response = String::new();
    reader.read_line(&mut response).map_err(|e| TqError::IoError(e))?;
    if response.trim().eq_ignore_ascii_case("y") {
        handle_delete_impl(name)
    } else {
        Err(TqError::InvalidConfig("Deletion aborted.".to_string()))
    }
}
```

## Pass Criteria

- Scenario 1 (--force): profile deleted, Ok(())
- Scenario 2 (non-TTY, no force): error returned, error message mentions `--force`
- Scenario 3: error message is actionable (includes usage hint)
- Scenario 4 (TTY + y): profile deleted, Ok(())
- Scenario 5 (TTY + n): error returned, profile preserved
- Scenario 6: prompt text matches `Delete profile '<name>'? [y/N]`
