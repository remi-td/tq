# TC-036-008: `/show indexes` Output Format

## Metadata

| **Title** | `/show indexes` Output Format |
| **Category** | Integration + Interactive |
| **Priority** | High |

| **Created** | 2026-02-13 |

## Purpose

Verify that `/show indexes` command displays index information in clear table format with correct columns and handles empty result sets gracefully.

## Acceptance Criteria Coverage

- **AC-18**: Table output shows: IndexName, IndexType, ColumnName, ColumnPosition
- **AC-24**: Integration tests for CLI behavior

## Scope

This test validates:
- Table output format with 4 columns
- Column headers: IndexName, IndexType, ColumnName, ColumnPosition
- Index information displayed correctly
- Multiple indexes for same table shown
- Multi-column indexes displayed (multiple rows per index)
- Empty result set (table has no indexes) handled gracefully
- Output readability and alignment

## Prerequisites

- Rust test framework available
- `tq` binary built with REPL support
- expectrl crate for PTY testing
- Integration test framework (std::process::Command)
- Database connection available
- Test database with tables containing indexes

## Test Procedure

### Integration Test 1: Table with Single-Column Index

```rust
#[test]
#[ignore] // Requires database connection
fn test_show_indexes_single_column_index() {
    let temp_db = create_test_database();
    let table_name = format!("test_idx_single_{}", random_suffix());

    // Create table with single-column index
    execute_sql(&format!(
        "CREATE TABLE {}.{} (id INT, name VARCHAR(50))",
        temp_db, table_name
    ));
    execute_sql(&format!(
        "CREATE INDEX idx_id ON {}.{} (id)",
        temp_db, table_name
    ));

    // Execute /show indexes in REPL
    let mut repl = spawn_repl().expect("Failed to spawn REPL");
    repl.send_line(&format!("USE {};", temp_db)).unwrap();
    repl.send_line(&format!("/show indexes {}", table_name)).unwrap();

    let output = repl.read_until_prompt().unwrap();

    // Verify column headers
    assert!(output.contains("IndexName"), "Should show IndexName column");
    assert!(output.contains("IndexType"), "Should show IndexType column");
    assert!(output.contains("ColumnName"), "Should show ColumnName column");
    assert!(output.contains("ColumnPosition"), "Should show ColumnPosition column");

    // Verify index data
    assert!(output.contains("idx_id"), "Should show index name");
    assert!(output.contains("id"), "Should show column name");

    // Cleanup
    execute_sql(&format!("DROP TABLE {}.{}", temp_db, table_name));
}
```

### Integration Test 4: Empty Result (No Indexes)

```rust
#[test]
#[ignore] // Requires database connection
fn test_show_indexes_no_indexes() {
    let temp_db = create_test_database();
    let table_name = format!("test_idx_none_{}", random_suffix());

    // Create table WITHOUT indexes
    execute_sql(&format!(
        "CREATE TABLE {}.{} (id INT, data VARCHAR(50))",
        temp_db, table_name
    ));

    // Execute /show indexes
    let mut repl = spawn_repl().expect("Failed to spawn REPL");
    repl.send_line(&format!("USE {};", temp_db)).unwrap();
    repl.send_line(&format!("/show indexes {}", table_name)).unwrap();

    let output = repl.read_until_prompt().unwrap();

    // Should show column headers but no data rows
    // OR show helpful message like "No indexes found"
    let has_headers = output.contains("IndexName");
    let has_message = output.contains("No indexes") || output.contains("no indexes");

    assert!(
        has_headers || has_message,
        "Should show headers or helpful message when no indexes"
    );

    // Should NOT show error
    assert!(
        !output.contains("error") && !output.contains("Error"),
        "Should not show error for table with no indexes"
    );

    // Cleanup
    execute_sql(&format!("DROP TABLE {}.{}", temp_db, table_name));
}
```

## Expected Results

### Integration/Interactive Test Results:
1. **Single-column index**: 4 column headers shown, index data displayed
2. **Multi-column index**: Multiple rows per index (one per column), positions shown
3. **Multiple indexes**: All indexes listed, each with columns
4. **No indexes**: Empty result or helpful message (no error)
5. **Primary key**: Primary key index shown with type indicator
6. **Qualified name**: Works with `database.table` syntax
7. **Output alignment**: Table format with aligned columns

## Pass/Fail Criteria

**PASS if:**
- All 7 tests pass
- Output shows 4 columns: IndexName, IndexType, ColumnName, ColumnPosition
- Single-column indexes displayed correctly
- Multi-column indexes show multiple rows with positions
- Multiple indexes all listed
- Empty result handled gracefully (no error)
- Primary key indexes shown with correct type
- Qualified table names work
- Output formatted as readable table (aligned)
- No database errors or crashes

**FAIL if:**
- Any test fails
- Wrong columns displayed
- Multi-column indexes not handled correctly
- Missing indexes in output
- Error shown for table with no indexes
- Primary key index missing or wrong type
- Qualified names don't work
- Output unreadable (misaligned, missing separators)
- Database errors or crashes
