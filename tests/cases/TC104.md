## Overview

Sprint 67 introduced pager search (`/pattern`, `n`, `N`, `\c`). AC-1 (search prompt opens in
status bar) and AC-11 (clean exit without terminal corruption) were strategy-classified REQUIRED
with an "interactive PTY" test but the test was fallback-accepted in Sprint 67. Sprint 68
removes the fallback: the test must be authored and executed.

This test uses `spawn_tq_repl_tiered_with_pager` — a variant of the tiered harness that omits
`--no-pager` so the pager activates on large result sets.

**Critical implementation requirement:** `spawn_tq_repl_tiered` includes `--no-pager` in its
command string. This test MUST NOT use that flag. The architect must either add a new helper
`spawn_tq_repl_tiered_with_pager` or pass a custom command to `TqPty::new` directly.

## TC104-I01: `test_pager_search_prompt_and_exit`

**Requirement:** AC-OBJ2-3 — at minimum, one PTY test that:
1. Opens the pager search prompt by sending `/`
2. Enters a pattern present in the result set
3. Observes `Pattern:` in PTY output (status bar updated)
4. Exits the pager with `q`
5. Confirms `tq>` returns (REPL prompt, clean exit)

**Location:** `tests/interactive_tests.rs`

**BLOCKED condition:** `TQ_LOGON` not set or database unreachable. Verdict is BLOCKED — not
APPROVED. A `skipped for reason: DB unavailable` label does NOT satisfy this AC in Sprint 68.

### Spawn Helper Required

The test requires a REPL session with the pager active. The standard `spawn_tq_repl_tiered`
uses `--no-pager`. The architect must provide:

```rust
fn spawn_tq_repl_tiered_with_pager(test_name: &str) -> TqPty {
    let bin_path = assert_cmd::cargo::cargo_bin!("tq");
    let cmd = format!("{} repl --no-syntax-highlight", bin_path.display());
    let session = expectrl::spawn(cmd).expect("Failed to spawn tq repl");
    TqPty::new(session, test_name, Timeouts::from_env())
}
```

This is identical to `spawn_tq_repl_tiered` except `--no-pager` is omitted.

### Query for Pager Activation

The test needs a query that returns more rows than `PagerConfig::default().effective_page_size()`.

**Primary query (recommended):**
```sql
SELECT ColumnName FROM DBC.ColumnsV WHERE DatabaseName = 'DBC' AND TableName = 'SessionInfoV'
```
This returns the columns of the `SessionInfoV` system view. If fewer than page_size rows are
returned, fall back to the broader query:

```sql
SELECT ColumnName FROM DBC.ColumnsV WHERE DatabaseName = 'DBC' AND TableName = 'AllTempTablesVX'
```

Or the reliably large query:
```sql
SELECT ColumnName FROM DBC.ColumnsV WHERE DatabaseName = 'DBC'
```
(hundreds of rows, always available on any Teradata instance)

The column header `ColumnName` is used as the search pattern needle (step 5 below), since it is
always present in the result set in string form.

### Test Execution Steps

```rust
#[test]
#[ignore]
fn test_pager_search_prompt_and_exit() {
    let mut p = spawn_tq_repl_tiered_with_pager("test_pager_search_prompt_and_exit");

    // Step 1: Wait for connection
    p.expect_stage(Stage::Connect, "Connected to")
        .expect("connect stage: 'Connected to' not seen");

    // Step 2: Warmup
    std::thread::sleep(Duration::from_secs(1));

    // Step 3: Submit a query returning many rows (triggers pager)
    p.session_mut()
        .send_line("SELECT ColumnName FROM DBC.ColumnsV WHERE DatabaseName = 'DBC'")
        .expect("send query");

    // Step 4: Wait for pager to activate — column header visible
    p.expect_stage(Stage::Query, "ColumnName")
        .expect("query stage: pager header 'ColumnName' not seen");

    // Step 5: Let pager settle
    std::thread::sleep(Duration::from_millis(500));

    // Step 6: Open search prompt
    p.session_mut().send("/").expect("send / to open search");
    std::thread::sleep(Duration::from_millis(200));

    // Step 7: Type search pattern and submit
    // "ColumnName" is guaranteed present in the column header / data
    p.session_mut()
        .send("ColumnName\n")
        .expect("send search pattern");

    // Step 8: Wait for status bar to show "Pattern:"
    p.expect_stage(Stage::Query, "Pattern:")
        .expect("query stage: 'Pattern:' not seen after search; status bar not updated");

    // Step 9: Exit pager
    p.session_mut().send("q").expect("send q to exit pager");

    // Step 10: Confirm REPL prompt returns (AC-11: no terminal corruption)
    p.expect_stage(Stage::Prompt, "tq>")
        .expect("prompt stage: 'tq>' not seen after pager exit; terminal may be corrupted");
}
```

### Pass Criteria

1. Step 4 succeeds: `ColumnName` seen in PTY output (pager is showing, query ran).
2. Step 8 succeeds: `Pattern:` seen in PTY output (search prompt processed the input).
3. Step 10 succeeds: `tq>` seen after `q` (REPL prompt returned; terminal not corrupted).

**All three steps must succeed for AC-OBJ2-3 to be APPROVED.**

### Alternative Needle for Step 8

If `Pattern:` appears ANSI-wrapped in the actual implementation (e.g., `Pattern:` is on the
alternate screen inside ANSI CSI sequences), use:

```rust
p.expect_stage(Stage::Query, expectrl::Regex("Pattern:|ColumnName"))
    .expect("query stage: search not acknowledged");
```

The `Regex` variant matches either the literal status bar string or the matched cell content.

### BLOCKED / FAIL handling

If the test produces `ExpectTimeout` at any stage:
- A PTY dump will be written to `tests/results/sprint-66/test_pager_search_prompt_and_exit.pty.log`
- Inspect the dump to determine which step failed
- If Stage::Connect times out: DB is unreachable — verdict is BLOCKED
- If Stage::Query times out after sending the query: pager did not activate — check `--no-pager` flag
- If Stage::Query times out after sending `Pattern:`: search prompt not observed — possible pager
  search implementation gap

## Notes

1. This test was strategy-classified REQUIRED in Sprint 67 and fallback-accepted. Sprint 68
   removes the fallback. If the database is unavailable, the sprint verdict is BLOCKED — not APPROVED.

2. The `spawn_tq_repl_tiered_with_pager` helper is new (Sprint 68). It differs from
   `spawn_tq_repl_tiered` only by omitting `--no-pager`. The architect must provide it.

3. The query `SELECT ColumnName FROM DBC.ColumnsV WHERE DatabaseName = 'DBC'` returns hundreds
   of rows on any Teradata instance. It is the most reliable choice for triggering pager mode.
   `DBC.ColumnsV` is readable by all sessions (SELECT privilege on DBC catalog views is granted
   to PUBLIC by default on Teradata installations).

4. The test uses `send_line` for the query (adds `\n`) and `send` for single keystrokes
   (`/`, `q`) to match the interactive PTY convention established in TC097 and TC098.
