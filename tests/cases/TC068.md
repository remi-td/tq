# Test Case TC068: Batch Mode - stdin Input with Heredoc

## Purpose

Verify that tq can execute SQL queries from shell heredocs, enabling multi-line SQL in shell scripts without temporary files.

## Scope

**Testing:**
- Heredoc input (<<EOF ... EOF)
- Multi-line SQL from heredoc
- Variable expansion in heredoc
- Quoted heredoc (no variable expansion)
- Multiple statements from heredoc

**Not Testing:**
- File input (covered in TC067)
- Simple echo (covered in TC066)
- Variable substitution feature (future sprint)

## Prerequisites

- tq binary built in release mode
- Valid TQ_LOGON configured
- Live Teradata database connection
- bash or sh shell

## Test Procedure

### Setup

```bash
# Ensure database is accessible
./target/release/tq ping
```

### Execution Steps

#### Step 1: Simple heredoc (single statement)

```bash
./target/release/tq query <<EOF
SELECT 1 AS test_value;
EOF
```

**Expected outcome:**
- Exit code: 0
- SQL executes successfully
- Result displayed as table
- stderr: empty

#### Step 2: Multi-line SQL with heredoc

```bash
./target/release/tq query <<EOF
SELECT employee_id, first_name, last_name, salary
FROM DBC.EmployeesV
WHERE salary > 50000
  AND department = 'Engineering'
ORDER BY salary DESC
SAMPLE 5;
EOF
```

**Expected outcome:**
- Exit code: 0
- Multi-line SQL parsed correctly
- Indentation preserved but not significant
- Results returned

#### Step 3: Heredoc with comments

```bash
./target/release/tq query <<EOF
-- This is a comment
SELECT 'test' AS col1;

/* Multi-line
   comment */
SELECT 2 AS col2;
EOF
```

**Expected outcome:**
- Exit code: 0
- Comments preserved for Teradata
- Both statements execute (multiple statements - see TC069)
- No SQL errors from comments

#### Step 4: Heredoc with JSON output

```bash
./target/release/tq query --format json <<EOF
SELECT 1 AS id, 'Alice' AS name;
EOF
```

**Expected outcome:**
- Exit code: 0
- stdout contains valid JSON
- Format flag applies to heredoc input

#### Step 5: Heredoc with shell variable expansion

```bash
TABLE="DBC.DatabasesV"
LIMIT=5

./target/release/tq query <<EOF
SELECT DatabaseName
FROM ${TABLE}
SAMPLE ${LIMIT};
EOF
```

**Expected outcome:**
- Exit code: 0
- Variables expanded by shell before passing to tq
- Query executes with DBC.DatabasesV and SAMPLE 5
- Results returned

#### Step 6: Quoted heredoc (no variable expansion)

```bash
TABLE="should_not_expand"

./target/release/tq query <<'EOF'
SELECT '${TABLE}' AS literal_value;
EOF
```

**Expected outcome:**
- Exit code: 0
- `${TABLE}` NOT expanded (quoted heredoc)
- Result shows literal string "${TABLE}"

#### Step 7: Heredoc in shell script

```bash
cat > /tmp/test_heredoc.sh <<'SCRIPT'
#!/bin/bash
set -e

TQ="./target/release/tq"

# Run query with heredoc
$TQ query <<EOF
SELECT CURRENT_DATE AS today,
       CURRENT_TIME AS now,
       USER AS current_user;
EOF

echo "Query completed successfully"
SCRIPT

chmod +x /tmp/test_heredoc.sh
/tmp/test_heredoc.sh
```

**Expected outcome:**
- Exit code: 0 (script succeeds)
- Query executes
- "Query completed successfully" printed
- Script demonstrates heredoc in shell automation

#### Step 8: Empty heredoc

```bash
./target/release/tq query <<EOF
EOF
```

**Expected outcome:**
- Exit code: 2 (usage error)
- stderr contains error about empty query
- stdout: empty

#### Step 9: Whitespace-only heredoc

```bash
./target/release/tq query <<EOF


EOF
```

**Expected outcome:**
- Exit code: 2 (usage error)
- stderr contains error about empty query
- stdout: empty

#### Step 10: Heredoc with SQL error

```bash
./target/release/tq query <<EOF
INVALID SQL SYNTAX;
EOF
```

**Expected outcome:**
- Exit code: 1 (runtime error)
- stderr contains Teradata error message
- stdout: empty

### Cleanup

```bash
rm -f /tmp/test_heredoc.sh
```

## Pass/Fail Criteria

**PASS:**
- Heredoc input works correctly
- Multi-line SQL parsed
- Shell variable expansion works (unquoted)
- Shell variable expansion disabled (quoted)
- Heredoc works in scripts
- All output formats work
- Empty heredoc rejected
- Error handling correct
- Exit codes correct

**FAIL:**
- Heredoc not read
- EOF terminator not recognized
- Variable expansion broken
- SQL parsing errors
- Heredoc doesn't work in scripts
- Crashes on empty input

## Notes

**Heredoc vs File vs Echo:**

| Method | Use Case | Pros | Cons |
|--------|----------|------|------|
| echo | One-liner | Simple | Limited to single line |
| heredoc | Multi-line script | No temp file, readable | Shell-specific syntax |
| --file | Saved scripts | Reusable, version control | Requires file |

**Shell Variable Expansion:**
- Unquoted heredoc (`<<EOF`): Variables expanded by shell
- Quoted heredoc (`<<'EOF'`): No expansion, literal text
- This is shell behavior, not tq behavior
- tq receives already-expanded text

**Best Practice for Scripts (from batch-mode.md section 6.6.1):**

```bash
#!/bin/bash
set -e  # Exit on any error

# Use heredoc for multi-line SQL
tq query <<EOF
SELECT employee_id, salary
FROM employees
WHERE department = 'Engineering'
ORDER BY salary DESC;
EOF

# Check exit code explicitly
if [ $? -eq 0 ]; then
    echo "Query succeeded"
else
    echo "Query failed" >&2
    exit 1
fi
```

**Performance:**
- No overhead vs echo or file
- stdin reading is fast (<10ms)
- Connection time dominates (100-200ms)
