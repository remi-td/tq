# TC-047-004: Enrich `tq describe` Output

## Metadata

| Field | Value |
|-------|-------|
| **Test ID** | TC-047-004 |
| **Title** | `tq describe` output includes object header, Comments column, Indexes section, and structured JSON |
| **Category** | Unit Test + Integration Test |
| **Priority** | High (P1) |
| **Feature** | Sprint 47 — Feature 4: Enrich `tq describe` Output |
| **Test Type** | Unit (no DB) + Integration (DB required, `#[ignore]`) |
| **DB Required** | No for unit tests; Yes for integration tests |
| **Created** | 2026-03-23 |
| **Acceptance Criteria** | AC-1, AC-2, AC-3, AC-4, AC-5 |

## Purpose

Verify that after the enrichment:
1. `tq describe <table>` output starts with a header block showing the qualified object name, type, and estimated row count.
2. The Columns table has a 5th column: Comments (CommentString from DBC.ColumnsV).
3. An Indexes section appears after Columns for tables (absent for views).
4. JSON output uses a structured `{"object", "type", "estimated_rows", "columns": [...], "indexes": [...]}` wrapper where `nullable` is a boolean and `default` is null (not "-") when absent.
5. Unit tests exist for all formatting functions in `describe.rs`.

## Acceptance Criteria Coverage

- **AC-1**: Output includes object header (database, table name, type) — spec: cli-interface.md §describe
- **AC-2**: Columns table includes CommentString column — spec: REQ-DESCRIBE-005
- **AC-3**: Indexes section shows primary and secondary indexes — spec: cli-interface.md §describe
- **AC-4**: JSON output uses structured wrapper — spec: REQ-DESCRIBE-009
- **AC-5**: Unit tests for describe.rs formatting functions

// TC-047-004-S: tq describe shows header, Columns, and Indexes sections
#[test]
#[ignore]
fn describe_table_shows_all_sections() {
    let output = Command::new(tq_binary())
        .args(["-l", &logon(), "describe", "dbc.tables"])
        .output()
        .expect("Failed to run tq describe");

    let stdout = String::from_utf8_lossy(&output.stdout);
    assert!(output.status.success(), "tq describe must exit 0 for valid table");
    assert!(stdout.contains("Table:"), "Output must contain 'Table:' header");
    assert!(stdout.contains("Columns:") || stdout.contains("Column"), "Output must contain Columns section");
    assert!(stdout.contains("Indexes:"), "Output must contain Indexes section for a table");
}

// TC-047-004-T: tq describe --format json returns structured JSON
#[test]
#[ignore]
fn describe_json_format_returns_structured_object() {
    let output = Command::new(tq_binary())
        .args(["-l", &logon(), "describe", "--format", "json", "dbc.tables"])
        .output()
        .expect("Failed to run tq describe --format json");

    let stdout = String::from_utf8_lossy(&output.stdout);
    assert!(output.status.success(), "tq describe --format json must exit 0");

    let json: serde_json::Value = serde_json::from_str(&stdout)
        .unwrap_or_else(|e| panic!("Output must be valid JSON: {}\nGot: {}", e, &stdout[..200.min(stdout.len())]));

    assert!(json["object"].is_string(), "JSON must have 'object' key");
    assert!(json["columns"].is_array(), "JSON must have 'columns' array");
    assert!(json["indexes"].is_array(), "JSON must have 'indexes' array");

    // Verify nullable is boolean
    if let Some(first_col) = json["columns"].as_array().and_then(|a| a.first()) {
        assert!(
            first_col["nullable"].is_boolean(),
            "JSON nullable must be boolean — got: {:?}",
            first_col["nullable"]
        );
    }
}

// TC-047-004-U: tq describe on a view omits Indexes and Rows (Est.) sections
#[test]
#[ignore]
fn describe_view_omits_indexes_and_rows() {

}

// TC-047-004-V: tq describe nonexistent exits 1 with Error: message
#[test]
#[ignore]
fn describe_nonexistent_object_exits_1_with_error() {

        .output()
