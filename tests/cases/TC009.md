## Purpose

Verify that tq can securely read passwords from files and properly validates file permissions.

## Scope

This test validates:
- --password-file flag functionality
- Password file reading
- File permission validation (Unix)
- Password override behavior
- Security warnings

## Prerequisites

- tq binary is built and available
- `.env` file configured with connection details (can be without password for testing)
- Unix-like system for permission tests (or skip on Windows)

## Test Procedure

### Step 1: Create password file with correct permissions
```bash
echo "testpassword" > /tmp/tq_test_pass
chmod 0600 /tmp/tq_test_pass
tq -l "testuser@testhost:1025/testdb" --password-file /tmp/tq_test_pass ping
```

### Step 2: Password file with insecure permissions
```bash
echo "testpassword" > /tmp/tq_test_pass_insecure
chmod 0644 /tmp/tq_test_pass_insecure
tq -l "testuser@testhost:1025/testdb" --password-file /tmp/tq_test_pass_insecure ping 2>&1 | grep -i "warning"
```

### Step 3: Password file overrides connection string password
```bash
echo "filepassword" > /tmp/tq_test_pass
chmod 0600 /tmp/tq_test_pass
# Connection string has wrong password, file has right one
tq -l "testuser:wrongpass@testhost:1025/testdb" --password-file /tmp/tq_test_pass ping
```

### Step 4: Nonexistent password file
```bash
tq -l "testuser@testhost:1025/testdb" --password-file /nonexistent/file ping 2>&1
echo "Exit code: $?"
```

### Step 5: Empty password file
```bash
touch /tmp/tq_test_pass_empty
chmod 0600 /tmp/tq_test_pass_empty
tq -l "testuser@testhost:1025/testdb" --password-file /tmp/tq_test_pass_empty ping 2>&1
```

### Cleanup:
```bash
rm -f /tmp/tq_test_pass* 2>/dev/null
```

## Expected Results

### Step 1 Output:
```
Database connection successful (XXXms)
```
Exit code: 0
No warnings about permissions

### Step 2 Output (stderr):
```
Warning: Password file '/tmp/tq_test_pass_insecure' has insecure permissions (644)
Expected: 0600 (owner read/write only)
Fix: chmod 0600 /tmp/tq_test_pass_insecure

Continuing anyway (use --strict to abort)...
```
Then attempts connection (may succeed or fail based on credentials)

### Step 3 Output:
Connection should use password from file, not from connection string
Should succeed if file password is correct

```
File: /nonexistent/file
Reason: No such file or directory

Check:
  - File exists and path is correct
  - You have permission to read the file
```
Exit code: 1

### Step 5 Output (stderr):
Should handle empty file gracefully, likely fail at authentication with empty password

## Pass/Fail Criteria

**PASS if:**
- Password read from file successfully
- File permissions validated on Unix systems
- Warning issued for insecure permissions
- Password file overrides connection string password
- Clear error for nonexistent files
- Empty files handled gracefully
- No password appears in error messages or logs
- Exit codes are correct

**FAIL if:**
- Cannot read password from file
- Permission checks missing or wrong
- Password visible in output/errors
- Incorrect precedence (file should override string)
- Program crashes on missing/empty files

## Notes

- Recommended pattern: connection string without password + password file
- File should have 0600 permissions (owner read/write only)
- Consider supporting pgpass-style format: host:port:db:user:pass
- Never log or display password content
- Whitespace should be trimmed from password file content
