## Purpose

Verify that `tq search` and `tq list` commands support `--page-size` and `--page` flags, produce correct pagination metadata in JSON output, and enforce mutual exclusion with `--limit`.

## Acceptance Criteria Coverage

- SL-PAG-REQ-1: `tq search tables <kw> --page-size N` paginates search results
- SL-PAG-REQ-2: `tq list tables --page-size N` paginates list results
- SL-PAG-REQ-3: JSON envelope includes pagination metadata
- SL-PAG-REQ-4: `--limit` and `--page-size` are mutually exclusive

## Scope

**Unit tests (no DB):**
1. Search: paginate `TableSearchResult` slice — page 1, page 2, last page
2. Search: paginate `ColumnSearchResult` slice
3. Search JSON output includes `pagination` object when `--page-size` is active
4. List: paginate list command results (tables, databases, views)
5. Mutual exclusion: error when `--limit` and `--page-size` both provided to search
6. Mutual exclusion: error when `--limit` and `--page-size` both provided to list

**Integration tests (live DB, `#[ignore]`):**
7. `tq search tables emp --format json --page-size 5` returns paginated JSON
8. `tq list tables --format json --page-size 10` returns paginated JSON

## Prerequisites

- Unit: no DB required
- Integration: live Teradata DB (`TQ_LOGON` set)

## Test Procedure

### Execution Commands

```bash
# Unit tests only
```

### Test Implementations

#### Test Group A: Search Pagination Unit Tests (in `src/commands/search.rs`)

**Test A1: `test_search_table_pagination_page1_json`**
- Setup: `Vec<TableSearchResult>` with 12 entries; PaginationOptions { page_size: 5, page: 1 }
- Call: `render_table_search_json` (or paginated variant) with pagination options
- Assert:
  - `parsed["ok"] == true`
  - `parsed["pagination"]["page"] == 1`
  - `parsed["pagination"]["page_size"] == 5`
  - `parsed["pagination"]["total_rows"] == 12`
  - `parsed["pagination"]["has_more"] == true`
  - `parsed["row_count"] == 5`
  - `parsed["data"].len() == 5`

**Test A2: `test_search_table_pagination_last_page_json`**
- Setup: 12 entries, PaginationOptions { page_size: 5, page: 3 }
- Assert:
  - `parsed["pagination"]["has_more"] == false`
  - `parsed["row_count"] == 2` (12 - 2*5 = 2 remaining)
  - `parsed["data"].len() == 2`

**Test A3: `test_search_column_pagination_json`**
- Setup: `Vec<ColumnSearchResult>` with 8 entries; PaginationOptions { page_size: 3, page: 2 }
- Assert:
  - `parsed["pagination"]["page"] == 2`
  - `parsed["row_count"] == 3`
  - `parsed["data"].len() == 3`

**Test A4: `test_search_no_pagination_backward_compat`**
- Setup: `Vec<TableSearchResult>` with 5 entries; no pagination options
- Assert:
  - `parsed["ok"] == true`
  - `parsed["row_count"] == 5`
  - `parsed.get("pagination")` is None
  - The existing JSON output format is unchanged

#### Test Group B: List Pagination Unit Tests (in `src/commands/list.rs`)

**Test B1: `test_list_tables_pagination_page1_json`**
- Setup: list tables result with 15 entries; PaginationOptions { page_size: 5, page: 1 }
- Assert:
  - `parsed["pagination"]["page"] == 1`
  - `parsed["pagination"]["total_rows"] == 15`
  - `parsed["pagination"]["has_more"] == true`
  - `parsed["data"].len() == 5`

**Test B2: `test_list_pagination_has_more_false`**
- Setup: list result with 10 entries; PaginationOptions { page_size: 5, page: 2 }
- Assert:
  - `parsed["pagination"]["has_more"] == false`
  - `parsed["data"].len() == 5`

#### Test Group C: Mutual Exclusion Error Tests

**Test C1: `test_search_error_limit_and_page_size_together`**

## Expected Results

Unit tests: all 8 pass without DB.
Integration tests: BLOCKED until DB is available.

## Pass/Fail Criteria

**PASS if:**
- All unit tests compile and pass
- Pagination metadata matches specification
- Mutual exclusion enforced with clear error messages
- No pagination fields in output when flags absent

**FAIL if:**
- `--limit` and `--page-size` can be combined without error
- Pagination fields appear in non-paginated output
- Search backward compatibility broken

**BLOCKED if (integration tests):**
- DB unreachable

## Notes

- `render_table_search_json` and `render_column_search_json` currently do not accept pagination options; the architect will add paginated variants or extend these functions
- After pagination is added, existing tests `test_render_table_search_json`, `test_render_column_search_json`, `test_json_envelope_structure` in `src/commands/search.rs` must continue to pass (backward compat regression)
- The `--limit` mutual exclusion should produce a user-friendly message: `error: --page-size and --limit are mutually exclusive; use one or the other`
