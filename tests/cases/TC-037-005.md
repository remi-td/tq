## Purpose

Verify that `/edit` handles error conditions gracefully with clear messages: when no previous query exists, and when no editor is available.

## Acceptance Criteria Coverage

- **AC-7**: Error handling: clear message when no previous query exists ("No previous query to edit")
- **AC-8**: Error handling: clear message when $EDITOR is not set and fallback `vi` not found

## Scope

This test validates:
- Error message when `last_sql` is None (no previous query)
- Error message exact text: "No previous query to edit"
- Error message when no editor available ($EDITOR unset, vi not found)
- Editor failure (non-zero exit code) handled gracefully
- Error messages displayed to user (not crashes)
- REPL remains usable after errors

## Prerequisites

- Rust test framework available
- `tq` binary built with REPL support
- expectrl crate for PTY testing
- Mock editor scripts for error scenarios
- Error handling implementation complete

### Interactive Test 3: Editor Failure Handled

```rust
#[test]
#[ignore] // Requires database connection
fn test_edit_handles_editor_failure_interactive() {
    use std::fs;
    use tempfile::TempDir;

    // Create mock editor that exits with error code
    let temp_dir = TempDir::new().unwrap();
    let mock_editor = temp_dir.path().join("mock_editor_error.sh");
    fs::write(&mock_editor, r#"#!/bin/bash
# Simulate editor failure
exit 1
"#).unwrap();

    #[cfg(unix)]
    {
        use std::os::unix::fs::PermissionsExt;
        let mut perms = fs::metadata(&mock_editor).unwrap().permissions();
        perms.set_mode(0o755);
        fs::set_permissions(&mock_editor, perms).unwrap();
    }

    std::env::set_var("EDITOR", mock_editor.to_str().unwrap());

    let mut repl = spawn_repl().expect("Failed to spawn REPL");

    // Execute a query first
    repl.send_line("SELECT 1;").unwrap();
    repl.expect("1").unwrap();

    // Execute /edit (editor will fail)
    repl.send_line("/edit").unwrap();

    // Should see error message about editor failure
    repl.expect_any(&["editor", "failed", "exit"])
        .expect("Should show editor failure message");

    // Verify REPL still usable
    repl.send_line("SELECT 2;").unwrap();
    repl.expect("2").unwrap();

    std::env::remove_var("EDITOR");
}
```

## Pass/Fail Criteria

**PASS if:**
- All unit tests pass
- All interactive tests pass (when PTY/database available)
- Error message exact: "No previous query to edit"
- Error message clear when no editor available
- Error message suggests setting $EDITOR
- Editor failure handled gracefully
- REPL usable after any error condition
- No crashes or panics from errors

**FAIL if:**
- Wrong error message or no error when no previous query
- Technical error message (mentions "None", "null", etc.)
- No error or unclear error when editor unavailable
- No guidance on how to fix (set $EDITOR)
- Editor failure crashes REPL
- REPL unusable after error
- Panics or unhandled errors
- Confusing error messages
