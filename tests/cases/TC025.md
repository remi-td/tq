## Purpose

Verify that tq can display query execution timing information when requested.

## Scope

This test validates:
- --timing flag functionality
- Timing accuracy
- Timing display format
- Timing with different output formats
- Performance measurement

## Prerequisites

- tq binary is built and available
- `.env` file configured with valid Teradata connection credentials

## Test Procedure

### Step 1: Query without timing (default)
```bash
# Using credentials from .env file
tq query "SELECT 1" | grep -i "time\|second\|ms"
```

### Step 2: Query with timing (table format)
```bash
tq query --timing "SELECT 1"
```

### Step 3: Query with timing (JSON format)
```bash
tq query --timing --format json "SELECT 1"
```

### Step 4: Query with timing (CSV format)
```bash
tq query --timing --format csv "SELECT 1"
```

### Step 5: Timing for slow query
```bash
tq query --timing "SELECT COUNT(*) FROM large_table"
```

### Step 6: Timing displayed in verbose mode
```bash
tq -v query "SELECT 1"
```

## Expected Results

### Step 1 Output:
No timing information in default output
Just the query results

### Step 2 Output:
```
+---+
| 1 |
+---+
| 1 |
+---+
1 row(s) in set (0.023s)

Query execution time: 0.023s
```
Timing information displayed after results

### Step 3 Output:
```json
[
  {
    "1": 1
  }
]

Query execution time: 0.015s
```
Timing as separate line (not in JSON)

### Step 4 Output:
```csv
1
1

Query execution time: 0.018s
```
Timing as separate line (not in CSV)

### Step 5 Output:
Should show longer execution time
Format: X.XXXs or XXXms for sub-second

### Step 6 Output:
Verbose mode should show timing breakdown:
- Connection time
- Query execution time
- Fetch time
- Total time

## Pass/Fail Criteria

**PASS if:**
- --timing flag adds timing information
- Timing is reasonably accurate
- Format is consistent (e.g., X.XXXs or XXXms)
- Works with all output formats
- Timing doesn't interfere with data output
- Multiple timing metrics in verbose mode

**FAIL if:**
- --timing has no effect
- Timing information missing
- Inaccurate timing (way off)
- Timing breaks output format
- Inconsistent formatting

## Notes

- Timing is useful for performance analysis
- Should measure actual query execution time
- Consider separate metrics: connection, execution, fetch
- Format examples:
  - 0.023s (23 milliseconds)
  - 1.234s (1.234 seconds)
  - 45.678s (45.678 seconds)
- Don't include in machine-readable output (JSON/CSV data)
- Show on stderr to separate from data?
- Consider adding to footer of table output
