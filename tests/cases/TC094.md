# TC094: BEGIN/END Depth Tracking in Statement Splitter

**Sprint:** 64
**Bug:** #42 — Stored-procedure BEGIN/END bodies split at internal semicolons in `--file` mode
**Component:** `src/sql/parser.rs` — `parse_statements()` function
**Test Type:** Unit tests (pure function, no DB required) + 1 integration test (live DB, `#[ignore]`)
**Related Strategy:** `tests/strategy/sprint-64-strategy.md` Feature 1

---

## Overview

These tests validate that the state-machine lexer in `parse_statements()` correctly tracks `BEGIN`/`END` block nesting for Teradata SPL objects (`PROCEDURE`, `TRIGGER`, `MACRO`). While inside a procedure body, internal `;` characters must NOT be treated as statement terminators.

All unit tests live in `src/sql/parser.rs` under `#[cfg(test)]`, appended after the existing test block, under the section comment `// --- Bug #42: BEGIN/END depth tracking ---`.

The integration test lives in `tests/integration_tests.rs`.

## TC094-A: Single procedure — exact issue #42 repro

**Location:** `src/sql/parser.rs` `#[cfg(test)]`
**Requirement:** #42-AC-1

```rust
#[test]
fn test_procedure_body_is_single_statement() {
    let sql = "\
REPLACE PROCEDURE demo_user.sp_tq_repro()
BEGIN
    DECLARE v INTEGER;
    SET v = 1;
    IF v = 1 THEN
        SET v = 2;
    END IF;
END;";
    let statements = parse_statements(sql).unwrap();
    assert_eq!(statements.len(), 1, "procedure body must be a single statement");
    assert!(
        statements[0].sql.contains("DECLARE v INTEGER"),
        "body must contain DECLARE"
    );
    assert!(
        statements[0].sql.contains("END IF"),
        "body must contain END IF"
    );
    assert!(
        statements[0].sql.contains("SET v = 2"),
        "body must contain inner SET"
    );
}
```

**Pass criteria:** `statements.len() == 1`, body contains all inner SQL fragments.

## TC094-C: BEGIN inside a string literal does not open a block

**Location:** `src/sql/parser.rs` `#[cfg(test)]`
**Requirement:** #42-AC-3

```rust
#[test]
fn test_begin_in_string_literal_does_not_affect_depth() {
    // The string 'BEGIN' inside a plain SELECT must NOT trigger body mode
    let sql = "SELECT 'BEGIN' AS kw; SELECT 'END' AS kw2;";
    let statements = parse_statements(sql).unwrap();
    assert_eq!(
        statements.len(),
        2,
        "BEGIN/END in string literals must not affect statement splitting"
    );
    assert_eq!(statements[0].sql, "SELECT 'BEGIN' AS kw");
    assert_eq!(statements[1].sql, "SELECT 'END' AS kw2");
}

#[test]
fn test_begin_in_string_inside_procedure_body_does_not_add_depth() {
    // A string literal 'BEGIN' inside a procedure body must not add extra nesting depth
    // so the procedure still ends at the correct END;
    let sql = "\
REPLACE PROCEDURE test_user.sp_str()
BEGIN
    SET v = 'BEGIN middle END';
END;
SELECT 1;";
    let statements = parse_statements(sql).unwrap();
    assert_eq!(statements.len(), 2, "procedure + trailing SELECT must be 2 statements");
    assert!(statements[0].sql.contains("'BEGIN middle END'"), "string literal preserved in body");
    assert_eq!(statements[1].sql, "SELECT 1");
}
```

**Pass criteria:** String-literal `BEGIN`/`END` tokens do not alter depth counter.

## TC094-G: Case-insensitive header detection (PROCEDURE, TRIGGER, MACRO)

**Location:** `src/sql/parser.rs` `#[cfg(test)]`
**Requirement:** #42-AC-6

```rust
#[test]
fn test_spl_headers_case_insensitive() {
    // Lowercase REPLACE PROCEDURE
    let sql_lower = "\
replace procedure test_user.sp_lower()
begin
    set v = 1;
end;";
    let stmts_lower = parse_statements(sql_lower).unwrap();
    assert_eq!(stmts_lower.len(), 1, "lowercase procedure header must be detected");

    // Mixed-case CREATE TRIGGER
    let sql_trigger = "\
Create Trigger test_user.trg_mixed
After Insert On test_user.t
For Each Row
Begin
    Set v = 1;
End;";
    let stmts_trigger = parse_statements(sql_trigger).unwrap();
    assert_eq!(stmts_trigger.len(), 1, "mixed-case CREATE TRIGGER must be detected");

    // CREATE MACRO
    let sql_macro = "\
CREATE MACRO test_user.mac_one AS (
    SELECT 1;
);";
    // Macros use parentheses as body delimiter, not BEGIN/END.
    // This test verifies the macro body's internal semicolon is NOT a boundary:
    let stmts_macro = parse_statements(sql_macro).unwrap();
    assert_eq!(stmts_macro.len(), 1, "CREATE MACRO body must be a single statement");
}
```

**Pass criteria:** All three SPL object types produce single statements regardless of keyword case.

**Note on MACRO:** Teradata MACRO bodies are enclosed in `(...)` not `BEGIN...END`. The implementation must handle this differently from PROCEDURE/TRIGGER. If macro support is deferred to a follow-up, this part of the test should be marked `#[ignore]` with a note.

```rust
#[ignore] // Requires live Teradata database (TQ_LOGON env var)
fn test_file_mode_procedure_deploys_successfully() {
    dotenvy::dotenv().ok();
    let logon = std::env::var("TQ_LOGON").expect("TQ_LOGON required for this test");

    // Write the exact repro script from Issue #42 to a temp file
    // Note: adjust schema to match the writable schema in the test DB
    let sql = "\
REPLACE PROCEDURE demo_user.sp_tq_repro()
BEGIN
    DECLARE v INTEGER;
    SET v = 1;
    IF v = 1 THEN
        SET v = 2;
    END IF;
END;";

    let dir = tempfile::tempdir().expect("tempdir");
    let sql_file = dir.path().join("repro_sp.sql");
    std::fs::write(&sql_file, sql).expect("write sql file");

    let bin = env!("CARGO_BIN_EXE_tq");
    let output = std::process::Command::new(bin)
        .args(["query", "--file", sql_file.to_str().unwrap()])
        .env("TQ_LOGON", &logon)
        .output()
        .expect("failed to spawn tq");

    let stderr = String::from_utf8_lossy(&output.stderr);
    let stdout = String::from_utf8_lossy(&output.stdout);

    assert!(
        output.status.success(),
        "tq query --file must succeed; exit={}, stderr={stderr}, stdout={stdout}",
        output.status
    );
    // Confirm no SQL splitting error in stderr
    assert!(
        !stderr.contains("syntax error") && !stderr.contains("Error at statement"),
        "must not contain SQL error; stderr={stderr}"
    );
}
```

**Pass criteria:** Binary exits 0 with no SQL syntax or statement-splitting error in stderr.
