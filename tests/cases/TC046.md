# Test Case TC046: Table Formatting - NULL Values and Proper Alignment

## Purpose

Verify that tables containing NULL values display correctly with proper alignment and that NULL handling doesn't interfere with column width calculations.

## Scope

**Testing:**
- NULL value display as "[NULL]"
- Column width calculations including NULL values
- Alignment when NULLs are present
- Mixed NULL and non-NULL data in same column

**Not Testing:**
- NULL handling in JSON/CSV formats (covered in TC015, TC016)
- NULL query semantics
- Very wide tables

## Prerequisites

- tq REPL mode active
- Live Teradata database connection
- Test data with NULL values available (or use DBC.Databases which has NULLs)

## Test Procedure

### Setup

```bash
# Start tq in REPL mode
./target/release/tq
```

### Execution Steps

**Step 1: Query table with NULL values**

```sql
tq> SELECT TOP 5
    DatabaseName,
    CommentString,
    AccessCount,
    LastAccessTimeStamp
    FROM DBC.DatabasesV
    ORDER BY DatabaseName;
```

**Expected outcome:**
- NULL values display as "[NULL]"
- "[NULL]" text aligns properly with non-NULL values in same column
- Column width accommodates both NULL and non-NULL values

**Step 2: Verify NULL display formatting**

Check that:
- NULL values show as "[NULL]" (6 characters)
- "[NULL]" is aligned consistently (left for text, right for numbers)
- Column width is calculated considering "[NULL]" as a possible value

**Step 3: Test column with all NULLs**

```sql
tq> SELECT TOP 3
    DatabaseName,
    CommentString,
    AccessCount
    FROM DBC.DatabasesV
    WHERE CommentString IS NULL
    AND AccessCount IS NULL;
```

**Expected outcome:**
- Columns with all NULLs still render properly
- Column width is reasonable (not excessively wide)
- Headers still align with data

**Step 4: Test mixed NULL and long values**

```sql
tq> SELECT
    CAST('Short' AS VARCHAR(100)) AS col1,
    CAST(NULL AS VARCHAR(100)) AS col2,
    CAST('This is a much longer string value' AS VARCHAR(100)) AS col3;
```

**Expected outcome:**
- Column widths adjust to actual data, not CAST type width
- NULL in col2 doesn't cause excessive width
- col3 is wider to accommodate long string
- All columns remain aligned

### Verification

**Visual Inspection:**

1. **NULL Display:**
   - [ ] All NULL values show as "[NULL]"
   - [ ] "[NULL]" is consistent across all NULL cells
   - [ ] No empty cells or blank spaces where NULLs should be

2. **Alignment:**
   - [ ] "[NULL]" aligns with non-NULL values in same column
   - [ ] For text columns: "[NULL]" is left-aligned
   - [ ] For numeric columns: "[NULL]" is right-aligned
   - [ ] Vertical separators remain straight

3. **Width Calculation:**
   - [ ] Columns with NULLs are not excessively wide
   - [ ] Column width = max(header, longest_value, "[NULL]")
   - [ ] No unnecessary padding around NULL values

**Specific Checks:**

Measure the "CommentString" column:
- When NULL: displays "[NULL]" (6 chars)
- When populated: may have 0-75+ characters
- Column width should be: max(len("CommentString"), max_data_length, 6)
- NOT: some arbitrary large value

### Cleanup

## Pass/Fail Criteria

**PASS:**
- All NULL values display as "[NULL]"
- "[NULL]" aligns correctly (left for text, right for numbers)
- Column widths are appropriate (no excessive padding due to NULLs)
- Mixed NULL and non-NULL data aligns correctly
- Headers remain aligned with data columns

**FAIL:**
- NULL values display as empty/blank (invisible)
- NULL values display inconsistently
- "[NULL]" causes column misalignment
- Columns with NULLs have excessive padding
- Headers misalign when NULLs are present

## Notes

**NULL Handling in tq:**

From TC015, we know tq displays NULL as "[NULL]" in table format. This test ensures that:
1. NULL display doesn't break column width calculations
2. The padding fix doesn't interfere with NULL formatting
3. Alignment rules are consistent for NULL and non-NULL values

**Column Width Formula:**

For any column, width should be:
```
width = max(
  len(header_text),
  max_length_of_all_data_values,
  len("[NULL]")  // = 6
) + padding (2-4 chars)
```

**Edge Case:**

If a column has only NULLs, its width should be:
```
width = max(len(header), 6) + padding
```

Not some arbitrary large value based on column type definition.

**Why This Matters:**

In Teradata, many system columns (like CommentString, AccessCount) are frequently NULL. If NULL handling causes width issues, system catalog queries (which users run often) will be unreadable.
