# Test Case TC044: Table Formatting - Basic 5 Column Layout

## Purpose

Verify that table output with 5 columns displays with proper alignment between headers and data values.

## Scope

**Testing:**
- Table header alignment
- Column value alignment under headers
- Proper padding for different data types
- Border/separator rendering

**Not Testing:**
- JSON/CSV formats
- NULL value handling (covered in TC046)
- Very wide tables (covered in TC045)

## Prerequisites

- tq REPL mode active
- Live Teradata database connection
- Test can use any table with 5+ columns or system catalog

## Test Procedure

### Setup

```bash
# Start tq in REPL mode
./target/release/tq
```

### Execution Steps

**Step 1: Query DBC.Databases with 5 columns**

```sql
tq> SELECT TOP 5 DatabaseName, CreatorName, OwnerName, PermSpace, JournalFlag
    FROM DBC.DatabasesV
    ORDER BY DatabaseName;
```

**Expected outcome:**
- Table displays with 5 columns
- Headers aligned with column separators
- Data values aligned under their respective headers
- Consistent spacing within each column

**Step 2: Verify header alignment**

Observe the output and check:
- Column headers appear directly above their data
- Vertical separators (┆) align consistently
- Header separator line (═) matches column widths

**Step 3: Verify data alignment**

Check that:
- Text values are left-aligned within their columns
- Numeric values are right-aligned within their columns
- All rows maintain consistent column widths
- No values overflow into adjacent columns

**Step 4: Test with simple query**

```sql
tq> SELECT 1 AS col1, 'test' AS col2, 12345 AS col3, 'a' AS col4, 999 AS col5;
```

**Expected outcome:**
- Perfect alignment even with short, known values
- Headers "col1", "col2", etc. align with their single values

### Verification

**Visual Inspection Checklist:**

- [ ] Headers are readable and properly positioned
- [ ] Vertical separators (┆) form straight lines
- [ ] Values do not overflow or misalign
- [ ] Table borders are complete and consistent
- [ ] Spacing looks professional and easy to read

**Specific Checks:**

1. Measure alignment with ruler or column counter:
   - Position of 'D' in "DatabaseName" header
   - Position of first character in "val" data value
   - These should be at the same column position

2. Check separator alignment:
   - All ┆ characters in the same column should be vertically aligned
   - No "jagged" separators

3. Verify readability:
   - Can you easily scan down a column and read all values?
   - Can you easily scan across a row and associate values with headers?

### Cleanup

```sql
tq> /quit
```

## Expected Results

**Table Output Should Look Like:**

```
╭──────────────┬─────────────┬───────────┬───────────┬─────────────╮
│ DatabaseName ┆ CreatorName ┆ OwnerName ┆ PermSpace ┆ JournalFlag │
╞══════════════╪═════════════╪═══════════╪═══════════╪═════════════╡
│ All          ┆ DBC         ┆ DBC       ┆         0 ┆ NN          │
├╌╌╌╌╌╌╌╌╌╌╌╌╌╌┼╌╌╌╌╌╌╌╌╌╌╌╌╌┼╌╌╌╌╌╌╌╌╌╌╌┼╌╌╌╌╌╌╌╌╌╌╌┼╌╌╌╌╌╌╌╌╌╌╌╌╌┤
│ DBC          ┆ DBC         ┆ DBC       ┆   1000000 ┆ NN          │
├╌╌╌╌╌╌╌╌╌╌╌╌╌╌┼╌╌╌╌╌╌╌╌╌╌╌╌╌┼╌╌╌╌╌╌╌╌╌╌╌┼╌╌╌╌╌╌╌╌╌╌╌┼╌╌╌╌╌╌╌╌╌╌╌╌╌┤
...
```

**Key Characteristics:**
- Headers and data are vertically aligned
- Column widths are appropriate for the data (not excessively wide)
- Text is left-aligned, numbers are right-aligned
- Separators form clean vertical lines
- Table fits in standard terminal width (80-120 columns)

**Anti-Pattern (What Should NOT Happen):**

```
╭──────────────────────────────────────────────────────────────┬─────────────
│ DatabaseName                                                 ┆ CreatorName
╞══════════════════════════════════════════════════════════════╪═════════════
│ val                                                          ┆ DBC
```

This shows excessive padding (60+ characters for "DatabaseName" when data is 3 characters).

## Pass/Fail Criteria

**PASS:**
- Headers align with data columns
- Separators form straight vertical lines
- Column widths are reasonable (no excessive padding)
- Table is readable and professional-looking
- Fits in standard terminal width

**FAIL:**
- Headers misaligned from data
- Jagged or broken separators
- Excessive column padding (>3x max data length)
- Values overflow into adjacent columns
- Table is unreadable or requires horizontal scrolling for 5 columns

## Notes

This test validates the core fix for Bug 1. The root cause was incorrect `set_width` calculation in comfy-table that multiplied `max_column_width` by column count, creating arbitrarily wide tables.

The fix should:
1. Remove erroneous `set_width` calculation
2. Use `ContentArrangement::DynamicFullWidth` or `Dynamic`
3. Let comfy-table calculate appropriate column widths from content
4. Respect terminal width constraints

This is a foundational test - if TC044 fails, all other table formatting tests will likely fail.
