## Purpose

Verify that /logon successfully switches database connections without exiting the REPL, preserving session state appropriately.

## Scope

This test validates:
- Connection switching works
- Old connection properly closed
- New connection established
- REPL state preserved (history, settings)
- Metadata cache cleared
- Prompt updated with new database
- Performance < 2s for connection switch

## Prerequisites

- tq binary built in release mode
- Access to TWO different Teradata databases
- Both databases configured and accessible
- REPL mode functional

## Test Procedure

### Step 1: Start REPL with first database
```bash
tq -l "user:pass@host:1025/database1" repl
```

### Step 2: Execute some queries and use Tab completion
```sql
tq[database1]> SELECT 1 AS test;
tq[database1]> SELECT * FROM <TAB>
# Note table list from database1
```

### Step 3: Switch to second database
```sql
tq[database1]> /logon user:pass@host:1025/database2
```

**Expected behavior:**
- Shows "Disconnecting from database1..."
- Shows "Connecting to database2..."
- Shows "Connected successfully"
- Prompt changes to tq[database2]>

### Step 4: Verify new connection works
```sql
tq[database2]> SELECT 2 AS test;
```

### Step 5: Check history preserved
```sql
# Press Up arrow
```

**Expected behavior:**
- Previous queries still in history
- Can recall "SELECT 1 AS test" from database1

### Step 6: Verify metadata cache cleared
```sql
tq[database2]> SELECT * FROM <TAB>
```

**Expected behavior:**
- Shows "Loading tables..." again
- Table list from database2 (different from Step 2)

### Step 7: Verify current connection
```sql
tq[database2]> /logon
```

**Expected behavior:**
- Shows database2 connection details

### Step 8: Switch back to first database
```sql
tq[database2]> /logon user:pass@host:1025/database1
```

**Expected behavior:**
- Successfully reconnects to database1

## Pass/Fail Criteria

**PASS if:**
- Connection switch succeeds
- Old connection closed properly
- New connection established
- Queries work in new database
- History preserved across switch
- Settings preserved (editor mode, pager, etc.)
- Metadata cache cleared
- Prompt updated
- Performance < 2s
- No errors or crashes

**FAIL if:**
- Connection switch fails
- Old connection not closed
- New database doesn't work
- History lost
- Settings lost
- Cache not cleared
- Performance > 2s consistently
- Errors or crashes

## Notes

- This is the primary /logon use case
- Critical for users working with multiple databases
- State preservation important for UX
- Cache invalidation critical for correctness
- Connection cleanup prevents resource leaks
