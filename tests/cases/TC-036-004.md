## Purpose

Verify that the `/repeat` metacommand correctly re-executes the last SQL statement in REPL mode, handles empty state gracefully, and supports the short alias `\r`.

## Acceptance Criteria Coverage

- **AC-8**: `/repeat` re-executes the last SQL statement
- **AC-9**: When no previous query exists, show clear message: "No previous query to repeat"
- **AC-13**: Short alias `\r` works (following psql convention)
- **AC-14**: Unit tests validate all behaviors

## Scope

This test validates:
- `/repeat` command parsing
- `\r` alias parsing (treated identically to `/repeat`)
- Re-execution of last SQL query from `ReplState.last_sql`
- Empty state handling (no previous query)
- Error message format: "No previous query to repeat"
- State management (last_sql tracked correctly)

## Prerequisites

- Rust test framework available
- `tq` binary built with REPL support
- expectrl crate for PTY testing
- Database connection available for interactive tests
- Metacommand handler implementation complete

## Test Procedure

### Unit Test 1: Command Parsing

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_repeat_command_parsed() {
        let input = "/repeat";
        let parsed = parse_metacommand(input);

        assert!(parsed.is_some(), "Should parse /repeat command");
        let command = parsed.unwrap();
        assert_eq!(command.name, "repeat", "Command name should be 'repeat'");
        assert!(command.args.is_empty(), "/repeat takes no arguments");
    }

    #[test]
    fn test_repeat_alias_r_parsed() {
        let input = r"\r";
        let parsed = parse_metacommand(input);

        assert!(parsed.is_some(), r"Should parse \r alias");
        let command = parsed.unwrap();
        assert_eq!(command.name, "repeat", r"\r should be treated as /repeat");
        assert!(command.args.is_empty(), r"\r takes no arguments");
    }

    #[test]
    fn test_repeat_with_no_previous_query() {
        let mut state = ReplState::new();
        // last_sql is None (no previous query)

        let result = handle_repeat_command(&mut state);

        assert!(result.is_err(), "Should return error when no previous query");
        let error = result.unwrap_err();
        assert!(
            error.contains("No previous query") || error.contains("no previous"),
            "Error message should indicate no previous query"
        );
    }

    #[test]
    fn test_repeat_with_previous_query() {
        let mut state = ReplState::new();
        state.last_sql = Some("SELECT 1;".to_string());

        let result = handle_repeat_command(&mut state);

        assert!(result.is_ok(), "Should succeed when previous query exists");
        let sql = result.unwrap();
        assert_eq!(sql, "SELECT 1;", "Should return last SQL query");
    }
}
```

## Expected Results

### Unit Test Results:
- `/repeat` command parsed correctly
- `\r` alias treated as `/repeat`
- Error returned when no previous query (last_sql = None)
- Last SQL returned when previous query exists

### Interactive Test Results:
- `/repeat` re-executes last SQL query and shows same output
- `\r` alias works identically to `/repeat`
- Clear error message when no previous query
- Only last query repeated (not older queries)
- Last SQL preserved after metacommands (like `/help`)
- `/repeat` can be executed multiple times in succession

## Pass/Fail Criteria

**PASS if:**
- All 4 unit tests pass
- All 6 interactive tests pass
- `/repeat` correctly re-executes last SQL query
- `\r` alias works identically to `/repeat`
- Clear error message when no previous query exists
- Only most recent SQL query is repeated
- Metacommands don't clear last_sql state
- `/repeat` can be chained (repeated multiple times)
- No regressions in REPL state management

**FAIL if:**
- Any unit or interactive test fails
- `/repeat` executes wrong query
- `\r` alias doesn't work or behaves differently
- No error message or confusing message when no previous query
- `/repeat` executes older queries instead of last one
- Metacommands clear last_sql (should preserve it)
- `/repeat` fails after previous `/repeat`
- Database errors or crashes
