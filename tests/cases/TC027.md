## Purpose

Verify that tab completion works correctly after JOIN keywords (INNER JOIN, LEFT JOIN, RIGHT JOIN, FULL JOIN, CROSS JOIN), showing available table names.

## Scope

This test validates:
- Tab completion after various JOIN keywords
- Context detection in multi-line queries
- Completion works regardless of JOIN type
- Already-selected tables can still complete (for joins)
- Query complexity doesn't break completion

## Prerequisites

- tq binary built in release mode
- Valid Teradata connection credentials configured in .env
- Test database with multiple tables
- REPL mode functional
- TC026 passed (basic FROM completion working)

## Test Procedure

### Step 1: Start REPL
```bash
tq repl
```

### Step 2: Test completion after INNER JOIN
```sql
tq> SELECT * FROM employees e INNER JOIN <TAB>
```

### Step 3: Test completion after LEFT JOIN
```sql
tq> SELECT * FROM employees e LEFT JOIN <TAB>
```

### Step 4: Test completion after RIGHT JOIN
```sql
tq> SELECT * FROM employees e RIGHT JOIN <TAB>
```

### Step 5: Test completion after FULL JOIN
```sql
tq> SELECT * FROM employees e FULL JOIN <TAB>
```

### Step 6: Test completion after CROSS JOIN
```sql
tq> SELECT * FROM employees e CROSS JOIN <TAB>
```

### Step 7: Test completion after simple JOIN
```sql
tq> SELECT * FROM employees e JOIN <TAB>
```

### Step 8: Test multi-line query with JOIN
```sql
tq> SELECT e.*, d.*
    FROM employees e
    INNER JOIN <TAB>
```

### Step 9: Test multiple JOINs in sequence
```sql
tq> SELECT * FROM employees e
    JOIN departments d ON e.dept_id = d.id
    LEFT JOIN <TAB>
```

### Step 10: Test prefix matching after JOIN
```sql
tq> SELECT * FROM employees e JOIN dep<TAB>
```

## Expected Results

### Step 2-7 Output:
All JOIN types should trigger completion:
```
customers    employees    orders    products    departments
```
(Or similar based on available tables)

### Step 8 Output:
Completion works on continuation line:
```
customers    employees    orders    products    departments
```

### Step 9 Output:
Completion works after second JOIN:
```
customers    employees    orders    products    departments
```

### Step 10 Output:
```
tq> SELECT * FROM employees e JOIN departments
```
Auto-completes if single match to "departments"

## Pass/Fail Criteria

**PASS if:**
- Tab completion works after all JOIN types
- Works in multi-line queries
- Works with multiple JOINs in same query
- Prefix matching works after JOIN
- Performance consistent with FROM completion
- No errors or crashes

**FAIL if:**
- Completion doesn't trigger after JOIN keywords
- Works for some JOIN types but not others
- Multi-line queries break completion
- Performance significantly degrades
- Errors or crashes

## Notes

- Reuses same table cache as FROM completion
- Should handle whitespace variations: "JOIN<TAB>", "JOIN <TAB>", "JOIN  <TAB>"
- Multi-line detection important for real-world queries
- Context parser must identify JOIN keyword even with table aliases
