## Purpose

Verify that -v/--verbose and -q/--quiet flags control output verbosity appropriately.

## Scope

This test validates:
- Default output level
- -v (verbose) flag
- -vv, -vvv (increasing verbosity)
- -q/--quiet flag
- Interaction with different commands
- Stderr vs stdout output

## Prerequisites

- tq binary is built and available
- `.env` file configured with valid Teradata connection credentials

## Test Procedure

### Step 1: Default output (ping)
```bash
# Using credentials from .env file
tq ping
```

### Step 2: Verbose output (ping)
```bash
tq -v ping
```

### Step 3: Very verbose output
```bash
tq -vv ping
```

### Step 4: Maximum verbosity
```bash
tq -vvv ping
```

### Step 5: Quiet mode (ping)
```bash
tq -q ping
```

### Step 6: Query with verbose
```bash
tq -v query "SELECT 1"
```

### Step 7: Query with quiet
```bash
tq -q query "SELECT 1"
```

### Step 8: Check stderr separation
```bash
tq -v ping 2> /tmp/stderr.log 1> /tmp/stdout.log
echo "=== STDERR ==="
cat /tmp/stderr.log
echo "=== STDOUT ==="
cat /tmp/stdout.log
rm /tmp/stderr.log /tmp/stdout.log
```

## Expected Results

### Step 1 Output:
```
Database connection successful (XXXms)
```
Minimal, user-friendly output

### Step 2 Output (-v):
```
Connecting to testhost:1025...
Using authentication: TD2
Database: testdb
Connection established (XXXms)
Database connection successful (XXXms)
```
Additional connection details

### Step 3 Output (-vv):
Should include even more details:
- Connection parameters
- SQL queries being executed
- Result set information

### Step 4 Output (-vvv):
Maximum debug information:
- Driver-level logs
- Low-level operations
- Timing breakdowns

### Step 5 Output (-q):
```
Database connection successful (XXXms)
```
Or possibly just:
Exit code 0, minimal or no output

### Step 6 Output:
Results plus verbose connection/query information

### Step 7 Output:
Just the query results, no extra messages

### Step 8 Output:
Verbose/debug messages should be on stderr
Query results should be on stdout
Allows separation of data from metadata

## Pass/Fail Criteria

**PASS if:**
- Default output is balanced (not too much, not too little)
- -v adds helpful debugging information
- Multiple -v increase verbosity
- -q suppresses non-essential output
- Results always appear (even in quiet mode)
- Verbose output goes to stderr
- Data output goes to stdout
- Exit codes unchanged by verbosity

**FAIL if:**
- -v has no effect
- -q suppresses results
- Verbose output mixed with data on stdout
- No clear verbosity levels
- Errors suppressed in quiet mode

## Notes

- Verbose is for debugging
- Quiet is for scripting (minimal noise)
- Data should always reach stdout
- Metadata/debug to stderr
- Consider environment variable: TQ_LOG=debug
- Default should be appropriate for interactive use
- Quiet still shows errors
