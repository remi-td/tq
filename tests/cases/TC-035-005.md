## Purpose

Verify that the `--profile <name>` flag correctly resolves profiles from both user and project configs, with proper precedence when profile names conflict.

## Acceptance Criteria Coverage

- **AC-5**: `--profile` flag works with both user and project profiles - Profile resolution
- **AC-6**: Project profiles take precedence over user profiles with same name - Precedence validation

## Scope

This test validates:
- `--profile` resolves user-only profiles
- `--profile` resolves project-only profiles
- `--profile` resolves merged profiles (name conflict)
- Project profile fields override user profile fields
- User profile fields inherited when not in project profile
- Profile resolution works in batch and REPL modes
- Error message when profile not found in either source

## Prerequisites

- Rust test framework available
- tempfile crate available
- `tq` binary compiled
- Profile resolution implementation complete

## Test Procedure

### Test Implementation:

```rust
#[cfg(test)]
mod tests {
    use std::fs;
    use std::process::Command;
    use tempfile::TempDir;

    #[test]
    fn test_profile_resolution_user_only() {
        // Create temp directory with user config
        let temp_dir = TempDir::new().unwrap();
        let user_config_dir = temp_dir.path().join(".tq");
        fs::create_dir(&user_config_dir).unwrap();

        let user_config_path = user_config_dir.join("config.toml");
        let user_config_content = r#"
            [profiles.myprofile]
            host = "localhost"
            database = "testdb"
            user = "alice"
        "#;
        fs::write(&user_config_path, user_config_content).unwrap();

        // Run tq with --profile (dry run to verify profile loads)
        // Use a command that doesn't require database (e.g., --version with profile)
        let output = Command::new("cargo")
            .args(&["run", "--", "--profile", "myprofile", "--help"])
            .env("HOME", temp_dir.path())
            .output()
            .expect("Failed to execute tq");

        // Should succeed (profile found in user config)
        assert!(
            output.status.success(),
            "Should resolve user-only profile without error"
        );
    }

    #[test]
    fn test_profile_resolution_project_only() {
        // Create temp directory with project config
        let temp_dir = TempDir::new().unwrap();
        let project_config_path = temp_dir.path().join(".tq.toml");
        let project_config_content = r#"
            [profiles.projprofile]
            host = "dev.company.com"
            database = "shared_dev"
        "#;
        fs::write(&project_config_path, project_config_content).unwrap();

        // Run tq with --profile from project directory
        let output = Command::new("cargo")
            .args(&["run", "--", "--profile", "projprofile", "--help"])
            .current_dir(temp_dir.path())
            .env("HOME", "/nonexistent") // No user config
            .output()
            .expect("Failed to execute tq");

        // Should succeed (profile found in project config)
        assert!(
            output.status.success(),
            "Should resolve project-only profile without error"
        );
    }

    #[test]
    fn test_profile_resolution_merged_project_wins() {
        // Create both configs with same profile name
        let temp_dir = TempDir::new().unwrap();

        // User config: dev profile
        let user_config_dir = temp_dir.path().join(".tq");
        fs::create_dir(&user_config_dir).unwrap();
        let user_config_path = user_config_dir.join("config.toml");
        let user_config_content = r#"
            [profiles.dev]
            host = "localhost"
            database = "my_local_dev"
            user = "alice"
            password_file = "~/.tq/passwords/dev"
        "#;
        fs::write(&user_config_path, user_config_content).unwrap();

        // Project config: dev profile (overrides host and database)
        let project_config_path = temp_dir.path().join(".tq.toml");
        let project_config_content = r#"
            [profiles.dev]
            host = "dev.company.com"
            database = "shared_dev"
            logmech = "LDAP"
        "#;
        fs::write(&project_config_path, project_config_content).unwrap();

        // Run tq with --profile dev and verbose mode to see resolution
        // We can't test connection without database, but we can verify profile loads
        let output = Command::new("cargo")
            .args(&["run", "--", "--profile", "dev", "--help"])
            .current_dir(temp_dir.path())
            .env("HOME", temp_dir.path())
            .output()
            .expect("Failed to execute tq");

        // Should succeed (profile resolved, project overrides user)
        assert!(
            output.status.success(),
            "Should resolve merged profile (dev) without error"
        );

        // Note: Without database, we can't test actual connection values
        // Those are tested in unit tests (TC-035-002)
        // Here we just verify the profile is recognized
    }

    #[test]
    fn test_profile_resolution_not_found() {
        // Create temp directory with configs but missing the requested profile
        let temp_dir = TempDir::new().unwrap();

        // User config: only "dev" profile
        let user_config_dir = temp_dir.path().join(".tq");
        fs::create_dir(&user_config_dir).unwrap();
        let user_config_path = user_config_dir.join("config.toml");
        let user_config_content = r#"
            [profiles.dev]
            host = "localhost"
        "#;
        fs::write(&user_config_path, user_config_content).unwrap();

        // Run tq with --profile nonexistent
        let output = Command::new("cargo")
            .args(&["run", "--", "--profile", "nonexistent", "--help"])
            .env("HOME", temp_dir.path())
            .output()
            .expect("Failed to execute tq");

        // Should fail with clear error message
        assert!(
            !output.status.success(),
            "Should error when profile not found"
        );

        let stderr = String::from_utf8_lossy(&output.stderr);
        assert!(
            stderr.contains("profile") && (stderr.contains("not found") || stderr.contains("nonexistent")),
            "Error should mention profile not found"
        );
        assert!(
            stderr.contains("dev"),
            "Error should list available profiles"
        );
    }

    #[test]
    fn test_profile_resolution_field_override_batch() {
        // Test that profile resolution works in batch mode
        // Create configs with field override scenario
        let temp_dir = TempDir::new().unwrap();

        // User config: dev profile with host
        let user_config_dir = temp_dir.path().join(".tq");
        fs::create_dir(&user_config_dir).unwrap();
        let user_config_path = user_config_dir.join("config.toml");
        let user_config_content = r#"
            [profiles.dev]
            host = "user-host.com"
            user = "alice"
        "#;
        fs::write(&user_config_path, user_config_content).unwrap();

        // Project config: dev profile with different host
        let project_config_path = temp_dir.path().join(".tq.toml");
        let project_config_content = r#"
            [profiles.dev]
            host = "project-host.com"
            database = "shared_db"
        "#;
        fs::write(&project_config_path, project_config_content).unwrap();

        // Run tq profiles to see merged result
        let output = Command::new("cargo")
            .args(&["run", "--", "profiles"])
            .current_dir(temp_dir.path())
            .env("HOME", temp_dir.path())
            .output()
            .expect("Failed to execute tq profiles");

        let stdout = String::from_utf8_lossy(&output.stdout);

        // Verify project host wins
        assert!(
            stdout.contains("project-host.com"),
            "Should show project host (not user host)"
        );
        assert!(
            !stdout.contains("user-host.com") || stdout.contains("[user]"),
            "User host should not appear or be marked as overridden"
        );
        assert!(
            stdout.contains("alice"),
            "Should show user's username (inherited)"
        );
        assert!(
            stdout.contains("shared_db"),
            "Should show project database"
        );
    }

    #[test]
    fn test_profile_resolution_with_cli_flag_override() {
        // Test precedence: CLI flags > project profile > user profile
        let temp_dir = TempDir::new().unwrap();

        // User config
        let user_config_dir = temp_dir.path().join(".tq");
        fs::create_dir(&user_config_dir).unwrap();
        let user_config_path = user_config_dir.join("config.toml");
        let user_config_content = r#"
            [profiles.dev]
            host = "user-host.com"
        "#;
        fs::write(&user_config_path, user_config_content).unwrap();

        // Project config
        let project_config_path = temp_dir.path().join(".tq.toml");
        let project_config_content = r#"
            [profiles.dev]
            host = "project-host.com"
            database = "project-db"
        "#;
        fs::write(&project_config_path, project_config_content).unwrap();

        // Run tq with --profile dev --database cli-override-db
        // (Can't test actual connection, but can verify command accepts the flags)
        let output = Command::new("cargo")
            .args(&[
                "run",
                "--",
                "--profile",
                "dev",
                "--database",
                "cli-override-db",
                "--help",
            ])
            .current_dir(temp_dir.path())
            .env("HOME", temp_dir.path())
            .output()
            .expect("Failed to execute tq");

        // Should succeed (CLI flag overrides both configs)
        assert!(
            output.status.success(),
            "Should accept profile with CLI flag override"
        );

        // Note: Actual connection values tested in unit tests
        // This integration test verifies flags are accepted together
    }
}
```

## Expected Results

All integration tests pass:
- User-only profile resolves correctly
- Project-only profile resolves correctly
- Merged profile (name conflict) uses project values with user inheritance
- Profile not found produces clear error with available profiles list
- Field override works in batch mode (project host overrides user host)
- CLI flags override both config sources
