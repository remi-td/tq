## Purpose

Verify that tq provides comprehensive help information and version details following UNIX conventions.

## Scope

This test validates:
- --help flag (short and long form)
- --version flag (short and long form)
- Subcommand help
- Help text clarity and completeness
- Exit codes for help/version

## Prerequisites

- tq binary is built and available

## Test Procedure

### Step 1: Main help (long form)
```bash
tq --help
```

### Step 2: Main help (short form)
```bash
tq -h
```

### Step 3: Version (long form)
```bash
tq --version
```

### Step 4: Version (short form)
```bash
tq -V
```

### Step 5: Subcommand help - ping
```bash
tq ping --help
```

### Step 6: Subcommand help - query
```bash
tq query --help
```

### Step 7: Help command
```bash
tq help
```

### Step 8: Help for specific subcommand
```bash
tq help query
```

### Step 9: Check exit codes
```bash
tq --help > /dev/null
echo "Help exit code: $?"
tq --version > /dev/null
echo "Version exit code: $?"
```

## Expected Results

### Step 1-2 Output:
Should display comprehensive help including:
- Brief description of tq
- Usage syntax
- List of subcommands with descriptions
- Global options with descriptions
- Environment variables
- Examples section
- Configuration information
- Project URL or documentation link

Output should be the same for both -h and --help
Exit code: 0

### Step 3-4 Output:
```
tq 0.1.0
```
Or with additional information:
```
tq 0.1.0 (release)
Commit: 369af18
Built: 2026-01-16
Target: x86_64-unknown-linux-musl
```
Exit code: 0

### Step 5 Output:

## Pass/Fail Criteria

**PASS if:**
- --help and -h show comprehensive help
- --version and -V show version information
- Subcommand help is available and detailed
- Examples are provided and helpful
- Text is well-formatted and readable
- Exit codes are 0 for help/version
- No errors or warnings in output

**FAIL if:**
- Help is missing or incomplete
- Version information not available
- Subcommand help missing
- Poor formatting or unclear text
- Exit codes are non-zero
- Broken or unclear examples

## Notes

- Help text is critical for user experience
- Should follow clap's auto-generated format
- Consider custom examples section
- Version should include commit SHA for debugging
- Help should be concise but comprehensive
- Consider man page generation for future
