## Purpose

Verify that tq respects color output settings and terminal detection for appropriate use of ANSI color codes.

## Scope

This test validates:
- Auto color detection (TTY vs pipe)
- --color always
- --color never
- --color auto (default)
- NO_COLOR environment variable
- TQ_COLOR environment variable

## Prerequisites

- tq binary is built and available
- `.env` file configured with valid Teradata connection credentials

## Test Procedure

### Step 1: Default color in TTY
```bash
# Using credentials from .env file
tq query "SELECT 1"
# Observe if colors appear in interactive terminal
```

### Step 2: Default color when piped
```bash
tq query "SELECT 1" | cat
# Check if output contains ANSI codes
```

### Step 3: Force color always
```bash
tq --color always query "SELECT 1" | cat
# Should contain ANSI color codes even when piped
```

### Step 4: Force color never
```bash
tq --color never query "SELECT 1"
# No ANSI codes even in TTY
```

### Step 5: Auto mode (explicit)
```bash
tq --color auto query "SELECT 1"
# Should match terminal detection
```

### Step 6: NO_COLOR environment variable
```bash
NO_COLOR=1 tq query "SELECT 1"
# Should disable colors
```

### Step 7: TQ_COLOR environment variable
```bash
export TQ_COLOR=never
tq query "SELECT 1"
unset TQ_COLOR
# Should disable colors
```

### Step 8: Detect ANSI codes in output
```bash
# With color
tq --color always query "SELECT 1" > /tmp/with_color.txt
grep -a $'\033' /tmp/with_color.txt && echo "Has ANSI codes" || echo "No ANSI codes"

# Without color
tq --color never query "SELECT 1" > /tmp/no_color.txt
grep -a $'\033' /tmp/no_color.txt && echo "Has ANSI codes" || echo "No ANSI codes"

rm /tmp/with_color.txt /tmp/no_color.txt
```

## Expected Results

### Step 1 Output:
If in interactive terminal: colors visible
Table borders, headers might be colored

### Step 2 Output:
No ANSI escape codes (auto-detection knows it's piped)
Clean output suitable for processing

### Step 3 Output:

Output: `^[[...m` sequences visible with cat -A

No colors, plain text only

### Step 6 Output:
No colors (NO_COLOR respected)

## Pass/Fail Criteria

**PASS if:**
- Auto-detection works (colors in TTY, none in pipe)
- --color always forces colors
- --color never disables colors
- NO_COLOR environment variable disables colors
- TQ_COLOR environment variable works
- CLI flag overrides environment
- No broken/malformed ANSI codes

**FAIL if:**
- Colors appear when piped (auto mode)
- Colors missing in TTY (auto mode)
- Flags have no effect
- Environment variables ignored
- Broken ANSI codes in output

## Notes

- Color improves readability in terminals
- Must be disabled for pipes/scripts
- NO_COLOR is standard convention (see no-color.org)
- ANSI codes start with ESC [ (\\033[)
- Consider color schemes: errors red, success green, etc.
- Terminal detection: std::io::IsTerminal
- Precedence: --color flag > NO_COLOR > TQ_COLOR > auto
