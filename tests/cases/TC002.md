## Purpose

Verify that `tq ping` handles connection failures gracefully with appropriate error messages and exit codes.

## Scope

This test validates:
- Error handling for unreachable hosts
- Error message clarity
- Exit code 1 on failure
- stderr output for errors

## Prerequisites

- tq binary is built and available
- `.env` file configured (can be temporarily modified or overridden for testing)
- Use an invalid/unreachable hostname for testing failure scenarios

## Test Procedure

### Step 1: Test with invalid hostname
```bash
tq -l "user:pass@invalid-host-12345:1025/db" ping
```

### Step 2: Check exit code
```bash
echo $?
```

### Step 3: Test with refused connection (wrong port)
```bash
tq -l "user:pass@localhost:9999/db" ping
```

### Step 4: Test with missing credentials
```bash
# Temporarily rename .env if it exists and unset environment variable
mv .env .env.backup 2>/dev/null || true
unset TQ_LOGON
tq ping
# Restore .env
mv .env.backup .env 2>/dev/null || true
```

## Expected Results

### Step 1 Output (stderr):
```
Error: Failed to connect to invalid-host-12345:1025

Possible causes:
  - Hostname does not resolve
  - Network is unreachable
  - Firewall is blocking connection
  - Database is not running

Troubleshooting:
  - Verify hostname: ping invalid-host-12345
  - Check port is correct: 1025
  - Confirm credentials are valid
```
Exit code: 1

### Step 2 Output:
```
1
```

### Step 3 Output (stderr):
Should show connection refused error with helpful message about checking the port

### Step 4 Output (stderr):
```
Error: Connection string not provided

Provide connection via:
  - --logon flag: tq -l "user:pass@host:1025/db" ping
  - TQ_LOGON environment variable
  - Configuration file
```
Exit code: 2 (usage error)

## Pass/Fail Criteria

**PASS if:**
- Exit code is 1 for connection failures
- Exit code is 2 for usage errors (missing credentials)
- Error messages are clear and actionable
- Errors are written to stderr, not stdout
- No stack traces in user-facing output

**FAIL if:**
- Exit code is 0 when connection fails
- Error messages are cryptic or missing
- Errors appear on stdout
- Program panics or crashes

## Notes

- Error messages should be user-friendly, not technical
- Should suggest troubleshooting steps
- No sensitive information (passwords) in error output
