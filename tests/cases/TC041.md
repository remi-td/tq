## Purpose

Verify that /logon meets performance requirements and handles slow/timeout scenarios appropriately.

## Scope

This test validates:
- Connection establishment < 2s for healthy database
- Timeout after 30s (or configured value)
- Progress indication for slow connections
- Graceful timeout handling
- User can cancel during connection
- Performance measurement accuracy

## Prerequisites

- tq binary built in release mode
- Access to healthy database (fast connection)
- Ability to simulate slow connection (optional)
- REPL mode functional

## Test Procedure

### Step 1: Measure connection time to healthy database
```sql
# Use external timer or note timestamps
tq> /logon user:pass@fasthost:1025/db
# Note time from command to "Connected successfully"
```

**Expected behavior:**
- Connection completes in < 2s

### Step 2: Test connection to slow/overloaded database (if available)
```sql
tq> /logon user:pass@slowhost:1025/db
```

**Expected behavior:**
- Shows "Connecting to slowhost..." message
- May show progress indicator or waiting messages
- Eventually connects or times out

### Step 3: Test timeout on unreachable host
```sql
tq> /logon user:pass@unreachable:1025/db
```

**Expected behavior:**
- Shows connecting message
- Progress indicators every 5-10s
- Timeout after 30s with clear message
- Old connection preserved

### Step 4: Test cancellation during connection (if Ctrl-C supported)
```sql
tq> /logon user:pass@slowhost:1025/db
# Press Ctrl-C while connecting
```

**Expected behavior:**
- Connection attempt cancelled
- Returns to prompt
- Old connection preserved

### Step 5: Verify prompt connection info
```sql
tq[db]> /logon user:pass@newhost:1025/newdb
# Watch prompt change
```

**Expected behavior:**
- Prompt updates immediately after successful connection

## Pass/Fail Criteria

**PASS if:**
- Healthy connection < 2s
- Timeout at 30s (configurable)
- Progress indication for slow connections
- Timeout message clear and helpful
- Cancellation works (if implemented)
- Old connection preserved on timeout
- Prompt updates immediately after connection
- No hangs or indefinite waits

**FAIL if:**
- Fast connection > 2s consistently
- No timeout (hangs indefinitely)
- No progress indication
- Can't cancel slow connection
- Old connection lost on timeout
- Prompt not updated

## Notes

- Performance critical for good UX
- Timeout prevents indefinite hangs
- Progress indication reduces user anxiety
- 30s timeout is reasonable default
- Should be configurable via environment variable
- Cancellation nice-to-have but not critical
- Network conditions affect timing - use ranges not exact values
