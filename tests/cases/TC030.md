## Purpose

Verify that table metadata cache is properly invalidated when the connection changes, ensuring completion always shows current database tables.

## Scope

This test validates:
- Cache cleared on /logon command
- New metadata loaded after connection change
- No stale table lists from previous database
- Cache scope is per-session, not global

## Prerequisites

- tq binary built in release mode
- Access to TWO different Teradata databases with different table lists
- Both databases configured and accessible
- REPL mode and /logon metacommand functional

## Test Procedure

### Step 1: Start REPL and cache table list from first database
```bash
tq -l "user:pass@host:1025/database1" repl
```

```sql
tq[database1]> SELECT * FROM <TAB>
# Note the list of tables displayed
```

### Step 2: Switch to second database using /logon
```sql
tq[database1]> /logon user:pass@host:1025/database2
```

### Step 3: Request table completion in new database
```sql
tq[database2]> SELECT * FROM <TAB>
# Should show "Loading tables..." again
# List should be different from Step 1
```

### Step 4: Verify caching works in new database
```sql
tq[database2]> SELECT * FROM <TAB>
# Second time should be instant (cached)
# Same list as Step 3
```

### Step 5: Switch back to first database
```sql
tq[database2]> /logon user:pass@host:1025/database1
```

### Step 6: Verify cache cleared again
```sql
tq[database1]> SELECT * FROM <TAB>
# Should reload, not use cache from Step 1
```

## Expected Results

### Step 1 Output:
```
Loading tables...
db1_table1    db1_table2    db1_table3    db1_customers    db1_employees
```
(Tables specific to database1)

### Step 2 Output:
```
Disconnecting from host:1025/database1...

Connected successfully.
```

### Step 3 Output:
```

```
(Tables specific to database2 - different from Step 1)

### Step 4 Output:
```
db2_table1    db2_table2    db2_orders    db2_products
```
(Instant, no "Loading tables..." message)

### Step 5 Output:
```
Disconnecting from host:1025/database2...
Connecting to host:1025/database1...
Connected successfully.
```

### Step 6 Output:
```
Loading tables...
db1_table1    db1_table2    db1_table3    db1_customers    db1_employees
```
(Reloaded, shows "Loading tables..." again)

## Pass/Fail Criteria

**PASS if:**
- Cache cleared on /logon command
- Each database shows correct table list
- No cross-contamination between databases
- "Loading tables..." appears after each /logon
- Caching still works within each session
- Correct tables shown for each database

**FAIL if:**
- Cache not cleared on connection change
- Shows tables from wrong database
- Cache persists across /logon
- Doesn't reload after connection change
- Mix of tables from different databases

## Notes

- This test requires access to multiple databases
- Alternative: Create/drop tables in same database to verify cache refresh
- Cache invalidation critical for correct behavior
- Users working with multiple databases depend on this
- May need /refresh metacommand for manual cache invalidation in future
