## Purpose

Verify that tq can write query results directly to files using --output flag.

## Scope

This test validates:
- --output flag functionality
- File creation and overwriting
- Writing different formats to files
- stdout redirection vs --output
- File permission errors

## Prerequisites

- tq binary is built and available
- `.env` file configured with valid Teradata connection credentials
- Write permissions in test directory

## Test Procedure

### Step 1: Output table format to file
```bash
# Using credentials from .env file
tq query --output /tmp/test_output.txt "SELECT 1 AS test"
cat /tmp/test_output.txt
rm /tmp/test_output.txt
```

### Step 2: Output JSON to file
```bash
tq query --format json --output /tmp/test_output.json "SELECT 1 AS id, 'Alice' AS name"
cat /tmp/test_output.json
rm /tmp/test_output.json
```

### Step 3: Output CSV to file
```bash
tq query --format csv --output /tmp/test_output.csv "SELECT 'a' AS col1, 'b' AS col2"
cat /tmp/test_output.csv
rm /tmp/test_output.csv
```

### Step 4: Overwrite existing file
```bash
echo "old content" > /tmp/test_overwrite.txt
tq query --output /tmp/test_overwrite.txt "SELECT 'new' AS content"
cat /tmp/test_overwrite.txt
rm /tmp/test_overwrite.txt
```

### Step 5: Compare --output vs redirection
```bash
tq query --format csv "SELECT 1" > /tmp/test_redirect.csv
tq query --format csv --output /tmp/test_output_flag.csv "SELECT 1"
diff /tmp/test_redirect.csv /tmp/test_output_flag.csv
rm /tmp/test_redirect.csv /tmp/test_output_flag.csv
```

### Step 6: Output to unwritable location
```bash
tq query --output /root/test.txt "SELECT 1" 2>&1
echo "Exit code: $?"
```

### Step 7: Verify stderr still goes to terminal
```bash
tq query --output /tmp/test.txt "INVALID SQL" 2>&1
rm -f /tmp/test.txt
```

## Pass/Fail Criteria

**PASS if:**
- --output flag creates file successfully
- All formats work with --output
- Existing files are overwritten
- --output behavior matches stdout redirection
- Permission errors are handled gracefully
- stderr still goes to terminal when using --output
- Exit codes are correct

**FAIL if:**
- Cannot write to file
- File not created or empty when should have content
- Permission errors cause crashes
- stderr mixed with file output
- Incorrect exit codes

## Notes

- --output is alternative to shell redirection (> file)
- Advantage: keeps stderr on terminal for errors
- Should overwrite existing files (or fail if can't)
- Consider adding --append flag in future
- File permissions default to 0644 on Unix
