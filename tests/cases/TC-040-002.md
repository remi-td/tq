# TC-040-002: Variable Substitution - CLI Batch Integration Tests

**Sprint:** 40
**Feature:** Variable Substitution Engine - CLI Integration
**Type:** Integration Tests
**Location:** `tests/params_integration.rs` (new file)
**Framework:** `std::process::Command`
**Estimated Test Count:** 12 (9 without database, 3 with database marked `#[ignore]`)
**External Dependencies:** File system (YAML fixture files), Teradata database for `#[ignore]` tests
**Database Required:** No for 9 tests; Yes for 3 `#[ignore]` tests

---

## Overview

These integration tests validate the CLI surface of the variable substitution feature: flag parsing, SQL input source compatibility, error propagation to CLI output, and the help topic. Tests spawn the real `tq` binary.

---

## Tests Without Database (no `#[ignore]`)

### TC-040-002-001: Long `--params` flag accepted

**Name:** `test_params_long_flag_accepted`

**Command:** `tq --params tests/fixtures/params/basic.yaml query "SELECT 1"`

**Expected behavior:** Process may exit with connection error (no DB), but NOT with an argument parsing error. The `--params` flag must be recognized by clap.

**Asserts:**
- Exit code is NOT 2 (usage error)
- stderr does NOT contain `"unrecognized argument"` or `"unexpected argument"`
- stderr does NOT contain `"--params"` in an error context

---

**Expected behavior:** Same as TC-040-002-001 but with short flag

**Asserts:**
- Exit code is NOT 2
- stderr does NOT contain `"-p"` in an unrecognized argument error context

### TC-040-002-003: Parameter file not found produces clear error

**Name:** `test_params_file_not_found`

**Command:** `tq --params tests/fixtures/params/definitely_does_not_exist_xyz.yaml query "SELECT 1"`

**Expected behavior:** Exit non-zero; error message on stderr mentions the file path and indicates it was not found

**Asserts:**
- Exit code != 0
- stderr contains `"definitely_does_not_exist_xyz.yaml"` (the file path)
- stderr contains text suggesting file not found (e.g., `"not found"`, `"No such file"`, `"cannot open"`)

### TC-040-002-006: Multiple `-p` flags accepted (later overrides)

**Name:** `test_params_multiple_flags_accepted`

**Command:** `tq -p tests/fixtures/params/override_a.yaml -p tests/fixtures/params/override_b.yaml query "SELECT '{{env}}'"`

**Expected behavior:** Both flags accepted; if connection fails, error is DB-related not argument-parsing. If verbose output is available, can verify `env = production`.

**Asserts:**
- Exit code is NOT 2 (argument parsing error)
- No `"unrecognized argument"` errors relating to `-p`

---

### TC-040-002-007: Help topic `tq help params` exists

**Name:** `test_help_params_topic_exists`

**Command:** `tq help params`

**Expected behavior:** Exit 0; stdout contains variable substitution documentation

**Asserts:**
- Exit code == 0
- stdout contains `"params"` or `"variable"` or `"substitut"` (case-insensitive)
- stdout contains `"{{"`  (the marker syntax documented)

---

### TC-040-002-008: SQL without markers passes through (no substitution error)

**Name:** `test_params_no_markers_passthrough`

**Command:** `tq --params tests/fixtures/params/basic.yaml query "SELECT 1"`

**Expected behavior:** The presence of a params file with no `{{markers}}` in the SQL does not cause any substitution-related error. The command fails only on DB connection (acceptable) or succeeds.

**Asserts:**
- stderr does NOT contain `"undefined"` variable error
- stderr does NOT contain `"substitut"` error
- Exit code is 0 (if DB connected) or 1 (DB connection failure) but NOT 2

---

### TC-040-002-009: Nested YAML path substitution CLI end-to-end

**Name:** `test_params_nested_path_substitution_cli`

**Command:** `tq --params tests/fixtures/params/nested.yaml query "SELECT '{{target.db}}'"`

**Expected behavior:** Substitution produces `SELECT 'mydb'`. If DB is unavailable, the connection error occurs AFTER substitution (the substituted SQL is `SELECT 'mydb'` not the original with the marker). If the binary provides a `--dry-run` or `--verbose` mode showing the substituted SQL, assert on that output. Otherwise, assert only that the error is connection-related (not substitution-related).

**Asserts:**
- stderr does NOT contain `"undefined"` or `"substitut"` errors
- Exit code is 0 (DB connected) or 1 (connection failure), but NOT 2

## Test Infrastructure Notes

- Binary path: use `env!("CARGO_BIN_EXE_tq")` for the path to the compiled tq binary
- Create fixture files in `tests/fixtures/params/` as part of test setup or as static files committed to the repository
- Use `std::process::Command` with `.stdout(Stdio::piped()).stderr(Stdio::piped())`
- For environment variable tests: set env vars on the `Command` object, not the process, to avoid pollution
