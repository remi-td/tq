## Purpose

Verify that column name completion works correctly in queries with JOIN clauses, including qualified column references with table aliases.

## Scope

This test validates:
- Column completion with table aliases
- Multi-table context detection
- Qualified column completion (e.g., e.<TAB>)
- Ambiguous column handling
- Columns from multiple tables displayed with prefixes

## Prerequisites

- tq binary built in release mode
- Valid Teradata connection credentials configured in .env
- Test database with tables that have foreign key relationships
- REPL mode functional
- TC031 passed (basic column completion working)

## Test Procedure

### Step 1: Start REPL
```bash
tq repl
```

### Step 2: Test qualified column completion with table alias
```sql
tq> SELECT e.<TAB> FROM employees e
```

**Expected behavior:**
- Shows columns from employees table
- Prefixed with alias: e.employee_id, e.first_name, etc.

### Step 3: Test completion in JOIN with specific alias
```sql
tq> SELECT * FROM employees e
    JOIN departments d ON e.<TAB>
```

**Expected behavior:**
- Shows employees columns with e. prefix
- Filters to columns from employees table only

### Step 4: Test ambiguous context (multiple tables)
```sql
tq> SELECT * FROM employees e
    JOIN departments d ON e.department_id = d.id
    WHERE <TAB>
```

**Expected behavior:**
- Shows columns from both tables with alias prefixes
- Format: e.employee_id (INT), d.name (VARCHAR), etc.
- OR shows message: "(Multiple tables in query. Specify table: e.<TAB> or d.<TAB>)"

### Step 5: Test second table alias completion
```sql
tq> SELECT * FROM employees e
    JOIN departments d ON e.department_id = d.id
    WHERE d.<TAB>
```

**Expected behavior:**
- Shows columns from departments table only
- Prefixed with d.

### Step 6: Test multiple JOINs
```sql
tq> SELECT * FROM employees e
    JOIN departments d ON e.dept_id = d.id
    JOIN projects p ON e.project_id = p.id
    WHERE p.<TAB>
```

**Expected behavior:**
- Shows columns from projects table with p. prefix

## Pass/Fail Criteria

**PASS if:**
- Qualified completion (e.<TAB>) works correctly
- Shows only columns from specified table
- Multi-table queries handled appropriately
- All table aliases recognized
- Type hints displayed
- No crashes or errors

**FAIL if:**
- Qualified completion doesn't work
- Shows wrong table's columns
- Can't distinguish between table aliases
- Crashes on JOIN queries
- Performance significantly degrades

## Notes

- JOIN queries more complex than single table
- Table alias detection critical for correct completion
- Ambiguous context should either show all columns with prefixes OR prompt user to qualify
- SQL parsing required to extract table aliases and context
- May have limitations with complex queries (nested, CTEs) - acceptable for v1
