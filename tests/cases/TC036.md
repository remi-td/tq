## Purpose

Verify that the /logon metacommand without arguments displays current connection information clearly and accurately.

## Scope

This test validates:
- /logon with no arguments shows connection details
- Displays host, database, username
- Shows authentication mechanism
- Displays session ID
- Shows connection duration
- Clear, readable format

## Prerequisites

- tq binary built in release mode
- Valid Teradata connection credentials configured in .env
- REPL mode functional

## Test Procedure

### Step 1: Start REPL with connection
```bash
tq -l "testuser:testpass@testhost:1025/testdb" repl
```

### Step 2: Execute /logon with no arguments
```sql
tq> /logon
```

### Step 3: Wait a few seconds and check again
```bash
# Wait 30 seconds
```

```sql
tq> /logon
# Verify duration updated
```

### Step 4: Test alias \c
```sql
tq> \c
```

**Expected behavior:**
- Same output as /logon

### Step 5: Execute query then check connection
```sql
tq> SELECT 1 AS test;
tq> /logon
```

**Expected behavior:**
- Connection info unchanged by query

## Expected Results

### Step 2 Output:
```
Current Connection:
  Host: testhost:1025
  Database: testdb
  User: testuser
  Authentication: TD2
  Session ID: [session-id]
  Connected: [timestamp] ([duration] ago)
  Status: Active
```

### Step 3 Output:
Similar to Step 2 but with updated duration
(e.g., "30s ago" or "1m 5s ago")

### Step 4 Output:
Same as Step 2 (alias works)

### Step 5 Output:
Same connection info, Status: Active

## Pass/Fail Criteria

**PASS if:**
- /logon shows current connection details
- All fields displayed correctly
- Duration updates over time
- Alias \c works identically
- Format is clear and readable
- No sensitive information exposed (password masked)

**FAIL if:**
- /logon doesn't show connection info
- Missing fields
- Incorrect information
- Password exposed
- Error or crash

## Notes

- This is the simplest /logon use case
- Should work immediately after connection
- Duration should be human-readable (1m 30s, not 90000ms)
- Session ID may be numeric or alphanumeric
- Authentication mechanism: TD2, LDAP, KRB5, TDNEGO
