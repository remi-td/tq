## Purpose

Verify that tq can read SQL queries from stdin for pipeline integration.

## Scope

This test validates:
- stdin input handling
- echo pipe support
- cat pipe support
- heredoc support
- stdin vs file vs argument precedence

## Prerequisites

- tq binary is built and available
- `.env` file configured with valid Teradata connection credentials

## Test Procedure

### Step 1: Pipe from echo
```bash
# Using credentials from .env file
echo "SELECT 1 AS test" | tq query
```

### Step 2: Pipe from cat
```bash
cat > /tmp/test_query.sql << 'EOF'
SELECT 'Hello' AS greeting, 123 AS number
EOF
cat /tmp/test_query.sql | tq query
rm /tmp/test_query.sql
```

### Step 3: Heredoc
```bash
tq query << 'EOF'
SELECT
    'Multi-line' AS line1,
    'Query' AS line2
EOF
```

### Step 4: Stdin with JSON output
```bash
echo "SELECT 1, 2, 3" | tq query --format json
```

### Step 5: Stdin with CSV output
```bash
echo "SELECT 'a', 'b', 'c'" | tq query --format csv
```

### Step 6: Empty stdin
```bash
echo "" | tq query 2>&1
```

### Step 7: Verify argument takes precedence over stdin
```bash
echo "SELECT 1" | tq query "SELECT 2"
```

## Pass/Fail Criteria

**PASS if:**
- Reads SQL from stdin successfully
- Works with echo, cat, heredoc
- Output format flags work with stdin
- Empty stdin produces clear error
- Precedence: argument > file > stdin
- Exit codes are correct
- Multiline queries supported

**FAIL if:**
- Cannot read from stdin
- Multiline queries fail
- Format flags don't work
- Precedence is incorrect
- Unclear errors for empty stdin

## Notes

- stdin is standard UNIX pattern: echo "cmd" | tool
- Useful for piping SQL from scripts
- When no argument and no --file, should read from stdin
- Should detect if stdin is terminal (interactive) vs pipe
- May need to handle Ctrl-D (EOF) gracefully
