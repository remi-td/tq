## Purpose

Validate that `tq sysconfig` works as a batch mode CLI command:
- CLI argument dispatch is wired correctly
- `--format` flag works for table, csv, and json output
- Exit codes are correct
- Command is visible in help text

Three tests run without a database (CLI wiring validation). Two tests require a live database (marked `#[ignore]`).

## Acceptance Criteria Coverage

- **AC-4**: `tq sysconfig` batch mode command with table/csv/json output formats

## Prerequisites

- `tq` binary built (`cargo build --release` or `cargo build`)
- Live Teradata database configured in `.env` for `#[ignore]` tests

## Test Procedure

**Location:** `tests/integration_sysconfig.rs`

```rust
//! Integration tests for tq sysconfig batch mode command

use std::process::Command;

fn tq_bin() -> std::path::PathBuf {
    assert_cmd::cargo::cargo_bin!("tq")
}

fn logon_string() -> String {
    // Load from .env or TQ_LOGON environment variable
    dotenvy::dotenv().ok();
    std::env::var("TQ_LOGON").expect("TQ_LOGON must be set for live database tests")
}

// ============================================================================
// Tests that do NOT require a database (CLI wiring validation)
// ============================================================================

#[test]
fn test_sysconfig_subcommand_exists_in_help() {
    // Verify tq --help lists sysconfig as a subcommand
    let output = Command::new(tq_bin())
        .arg("--help")
        .output()
        .expect("Failed to execute tq --help");

    let stdout = String::from_utf8_lossy(&output.stdout);
    let stderr = String::from_utf8_lossy(&output.stderr);
    let all_output = format!("{}{}", stdout, stderr);

    assert!(
        all_output.contains("sysconfig"),
        "tq --help must list 'sysconfig' subcommand, got: {}",
        all_output
    );
}

#[test]
fn test_sysconfig_help_subcommand_succeeds() {
    // tq help sysconfig (or tq sysconfig --help) should exit 0 with usage text
    let output = Command::new(tq_bin())
        .args(&["sysconfig", "--help"])
        .output()
        .expect("Failed to execute tq sysconfig --help");

    let stdout = String::from_utf8_lossy(&output.stdout);
    let stderr = String::from_utf8_lossy(&output.stderr);
    let all_output = format!("{}{}", stdout, stderr);

    // Should succeed (exit 0) or show help text
    assert!(
        all_output.contains("sysconfig") || output.status.success(),
        "tq sysconfig --help should display help text, got: {}",
        all_output
    );
}

#[test]
fn test_sysconfig_without_logon_exits_nonzero() {
    // Without --logon or TQ_LOGON env var, should fail with usage/connection error
    let output = Command::new(tq_bin())
        .arg("sysconfig")
        .env_remove("TQ_LOGON")
        .output()
        .expect("Failed to execute tq sysconfig");

    assert!(
        !output.status.success(),
        "tq sysconfig without credentials should exit non-zero"
    );
}

// ============================================================================
// Tests that require a live database (marked #[ignore])
// ============================================================================

#[test]
#[ignore] // Requires live database: cargo test --test integration_sysconfig -- --ignored
fn test_sysconfig_table_format_default() {
    let logon = logon_string();

    let output = Command::new(tq_bin())
        .args(&["sysconfig", "--logon", &logon])
        .output()
        .expect("Failed to execute tq sysconfig");

    let stdout = String::from_utf8_lossy(&output.stdout);
    let stderr = String::from_utf8_lossy(&output.stderr);

    assert!(
        output.status.success(),
        "tq sysconfig should succeed with valid credentials. stderr: {}",
        stderr
    );

    // Default output (table format) should contain version or AMP information
    assert!(
        stdout.contains("VERSION") || stdout.contains("AMP") || stdout.contains("version"),
        "Table output should contain system configuration data. stdout: {}",
        stdout
    );
}

#[test]
#[ignore] // Requires live database: cargo test --test integration_sysconfig -- --ignored
fn test_sysconfig_csv_format() {
    let logon = logon_string();

    let output = Command::new(tq_bin())
        .args(&["sysconfig", "--logon", &logon, "--format", "csv"])
        .output()
        .expect("Failed to execute tq sysconfig --format csv");

    let stdout = String::from_utf8_lossy(&output.stdout);

    assert!(
        output.status.success(),
        "tq sysconfig --format csv should succeed"
    );

    // CSV output should have a header line with comma-separated fields
    let lines: Vec<&str> = stdout.lines().collect();
    assert!(!lines.is_empty(), "CSV output must have content");

    let header = lines[0];
    assert!(
        header.contains(','),
        "CSV header should be comma-separated, got: {}",
        header
    );
}

#[test]
#[ignore] // Requires live database: cargo test --test integration_sysconfig -- --ignored
fn test_sysconfig_json_format() {
    let logon = logon_string();

    let output = Command::new(tq_bin())
        .args(&["sysconfig", "--logon", &logon, "--format", "json"])
        .output()
        .expect("Failed to execute tq sysconfig --format json");

    let stdout = String::from_utf8_lossy(&output.stdout);

    assert!(
        output.status.success(),
        "tq sysconfig --format json should succeed"
    );

    // JSON output must be parseable
    let parsed: Result<serde_json::Value, _> = serde_json::from_str(&stdout);
    assert!(
        parsed.is_ok(),
        "tq sysconfig --format json must produce valid JSON, got: {}",
        stdout
    );

    // Must be a JSON array
    let json = parsed.unwrap();
    assert!(
        json.is_array(),
        "JSON output must be an array of config entries"
    );
}
```

## Expected Results

### Without Database (3 tests):
- `tq --help` output mentions "sysconfig"
- `tq sysconfig --help` displays usage text
- `tq sysconfig` without credentials exits non-zero

### With Live Database (2 tests, `#[ignore]`):
- `tq sysconfig` default output contains system configuration data
- `tq sysconfig --format csv` produces comma-separated output
- `tq sysconfig --format json` produces valid JSON array

## Pass/Fail Criteria

**PASS if:**
- All 3 no-DB tests pass
- All 2 live-DB tests pass (when database available)
- Exit code is 0 for successful operations
- Exit code non-zero when credentials missing

**FAIL if:**
- `sysconfig` not found in CLI help (CLI wiring broken)
- Any format flag (csv, json) produces wrong output structure
- `tq sysconfig` exits 0 without valid credentials
- JSON output is invalid JSON

## Notes

- Run no-DB tests: `cargo test --test integration_sysconfig`
- Run live-DB tests: `cargo test --test integration_sysconfig -- --ignored`
- Configure database: set `TQ_LOGON` in `.env` file
