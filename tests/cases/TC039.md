## Purpose

Verify that /logon preserves appropriate REPL state (history, settings) while clearing connection-specific state (metadata cache).

## Scope

This test validates:
- Command history preserved
- Editor mode setting preserved
- Pager setting preserved
- Colors setting preserved
- Table metadata cache cleared
- Column metadata cache cleared
- Prompt updated
- No query result carryover

## Prerequisites

- tq binary built in release mode
- Access to two different databases
- REPL mode functional
- Settings metacommands functional (/pager, /colors, etc.)

## Test Procedure

### Step 1: Start REPL and configure settings
```bash
tq -l "user:pass@host:1025/db1" repl
```

```sql
tq[db1]> /pager off
tq[db1]> /colors on
# If Vi mode supported:
# tq[db1]> /set editor vi
```

### Step 2: Execute some queries for history
```sql
tq[db1]> SELECT 1 AS first_query;
tq[db1]> SELECT 2 AS second_query;
tq[db1]> SELECT 3 AS third_query;
```

### Step 3: Use tab completion to cache metadata
```sql
tq[db1]> SELECT * FROM <TAB>
# Cache table list
tq[db1]> SELECT * FROM employees WHERE <TAB>
# Cache employee columns
```

### Step 4: Switch connection
```sql
tq[db1]> /logon user:pass@host:1025/db2
```

### Step 5: Verify command history preserved
```sql
# Press Up arrow multiple times
```

**Expected behavior:**
- Shows previous queries: SELECT 3..., SELECT 2..., SELECT 1...

### Step 6: Verify settings preserved
```sql
tq[db2]> /pager
tq[db2]> /colors
```

**Expected behavior:**
- Pager: off (preserved from Step 1)
- Colors: on (preserved from Step 1)

### Step 7: Verify metadata cache cleared
```sql
tq[db2]> SELECT * FROM <TAB>
```

**Expected behavior:**
- Shows "Loading tables..." (cache cleared)
- Shows tables from db2 (not db1)

### Step 8: Verify column cache cleared
```sql
tq[db2]> SELECT * FROM employees WHERE <TAB>
```

**Expected behavior:**
- Shows "Loading columns..." (cache cleared)
- May show different columns if schema differs

### Step 9: Execute query and verify result doesn't carry over
```sql
tq[db2]> SELECT 'db2' AS database_name;
# Then switch back
tq[db2]> /logon user:pass@host:1025/db1
# Try to export last result (if /export supported)
# tq[db1]> /export csv test.csv
```

**Expected behavior:**
- Last result cleared on connection change
- Can't export result from previous connection

## Pass/Fail Criteria

**PASS if:**
- Command history preserved across /logon
- Settings preserved (pager, colors, editor)
- Table cache cleared on /logon
- Column cache cleared on /logon
- Prompt updated to new database
- Query results cleared (not carried over)
- REPL functions normally after switch

**FAIL if:**
- History lost
- Settings reset to defaults
- Cache not cleared (shows wrong database)
- Prompt not updated
- State corrupted

## Notes

- State preservation critical for good UX
- Users expect history and settings to persist
- Cache invalidation critical for correctness
- Clear distinction: preserve UI state, clear data cache
- Query result clearing prevents confusion
