# TC-040-003: Variable Substitution - REPL Metacommand Interactive Tests

**Sprint:** 40
**Feature:** Variable Substitution Engine - REPL `/params` Metacommand
**Type:** Interactive Tests (expectrl PTY)
**Location:** `tests/interactive_tests.rs` (append to existing file)
**Framework:** expectrl crate (existing infrastructure)
**Estimated Test Count:** 6
**External Dependencies:** Live Teradata database, PTY terminal
**Database Required:** Yes (all tests marked `#[ignore]`)

---

## Overview

These interactive tests validate the REPL `/params` metacommand using PTY simulation via the `expectrl` crate. They cover tab completion, metacommand lifecycle (load/show/unload), state persistence across queries, error handling for missing files, and parameter use in executed SQL.

All tests require a live database connection and are marked `#[ignore]`. Run with:
```bash
cargo test --test interactive_tests params -- --ignored --test-threads=1
```

## Tests (all `#[ignore]`)

### TC-040-003-001: Tab completion shows `/params` metacommand

**Name:** `test_params_tab_completion_shows_metacommand` - `#[ignore]`

**Procedure:**
1. Spawn REPL via expectrl with valid database connection
2. Wait for `tq>` prompt
3. Type `/par` (partial command prefix)
4. Send Tab key
5. Observe completion output

**Expected:**
- Completion list contains `/params` (the full metacommand name)

**Asserts:**
- Output after Tab contains `"params"` or `/params`

**Rationale:** AC-10 requires tab completion for `/params`

### TC-040-003-002: Load parameter file via `/params load`

**Name:** `test_params_load_command` - `#[ignore]`

**Procedure:**
1. Spawn REPL
2. Wait for `tq>` prompt
3. Type `/params load tests/fixtures/params/basic.yaml` and press Enter
4. Wait for response

**Expected:**
- REPL outputs a confirmation message (e.g., "Loaded parameters from...", "Parameters loaded", or similar)
- REPL does NOT crash or display a parse error
- Prompt returns to `tq>`

**Asserts:**
- No error message containing `"error"`, `"failed"`, or `"not found"` in response
- Prompt `tq>` returns

### TC-040-003-004: Parameters used in subsequent query

**Name:** `test_params_variable_used_in_query` - `#[ignore]`

**Procedure:**
1. Spawn REPL
2. Load `tests/fixtures/params/basic.yaml` via `/params load`
3. Execute SQL: `SELECT '{{table}}';` (with semicolon to trigger execution)

**Asserts:**

**Rationale:** AC-7 requires the loaded parameters to be used in subsequent query execution

### TC-040-003-005: `/params unload` clears parameter state

**Name:** `test_params_unload_clears_state` - `#[ignore]`

**Procedure:**
1. Spawn REPL
2. Load `tests/fixtures/params/basic.yaml` via `/params load`
3. Verify load via `/params show` (should show `table` and `schema`)
4. Type `/params unload` and press Enter
5. Execute SQL: `SELECT '{{table}}';`
6. Observe result

**Expected:**
- Step 3: `/params show` displays variables
- Step 5: `/params unload` outputs a confirmation (e.g., "Parameters cleared")
- Step 6: Query produces a "undefined variable" error (not database error), since `table` is no longer defined

**Asserts:**
- After unload, executing `{{table}}` in SQL produces an error containing `"table"` (variable name) or `"undefined"`

**Rationale:** AC-7 requires `/params unload` to clear loaded parameters

### TC-040-003-006: `/params load` with non-existent file shows error without REPL crash

**Name:** `test_params_load_nonexistent_file` - `#[ignore]`

**Procedure:**
1. Spawn REPL
2. Type `/params load /does/not/exist/xyz_params.yaml` and press Enter

**Expected:**

**Asserts:**

## Implementation Notes

- Use `expectrl::spawn` to start the REPL process
- Use `expectrl::session.expect()` to wait for specific output strings
- Use `expectrl::session.send()` to send commands and `send_line()` for commands with Enter
- Timeout: set reasonable timeout per step (e.g., 5-10 seconds for REPL prompts)
- Tab key: send as `"\t"` escape sequence
- All tests require the `TQ_LOGON` environment variable to be set (from `.env` file)
- Tests should be in a module `mod params_repl_tests` within `tests/interactive_tests.rs`
- Run with `--test-threads=1` to avoid parallel REPL session conflicts
