# Test Case TC053: Tab Completion - Cache Cleared After CREATE TABLE DDL

## Purpose

Verify that the table metadata cache is invalidated and refreshed after successful CREATE TABLE statements, so new tables appear in completion immediately.

## Prerequisites

- tq REPL mode active
- Live Teradata database connection
- Permission to CREATE and DROP tables in current database

## Test Procedure

### Step 1: Establish baseline - Tab completion before CREATE

```sql
tq> SELECT * FROM <TAB>
[Note the list of tables - "test_sprint8" should NOT be present]
```

### Step 2: Create a new table

```sql
tq> CREATE TABLE test_sprint8 (id INTEGER, name VARCHAR(50));
```

**Expected:**
- Table created successfully
- Message: "Table created successfully." or similar
- Internal note: "[Cache invalidated for current database]"

### Step 3: Verify new table appears in completion

```sql
tq> SELECT * FROM <TAB>
```

**Expected:**
- "test_sprint8" now appears in table list
- May show brief loading indicator (cache refresh)
- List includes both old tables and new "test_sprint8"

### Step 4: Verify filtering works with new table

```sql
tq> SELECT * FROM test<TAB>
```

**Expected:**
- Filters to "test_sprint8" and other tables starting with "test"
- New table is included in filtered results

### Step 5: Cleanup

```sql
tq> DROP TABLE test_sprint8;
tq> /quit
```

## Verification

- [ ] Tab completion before CREATE doesn't show new table
- [ ] CREATE TABLE executes successfully
- [ ] Tab completion after CREATE shows new table
- [ ] Cache refresh happens automatically (user doesn't need to reconnect)
- [ ] New table is filterable by typing

## Pass/Fail Criteria

**PASS:**
- New table appears in completion immediately after CREATE
- Cache is refreshed automatically
- No manual refresh needed
- Completion remains fast (<500ms)

**FAIL:**
- New table doesn't appear in completion after CREATE
- User must restart tq to see new table
- Cache is not invalidated on DDL
- Completion breaks after CREATE

## Notes

From sprint-8-ux-design.md:
> "After successful DDL statements, invalidate relevant cache"

DDL statements that should trigger cache refresh:
- CREATE TABLE
- CREATE VIEW
- ALTER TABLE (rename)

Cache invalidation should be:
- Automatic (no user action required)
- Database-specific (only invalidate affected database)
- Non-blocking (background refresh if possible)
