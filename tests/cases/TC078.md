# Test Case TC078: Table Display - Very Wide Terminal Handling (160 cols)

## Purpose

Verify that table display correctly handles very wide terminals (160 columns) and shows even more columns while preventing excessive width that hurts readability.

## Scope

**Testing:**
- Terminal width detection (160 columns)
- Maximum columns shown without degrading readability
- Column width limits (max 40 chars per column)
- All columns shown if they fit
- No "(+n cols)" if all columns visible

**Not Testing:**
- Narrower terminals (TC076, TC077)
- Ultra-wide terminals (TC079)

## Prerequisites

- tq binary with Sprint 11 fixes
- Terminal set to 160 columns (or wider monitor)
- Test query with 10+ columns

## Test Procedure

### Setup

```bash
# Set terminal to 160 columns
tput cols  # Verify: 160

./target/release/tq repl
```

### Execution Steps

**Step 1: Execute 10-column query**

```sql
tq> SELECT TOP 5
    DatabaseName,
    TableName,
    CreatorName,
    OwnerName,
    RequestText,
    TableKind,
    ProtectionType,
    JournalFlag,
    CreatorName,
    RequestTxtOverflow
  FROM DBC.TablesV
  ORDER BY DatabaseName;
```

**Expected outcome:**
- Most or all columns visible (8-10 columns)
- If all fit: NO "(+n cols)" indicator
- If still truncated: Very few hidden (1-2)
- Columns not excessively wide

**Step 2: Test query with few columns that all fit**

```sql
tq> SELECT TOP 5
    DatabaseName,
    TableName,
    CreatorName
  FROM DBC.TablesV;
```

**Expected outcome:**
- All 3 columns shown
- NO "(+n cols)" indicator
- NO "..." in body rows
- NO footer about hidden columns
- Clean table display

**Step 3: Verify column width limits**

Observe column widths:

**Expected outcome:**
- No single column exceeds ~40 characters
- Long text truncated within cell (with "...")
- Not: entire column consuming 100+ chars

**Step 4: Measure total width**

**Expected outcome:**
- Table fits within 160 columns
- Reasonable width utilization
- Not overly conservative

### Verification

**Layout Checklist:**

- [ ] Many or all columns visible (8-10)
- [ ] Fits within 160 columns
- [ ] Individual columns not excessively wide
- [ ] Readability excellent
- [ ] Professional appearance

**Edge Case Check:**

- [ ] Query with <10 columns shows all (no truncation)
- [ ] Query with >15 columns still truncates appropriately

### Cleanup

```bash
tq> /quit
```

## Pass/Fail Criteria

**PASS:**
- Shows 8-10+ columns in 160-col terminal
- Fits within terminal width
- No excessive column widths (max ~40 chars)
- All-columns-fit case handled (no "+n" when not needed)
- Readability maintained

**FAIL:**
- Shows same columns as 80-col (width ignored)
- Exceeds 160 columns
- Single column consumes 100+ chars
- Shows "+n cols" when all columns fit
- Layout degraded

## Notes

**Column Width Limits:**

Even in very wide terminals, individual columns should max out:
- Max 40 characters per column (readability)
- Long text truncated within cell: "This is a very long text that..."
- Prevents one column from dominating width

**All-Columns-Visible Case:**

Implementation must detect:
```rust
if all_columns_fit {
    // Don't show "+n cols" indicator
    // Don't show "..." in body
    // Don't show "Hidden columns" footer
}
```
