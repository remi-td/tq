# Test Case TC057: Result Paging - Vertical Paging with j/k Keys

## Purpose

Verify that when query results exceed terminal height, the pager activates and allows vertical navigation using j (down) and k (up) keys, similar to vim/less pagers.

## Prerequisites

- tq REPL mode active
- Live Teradata database connection
- Pager enabled (default or via `/pager on`)
- Terminal height known (use `tput lines`)

## Test Procedure

### Step 1: Query with many rows (>terminal height)

```sql
tq> SELECT TOP 1000 * FROM DBC.TablesV;
```

**Expected:**
- Query executes
- Results begin displaying
- Pager activates (results don't scroll past)
- Status line appears at bottom: "Lines 1-25 of 1000 (2%) - j/k to scroll, q to quit" (or similar)
- Terminal enters interactive mode (not dumping all output)

### Step 2: Navigate down with 'j' key

Press 'j' repeatedly (10 times)

**Expected:**
- Each 'j' press scrolls down one line
- Status line updates: "Lines 11-35 of 1000 (3%)"
- Content scrolls smoothly
- Headers may stay visible or scroll (either is acceptable)

### Step 3: Navigate up with 'k' key

Press 'k' repeatedly (5 times)

**Expected:**
- Each 'k' press scrolls up one line
- Status line updates: "Lines 6-30 of 1000 (3%)"
- Can scroll back to previously viewed content
- Reaches top and stops (can't scroll above line 1)

### Step 4: Test boundary conditions

Press 'k' many times to reach top:

**Expected:**
- Stops at line 1 (doesn't wrap or error)
- Status shows "Lines 1-25 of 1000 (0%)"

Press 'j' many times to reach bottom:

**Expected:**
- Scrolls to last page
- Status shows "Lines 975-1000 of 1000 (100%)" (or similar)
- Stops at bottom (doesn't wrap)

### Step 5: Exit pager

Press 'q' or 'Esc'

**Expected:**
- Pager exits cleanly
- Returns to REPL prompt
- Terminal restored to normal mode
- Can execute next query

## Verification

**Pager Activation:**
- [ ] Pager activates for results > terminal height
- [ ] Results don't scroll past terminal
- [ ] Status line is visible

**Navigation:**
- [ ] 'j' scrolls down one line
- [ ] 'k' scrolls up one line
- [ ] Navigation is responsive (<100ms per keypress)
- [ ] Stops at boundaries (top/bottom)

**Status Line:**
- [ ] Shows current line range
- [ ] Shows total line count
- [ ] Shows percentage
- [ ] Updates on every scroll

**Exit:**
- [ ] 'q' exits pager
- [ ] 'Esc' exits pager (if supported)
- [ ] Returns to REPL prompt
- [ ] Terminal is clean (no artifacts)

## Pass/Fail Criteria

**PASS:**
- Pager activates for large result sets
- j/k keys work for vertical navigation
- Status line shows progress
- Boundaries handled correctly
- Exit works cleanly

**FAIL:**
- Pager doesn't activate (all output dumps) ← PRIMARY BUG
- j/k keys don't work or are not recognized
- No status line visible
- Can't exit pager (stuck)
- Terminal corrupted after pager exit

## Notes

From sprint-8-root-cause-analysis.md:
> "The pager module exists (`src/commands/repl/pager.rs`) but is NEVER INTEGRATED into the execution flow"
> "The `execute_sql_with_state` function directly calls `write_output_with_timing` with NO check for `state.is_pager_enabled()` and NO call to `PagedOutput::new()`"

This is the PRIMARY bug for Sprint 8 Bug 3.

Expected fix:
1. Check if pager is enabled in state
2. Check if result exceeds terminal height
3. If yes, activate pager mode
4. Switch terminal to raw mode
5. Set up keyboard event loop for j/k/q keys
6. Render visible portion with status line
7. Restore terminal on exit
