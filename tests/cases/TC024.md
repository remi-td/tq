## Purpose

Verify that tq ping command supports multiple attempts with configurable intervals, similar to network ping.

## Scope

This test validates:
- --count flag functionality
- --interval flag functionality
- Multiple connection attempts
- Timing between attempts
- Summary statistics

## Prerequisites

- tq binary is built and available
- `.env` file configured with valid Teradata connection credentials

## Test Procedure

### Step 1: Single ping (default)
```bash
# Using credentials from .env file
time tq ping
```

### Step 2: Multiple pings (count)
```bash
tq ping --count 3
```

### Step 3: Custom interval
```bash
time tq ping --count 3 --interval 500ms
```

### Step 4: Long interval
```bash
time tq ping --count 2 --interval 2s
```

### Step 5: Short form flags
```bash
tq ping -c 3 -i 1s
```

### Step 6: Count with failed connection
```bash
tq -l "user:pass@invalid-host:1025/db" ping --count 3 2>&1
```

## Expected Results

### Step 1 Output:
```
Database connection successful (XXXms)
```
Single attempt, minimal time
Exit code: 0

### Step 2 Output:
```
Database connection successful (XXXms)
Database connection successful (XXXms)
Database connection successful (XXXms)

--- ping statistics ---
3 attempts, 3 successful, 0 failed
Round-trip min/avg/max = XX/XX/XX ms
```
Three attempts, summary statistics
Exit code: 0

### Step 3 Output:
Total time should be approximately 1-1.5 seconds
(3 pings + 2 intervals of 500ms = ~1s + ping time)

### Step 4 Output:
Total time should be approximately 4+ seconds
(2 pings + 1 interval of 2s)

### Step 5 Output:
Same as Step 2 (short form flags work)

### Step 6 Output (stderr):
```
Database connection failed
Database connection failed
Database connection failed

--- ping statistics ---
3 attempts, 0 successful, 3 failed
```
Exit code: 1

## Pass/Fail Criteria

**PASS if:**
- --count correctly specifies number of attempts
- --interval controls delay between attempts
- Timing is approximately correct (within margin)
- Summary statistics shown for multiple pings
- Both long and short flag forms work
- Failures are reported correctly
- Exit codes correct (0 for success, 1 for all failures)

**FAIL if:**
- Count flag ignored
- Interval not respected
- No summary statistics
- Timing significantly off
- Short forms don't work
- Incorrect exit codes

## Notes

- Similar to network ping: ping -c 3 -i 1 host
- Useful for monitoring database availability
- Can detect intermittent connection issues
- Statistics help identify performance trends
- Consider adding: packet loss percentage, jitter
- Future: continuous ping mode (until Ctrl-C)
- Default: count=1, interval=1s
