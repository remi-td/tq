# Test Case TC056: Tab Completion - Handles Multiple Databases Gracefully

## Purpose

Verify that tab completion handles environments with many databases (10+) without performance degradation or UI clutter.

## Prerequisites

- tq REPL mode active
- Teradata system with 10+ databases (or create test databases)

## Test Procedure

### Step 1: Tab completion with many databases

```sql
tq> SELECT * FROM <TAB>
```

**Expected:**
- Database list may be long but displayed clearly
- May show "...and X more databases" if too many
- Scrollable or paginated list
- Performance remains acceptable (<500ms)

### Step 2: Filter large database list

```sql
tq> SELECT * FROM D<TAB>
```

**Expected:**
- Filters to databases starting with 'D'
- Reduces list to manageable size
- Fast response

### Step 3: Access tables in multiple databases

```sql
tq> SELECT * FROM DBC.<TAB>
[Wait for completion]

tq> SELECT * FROM val.<TAB>
[Wait for completion]

tq> SELECT * FROM mldb.<TAB>
[Wait for completion]
```

**Expected:**
- Each database's tables are cached separately
- Switching between databases is fast after first load
- No cache interference between databases

## Verification

- [ ] Completion works with 10+ databases
- [ ] UI handles large database list (scrolling, truncation, or filtering)
- [ ] Performance acceptable (<500ms per database first access)
- [ ] Cached access is fast (<50ms)
- [ ] Database-specific caches don't interfere

## Pass/Fail Criteria

**PASS:**
- Handles 10+ databases without issues
- UI presents large lists clearly
- Performance is acceptable
- Caching works correctly per database

**FAIL:**
- Crashes with many databases
- UI becomes unusable with large lists
- Extreme performance degradation (>2s)
- Cache confusion (wrong database's tables shown)

## Notes

From sprint-8-ux-design.md:
> "Because there can be a massive amount of objects in a Teradata system (millions of tables), we should intelligently fetch and cache objects... typically a user will not use more than 2-3 databases in the same session"

Lazy loading strategy:
- Load all database names (small list, fast)
- Load current DB tables only
- Load other database tables on-demand
- Cache per database with LRU eviction if needed

Typical Teradata environment:
- System databases: 5-10 (DBC, All, TD_SYSXML, etc.)
- User databases: varies (1-100+)
- Tables per database: 10-10,000+
