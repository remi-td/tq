## Overview

Since Sprint 65, the 8 interactive watch tests (TC097-A..H) and the pager search test (TC104) have
been blocked by reedline's `ESC[6n` cursor-position request (CPR). The PTY harness never replied,
causing reedline to loop with "Error reading input: The cursor position could not be read within a
normal duration" until the stage timeout expired.

Sprint 68 confirmed the root cause from PTY dump evidence. Sprint 69 fixes it by implementing a
`ESC[6n` → `ESC[1;1R` synthetic response in the PTY harness.

This test case covers four validation layers:

1. **TC107-U01 (unit):** The CPR responder mechanism works correctly in isolation.
2. **TC107-structural (grep):** The cursor guard early-return in TC104 is removed.
3. **TC107-A..H (interactive PTY):** All 8 watch tests now PASS on live DB — no "PTY dump present"
   fallback; PASS means `test ... ok`, not just observable failure.
4. **TC107-TC104 (interactive PTY):** `test_pager_search_prompt_shows_match_count` reaches its
   `Pattern: DBC` assertion without the early-return guard firing.

**Sprint 68 "PTY dump = acceptable" bar is RETIRED for TC107-A..H.** The cursor fix's purpose is
to make the tests pass. Outcome (b) from Sprint 68 (PTY dump present, test still fails) is FAIL in
Sprint 69 for AC-PTY-2.

## TC107-U01: CPR Responder Mechanism Unit Test

**Requirement:** AC-PTY-1 at the mechanism level — the new harness code correctly synthesises
`ESC[1;1R` when `ESC[6n` is detected.

**BLOCKED condition:** Never blocked. No external dependencies.

**Location:** `tests/common/pty_harness.rs` `#[cfg(test)]` module

**What to test:**

The architect will expose the CPR responder as a testable function. The exact API depends on the
implementation choice, but the test must verify:

1. Input containing `\x1b[6n` produces the response `\x1b[1;1R`.
2. Input NOT containing `\x1b[6n` produces no response (or `None` / empty slice).
3. Input with `\x1b[6n` embedded in other bytes is handled correctly.
4. Multiple `\x1b[6n` occurrences each get a response (if the implementation supports it).

**Function signature (as defined by the architect):**

```rust
pub(crate) fn detect_cpr_query(bytes: &[u8]) -> bool
```

Located in `tests/common/pty_harness.rs`. Returns `true` if `bytes` contains the ANSI cursor-position
request sequence `ESC[6n` (`\x1b[6n`); returns `false` otherwise. The harness calls this function
on bytes read from the PTY master and writes `ESC[1;1R` back when it returns `true`.

**Test code:**

```rust
/// TC107-U01 — detect_cpr_query detects ESC[6n and rejects non-CPR input.
#[test]
fn detect_cpr_query_detects_cursor_position_request() {
    // Case 1: bare CPR sequence — must be detected.
    assert!(
        detect_cpr_query(b"\x1b[6n"),
        "detect_cpr_query must return true for bare ESC[6n"
    );

    // Case 2: no CPR in input — must return false.
    assert!(
        !detect_cpr_query(b"hello world tq>"),
        "detect_cpr_query must return false when ESC[6n is absent"
    );

    // Case 3: CPR embedded in surrounding bytes — must still be detected.
    assert!(
        detect_cpr_query(b"tq> \x1b[6n some text"),
        "detect_cpr_query must return true for embedded ESC[6n"
    );

    // Case 4: similar but different ANSI sequence (ESC[6m, not 6n) — must NOT match.
    assert!(
        !detect_cpr_query(b"\x1b[6m"),
        "detect_cpr_query must return false for ESC[6m (not ESC[6n)"
    );
}
```

**Pass criterion:** All four assertions pass.

**Note:** The function is `pub(crate)` in `tests/common/pty_harness.rs`. Because test helper code
in `tests/common/` is compiled as part of the integration test crate, the unit test can live in
a `#[cfg(test)]` module in `pty_harness.rs` and call `detect_cpr_query` directly (no `use` path
needed beyond the module boundary). If the architect places it in a sub-module, adjust the path
accordingly (e.g., `use super::detect_cpr_query;`).
