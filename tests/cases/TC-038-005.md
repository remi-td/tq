## Purpose

Validate error handling for the `/sysconfig` command:
- Privilege errors produce clear, actionable guidance
- Error messages identify what privilege is needed and how to grant it
- REPL does not crash on database errors

## Acceptance Criteria Coverage

- **AC-7**: Error handling for privilege errors with actionable guidance

## Prerequisites

- Rust test framework for unit tests (no database)
- Live database with insufficient privileges for interactive test (or simulate via test setup)

## Test Procedure

### Unit Tests (no database required)

**Location:** `src/commands/sysconfig.rs` tests module

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_privilege_error_detection() {
        // Test that privilege-related error strings are detected correctly
        let privilege_errors = vec![
            "3523 The user does not have SELECT access to DBC",
            "GRANT SELECT privilege required",
            "access denied",
            "permission denied",
        ];

        for err_msg in privilege_errors {
            assert!(
                is_privilege_error(err_msg),
                "Should detect privilege error in: {}",
                err_msg
            );
        }
    }

    #[test]
    fn test_non_privilege_error_not_detected() {
        let non_privilege_errors = vec![
            "syntax error",
            "network timeout",
            "connection refused",
        ];

        for err_msg in non_privilege_errors {
            // A network error or syntax error should not be flagged as privilege error
            // (though it may be - this validates we don't over-classify)
            let _ = is_privilege_error(err_msg); // Should not panic
        }
    }

    #[test]
    fn test_privilege_error_message_mentions_dbc_view() {
        let mut output = Vec::new();
        write_privilege_error_guidance(&mut output).unwrap();
        let s = String::from_utf8(output).unwrap();

        // Must mention the relevant DBC view(s)
        assert!(
            s.contains("DBC") || s.contains("DBCInfoV"),
            "Privilege error message must mention the relevant DBC view. Got: {}",
            s
        );
    }

    #[test]
    fn test_privilege_error_message_includes_grant_syntax() {
        let mut output = Vec::new();
        write_privilege_error_guidance(&mut output).unwrap();
        let s = String::from_utf8(output).unwrap();

        // Must include GRANT keyword or equivalent instruction
        assert!(
            s.contains("GRANT") || s.contains("grant") || s.to_lowercase().contains("dba"),
            "Privilege error message must include how to grant access. Got: {}",
            s
        );
    }
}
```

### Interactive Test (live database, #[ignore])

**Location:** `tests/interactive_tests.rs` (append)

```rust
#[test]
#[ignore] // Requires live database: cargo test -- --ignored --test-threads=1
fn test_sysconfig_privilege_error_shows_guidance() {
    // This test validates that when privilege errors occur, the REPL shows
    // actionable guidance rather than a raw error code.
    // NOTE: This test is best validated manually with a restricted user account.
    // With a DBA account, /sysconfig succeeds - this test validates the output format.
    let mut p = spawn_tq_repl();

    p.expect("Connected to").expect("Failed to connect to database");
    std::thread::sleep(Duration::from_millis(1000));

    p.send_line("/sysconfig").expect("Failed to send /sysconfig");
    std::thread::sleep(Duration::from_millis(3000));

    let output = p.read_until_prompt().unwrap_or_default();
    let output_str = String::from_utf8_lossy(&output);

    // Either:
    // (a) Command succeeds (DBA account) - output has data
    // (b) Command fails with privilege error - output has guidance
    // In both cases the REPL must return to prompt (no crash, no hang)

    // The REPL must not hang - if we got here, prompt returned
    assert!(
        !output_str.is_empty(),
        "/sysconfig must produce some output (data or error message)"
    );

    // If it's an error, must contain actionable guidance
    if output_str.to_lowercase().contains("error") || output_str.to_lowercase().contains("privilege") {
        assert!(
            output_str.contains("GRANT") || output_str.contains("DBA") ||
            output_str.to_lowercase().contains("required"),
            "Privilege error must include actionable guidance. Got: {}",
            output_str
        );
    }

    p.send_line("/quit").expect("Failed to quit REPL");
    std::thread::sleep(Duration::from_millis(500));
}
```

## Expected Results

### Unit Tests:
- Privilege error detection correctly identifies access-related errors
- Privilege error message contains "DBC" or "DBCInfoV"
- Privilege error message includes GRANT syntax or DBA instruction

### Interactive Test:
- `/sysconfig` produces output (data or error message) - no hang
- If error occurs: message includes actionable guidance

## Pass/Fail Criteria

**PASS if:**
- Unit tests detect privilege error strings correctly
- Error message references the relevant DBC view
- Error message explains how to resolve the issue
- REPL does not crash or hang on any error

**FAIL if:**
- Privilege error produces raw error code with no guidance
- Error message missing GRANT syntax or explanation
- REPL hangs or crashes on database error

## Notes

- Unit tests run without database (no `#[ignore]`)
- Interactive test runs with database but validates both success and error paths
- For full privilege error testing: requires a restricted user account (manual setup)
- Pattern follows `sessions.rs` privilege error handling (established in Sprint 26)
