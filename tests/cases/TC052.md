# Test Case TC052: Tab Completion - Error Messages When Metadata Query Fails

## Purpose

Verify that when metadata queries fail (permissions, timeout, connection lost), clear error messages are shown to the user instead of silent failure.

## Prerequisites

- tq REPL mode active
- Ability to simulate failure conditions (or test with restricted permissions)

## Test Procedure

### Scenario 1: Permission Denied on DBC.TablesV

If user lacks SELECT on DBC.TablesV:

```sql
tq> SELECT * FROM <TAB>
```

**Expected:**
```
Warning: Cannot load table list (permission denied to DBC.TablesV)
Tab completion for tables unavailable.

Suggestion: Contact DBA to grant SELECT on DBC.TablesV
```

### Scenario 2: Connection Lost

Disconnect database (if possible) or test with connection that times out:

```sql
tq> SELECT * FROM <TAB>
```

**Expected:**
```
Error: Connection lost. Cannot retrieve table list.

Suggestion: Use /ping to check connection or /logon to reconnect.
```

### Scenario 3: Query Timeout

If metadata query takes >500ms (timeout threshold):

```sql
tq> SELECT * FROM <TAB>
```

**Expected:**
```
Warning: Table list query timed out after 500ms
Tab completion for tables unavailable.

Suggestion: Database may be slow. Try again or continue typing manually.
```

### Scenario 4: Empty Database

Connect to database with no tables:

```sql
tq> SELECT * FROM <TAB>
```

**Expected:**
```
(No tables found in current database)

Suggestion: Check you're connected to the correct database with /session
```

## Verification

For each error scenario:
- [ ] Error message is displayed to user (not just logged)
- [ ] Message clearly explains what went wrong
- [ ] Message provides actionable suggestion
- [ ] User can continue using REPL (not crashed)
- [ ] User can type table names manually (completion just unavailable)

## Pass/Fail Criteria

**PASS:**
- All error conditions display clear messages
- Messages include suggestions for resolution
- User is informed why completion failed
- REPL remains usable

**FAIL:**
- Silent failure (Tab does nothing, no error shown) ← CURRENT BUG
- Cryptic error messages
- Error causes crash or hang
- No guidance on how to resolve

## Notes

From sprint-8-root-cause-analysis.md:
> "Errors are logged and stored in `last_error`, but `last_error` is never displayed to the user during completion."

The fix must:
1. Detect metadata query failures
2. Display error to user (not just log)
3. Provide helpful suggestions
4. Allow user to continue (graceful degradation)
