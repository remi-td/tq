## Overview

These tests validate the tiered-timeout PTY harness introduced in Sprint 66. The harness
replaces the single flat `expect_timeout` in `spawn_tq_repl()` with three named tiers
(connect/auth, prompt-ready, query-result), environment-variable overrides for each tier,
a `PtyError` enum with one variant per tier, and a `dump_pty_buffer()` function that
writes the last 4096 bytes of the PTY read buffer to a file on timeout.

Unit tests (TC-66-U01..U04) live inside `tests/common/pty_harness.rs` under
`#[cfg(test)]` and require no database or PTY. The interactive regression (TC-66-I01)
lives in `tests/interactive_tests.rs`, is marked `#[ignore]`, and requires a live
Teradata endpoint configured via `TQ_LOGON`.

## TC-66-U01: `Timeouts` defaults

**Requirement:** F1-AC-1 — `spawn_tq_repl()` accepts three named timeout tiers with
specified defaults: connect/auth = 45 s, prompt-ready = 15 s, query-result = 60 s.

**Location:** `tests/common/pty_harness.rs`, `#[cfg(test)]`

```rust
#[test]
fn tiered_timeouts_default_values() {
    // Ensure env overrides are absent so defaults are used.
    // Safety: single-threaded test environment assumed for env mutation.
    std::env::remove_var("TQ_TEST_CONNECT_TIMEOUT");
    std::env::remove_var("TQ_TEST_PROMPT_TIMEOUT");
    std::env::remove_var("TQ_TEST_QUERY_TIMEOUT");

    let t = Timeouts::from_env();

    assert_eq!(t.connect, Duration::from_secs(45), "connect default must be 45 s");
    assert_eq!(t.prompt, Duration::from_secs(15), "prompt default must be 15 s");
    assert_eq!(t.query, Duration::from_secs(60), "query default must be 60 s");
}
```

**Pass criteria:** `connect == 45s`, `prompt == 15s`, `query == 60s`. Note: actual struct stores `Duration` fields named `connect`, `prompt`, `query` (not `*_secs: u64`). The test-code here uses the shipped shape.

## TC-66-U03: `dump_pty_buffer()` writes last 4096 bytes

**Requirement:** F1-AC-3 — on ANY expect timeout the last 4096 bytes of the PTY read
buffer are written to `tests/results/sprint-66/<test_name>.pty.log`.

This unit test validates the dump function directly with synthesised bytes, without a PTY.

**Location:** `tests/common/pty_harness.rs`, `#[cfg(test)]`

**Prerequisite:** `tempfile` in `[dev-dependencies]` (add if absent).

```rust
#[test]
fn dump_pty_buffer_writes_last_4096_bytes() {
    // Synthesise 8000 bytes: first 3904 bytes = 0xAA, last 4096 bytes = 0xBB
    let mut input: Vec<u8> = vec![0xAAu8; 3904];
    input.extend(vec![0xBBu8; 4096]);
    assert_eq!(input.len(), 8000);

    let dir = tempfile::tempdir().expect("tempdir failed");
    let path = dir.path().join("test_dump.pty.log");

    dump_pty_buffer(&input, &path).expect("dump_pty_buffer must not fail");

    let written = std::fs::read(&path).expect("dump file must exist after call");

    // Must not exceed 4096 bytes
    assert!(
        written.len() <= 4096,
        "dump must write at most 4096 bytes; wrote {}",
        written.len()
    );

    // Content must be the tail (all 0xBB for this input)
    let expected = &input[input.len() - written.len()..];
    assert_eq!(
        written, expected,
        "dump must contain the tail bytes of the input buffer"
    );
}
```

**Pass criteria:** File exists, `len <= 4096`, content equals tail of input.

## TC-66-U04: Environment overrides are parsed correctly

**Requirement:** F1-AC-4 — `TQ_TEST_CONNECT_TIMEOUT`, `TQ_TEST_PROMPT_TIMEOUT`,
`TQ_TEST_QUERY_TIMEOUT` override the defaults when set.

**Location:** `tests/common/pty_harness.rs`, `#[cfg(test)]`

```rust
#[test]
fn tiered_timeouts_env_overrides() {
    // Set overrides
    std::env::set_var("TQ_TEST_CONNECT_TIMEOUT", "90");
    std::env::set_var("TQ_TEST_PROMPT_TIMEOUT",  "30");
    std::env::set_var("TQ_TEST_QUERY_TIMEOUT",   "120");

    let t = Timeouts::from_env();

    // Restore immediately to avoid cross-test pollution
    std::env::remove_var("TQ_TEST_CONNECT_TIMEOUT");
    std::env::remove_var("TQ_TEST_PROMPT_TIMEOUT");
    std::env::remove_var("TQ_TEST_QUERY_TIMEOUT");

    assert_eq!(t.connect, Duration::from_secs(90),  "TQ_TEST_CONNECT_TIMEOUT=90 must override default");
    assert_eq!(t.prompt,  Duration::from_secs(30),  "TQ_TEST_PROMPT_TIMEOUT=30 must override default");
    assert_eq!(t.query,   Duration::from_secs(120), "TQ_TEST_QUERY_TIMEOUT=120 must override default");
}
```

**Pass criteria:** All three fields equal the env-var values, not the defaults.

**Requirement:** F1-AC-5 — at least one existing interactive test is updated to use the

**Location:** `tests/interactive_tests.rs`

```rust

#[ignore] // Requires live Teradata database (TQ_LOGON) + PTY
fn test_repl_startup_and_quit() {
    // spawn_tq_repl() now uses Timeouts internally.
    // This test is the migration proof required by F1-AC-5.
    let mut p = spawn_tq_repl();

    // Stage 1: connect/auth — must complete within connect timeout (default 45 s)
    p.expect("Connected to")
        .expect("ConnectTimeout: tq did not print 'Connected to' within connect timeout");

    // Stage 2: prompt-ready — REPL prompt must appear within prompt timeout (default 15 s)
    p.expect(expectrl::Regex("tq>|tq >"))
        .expect("PromptTimeout: REPL prompt did not appear within prompt timeout");

    // Stage 3: clean exit
    p.send_line("/quit").expect("Failed to send /quit");

    p.expect("Goodbye")
        .expect("QueryTimeout: 'Goodbye' not received within query timeout");
}
```

**Pass criteria:** All three `expect()` calls succeed; no `PtyError` abort; on failure,
a `.pty.log` file is written to `tests/results/sprint-66/` and the failure message
references it.

## Implementation Notes

1. The unit tests (TC-66-U01..U04) live **inside** `tests/common/pty_harness.rs` under
   `#[cfg(test)]`. The architect owns the implementation; these test cases specify
   the exact assertions to validate against.
2. `dump_pty_buffer` must be a public function (pub or pub(crate)) reachable from the
   unit test module. If it is a closure inlined into the error handler, the unit test
   cannot call it — the architect must extract it.
3. `Timeouts::from_env()` must be a standalone constructor so TC-66-U01 and
   TC-66-U04 can call it without constructing a full PTY session.
4. TC-66-U04 mutates env vars. Rust test runner runs tests in parallel threads by default.
   If this causes flakiness, run with `-- --test-threads=1` or use a mutex guard.
5. `tempfile` crate: required by TC-66-U03. Confirm it is in `[dev-dependencies]` in
   `Cargo.toml`; if not, the architect must add it before TC-66-U03 compiles.
6. TC-66-I01 is the migration of `test_repl_startup_and_quit`. The architect performs
   the migration; the QA test case above is the specification of what "migrated and
   passing" means.
7. The `.pty.log` dump path (`tests/results/sprint-66/<test_name>.pty.log`) must be
   created by the harness even if the directory does not yet exist — the harness should
   call `std::fs::create_dir_all` on the parent before writing.
