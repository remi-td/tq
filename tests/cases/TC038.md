## Purpose

Verify that /logon handles connection failures gracefully, preserving the existing connection when the new connection attempt fails.

## Scope

This test validates:
- Connection failure error handling
- Old connection preserved on failure
- Clear error messages
- Helpful troubleshooting suggestions
- REPL remains functional after failure
- Different failure modes handled

## Prerequisites

- tq binary built in release mode
- Valid working connection to start REPL
- Ability to provide invalid connection details

## Test Procedure

### Step 1: Start REPL with valid connection
```bash
tq -l "user:pass@goodhost:1025/gooddb" repl
```

### Step 2: Verify current connection works
```sql
tq[gooddb]> SELECT 1 AS test;
```

### Step 3: Attempt connection to invalid host
```sql
tq[gooddb]> /logon user:pass@invalidhost:1025/db
```

**Expected behavior:**
- Connection attempt fails
- Error message displayed
- Old connection preserved
- Prompt still shows [gooddb]

### Step 4: Verify old connection still works
```sql
tq[gooddb]> SELECT 2 AS test;
```

### Step 5: Attempt connection with wrong password
```sql
tq[gooddb]> /logon user:wrongpass@goodhost:1025/gooddb
```

**Expected behavior:**
- Authentication fails
- Clear error message
- Old connection preserved

### Step 6: Attempt connection to nonexistent database
```sql
tq[gooddb]> /logon user:pass@goodhost:1025/nonexistent
```

**Expected behavior:**
- Database not found error
- Old connection preserved

### Step 7: Attempt connection with invalid format
```sql
tq[gooddb]> /logon invalid-format
```

**Expected behavior:**
- Invalid format error
- Shows expected format
- Examples provided

### Step 8: Verify /logon shows original connection
```sql
tq[gooddb]> /logon
```

**Expected behavior:**
- Still shows gooddb connection details

## Pass/Fail Criteria

**PASS if:**
- All connection failures handled gracefully
- Old connection preserved on failure
- Clear, specific error messages
- Helpful troubleshooting suggestions
- REPL continues working after failures
- No crashes or hangs
- Prompt unchanged on failure
- Invalid format caught early

**FAIL if:**
- REPL crashes on connection failure
- Old connection lost
- User left in disconnected state
- Error messages unclear or unhelpful
- Hangs on connection timeout
- No recovery possible

## Notes

- Error handling critical for production use
- Users will frequently mistype connection strings
- Network issues common in enterprise environments
- Preserving old connection is key requirement
- Timeout should be reasonable (30s max)
- Different error types need different messages
