# Test Case TC062: Result Paging - Exit Pager with q or Esc

## Purpose

Verify that the pager can be exited cleanly using 'q' or 'Esc' keys, restoring terminal to normal mode and returning to REPL prompt.

## Prerequisites

- tq REPL mode active
- Pager enabled
- Large query result

## Test Procedure

### Step 1: Activate pager

```sql
tq> SELECT TOP 100 * FROM DBC.TablesV;
```

### Step 2: Exit with 'q' key

Press 'q'

**Expected:**
- Pager exits immediately
- Terminal returns to normal mode
- REPL prompt appears: `tq>`
- No artifacts or corrupted display
- Can execute next command immediately

### Step 3: Test exit with 'Esc' key

```sql
tq> SELECT TOP 100 * FROM DBC.TablesV;
```

Press 'Esc'

**Expected:**
- Pager exits (same behavior as 'q')
- Clean return to REPL prompt

### Step 4: Verify terminal restoration

After exiting pager, check:
- Terminal is in normal mode (not raw mode)
- Cursor is visible
- Typing shows characters normally
- Terminal dimensions correct
- No scrollback corruption

Execute a simple query:
```sql
tq> SELECT 1 AS test;
```

**Expected:**
- Query executes normally
- Output displays correctly
- No lingering pager effects

### Step 5: Test exit from different pager positions

**At beginning:**
```sql
tq> SELECT TOP 100 * FROM DBC.TablesV;
[Immediately press 'q']
```

**In middle:**
```sql
tq> SELECT TOP 100 * FROM DBC.TablesV;
[Press 'j' several times, then 'q']
```

**At end:**
```sql
tq> SELECT TOP 100 * FROM DBC.TablesV;
[Press PageDown to end, then 'q']
```

**Expected:**
- Exit works from any position
- No difference in terminal restoration
- Clean exit every time

## Verification

**Exit Functionality:**
- [ ] 'q' exits pager
- [ ] 'Esc' exits pager
- [ ] Exit is immediate (<100ms)
- [ ] No confirmation prompt needed

**Terminal Restoration:**
- [ ] Terminal in normal mode (not raw mode)
- [ ] Cursor visible
- [ ] Typing works normally
- [ ] REPL prompt appears correctly
- [ ] No visual artifacts

**State Restoration:**
- [ ] Can execute new queries
- [ ] REPL is fully functional
- [ ] No "stuck" state
- [ ] Terminal dimensions correct

**Error Handling:**
- [ ] Ctrl+C also exits pager (if implemented)
- [ ] Exit works even if pager is in error state
- [ ] No way to get "stuck" in pager

## Expected Results

**Sequence:**
```
tq> SELECT TOP 100 * FROM DBC.TablesV;
[Pager displays results]
[User presses 'q']
tq> [Clean prompt, ready for next command]
```

**Terminal State After Exit:**
- Normal input mode restored
- Cursor blinking at prompt
- No pager UI elements visible
- Scrollback intact (query output visible if scrolled back)

## Pass/Fail Criteria

**PASS:**
- Both 'q' and 'Esc' exit pager
- Exit is clean and immediate
- Terminal fully restored
- REPL ready for next command
- Works from any pager position

**FAIL:**
- Can't exit pager (stuck)
- Exit crashes or hangs
- Terminal corrupted after exit
- REPL not responsive after exit
- Need to restart tq to recover

## Notes

This is a CRITICAL test because users must be able to exit the pager reliably. A broken exit mechanism makes the tool unusable.

**Terminal Mode Management:**

Proper cleanup sequence:
1. Capture exit key ('q' or 'Esc')
2. Exit keyboard event loop
3. Restore terminal mode (from raw to normal)
4. Clear pager UI
5. Return to REPL prompt

Using crossterm:
```rust
// On enter pager
crossterm::terminal::enable_raw_mode()?;

// On exit pager
crossterm::terminal::disable_raw_mode()?;
```

**Panic Safety:**

Exit should work even if pager panics:
- Use defer/RAII pattern for terminal restoration
- Ensure raw mode is disabled even on error
- Catch panics and restore terminal before propagating

**Ctrl+C Handling:**

While in pager, Ctrl+C should:
- Exit pager (same as 'q')
- NOT exit entire tq process
- Restore terminal
- Return to REPL prompt

This requires signal handling or keyboard event loop that treats Ctrl+C specially.
