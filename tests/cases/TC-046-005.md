## Purpose

Verify that the three new subcommands (`tq describe`, `tq list`, `tq show-indexes`) appear in `tq --help`, and that their individual `--help` output contains the `--format` flag. Also verify that missing required arguments produce informative error messages with non-zero exit codes.

These tests run without a database connection by spawning the `tq` binary with `--help` or invalid arguments.

## Acceptance Criteria Coverage

- **AC-7**: All new commands appear in `tq --help` and `tq help`
- **AC-6**: All new commands support `--format table|csv|json` flag (help-text evidence)

## Prerequisites

- `tq` binary compiled (`cargo build`)
- No database connection needed

## Test Procedure

### Test Implementation (in `tests/cli_commands_46.rs`)

```rust
use std::process::Command;

fn tq_bin() -> std::path::PathBuf {
    let mut path = std::env::current_exe().expect("current exe path");
    path.pop();
    path.pop();
    path.push("tq");
    path
}

// TC-046-005-A: tq --help contains all three new command names
#[test]
fn test_global_help_contains_new_commands() {
    let output = Command::new(tq_bin())
        .arg("--help")
        .output()
        .expect("Failed to run tq --help");

    let stdout = String::from_utf8_lossy(&output.stdout);
    assert!(
        stdout.contains("describe"),
        "tq --help missing 'describe'\n{}", stdout
    );
    assert!(
        stdout.contains("list"),
        "tq --help missing 'list'\n{}", stdout
    );
    assert!(
        stdout.contains("show-indexes"),
        "tq --help missing 'show-indexes'\n{}", stdout
    );
}

// TC-046-005-B: tq describe --help shows --format flag
#[test]
fn test_describe_help_shows_format_flag() {
    let output = Command::new(tq_bin())
        .args(["describe", "--help"])
        .output()
        .expect("Failed to run tq describe --help");

    let stdout = String::from_utf8_lossy(&output.stdout);
    assert!(
        stdout.contains("--format") || stdout.contains("format"),
        "tq describe --help missing '--format'\n{}", stdout
    );
    // Should mention the valid format values
    assert!(
        stdout.contains("json") || stdout.contains("csv") || stdout.contains("table"),
        "tq describe --help missing format values\n{}", stdout
    );
}

// TC-046-005-C: tq list --help shows databases/tables/views subcommands
#[test]
fn test_list_help_shows_subcommands() {
    let output = Command::new(tq_bin())
        .args(["list", "--help"])
        .output()
        .expect("Failed to run tq list --help");

    let stdout = String::from_utf8_lossy(&output.stdout);
    assert!(
        stdout.contains("databases"),
        "tq list --help missing 'databases'\n{}", stdout
    );
    assert!(
        stdout.contains("tables"),
        "tq list --help missing 'tables'\n{}", stdout
    );
    assert!(
        stdout.contains("views"),
        "tq list --help missing 'views'\n{}", stdout
    );
}

// TC-046-005-D: tq show-indexes --help shows --format flag
#[test]
fn test_show_indexes_help_shows_format_flag() {
    let output = Command::new(tq_bin())
        .args(["show-indexes", "--help"])
        .output()
        .expect("Failed to run tq show-indexes --help");

    let stdout = String::from_utf8_lossy(&output.stdout);
    assert!(
        stdout.contains("--format") || stdout.contains("format"),
        "tq show-indexes --help missing '--format'\n{}", stdout
    );
}

// TC-046-005-E: tq describe (no table) exits non-zero with error message
#[test]
fn test_describe_missing_table_exits_nonzero() {
    let output = Command::new(tq_bin())
        .arg("describe")
        .output()
        .expect("Failed to run tq describe");

    assert!(
        !output.status.success(),
        "Expected non-zero exit code when table argument is missing"
    );
    // Error output should mention the required argument or usage
    let stderr = String::from_utf8_lossy(&output.stderr);
    let stdout = String::from_utf8_lossy(&output.stdout);
    let combined = format!("{}{}", stderr, stdout);
    assert!(
        combined.contains("TABLE") || combined.contains("table") || combined.contains("required") || combined.contains("Usage"),
        "Expected error about missing argument\ncombined: {}", combined
    );
}

// TC-046-005-F: tq list (no subcommand) exits non-zero or shows usage
#[test]
fn test_list_missing_subcommand_exits_nonzero() {
    let output = Command::new(tq_bin())
        .arg("list")
        .output()
        .expect("Failed to run tq list");

    // Either exit non-zero (clap error) or exit 0 with usage (if list prints help)
    // Either way, output must contain meaningful information about subcommands
    let stderr = String::from_utf8_lossy(&output.stderr);
    let stdout = String::from_utf8_lossy(&output.stdout);
    let combined = format!("{}{}", stderr, stdout);
    assert!(
        combined.contains("databases") || combined.contains("tables") || combined.contains("Usage") || combined.contains("error"),
        "Expected subcommand guidance\ncombined: {}", combined
    );
}
```

## Pass/Fail Criteria

**PASS if:**
- All 6 tests pass with `cargo test --test cli_commands_46`
- New commands visible in global help
- Individual command help shows `--format` flag
- Missing arguments produce non-zero exit and informative error

**FAIL if:**
- "describe", "list", or "show-indexes" absent from `tq --help` — commands not registered
- `--format` absent from per-command help — flag not defined on new commands
- `tq describe` exits 0 with no argument — missing required argument constraint

## Notes

- These tests spawn the actual `tq` binary. `cargo build` must be run before `cargo test --test` if using a separate integration test file.
- Alternatively, the tests can be compiled into the main test binary using `tests/integration_tests.rs`.
- clap v4 by default writes errors to stderr and usage to stdout when `--help` is used. The assertions check both streams via `combined` for robustness.
- The `tq_bin()` helper locates the binary next to the test binary in the Cargo target directory. This works with `cargo test` when the workspace is configured correctly.
