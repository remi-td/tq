### Corrections made during implementation (relative to the original strategy wording)

- **TC110-I08 scope narrowed.** The strategy doc's original phrasing ("regardless of `--color` flag
  value") does not match the actual `ColorChoice::should_use_color()` implementation
  (`src/cli.rs:1497`): `Always` unconditionally returns `true` and never consults `NO_COLOR`; only
  the `Auto` branch checks it. `NO_COLOR` suppression is therefore verified against the *default*
  (`Auto`) mode only, matching TC110-U20 exactly. An explicit `--color always` intentionally
  overriding `NO_COLOR` is standard CLI convention, not a bug, and is exercised (color present) by
  TC110-I02/I04 instead.
- **TC110-I05/I06 moved from plain subprocess to PTY.** `run_watch` (`src/commands/watch.rs`) calls
  `crossterm::terminal::enable_raw_mode()`, which fails immediately against a piped (non-TTY)
  subprocess. Both tests spawn through `expectrl::Session::spawn(std::process::Command)` instead,
  mirroring the existing PTY pattern in `tests/interactive_tests.rs`'s
  `/sessions --watch` tests, and assert on watch-frame text content rather than wall-clock refresh
  timing (more deterministic than counting refresh cycles under CI timing variance).

### File-only config (Phase 2 ruling #4)

No test in this file sets a `TQ_MONITORING_*` environment variable — `[monitoring]` is file-only by
design (`Env::prefixed("TQ_").split("_")` cannot round-trip keys that themselves contain
underscores, e.g. `cpu_warning`). All threshold/color fixtures are written to `.tq.toml` via
`tests/helpers/mod.rs::create_project_config`.
