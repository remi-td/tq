## Purpose

Verify that tq correctly handles NULL values across different output formats with proper type preservation.

## Scope

This test validates:
- NULL representation in table format
- NULL representation in JSON format
- NULL representation in CSV format
- Visual distinction in table output
- Proper JSON null (not string "null")

## Prerequisites

- tq binary is built and available
- `.env` file configured with valid Teradata connection credentials

## Test Procedure

### Step 1: NULL in table format
```bash
# Using credentials from .env file
tq query "SELECT 'Alice' AS name, NULL AS middle_name, 'Smith' AS last_name"
```

### Step 2: NULL in JSON format
```bash
tq query --format json "SELECT 1 AS id, NULL AS field, 'test' AS name"
```

### Step 3: NULL in CSV format
```bash
tq query --format csv "SELECT 'a' AS col1, NULL AS col2, 'c' AS col3"
```

### Step 4: Multiple NULLs
```bash
tq query --format json "SELECT NULL AS a, NULL AS b, NULL AS c"
```

### Step 5: Mixed types with NULL
```bash
tq query --format json "SELECT 1 AS num, NULL AS empty, true AS bool, 'text' AS str"
```

### Step 6: Validate JSON null with jq
```bash
tq query --format json "SELECT NULL AS field" | jq '.[0].field'
```

## Expected Results

### Step 1 Output:
```
+-------+-------------+-----------+
| name  | middle_name | last_name |
+-------+-------------+-----------+
| Alice | [NULL]      | Smith     |
+-------+-------------+-----------+
1 row(s) in set (X.XXXs)
```
- NULL displayed as [NULL] or similar distinct marker
- Potentially grayed out or styled differently
- Clearly distinguishable from empty string

### Step 2 Output:
```json
[
  {
    "id": 1,
    "field": null,
    "name": "test"
  }
]
```
- JSON null (not string "null" or "NULL")
- Valid JSON syntax

### Step 3 Output:
```csv
col1,col2,col3
a,,c
```
- Empty field for NULL (RFC 4180 compliant)
- Not the string "NULL"

### Step 4 Output:
```json
[
  {
    "a": null,
    "b": null,
    "c": null
  }
]
```
All fields are JSON null

### Step 5 Output:
```json
[
  {
    "num": 1,
    "empty": null,
    "bool": true,
    "str": "text"
  }
]
```
Mixed types preserved, NULL is null

### Step 6 Output:
```
null
```
jq recognizes it as null value, not string

## Pass/Fail Criteria

**PASS if:**
- NULL is visually distinct in table format
- JSON output uses actual null (not string)
- CSV output uses empty field for NULL
- NULL is distinguishable from empty string
- jq correctly parses JSON null
- Consistent NULL handling across formats

**FAIL if:**
- NULL not distinguishable from empty string
- JSON uses string "null" instead of null
- CSV uses "NULL" string instead of empty
- Inconsistent handling across formats
- Invalid JSON due to NULL handling

## Notes

- NULL handling is critical for data accuracy
- Different formats have different conventions:
  - Table: [NULL] or similar visual marker
  - JSON: null keyword
  - CSV: empty field (no quotes)
- NULL ≠ empty string in databases
- Some databases distinguish NULL from empty string
- Consider testing with various data types (numeric NULL, date NULL, etc.)
