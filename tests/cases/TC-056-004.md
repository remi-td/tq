### Part A: Unit Tests for `markdown_escape_pipe()` (in `src/commands/format_helpers.rs`)

Add to the existing `#[cfg(test)]` block in `format_helpers.rs`:

```rust
// markdown_escape_pipe tests
#[test]
fn test_markdown_escape_pipe_basic() {
    assert_eq!(markdown_escape_pipe("hello|world"), "hello\\|world");
}

#[test]
fn test_markdown_escape_pipe_no_pipe() {
    assert_eq!(markdown_escape_pipe("hello world"), "hello world");

    assert_eq!(markdown_escape_pipe(""), "");

```

### Part B: Unit Tests for REPL `/search` Dispatch (in `src/commands/search.rs`)

The `execute_for_repl` function dispatches on subcommand string. Since it requires a `DatabaseClient`, we test with a mock writer to verify the routing produces expected header text or error message. If the function requires a live DB to produce output, we test the error branch (unknown alias) without DB and mark DB-requiring routing tests as `#[ignore]`.

**Alternative approach (preferred):** Extract dispatch logic into a pure `resolve_search_subcommand(subcommand: &str) -> Option<SearchObjectType>` helper function and test that directly without DB.

```rust
// In src/commands/search.rs tests:

#[test]
fn test_dispatch_table_aliases() {
    // If resolve_search_subcommand() helper exists:
    assert_eq!(resolve_search_subcommand("table"), Some(SearchObjectType::Tables));
    assert_eq!(resolve_search_subcommand("tables"), Some(SearchObjectType::Tables));
    assert_eq!(resolve_search_subcommand("t"), Some(SearchObjectType::Tables));
}

#[test]
fn test_dispatch_column_aliases() {
    assert_eq!(resolve_search_subcommand("column"), Some(SearchObjectType::Columns));
    assert_eq!(resolve_search_subcommand("columns"), Some(SearchObjectType::Columns));
    assert_eq!(resolve_search_subcommand("col"), Some(SearchObjectType::Columns));
    assert_eq!(resolve_search_subcommand("c"), Some(SearchObjectType::Columns));
}

#[test]
fn test_dispatch_unknown_alias() {
    assert_eq!(resolve_search_subcommand("foobar"), None);
}
```
