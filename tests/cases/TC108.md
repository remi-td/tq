# TC108: Composed Search Status Bar Unit Tests (Sprint 69, Objective 2)

**Sprint:** 69
**Feature:** Objective 2 — Pager search status bar position context: `Pattern: <pat>  (M matches)  |  Rows X-Y of Z`
**Component:** `src/commands/repl/pager.rs`
**Test Type:** Unit tests (no DB, no PTY) — `render_status_bar_to_buffer`
**Related Strategy:** `tests/strategy/sprint-69-strategy.md` — Objective 2
**Specification:** `docs/specifications/repl.md` — REQ-PAGER-SEARCH-009.2 through 009.7

---

## Overview

Sprint 69 updates `render_status_bar_to_buffer` to produce a composed status bar when a search is
active. Instead of just `Pattern: <pat>  (M matches)`, the wide-terminal format is:

```
Pattern: <pat>  (M matches)  |  Rows X-Y of Z
```

Where `  |  ` is the separator (two spaces, pipe, two spaces) and `Rows X-Y of Z` is the compact
row context without a percentage. When the terminal is too narrow to show the full string (by the
rule `full_composed_width > terminal_width - 2`), the row context is dropped entirely.

This test case provides 7 unit tests (TC108-U01..U07) covering the composition rule and its edge
cases, plus a maintenance check confirming that existing pre-Sprint-69 status bar unit tests still
pass after the implementation change.

All tests use the existing `status_bar_to_string(pager: &Pager) -> String` helper and
`make_pager_with_data(rows, page_size)` fixture already in `src/commands/repl/pager.rs #[cfg(test)]`.

## TC108-U01: Full Composed Format on Wide Terminal

**Requirement:** REQ-PAGER-SEARCH-009.3 — full composed string when width fits.

**Location:** `src/commands/repl/pager.rs` `#[cfg(test)]`

**Test code:**

```rust
#[test]
fn status_bar_search_active_shows_composed_with_row_context() {
    // REQ-PAGER-SEARCH-009.3: full composed string on a wide terminal.
    // REQ-PAGER-SEARCH-009.7: no column range in search-active status.
    let mut pager = make_pager_with_data(50, 20);
    pager.term_width = 120; // Wide enough for full composed string.
    pager.submit_search("val_");  // Matches multiple cells -> "matches" plural

    let out = status_bar_to_string(&pager);

    // Full composed string present.
    assert!(
        out.contains("Pattern: val_  (") && out.contains("  |  Rows "),
        "Wide terminal must show full composed format: {:?}", out
    );
    // Row context format: compact, no percentage.
    assert!(
        out.contains("Rows 1-20 of 50"),
        "Row context must be 'Rows X-Y of Z': {:?}", out
    );
    // No column range in search-active state (REQ-PAGER-SEARCH-009.7).
    assert!(
        !out.contains("Columns"),
        "Search-active status must not include Columns range: {:?}", out
    );
}
```

**Pass criterion:** All three assertions pass.

## TC108-U02: Separator Is Exactly `  |  ` (Two Spaces Pipe Two Spaces)

**Requirement:** REQ-PAGER-SEARCH-009.3 — separator between search and row segments.

**Test code:**

```rust
#[test]
fn status_bar_search_composed_separator_exact() {
    // REQ-PAGER-SEARCH-009.3: separator is "  |  " (2 space, pipe, 2 space).
    let mut pager = make_pager_with_data(50, 20);
    pager.term_width = 120;
    pager.submit_search("val_");

    let out = status_bar_to_string(&pager);

    assert!(
        out.contains("  |  Rows"),
        "Separator must be exactly '  |  ' (two spaces, pipe, two spaces): {:?}", out

    // Ensure it is NOT single-space variants.
    assert!(
        !out.contains(" | Rows") || out.contains("  |  Rows"),
        "Must not use single-space separator: {:?}", out
    );
}
```

**Note:** The second assert is lenient — if `"  |  Rows"` is present, the single-space variant
check is redundant. The test captures the intent: the spec says `  |  ` not ` | `.

## TC108-U04: Row Context Dropped When Full Composed String Exceeds `terminal_width - 2`

**Requirement:** REQ-PAGER-SEARCH-009.4 — row context dropped entirely (not partially shown).

**Fixture design:**
- `term_width = 30`
- Pattern `"val_"` with a fixture that has enough matches to confirm composition
- `make_pager_with_data(50, 10)` → total rows 50, page_size 10
- Full composed = `Pattern: val_  (N matches)  |  Rows 1-10 of 50` ≈ 47+ chars
- `term_width - 2 = 28` → full composed does NOT fit → row context dropped
- Search segment = `Pattern: val_  (N matches)` ≈ 26 chars → fits within 28

**Test code:**

```rust
#[test]
fn status_bar_search_narrow_drops_row_context_entirely() {
    // REQ-PAGER-SEARCH-009.4: row context dropped entirely when full composed
    // string exceeds terminal_width - 2. Row context is never partially shown.
    let mut pager = make_pager_with_data(50, 10);
    pager.term_width = 30; // Too narrow for full composed string.
    pager.submit_search("val_");

    let out = status_bar_to_string(&pager);

    // Search segment must still be present.
    assert!(
        out.contains("Pattern: val_  ("),
        "Narrow terminal must still show search segment: {:?}", out
    );
    // Row context must be absent entirely.
    assert!(
        !out.contains("  |  Rows") && !out.contains("Rows "),
        "Narrow terminal must NOT show any row context: {:?}", out
    );
}
```

**Important calibration note for the architect:** `make_pager_with_data(50, 10)` must produce a
pager where `visible_column_count()` is sane for `term_width = 30`. The status bar renderer uses
`term_width` from `pager.term_width` directly for the composition width check. If the fixture does
not set `pager.term_width`, the default (often 80 or 120) will be used — the test must explicitly
set `pager.term_width = 30`.

## TC108-U05: Search Segment Truncated When Very Narrow Terminal

**Requirement:** REQ-PAGER-SEARCH-009.4 — when even the search segment is wider than
`terminal_width - 2`, the search segment is truncated to fit.

**Fixture design:**
- `term_width = 20` (`term_width - 2 = 18`)
- Long pattern: `"very_long_pattern_value"` (23 chars)
- Search segment alone: `Pattern: very_long_pattern_value  (N matches)` >> 18 chars
- Expected output length (excluding `\r\n`): <= 18

**Test code:**

```rust
#[test]
fn status_bar_search_very_narrow_truncates_search_segment() {
    // REQ-PAGER-SEARCH-009.4: when even the search segment alone exceeds
    // terminal_width - 2, it is truncated to terminal_width - 2.
    let mut pager = make_pager_with_data(50, 10);
    pager.term_width = 20;
    pager.submit_search("very_long_pattern_value");  // May produce 0 matches; that's fine.
    // Even the not-found or match-count variant of the search segment exceeds 18 chars.

    let out = status_bar_to_string(&pager);
    // Strip \r\n for length check.
    let line = out.trim_end_matches(|c| c == '\r' || c == '\n');

    assert!(
        line.len() <= (pager.term_width as usize).saturating_sub(2),
        "Search segment must be truncated to terminal_width - 2 = {} chars; got {} chars: {:?}",
        pager.term_width as usize - 2,
        line.len(),
        out
    );
    // Still starts with "Pattern:" — not truncated before the prefix.
    assert!(
        line.starts_with("Pattern:"),
        "Truncated segment must still start with 'Pattern:': {:?}", out
    );
}
```

**Note:** If `make_pager_with_data` does not support patterns that produce zero matches for this
test, use a different pattern like `"xxxxxx_no_match"` and handle the `not found` case — the
truncation rule still applies to `Pattern: xxxxxx_no_match  not found`.

## TC108-U06: Row Context Updates After Scroll (Composed Status Persists)

**Requirement:** REQ-PAGER-SEARCH-009.6 — composed status persists; row numbers update live.

**Test code:**

```rust
#[test]
fn status_bar_search_row_context_updates_after_scroll() {
    // REQ-PAGER-SEARCH-009.6: composed status persists across scroll.
    // Row numbers must update when row_offset changes.
    let mut pager = make_pager_with_data(100, 20);
    pager.term_width = 120;
    pager.submit_search("val_");

    // Initial render: rows 1-20 of 100.
    let out1 = status_bar_to_string(&pager);
    assert!(out1.contains("Rows 1-20 of 100"), "Initial row context: {:?}", out1);
    assert!(out1.contains("Pattern: val_  ("), "Pattern still present: {:?}", out1);

    // Scroll down 10 rows.
    pager.row_offset = 10;
    let out2 = status_bar_to_string(&pager);

    // Row numbers updated.
    assert!(
        out2.contains("Rows 11-30 of 100"),
        "Row context must update after scroll to row_offset=10: {:?}", out2
    );
    // Pattern and match count unchanged.
    assert!(
        out2.contains("Pattern: val_  ("),
        "Pattern must persist across scroll: {:?}", out2
    );
    assert!(
        out2.contains("  |  Rows"),
        "Separator and row context segment must persist: {:?}", out2
    );
}
```

## TC108-U07: Not-Found Path Does Not Include Row Context

**Requirement:** REQ-PAGER-SEARCH-003 boundary — `Pattern: <pat>  not found` is unchanged by
the composed status bar implementation. Row context is NOT appended to the not-found line.

**Test code:**

```rust
#[test]
fn status_bar_search_not_found_has_no_row_context() {
    // REQ-PAGER-SEARCH-009 boundary / REQ-PAGER-SEARCH-003:
    // "not found" path must NOT include row context segment.
    let mut pager = make_pager_with_data(50, 20);
    pager.term_width = 120;
    pager.submit_search("xyzzy_no_match_guaranteed");  // Pattern guaranteed to produce 0 matches.

    // Not-found format preserved exactly.
    assert!(
        out.contains("not found"),
        "No-match search must show 'not found': {:?}", out

    assert!(
        !out.contains("  |  Rows"),
        "Not-found status must NOT include row context: {:?}", out
    );
    // Pattern is still shown.
    assert!(
        out.contains("Pattern: xyzzy_no_match_guaranteed  not found"),
        "Not-found format must be 'Pattern: <pat>  not found': {:?}", out
    );
}
```

## Notes

1. All 7 new unit tests are in `src/commands/repl/pager.rs` `#[cfg(test)]`, alongside the existing
   `status_bar_*` tests. No new files needed.

2. The `make_pager_with_data(rows, page_size)` helper must set `term_width` explicitly. Check the
   helper implementation before finalising TC108-U01/U03/U06 to ensure the default `term_width` is
   wide enough (>= 80) to show the composed string in the wide-terminal tests.

3. TC108-U04 requires `term_width = 30` to force the narrow path. The test explicitly sets
   `pager.term_width = 30` after constructing the fixture — the helper's default does not matter.

4. TC108-U05 uses a long pattern. If `submit_search` for a no-match pattern behaves differently
   (e.g., sets `search_status = SearchStatus::NotFound` immediately), the output will be
   `Pattern: very_long_pattern_value  not found` rather than `Pattern: very_long_pattern_value  (0 matches)`.
   Both forms exceed 18 chars and both should be truncated. The test's `line.len() <= 18` assertion
   is agnostic to which form is rendered.

5. TC108-U06 sets `pager.row_offset = 10` directly. This is valid for `#[cfg(test)]` tests since
   `row_offset` is a struct field. The test does NOT call a scroll function — it directly mutates
   the field to verify that the renderer reads from it.
