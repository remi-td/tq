# TC-036-009: `/show indexes` Error Handling

## Purpose

Verify that `/show indexes` command handles error conditions gracefully with clear, actionable error messages for non-existent tables, permission denied, and missing arguments.

## Acceptance Criteria Coverage

- **AC-19**: Error handling for non-existent table with clear message
- **AC-20**: Error handling for permission denied with guidance

## Scope

This test validates:
- Non-existent table error message
- Non-existent database error message
- Permission denied error message (if applicable)
- Missing argument error message
- Error message clarity and actionability
- Suggestions for resolving errors
- No crashes or panics on errors

## Prerequisites

- Rust test framework available
- `tq` binary built with REPL support
- expectrl crate for PTY testing
- Integration test framework (std::process::Command)
- Database connection available
- Test database with appropriate permissions

## Test Procedure

### Integration Test 1: Non-Existent Table Error

```rust
#[test]
#[ignore] // Requires database connection
fn test_show_indexes_nonexistent_table() {
    let temp_db = create_test_database();
    let nonexistent_table = format!("nonexistent_table_{}", random_suffix());

    // Execute /show indexes on non-existent table
    let mut repl = spawn_repl().expect("Failed to spawn REPL");
    repl.send_line(&format!("USE {};", temp_db)).unwrap();
    repl.send_line(&format!("/show indexes {}", nonexistent_table)).unwrap();

    let output = repl.read_until_prompt().unwrap();

    // Verify clear error message
    assert!(
        output.contains("does not exist") ||
        output.contains("not found") ||
        output.contains("unknown table"),
        "Should indicate table does not exist"
    );

    // Verify table name mentioned in error
    assert!(
        output.contains(&nonexistent_table),
        "Error should mention the table name"
    );

    // Should not crash or panic
    assert!(
        !output.contains("panic") && !output.contains("PANIC"),
        "Should not panic on non-existent table"
    );
}
```

### Interactive Test 6: Error Message Clarity

```rust
#[test]
#[ignore] // Requires database connection
fn test_show_indexes_error_message_clarity() {
    let mut repl = spawn_repl().expect("Failed to spawn REPL");
    let nonexistent = "this_table_definitely_does_not_exist_12345";

    repl.send_line(&format!("/show indexes {}", nonexistent)).unwrap();

    let output = repl.read_until_prompt().unwrap();

    // Error message should be clear (not cryptic SQL error)
    assert!(
        !output.contains("SQLSTATE") || output.contains("does not exist"),
        "Error should be user-friendly, not just SQL error code"
    );

    // Should mention the table name
    assert!(
        output.contains(nonexistent),
        "Error should mention the table name user specified"
    );

    // Should not expose internal implementation details
    assert!(
        !output.contains("DBC.IndicesV") || output.contains("table"),
        "Error should be user-focused, not implementation-focused"
    );
}
```

## Pass/Fail Criteria

**PASS if:**
- All 8 tests pass
- Non-existent table error is clear and mentions table name
- Non-existent database error is clear
- Missing argument error shows correct usage
- Permission denied error provides guidance
- No panics or crashes on any error
- Error messages are user-friendly (not just SQL errors)
- Helpful suggestions provided (e.g., use `/list tables`)
- Ambiguous context handled gracefully
- No internal implementation details exposed

**FAIL if:**
- Any test fails
- Error messages cryptic or confusing
- No mention of table name in errors
- Missing argument has no usage hint
- Permission errors don't provide guidance
- Panics or crashes on errors
- Raw SQL errors exposed to user
- No helpful suggestions for common mistakes
- Ambiguous context causes panic
