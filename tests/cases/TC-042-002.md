# TC-042-002: Multi-Line SQL Statements (Bug #29)

**Test ID:** TC-042-002
**Feature:** SQL Parser - Multi-Line Statement Preservation
**Priority:** P0 - Critical
**Test Type:** Unit
**Sprint:** 42
**Created:** 2026-03-21
**Requirement References:** REQ-PARSE-004, REQ-PARSE-014, REQ-PARSE-015, AC-3, AC-7, AC-8, AC-11
**GitHub Issue:** #29 - Multi-line SQL statements fail in file execution mode

---

## Objective

Verify that the new parser correctly treats a SQL statement that spans multiple lines as a single statement, preserves all internal whitespace including newlines verbatim, and accurately tracks line numbers for each statement regardless of how many lines precede it.

## Background

Bug #29 describes a failure where multi-line statements are submitted as multiple incomplete fragments. For example:

```sql
SELECT
    employee_id,
    first_name
FROM employees
WHERE department_id = 10;
```

The naive `split(';')` approach works for this case (there is only one semicolon), but the line number tracking breaks down when multiple multi-line statements appear in sequence, causing error messages to report wrong line numbers. Additionally, the `trim()` call on each segment may strip meaningful internal whitespace from statements.

REQ-PARSE-004 requires that internal whitespace (including newlines) is preserved verbatim.

## Test Cases

All tests are unit tests in `src/sql/parser.rs` `#[cfg(test)]` module.

### TS42-U07: Multi-line SELECT is a single statement

```rust
#[test]
fn test_multiline_select_single_statement() {
    // REQ-PARSE-004: newlines within a statement are preserved
    let sql = "SELECT\n    employee_id,\n    first_name,\n    last_name\nFROM employees\nWHERE department_id = 10\nORDER BY last_name;";
    let statements = parse_statements(sql).expect("parse should succeed");
    assert_eq!(statements.len(), 1, "multi-line SELECT must be a single statement");
    assert_eq!(statements[0].statement_number, 1);
    assert_eq!(statements[0].start_line, 1);
    // All keywords must be present (statement not truncated)
    assert!(statements[0].sql.contains("SELECT"));
    assert!(statements[0].sql.contains("FROM employees"));
    assert!(statements[0].sql.contains("WHERE department_id = 10"));
    assert!(statements[0].sql.contains("ORDER BY last_name"));
}
```

**Expected Result:** 1 statement containing all 7 lines of SQL.

### TS42-U09: Blank lines within a statement do not create additional statements

```rust
#[test]
fn test_blank_lines_within_statement_not_split() {
    // AC-7, REQ-PARSE-004: blank lines within a statement are whitespace, not boundaries
    // Note: A blank line inside a SELECT that has no semicolons yet is still one statement
    let sql = "SELECT 1\n\nFROM dual;";
    let statements = parse_statements(sql).expect("parse should succeed");
    assert_eq!(
        statements.len(), 1,
        "blank line within statement must not split it"
    );
    assert!(statements[0].sql.contains("SELECT 1"));
    assert!(statements[0].sql.contains("FROM dual"));
}
```

**Expected Result:** 1 statement.

### TS42-U10: Line numbers accurate for consecutive multi-line statements

```rust
#[test]
fn test_line_number_preserved_for_multiline_statement() {
    // REQ-PARSE-015: start_line records where the statement began
    // REQ-PARSE-014: line counter never resets between statements
    let sql = "SELECT 1\nFROM dual;\nSELECT 2\nFROM dual;";
    // Lines:  1        2           3        4
    let statements = parse_statements(sql).expect("parse should succeed");
    assert_eq!(statements.len(), 2);
    assert_eq!(statements[0].start_line, 1, "first statement starts on line 1");
    assert_eq!(statements[1].start_line, 3, "second statement starts on line 3");
}
```

**Expected Result:** 2 statements; start_line values are 1 and 3 respectively.

### TS42-U10c: Line number counter never resets between statements

```rust
#[test]
fn test_line_numbers_never_reset_between_statements() {
    // REQ-PARSE-014: counter must not reset between statements
    // 5 statements each starting on distinct line numbers
    let sql = "SELECT 1;\nSELECT 2;\nSELECT 3;\nSELECT 4;\nSELECT 5;";
    let statements = parse_statements(sql).expect("parse should succeed");
    assert_eq!(statements.len(), 5);
    assert_eq!(statements[0].start_line, 1);
    assert_eq!(statements[1].start_line, 2);
    assert_eq!(statements[2].start_line, 3);
    assert_eq!(statements[3].start_line, 4);
    assert_eq!(statements[4].start_line, 5);
}
```

**Expected Result:** Each statement has its correct line number (1 through 5).

### TS42-U11: Multi-line statement with internal whitespace preserved

```rust
#[test]
fn test_internal_whitespace_preserved_verbatim() {
    // REQ-PARSE-004: "The parser never collapses or strips internal whitespace"
    // The SQL sent to the database must contain the actual newlines and indentation
    let sql = "SELECT\n    a,\n    b,\n    c\nFROM t;";
    let statements = parse_statements(sql).expect("parse should succeed");
    assert_eq!(statements.len(), 1);
    // Internal newlines and indentation must be in the output SQL
    assert!(
        statements[0].sql.contains('\n'),
        "internal newlines must be preserved in the sql field"
    );
    assert!(
        statements[0].sql.contains("    a,"),
        "indentation must be preserved"
    );
}
```

**Expected Result:** The `sql` field contains the newlines and indentation as written.

### TS42-U12: Windows line endings (CRLF) are handled correctly

```rust
#[test]
fn test_windows_line_endings_multiline() {
    // REQ-PARSE-014: line numbers increment on \n; \r\n counts as one line
    let sql = "SELECT 1;\r\nSELECT 2;\r\n";
    let statements = parse_statements(sql).expect("parse should succeed");
    assert_eq!(statements.len(), 2);
    assert_eq!(statements[0].start_line, 1);
    assert_eq!(statements[1].start_line, 2);
}
```

**Expected Result:** 2 statements with correct line numbers. `\r\n` is a single line boundary.

### TS42-U13: Statement spanning 10+ lines

```rust
#[test]
fn test_statement_spanning_many_lines() {
    // A realistically large multi-line SQL statement
    let sql = r#"SELECT
    t1.col1,
    t1.col2,
    t2.col3,
    t2.col4,
    t3.col5
FROM table1 t1
JOIN table2 t2
    ON t1.id = t2.foreign_id
JOIN table3 t3
    ON t2.id = t3.foreign_id
WHERE t1.status = 'active'
    AND t2.created_date > DATE '2025-01-01'
ORDER BY t1.col1;
"#;
    let statements = parse_statements(sql).expect("parse should succeed");
    assert_eq!(statements.len(), 1);
    assert_eq!(statements[0].start_line, 1);
    assert!(statements[0].sql.contains("SELECT"));
    assert!(statements[0].sql.contains("ORDER BY t1.col1"));
}
```

**Expected Result:** 1 statement; the complex multi-line SQL is fully preserved.
