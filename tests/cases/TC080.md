# Test Case TC080: Table Display - Batch Mode vs TTY Mode Column Visibility

## Purpose

Verify that table display behaves differently in batch mode (non-TTY) vs REPL/TTY mode:
- TTY mode: Truncates columns to terminal width
- Batch mode: Shows ALL columns (no truncation)

This ensures scripts and pipes get complete data while interactive use stays readable.

## Scope

**Testing:**
- TTY mode: Column truncation enabled
- Batch mode: All columns shown
- isatty() detection works correctly
- Piped output shows all data
- File redirection shows all data

**Not Testing:**
- JSON/CSV formats (different code paths)
- Performance

## Prerequisites

- tq binary with Sprint 11 fixes
- Teradata connection available
- Test query with 10+ columns
- Terminal with standard width (80-120 cols)

## Test Procedure

### Setup

```bash
# Ensure we have a query that produces >10 columns
# DBC.TablesV has ~15 columns
```

### Execution Steps

**Step 1: Execute query in REPL (TTY mode)**

```bash
./target/release/tq repl

tq> SELECT TOP 5 * FROM DBC.TablesV;
```

**Expected outcome:**
- Columns truncated to fit terminal
- "(+n cols)" indicator shown
- "..." in body rows
- Interactive-friendly display

**Step 2: Execute same query in batch mode (via pipe)**

```bash
echo "SELECT TOP 5 * FROM DBC.TablesV;" | ./target/release/tq query
```

**Expected outcome:**
- ALL columns shown
- NO truncation
- NO "(+n cols)" indicator
- NO "..." indicators
- Complete data output
- May exceed terminal width (that's OK in batch)

**Step 3: Execute with output redirection**

```bash
./target/release/tq query "SELECT TOP 5 * FROM DBC.TablesV;" > output.txt
cat output.txt
```

**Expected outcome:**
- File contains all columns
- No truncation applied
- Complete data preserved

**Step 4: Execute via command substitution**

```bash
result=$(./target/release/tq query "SELECT TOP 5 * FROM DBC.TablesV;")
echo "$result"
```

**Expected outcome:**
- All columns captured
- No truncation
- Script gets complete data

**Step 5: Compare TTY vs batch output**

Count columns in each:

```bash
# TTY mode (interactive REPL)
# Count visible columns in table

# Batch mode
echo "SELECT * FROM DBC.TablesV LIMIT 1;" | ./target/release/tq query | head -3
# Count columns in header row
```

**Expected outcome:**
- TTY: 5-7 columns visible
- Batch: 15+ columns (all of them)
- Clear difference in behavior

**Step 6: Verify batch mode column count**

```bash
# Extract header row and count separators
echo "SELECT * FROM DBC.TablesV LIMIT 1;" | ./target/release/tq query | head -1 | tr -cd '│' | wc -c
```

**Expected outcome:**
- Count matches total column count + 1
- All columns present

## Pass/Fail Criteria

**PASS:**
- TTY mode truncates columns (TC076 behavior)
- Batch mode shows all columns (no truncation)
- isatty() detection works correctly
- Pipe output complete
- File redirection complete
- Mode switch is automatic and correct

**FAIL:**
- Batch mode truncates columns (data loss)
- TTY mode shows all columns (exceeds terminal, unreadable)
- isatty() always returns same value
- Mode detection broken
- Scripts can't get complete data

## Notes

**Why This Matters:**

Different use cases have different needs:

**Interactive (TTY):**
- Human reading terminal
- Readability matters most
- Truncate to fit screen
- Visual indicators helpful

**Batch (non-TTY):**
- Script processing data
- Completeness matters most
- Show everything
- Terminal width irrelevant

**Implementation:**

```rust
use std::io::IsTerminal;

if std::io::stdout().is_terminal() {
    // TTY mode: truncate columns
    display_truncated(results, terminal_width);
} else {
    // Batch mode: show all columns
    display_all_columns(results);
}
```

**Testing Importance:**

Sprint 10 added batch mode features. Need to ensure:
- Batch mode gets complete data (critical)
- TTY mode stays readable (Sprint 11 fix)
- Mode detection works reliably
- No regression in either mode

**Common Failure Mode:**

If batch mode truncates:
- Scripts get incomplete data
- Columns missing in output files
- Data loss in pipelines
- Breaking change for users
