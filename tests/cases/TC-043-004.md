# TC-043-004: Profile Delete - Happy Path and Errors

**Test ID:** TC-043-004
**Feature:** Profile Management - `tq profile delete`
**Priority:** P0 - Critical
**Test Type:** Integration (CLI process)
**Sprint:** 43
**Created:** 2026-03-21
**Requirement References:** AC-3, AC-5, AC-7, AC-8, AC-9, AC-10

---

## Objective

Verify that `tq profile delete <name> --force` correctly removes a named profile from the config file, produces a confirmation message, preserves all other profiles, and correctly rejects attempts to delete non-existent profiles. Also validates `tq profile list` as an alias for `tq profiles` (AC-10) and documents the code inspection approach for tab completion (AC-9).

---

## Test Environment

Temporary directory via `TQ_CONFIG_DIR` environment variable. No database required.

---

## Test Cases

### TS43-P-D01: Delete existing profile with --force (AC-3, AC-7, AC-8)

**Precondition:** Config file contains profiles `dev` and `prod`.

**Command:**
```
tq profile delete dev --force
```

**Expected Results:**
- Exit code: 0
- Confirmation message on stdout (e.g., `Profile 'dev' deleted successfully`)
- `dev` profile REMOVED from config file
- `prod` profile PRESERVED in config file

```rust
#[test]
fn test_profile_delete_with_force() {
    let tmp = tempfile::TempDir::new().unwrap();
    // Set up two profiles
    std::process::Command::new(env!("CARGO_BIN_EXE_tq"))
        .args(["profile", "add", "dev", "--host", "dev.example.com"])
        .env("TQ_CONFIG_DIR", tmp.path())
        .output().unwrap();
    std::process::Command::new(env!("CARGO_BIN_EXE_tq"))
        .args(["profile", "add", "prod", "--host", "prod.example.com"])
        .env("TQ_CONFIG_DIR", tmp.path())
        .output().unwrap();

    // Delete dev
    let output = std::process::Command::new(env!("CARGO_BIN_EXE_tq"))
        .args(["profile", "delete", "dev", "--force"])
        .env("TQ_CONFIG_DIR", tmp.path())
        .output().unwrap();

    assert!(output.status.success(), "delete must succeed, stderr: {}", String::from_utf8_lossy(&output.stderr));
    let stdout = String::from_utf8_lossy(&output.stdout);
    assert!(
        stdout.contains("dev") && (stdout.to_lowercase().contains("deleted") || stdout.to_lowercase().contains("removed") || stdout.to_lowercase().contains("success")),
        "must confirm deletion, got: {stdout}"
    );

    let contents = std::fs::read_to_string(tmp.path().join("config.toml")).unwrap();
    assert!(!contents.contains("dev.example.com"), "dev profile host must be removed");
    assert!(contents.contains("prod.example.com"), "prod profile must be preserved");
}
```

### TS43-P-D02: Delete without --force fails in non-TTY environment (AC-3)

**Precondition:** Config file contains profile `dev`.

**Command:**
```
tq profile delete dev
```

**Rationale:** The sprint planning states `--force` is required to skip the confirmation prompt. When run without a TTY (as in `std::process::Command`), the tool must either:
- Require `--force` and exit non-zero without it
- OR detect non-TTY and still prompt but pipe stdin is closed, causing it to abort

Either way, the profile must NOT be silently deleted.

**Expected Results:**
- Profile `dev` is NOT deleted from the config file
- Either exit code non-zero OR confirmation prompt is shown and no deletion occurs without input

```rust
#[test]
fn test_profile_delete_without_force_does_not_delete() {
    let tmp = tempfile::TempDir::new().unwrap();
    std::process::Command::new(env!("CARGO_BIN_EXE_tq"))
        .args(["profile", "add", "dev", "--host", "dev.example.com"])
        .env("TQ_CONFIG_DIR", tmp.path())
        .output().unwrap();

    let before = std::fs::read_to_string(tmp.path().join("config.toml")).unwrap();

    // Run delete without --force; stdin is not a TTY
    let output = std::process::Command::new(env!("CARGO_BIN_EXE_tq"))
        .args(["profile", "delete", "dev"])
        .env("TQ_CONFIG_DIR", tmp.path())
        .stdin(std::process::Stdio::null())
        .output().unwrap();

    // The profile must NOT be deleted regardless of exit code
    let after = std::fs::read_to_string(tmp.path().join("config.toml")).unwrap();
    assert!(
        after.contains("dev.example.com"),
        "dev profile must NOT be deleted without --force in non-TTY mode"
    );
    // Document: the exit code behavior may vary by implementation
    // If the architect makes --force mandatory: assert!(!output.status.success())
    // If the architect reads stdin and aborts on EOF: exit may be non-zero or zero depending on design
    let _ = output; // suppress unused warning
}
```

### TS43-P-D03: Delete non-existent profile returns error (AC-5)

**Precondition:** Config file exists but does NOT contain profile `ghost`.

**Command:**
```
tq profile delete ghost --force
```

**Expected Results:**
- Exit code: non-zero
- Error message mentions `ghost` and indicates profile not found
- Config file NOT modified

```rust
#[test]
fn test_profile_delete_nonexistent_profile_fails() {
    let tmp = tempfile::TempDir::new().unwrap();
    // Create a real profile so the config file exists
    std::process::Command::new(env!("CARGO_BIN_EXE_tq"))
        .args(["profile", "add", "real", "--host", "real.example.com"])
        .env("TQ_CONFIG_DIR", tmp.path())
        .output().unwrap();

    let before = std::fs::read_to_string(tmp.path().join("config.toml")).unwrap();

    let output = std::process::Command::new(env!("CARGO_BIN_EXE_tq"))
        .args(["profile", "delete", "ghost", "--force"])
        .env("TQ_CONFIG_DIR", tmp.path())
        .output().unwrap();

    assert!(!output.status.success(), "deleting non-existent profile must fail");
    let combined = format!(
        "{}{}",
        String::from_utf8_lossy(&output.stderr),
        String::from_utf8_lossy(&output.stdout)
    );
    assert!(
        combined.contains("ghost"),
        "error must mention profile name, got: {combined}"
    );
    assert!(
        combined.to_lowercase().contains("not found") || combined.to_lowercase().contains("does not exist") || combined.to_lowercase().contains("unknown"),
        "error must indicate profile not found, got: {combined}"
    );

    let after = std::fs::read_to_string(tmp.path().join("config.toml")).unwrap();
    assert_eq!(before, after, "config must be unmodified on error");
}
```

### TS43-P-D05: Profile list alias works (AC-10)

**Precondition:** Config file contains profiles `dev` and `prod`.

**Commands (both must produce the same output):**
```
tq profiles
tq profile list
```

**Expected Results:**
- Both commands succeed with exit code 0
- Both commands produce identical stdout output
- Both commands list the same profile names

```rust
#[test]
fn test_profile_list_alias_matches_profiles_command() {
    let tmp = tempfile::TempDir::new().unwrap();
    std::process::Command::new(env!("CARGO_BIN_EXE_tq"))
        .args(["profile", "add", "dev",  "--host", "dev.example.com"])
        .env("TQ_CONFIG_DIR", tmp.path())
        .output().unwrap();
    std::process::Command::new(env!("CARGO_BIN_EXE_tq"))
        .args(["profile", "add", "prod", "--host", "prod.example.com"])
        .env("TQ_CONFIG_DIR", tmp.path())
        .output().unwrap();

    let profiles_output = std::process::Command::new(env!("CARGO_BIN_EXE_tq"))
        .args(["profiles"])
        .env("TQ_CONFIG_DIR", tmp.path())
        .output().unwrap();

    let list_output = std::process::Command::new(env!("CARGO_BIN_EXE_tq"))
        .args(["profile", "list"])
        .env("TQ_CONFIG_DIR", tmp.path())
        .output().unwrap();

    assert!(profiles_output.status.success(), "`tq profiles` failed");
    assert!(list_output.status.success(), "`tq profile list` failed");

    let profiles_stdout = String::from_utf8_lossy(&profiles_output.stdout);
    let list_stdout = String::from_utf8_lossy(&list_output.stdout);

    // Both must list dev and prod
    assert!(profiles_stdout.contains("dev"),  "`tq profiles` must list 'dev'");
    assert!(profiles_stdout.contains("prod"), "`tq profiles` must list 'prod'");
    assert!(list_stdout.contains("dev"),      "`tq profile list` must list 'dev'");
    assert!(list_stdout.contains("prod"),     "`tq profile list` must list 'prod'");

    // Outputs should match (or at minimum contain the same profile names)
    assert_eq!(
        profiles_stdout.as_ref(),
        list_stdout.as_ref(),
        "`tq profile list` must produce identical output to `tq profiles`"
    );
}
```

### TS43-P-D06: Tab completion code inspection (AC-9)

**Test Type:** Code inspection (not a cargo test)

**Rationale:** Shell tab completion for profile names on `edit` and `delete` subcommands is a build artifact. Runtime tests cannot verify that typing `tq profile edit <TAB>` shows profile names. Instead, this is validated by inspecting the CLI argument definition source code.

**Procedure:**
1. Open `src/cli.rs`
2. Locate the `profile edit <name>` argument definition
3. Verify a completion source is registered for the `<name>` argument (e.g., `.value_hint(clap::ValueHint::Other)` combined with a custom completer, or an explicit `.add_completion()` / `.value_enum()` call that references profile names)
4. Repeat for `profile delete <name>`

**Expected Result:**
- The `<name>` positional argument for both `edit` and `delete` subcommands has a profile-name completer registered
- The completion logic calls the same function that `tq profiles` uses to enumerate profile names

**Execution:**
```bash
grep -n "profile" src/cli.rs | grep -i "edit\|delete\|complet\|hint"
```

**Pass Criteria:** The grep output shows completer registration for the profile name argument on both subcommands. If no completion hint is found, AC-9 is not satisfied and a defect should be filed.
