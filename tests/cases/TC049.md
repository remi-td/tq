# Test Case TC049: Tab Completion - FROM Shows Databases and Current DB Tables

## Purpose

Verify that pressing Tab after the FROM keyword displays both database names and table names in the current database, following Teradata's fully-qualified naming best practices.

## Scope

**Testing:**
- Tab completion after "FROM " keyword
- Display of database names
- Display of current database table names
- Visual grouping/separation of databases vs tables
- Completion filtering as user types

**Not Testing:**
- Column completion (covered in TC031-TC035)
- Error handling (covered in TC052)
- Cache management (covered in TC053-TC054)
- Performance (covered in TC042)

## Prerequisites

- tq REPL mode active
- Live Teradata database connection
- Current database set (check with `SELECT DATABASE;`)
- Multiple databases exist in Teradata system
- Current database has at least 3-5 tables

## Test Procedure

### Setup

```bash
# Start tq in REPL mode
./target/release/tq

# Verify current database
tq> SELECT DATABASE;
# Note the database name for test verification
```

### Execution Steps

**Step 1: Tab completion after FROM keyword**

```sql
tq> SELECT * FROM <TAB>
```

**Expected outcome:**
- Completion menu/list appears
- Shows database names (All, DBC, val, mldb, etc.)
- Shows table names in current database
- Clear visual distinction between databases and tables
- No "Loading..." message if metadata is already cached
- MAY show "Loading..." briefly on first Tab press (acceptable)

**Step 2: Verify database list**

Check the completion results include:
- [ ] Standard system databases: All, DBC, TD_SYSXML
- [ ] User databases (if any exist)
- [ ] Current database name appears (either in database section or implicitly)

**Step 3: Verify current database table list**

Check the completion results include:
- [ ] Tables that exist in current database
- [ ] Label or grouping indicating "Tables in current database: X" or similar
- [ ] At least 3-5 table names visible (if that many exist)

**Step 4: Verify visual organization**

Expected display format (one of these approaches):

**Option A: Grouped Display**
```
Databases:
    All    DBC    TD_SYSXML    val    mldb

Tables in current database (val):
    employees    customers    orders    products
```

**Option B: Inline Display**
```
[Databases] All    DBC    TD_SYSXML    val    mldb
[Tables]    employees    customers    orders    products
```

**Option C: Combined List**
```
All                  [database]
DBC                  [database]
employees            [table in current DB]
customers            [table in current DB]
orders               [table in current DB]
```

**Step 5: Test filtering by typing**

```sql
tq> SELECT * FROM e<TAB>
```

**Expected outcome:**
- Completion list filters to items starting with 'e'
- May show "employees" table if it exists
- May show no databases (none start with 'e')
- Filtering is case-insensitive

**Step 6: Test completion of database name**

```sql
tq> SELECT * FROM D<TAB>
```

**Expected outcome:**
- Filters to "DBC" (and possibly other databases starting with D)
- User can press Enter to select "DBC"
- After selecting "DBC", cursor is ready for next input

### Verification

**Critical Checks:**

1. **Tab Functionality:**
   - [ ] Tab key is recognized (not inserting tab character)
   - [ ] Completion menu appears
   - [ ] Can navigate completion options (with arrow keys if menu-based)

2. **Database List:**
   - [ ] At least 3 database names visible (All, DBC, and at least one other)
   - [ ] Database names are correct (match actual databases)
   - [ ] Current database is included or clearly indicated

3. **Table List:**
   - [ ] Tables from current database are shown
   - [ ] Table names are correct (match actual tables in current DB)
   - [ ] At least 3-5 tables visible (if that many exist)

4. **Visual Organization:**
   - [ ] Clear distinction between databases and tables
   - [ ] Labels or grouping indicators present
   - [ ] Layout is readable and not cluttered

5. **Responsiveness:**
   - [ ] Completion appears in <500ms (after cache is loaded)
   - [ ] First Tab may show loading indicator (acceptable)
   - [ ] Subsequent Tabs are instant (<50ms)

**Negative Checks (Should NOT Occur):**

- [ ] Tab does nothing (no response at all) ← PRIMARY BUG
- [ ] No visual feedback
- [ ] Empty completion list when databases/tables exist
- [ ] Only keywords shown (SELECT, WHERE) but no objects
- [ ] Error messages without helpful guidance

## Expected Results

**Correct Behavior Example 1: Grouped Display**

```sql
tq> SELECT * FROM <TAB>

── Databases ────────────────────────
  All    DBC    TD_SYSXML    mldb    val

── Tables (current: val) ───────────
  customers    employees    orders    products    suppliers
```

**Correct Behavior Example 2: Inline Display**

```sql
tq> SELECT * FROM <TAB>
[Databases]: All, DBC, TD_SYSXML, mldb, val
[Current DB (val)]: customers, employees, orders, products, suppliers
```

**Key Characteristics:**
- Both databases AND tables are visible
- Clear labeling distinguishes the two types
- Current database is identified
- User can complete to either a database name (to then add `.table`) or directly to a table in current DB

**Anti-Pattern (Bug Behavior - Should NOT Occur):**

```sql
tq> SELECT * FROM <TAB>
[Nothing happens - no response, no menu, no feedback]
```

OR:

```sql
tq> SELECT * FROM <TAB>
[Only shows keywords: SELECT, FROM, WHERE, JOIN]
```

## Pass/Fail Criteria

**PASS:**
- Tab after FROM shows completion menu
- Database names are displayed (≥3 databases)
- Current database table names are displayed (≥3 tables)
- Clear visual distinction between databases and tables
- Completion responds in <500ms
- User can filter and select items

**FAIL:**
- Tab does nothing (no response) ← PRIMARY BUG
- No completion menu appears
- Only keywords shown (no database/table names)
- Databases shown but NO tables from current database
- Tables shown but NO databases
- No visual distinction (user can't tell databases from tables)
- Completion takes >2 seconds on cached data
- Completion fails silently with no error message

## Notes

**Bug Context:**

From open-bugs.md:
> "Tab completion doesn't work at all, for either databases, tables or columns... And I don't see any indication as to what's happening."

This test verifies the fix for the most basic tab completion case: after FROM keyword.

**Teradata Naming Convention:**

Teradata uses fully-qualified naming: `database.table`
- Unqualified table names resolve to current database
- Best practice: Always use `database.table` format
- Therefore, showing databases first encourages best practice

**UX Design (from sprint-8-ux-design.md):**

> "So if a user does `select * from ...` we should hint either the database names (all databases in Teradata) or the table names in the current database. I would go with displaying all the databases first, and then the table names in the current database, simply because fully qualifying table names in a query is best practice, so we want to prime this."

**Root Cause (from sprint-8-root-cause-analysis.md):**

Multiple silent failure points:
1. Lock contention returns empty list silently
2. Metadata loading failure returns empty list silently
3. No loading indicator when fetching metadata
4. Errors logged but not shown to user

**Expected Fix:**

1. Surface errors to user when metadata loading fails
2. Show loading indicator on first Tab press
3. Actually display the loaded databases and tables
4. Ensure reedline integration is working
