# TC-043-005: Parser Remediation - Result Return Type and Error Location

**Test ID:** TC-043-005
**Feature:** Sprint 42 Parser Remediation - `parse_statements()` Result return type
**Priority:** P0 - Critical
**Test Type:** Unit + Integration (CLI error propagation)
**Sprint:** 43
**Created:** 2026-03-21
**Requirement References:** AC-13, AC-14, AC-15, AC-16, AC-17

---

## Objective

Verify that `parse_statements()` returns `Result<Vec<ParsedStatement>, ParseError>` for malformed SQL, that `ParseError` carries an accurate line number and column, and that the CLI surfaces parse errors to the user when reading a SQL file. Also validates that the existing happy-path behavior is unchanged (regression check).

---

## Test Environment

Pure unit tests - no database, no file system, no binary spawning required for unit tests. Integration tests spawn the `tq` binary with a temporary SQL file.

### TS43-PRS-01: Unterminated string on line 1 returns ParseError with line 1 (AC-13, AC-15)

**Location:** `src/sql/parser.rs` `#[cfg(test)]` module

```rust
#[test]
fn test_unterminated_string_line_1_returns_error() {
    // REQ-PARSE-007: EOF inside a string is a parse error
    let sql = "SELECT 'unterminated";
    let result = parse_statements(sql);
    assert!(result.is_err(), "unterminated string must return Err, not Ok");
    let err = result.unwrap_err();
    assert_eq!(
        err.line, 1,
        "error must reference line 1 where string opened, got line {}", err.line
    );
    // Column must be > 0
    assert!(err.column > 0, "error must include a column number > 0, got {}", err.column);
    // Error message must mention the issue
    let msg = format!("{err}");
    assert!(
        msg.to_lowercase().contains("unterminated") || msg.to_lowercase().contains("string") || msg.to_lowercase().contains("quote"),
        "error message must describe unterminated string, got: {msg}"
    );
}
```

**Expected Result:** `Err(ParseError { line: 1, column: N })` where N is the column where the string opened.

### TS43-PRS-08: Comment marker inside string is not treated as comment (AC-17)

**Location:** `src/sql/parser.rs` `#[cfg(test)]` module

This is the specific test identified in AC-17 that must be added.

```rust
#[test]
fn test_comment_marker_inside_string_is_not_comment() {
    // REQ-PARSE-005: Inside a string, -- and /* are not special
    // A '--' inside a string must not start a line comment
    let sql = "SELECT '-- not a comment' AS s;";
    let result = parse_statements(sql);
    assert!(result.is_ok(), "must parse successfully");
    let stmts = result.unwrap();
    assert_eq!(stmts.len(), 1, "must be exactly 1 statement");
    assert!(
        stmts[0].sql.contains("'-- not a comment'"),
        "string content with comment marker must be preserved intact"
    );

    // '/* ... */' inside a string must not start a block comment
    let sql2 = "SELECT '/* also not a comment */' AS s;";
    let result2 = parse_statements(sql2);
    assert!(result2.is_ok(), "must parse successfully");
    let stmts2 = result2.unwrap();
    assert_eq!(stmts2.len(), 1);
    assert!(
        stmts2[0].sql.contains("'/* also not a comment */'"),
        "block comment marker inside string must be treated as string content"
    );
}
```

**Expected Result:** Both inputs parse successfully with comment markers preserved verbatim in string content.

### TS43-PRS-10: Integration - CLI surfaces parse error from --file (AC-13, AC-14)

**Location:** `tests/integration_tests.rs`

**Rationale:** Unit tests validate the parser function. This test validates that the error propagates through the CLI and reaches the user's terminal via stderr.

```rust
#[test]
fn test_cli_parse_error_propagated_from_file() {
    use std::io::Write;
    let mut sql_file = tempfile::NamedTempFile::new().unwrap();
    writeln!(sql_file, "SELECT 'this string is never closed").unwrap();

    let output = std::process::Command::new(env!("CARGO_BIN_EXE_tq"))
        .args(["query", "--file", sql_file.path().to_str().unwrap()])
        .output()
        .expect("failed to run tq");

    assert!(!output.status.success(), "parse error in file must cause non-zero exit");
    let stderr = String::from_utf8_lossy(&output.stderr);
    assert!(
        !stderr.is_empty(),
        "parse error must be reported on stderr"
    );
    // Error must reference line 1
    assert!(
        stderr.contains("1") || stderr.to_lowercase().contains("line") || stderr.to_lowercase().contains("unterminated"),
        "stderr must mention the error location or type, got: {stderr}"
    );
}

#[test]
fn test_cli_parse_error_for_unterminated_block_comment_from_file() {
    use std::io::Write;
    let mut sql_file = tempfile::NamedTempFile::new().unwrap();
    writeln!(sql_file, "SELECT 1;").unwrap();
    writeln!(sql_file, "/* this block comment is never closed").unwrap();

    let output = std::process::Command::new(env!("CARGO_BIN_EXE_tq"))
        .args(["query", "--file", sql_file.path().to_str().unwrap()])
        .output()
        .expect("failed to run tq");

    assert!(!output.status.success(), "unterminated block comment must cause non-zero exit");
    let stderr = String::from_utf8_lossy(&output.stderr);
    assert!(!stderr.is_empty(), "error must be reported on stderr");
    // Line 2 is where the comment opened
    assert!(
        stderr.contains("2") || stderr.to_lowercase().contains("comment") || stderr.to_lowercase().contains("unterminated"),
        "stderr must mention error location or type, got: {stderr}"
    );
}
```

**Note:** These tests do NOT require a database connection. The parse error occurs before any connection is attempted. The `query --file` command should fail at parse time, not connection time.

### TS43-PRS-11: Compilation check - all call sites handle Result (AC-16)

**Test Type:** Implicit (compilation)

This is not a test function. If `parse_statements()` is changed to return `Result`, any call site that assigns the return value to a `Vec` directly (without `.unwrap()`, `.expect()`, or `?`) will cause a compile error. The test is:

```
cargo build 2>&1
```

**Pass Criteria:** Zero compilation errors. If any call site was not updated, the compiler emits an error about type mismatch. This is caught automatically during `cargo test` (compilation is a prerequisite).

**Documentation:** The architect must update all call sites. Known call sites to verify:
- Batch mode file execution path (`src/commands/query.rs` or equivalent)
- Any REPL file execution path
- Any test helpers that call `parse_statements()`
