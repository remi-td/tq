## Purpose

Validate error handling for the `/locks` command:
- Privilege errors produce clear, actionable guidance (not raw error codes)
- "View not found" errors produce informative messages (DBC.LockInfoV may not exist on older Teradata)
- Error messages identify what privilege is needed
- REPL does not crash on database errors

## Acceptance Criteria Coverage

- **AC-7**: Error handling for privilege errors with actionable guidance

## Prerequisites

- Rust test framework for unit tests (no database)
- Live database for interactive test (validates error display format)

## Test Procedure

### Unit Tests (no database required)

**Location:** `src/commands/locks.rs` tests module

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_privilege_error_detected() {
        let privilege_errors = vec![
            "3523 The user does not have SELECT access to DBC",
            "GRANT SELECT privilege required",
            "access denied",
            "permission denied",
        ];

        for err_msg in privilege_errors {
            assert!(
                is_privilege_error(err_msg),
                "Should detect privilege error in: {}",
                err_msg
            );
        }
    }

    #[test]
    fn test_privilege_error_message_mentions_dbc_view() {
        let mut output = Vec::new();
        write_privilege_error_guidance(&mut output).unwrap();
        let s = String::from_utf8(output).unwrap();

        assert!(
            s.contains("DBC") || s.contains("LockInfoV"),
            "Privilege error must mention the relevant DBC view. Got: {}",
            s
        );
    }

    #[test]
    fn test_privilege_error_message_includes_grant_syntax() {
        let mut output = Vec::new();
        write_privilege_error_guidance(&mut output).unwrap();
        let s = String::from_utf8(output).unwrap();

        assert!(
            s.contains("GRANT") || s.contains("grant") || s.to_lowercase().contains("dba"),
            "Privilege error must include GRANT syntax or DBA guidance. Got: {}",
            s
        );
    }

    #[test]
    fn test_view_not_found_error_produces_helpful_message() {
        // Test that "view not found" errors are translated to helpful messages
        let view_not_found_errors = vec![
            "LockInfoV: object does not exist",
            "3807 Object 'LockInfoV' does not exist",
            "object not found",
        ];

        for err_msg in view_not_found_errors {
            let mut output = Vec::new();
            write_view_not_found_message(err_msg, &mut output).unwrap();
            let s = String::from_utf8(output).unwrap();

            assert!(
                !s.is_empty(),
                "View-not-found error must produce helpful message for: {}",
                err_msg
            );
        }
    }

    #[test]
    fn test_privilege_error_not_confused_with_view_not_found() {
        // These two different errors must be handled differently
        assert!(is_privilege_error("GRANT SELECT required"));
        // A view-not-found error may not be a privilege error
        // (The error codes differ: 3523 vs 3807)
        let _ = is_privilege_error("object does not exist"); // Should not panic
    }
}
```

### Interactive Test (live database, #[ignore])

**Location:** `tests/interactive_tests.rs` (append)

```rust
#[test]
#[ignore] // Requires live database: cargo test -- --ignored --test-threads=1
fn test_locks_privilege_error_shows_guidance() {
    // With DBA account: /locks succeeds - validates output format
    // With restricted account: /locks shows privilege guidance
    // In both cases: REPL must not crash
    let mut p = spawn_tq_repl();

    p.expect("Connected to").expect("Failed to connect to database");
    std::thread::sleep(Duration::from_millis(1000));

    p.send_line("/locks").expect("Failed to send /locks");
    std::thread::sleep(Duration::from_millis(3000));

    let output = p.read_until_prompt().unwrap_or_default();
    let output_str = String::from_utf8_lossy(&output);

    // REPL must return to prompt (read_until_prompt succeeded = no hang)
    // Output must be non-empty
    assert!(
        !output_str.is_empty(),
        "/locks must produce output (data or message)"
    );

    // If it's an error with privilege message, must be actionable
    if output_str.to_lowercase().contains("error") &&
       (output_str.to_lowercase().contains("privilege") ||
        output_str.to_lowercase().contains("access")) {
        assert!(
            output_str.contains("GRANT") || output_str.to_lowercase().contains("dba") ||
            output_str.to_lowercase().contains("required"),
            "Privilege error must include actionable guidance. Got: {}",
            output_str
        );
    }

    p.send_line("/quit").expect("Failed to quit REPL");
    std::thread::sleep(Duration::from_millis(500));
}
```

## Expected Results

### Unit Tests:
- Privilege error strings are detected correctly
- Privilege error message mentions the DBC view
- Privilege error message includes GRANT syntax
- View-not-found errors produce helpful messages (not raw error codes)

### Interactive Test:
- `/locks` produces output - no hang
- If privilege error occurs: message includes actionable guidance

## Pass/Fail Criteria

**PASS if:**
- All unit tests pass (error detection, message generation, view-not-found handling)
- Interactive test: REPL returns to prompt (no hang)
- If privilege error occurs in interactive test: message is actionable

**FAIL if:**
- Privilege error produces raw "3523" or similar error code with no guidance
- View-not-found error produces no message or raw error code
- REPL hangs or crashes on any error
- Error message references no DBC view

## Notes

- Unit tests run without database (no `#[ignore]`)
- Interactive test validates both error and success paths with one account type
- For comprehensive privilege error testing, a restricted user account is needed (manual)
- The "view not found" case is important because DBC.LockInfoV may not exist on all Teradata versions (Risk 1 from sprint planning)
- Pattern follows `sessions.rs` error handling (established Sprint 26, tested Sprint 27)
