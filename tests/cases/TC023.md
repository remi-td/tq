## Purpose

Verify that tq correctly escapes special characters in CSV output according to RFC 4180.

## Scope

This test validates:
- Comma escaping (field quoting)
- Quote escaping (quote doubling)
- Newline escaping (field quoting)
- Mixed special characters
- RFC 4180 compliance

## Prerequisites

- tq binary is built and available
- `.env` file configured with valid Teradata connection credentials

## Test Procedure

### Step 1: Field with commas
```bash
# Using credentials from .env file
tq query --format csv "SELECT 'Smith, John' AS name, 'Engineer, Senior' AS title"
```

### Step 2: Field with quotes
```bash
tq query --format csv "SELECT 'Say \"Hello\"' AS message"
```

### Step 3: Field with newlines
```bash
tq query --format csv "SELECT 'Line 1
Line 2' AS multiline"
```

### Step 4: Field with all special characters
```bash
tq query --format csv "SELECT 'Text with, comma \"and\" quote
and newline' AS complex"
```

### Step 5: Multiple rows with special characters
```bash
tq query --format csv "SELECT 'Normal' AS col1, 'With, comma' AS col2
UNION ALL
SELECT 'With \"quote\"', 'Normal'
UNION ALL
SELECT 'With
newline', 'Also, comma'"
```

### Step 6: Validate with CSV parser
```bash
tq query --format csv "SELECT 'Smith, John' AS name, 25 AS age" > /tmp/test.csv
# Try to parse with Python or other CSV tool
python3 -c "import csv; print(list(csv.reader(open('/tmp/test.csv'))))"
rm /tmp/test.csv
```

### Step 7: Empty fields and special chars
```bash
tq query --format csv "SELECT '' AS empty, 'With, comma' AS filled, '' AS empty2"
```

## Expected Results

### Step 1 Output:
```csv
name,title
"Smith, John","Engineer, Senior"
```
Fields with commas are quoted

### Step 2 Output:
```csv

"Say ""Hello"""
```
Quotes are doubled inside quoted field

### Step 3 Output:

```csv
"Line 1
Line 2"
```
Field with newline is quoted
Newline preserved inside quotes

### Step 4 Output:

All special characters properly escaped

## Pass/Fail Criteria

**PASS if:**
- Commas cause field quoting
- Quotes are doubled (escaped)
- Newlines cause field quoting and are preserved
- All special characters handled correctly
- Output is RFC 4180 compliant
- Standard CSV parsers can read the output
- No data corruption

**FAIL if:**
- Special characters not escaped
- Output cannot be parsed by standard tools
- Data corruption or loss
- Invalid CSV syntax
- Non-compliant with RFC 4180

## Notes

- RFC 4180 is the CSV standard
- Key rules:
  - Fields with commas, quotes, or newlines must be quoted
  - Quotes inside quoted fields are doubled ("")
  - CRLF or LF line endings
- Excel/LibreOffice should be able to open these files
- Python csv module is good validation tool
- Consider testing with various CSV validators
- Important for data exchange and import/export workflows
