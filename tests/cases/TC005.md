## Purpose

Verify that `tq query --format csv` produces RFC 4180 compliant CSV output suitable for data exchange.

## Scope

This test validates:
- CSV format output
- RFC 4180 compliance
- Header row inclusion/omission
- Field quoting and escaping
- NULL handling
- Excel compatibility

## Prerequisites

- tq binary is built and available
- `.env` file configured with valid Teradata connection credentials

## Test Procedure

### Step 1: Basic CSV output
```bash
# Using credentials from .env file
tq query --format csv "SELECT 'Alice' AS name, 25 AS age, 'IT' AS dept"
```

### Step 2: CSV without headers
```bash
tq query --format csv --no-header "SELECT 1, 2, 3"
```

### Step 3: CSV with special characters (commas, quotes)
```bash
tq query --format csv "SELECT 'Smith, John' AS name, '\"Quote\"' AS field"
```

### Step 4: CSV with NULL values
```bash
tq query --format csv "SELECT 'Alice' AS name, NULL AS middle_name"
```

### Step 5: Redirect to file
```bash
tq query --format csv "SELECT 1, 2, 3" > output.csv
cat output.csv
```

### Step 6: Use --output flag
```bash
tq query --format csv --output results.csv "SELECT 'test' AS col"
cat results.csv
```

## Expected Results

### Step 1 Output:
```csv
name,age,dept
Alice,25,IT
```
- Header row present
- Fields separated by commas
- No unnecessary quoting
- Unix line endings (\n)

### Step 2 Output:
```csv
1,2,3
```
No header row

### Step 3 Output:
```csv
name,field
"Smith, John","\"Quote\""
```
- Fields with commas are quoted
- Internal quotes are doubled
- Proper escaping

### Step 4 Output:
```csv
name,middle_name
Alice,
```
NULL represented as empty field

### Step 5 Output:
File contains:
```csv
1,2,3
```
Exit code: 0

### Step 6 Output:
results.csv contains:
```csv
col
test
```
Exit code: 0

## Pass/Fail Criteria

**PASS if:**
- Output is valid CSV (RFC 4180 compliant)
- Headers present by default, absent with --no-header
- Special characters properly quoted and escaped
- NULL values become empty fields
- File output works correctly
- Exit code is 0
- Can be imported into Excel/LibreOffice without errors

**FAIL if:**
- Invalid CSV syntax
- Missing or malformed headers
- Improper quoting/escaping
- NULL handling incorrect
- File I/O fails
- Exit code is non-zero

## Notes

- CSV is ideal for data exchange with spreadsheet applications
- RFC 4180 compliance ensures compatibility
- Consider testing with large datasets
- May need to test with various data types (dates, timestamps, etc.)
