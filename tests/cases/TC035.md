## Purpose

Verify that column metadata is cached efficiently per table and cache is invalidated appropriately on connection changes.

## Scope

This test validates:
- Per-table caching (not global)
- Cache persists across queries for same table
- Different tables have separate caches
- Cache cleared on /logon
- Performance improvement from caching

## Prerequisites

- tq binary built in release mode
- Valid Teradata connection credentials configured in .env
- Test database with multiple tables
- REPL mode functional
- /logon metacommand working

## Test Procedure

### Step 1: Start REPL and load columns for first table
```bash
tq repl
```

```sql
tq> SELECT * FROM employees WHERE <TAB>
# Note "Loading columns for 'employees'..." message
```

### Step 2: Request columns for same table again
```sql
tq> SELECT * FROM employees ORDER BY <TAB>
```

**Expected behavior:**
- No "Loading columns..." message
- Instant response (< 50ms)
- Same column list as Step 1

### Step 3: Request columns for different table
```sql
tq> SELECT * FROM departments WHERE <TAB>
```

**Expected behavior:**
- Shows "Loading columns for 'departments'..." (new table)
- Loads metadata for departments
- Different column list than employees

### Step 4: Return to first table
```sql
tq> SELECT * FROM employees WHERE <TAB>
```

**Expected behavior:**
- Instant (still cached from Step 1)
- No reload message

### Step 5: Switch connection with /logon
```sql
tq> /logon user:pass@host:1025/other_database
```

### Step 6: Request columns after connection change
```sql
tq[other_database]> SELECT * FROM employees WHERE <TAB>
```

**Expected behavior:**
- Shows "Loading columns..." again (cache cleared)
- Loads from new database
- May show different columns if schema differs

### Step 7: Test cache size limit (if implementing limit)
```sql
# Request columns for many different tables (> cache limit)
tq> SELECT * FROM table1 WHERE <TAB>
tq> SELECT * FROM table2 WHERE <TAB>
tq> SELECT * FROM table3 WHERE <TAB>
# ... continue for 100+ tables if available
```

**Expected behavior:**
- Older cached tables evicted when limit reached
- Least recently used (LRU) eviction
- No memory exhaustion

## Pass/Fail Criteria

**PASS if:**
- Columns cached per table
- Cache persists across multiple queries
- Different tables cached independently
- Cache cleared on /logon
- Performance improvement measurable (instant vs. 300ms)
- Cache size limited (no memory leak)
- LRU eviction works (if implemented)

**FAIL if:**
- No caching (reloads every time)
- Cache shared across tables incorrectly
- Cache not cleared on connection change
- Memory leak with many tables
- Performance not improved by cache

## Notes

- Caching critical for good UX
- Per-table cache more efficient than global
- Cache limit prevents memory exhaustion with many tables
- Typical cache size: 100 tables (configurable)
- LRU eviction ensures most-used tables stay cached
- Connection change must invalidate all cached columns
