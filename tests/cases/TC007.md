## Purpose

Verify that tq properly rejects invalid connection string formats with clear error messages.

## Scope

This test validates:
- Error detection for invalid formats
- Clear error messages
- Exit code 2 for usage errors
- Helpful suggestions in error output

## Prerequisites

- tq binary is built and available
- `.env` file can be temporarily removed/modified for testing

## Test Procedure

### Step 1: Completely invalid string
```bash
tq -l "invalid" ping 2>&1
echo "Exit code: $?"
```

### Step 2: Missing port
```bash
tq -l "user:pass@host/database" ping 2>&1
echo "Exit code: $?"
```

### Step 3: Invalid port (non-numeric)
```bash
tq -l "user:pass@host:abc/database" ping 2>&1
echo "Exit code: $?"
```

### Step 4: Missing host
```bash
tq -l "user:pass@:1025/database" ping 2>&1
echo "Exit code: $?"
```

### Step 5: Missing database
```bash
tq -l "user:pass@host:1025/" ping 2>&1
echo "Exit code: $?"
```

### Step 6: Empty connection string
```bash
tq -l "" ping 2>&1
echo "Exit code: $?"
```

### Step 7: No connection string at all
```bash
# Temporarily remove .env and unset environment variable
mv .env .env.backup 2>/dev/null || true
unset TQ_LOGON
tq ping 2>&1
echo "Exit code: $?"
# Restore .env
mv .env.backup .env 2>/dev/null || true
```

## Expected Results

### Step 1 Output (stderr):
```
Error: Invalid connection string format

Expected format: user:password@host:port/database
Received: invalid

Examples:
  alice:secret@dbhost:1025/mydb
  alice@dbhost:1025/mydb  (password from file or prompt)
```
Exit code: 2

### Step 2 Output (stderr):
```
Error: Invalid connection string format

Missing port number in connection string: user:pass@host/database

Expected format: user:password@host:port/database
```
Exit code: 2

### Step 3 Output (stderr):
```
Error: Invalid port number

Port must be a number between 1 and 65535
Received: abc
```
Exit code: 2

### Step 4-6 Output:
Similar error messages indicating the specific missing component
Exit code: 2

### Step 7 Output (stderr):
```
Error: Connection string not provided

Provide connection via:
  - --logon flag: tq -l "user:pass@host:1025/db" ping
  - TQ_LOGON environment variable
  - .env file in project directory
  - Configuration file (~/.config/tq/config.toml)
```
Exit code: 2

## Pass/Fail Criteria

**PASS if:**
- All invalid formats are rejected
- Exit code is 2 (usage error) for all cases
- Error messages clearly state what's wrong
- Error messages suggest correct format
- No stack traces or panics
- Errors written to stderr

**FAIL if:**
- Invalid formats are accepted
- Exit code is wrong (0 or 1)
- Error messages are unclear
- Program crashes or panics
- Errors on stdout instead of stderr

## Notes

- Usage errors (invalid input) should have exit code 2
- Runtime errors (connection failures) should have exit code 1
- Error messages should be actionable and educational
- Consider showing examples of correct format
