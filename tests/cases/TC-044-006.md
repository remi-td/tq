# TC-044-006: Profile Flag Naming - --logmech and --password-file Work on Profile Subcommands

**Sprint:** 44
**Feature:** Profile Flag Naming Fix (Sprint 43 Deferred)
**Acceptance Criteria:** AC-13, AC-14, AC-15
**Type:** CLI Integration Test + Unit Test Regression
**Requires DB:** No
**Requires Binary:** Yes (cargo build)

---

## Objective

Verify that `tq profile add` and `tq profile edit` subcommands accept `--logmech` and `--password-file` flags (the correct names aligned with global args), and that the old `--auth` and `--pass-file` flags are rejected.

Also verify that using `--logmech` globally and `--logmech` in the profile subcommand simultaneously does not cause a clap argument conflict.

## Preconditions

- Binary built: `cargo build`
- `TQ_CONFIG_DIR` environment variable used to redirect config to temp dir

## Test Scenarios

### Scenario 1: `--logmech` flag accepted on `tq profile add` (AC-13)

**Command:**
```bash
TQ_CONFIG_DIR=/tmp/tq-test-$$ tq profile add dev --host myhost --logmech LDAP
```

**Expected:** Exit code 0

**Assert:**
- Exit code equals 0
- `/tmp/tq-test-$$/config.toml` contains `logmech = "LDAP"`

### Scenario 2: `--password-file` flag accepted on `tq profile add` (AC-14)

**Command:**
```bash
TQ_CONFIG_DIR=/tmp/tq-test-$$ tq profile add dev --host myhost --password-file /tmp/mypasswd
```

**Expected:** Exit code 0

**Assert:**
- Exit code equals 0
- Config file contains `password_file = "/tmp/mypasswd"`

### Scenario 3: Old `--auth` flag rejected (AC-13)

**Command:**
```bash
TQ_CONFIG_DIR=/tmp/tq-test-$$ tq profile add dev --host myhost --auth LDAP
```

**Expected:** Exit code non-zero (clap error: unrecognized argument `--auth`)

**Assert:** Exit code != 0

### Scenario 4: Old `--pass-file` flag rejected (AC-14)

**Command:**
```bash
TQ_CONFIG_DIR=/tmp/tq-test-$$ tq profile add dev --host myhost --pass-file /tmp/pw
```

**Expected:** Exit code non-zero (clap error: unrecognized argument `--pass-file`)

**Assert:** Exit code != 0

### Scenario 5: No clap conflict when global and subcommand both use `--logmech` (AC-15)

**Command:**
```bash
TQ_CONFIG_DIR=/tmp/tq-test-$$ tq --logmech TD2 profile add dev --host myhost --logmech LDAP
```

**Expected:** Exit code 0 (no panic, no "argument used multiple times" error)

**Assert:**
- Exit code 0
- Config file contains `logmech = "LDAP"` (profile logmech takes the subcommand value)

### Scenario 6: `--logmech` flag accepted on `tq profile edit` (AC-13 regression)

**Setup:** Pre-existing profile `dev` with `logmech = "TD2"` in temp config

**Command:**
```bash
TQ_CONFIG_DIR=/tmp/tq-test-$$ tq profile edit dev --logmech LDAP
```

**Expected:** Exit code 0, config updated to `logmech = "LDAP"`

## Implementation

```rust
// tests/cli_profile_flags.rs

use std::process::Command;
use tempfile::TempDir;

fn tq_binary() -> std::path::PathBuf {
    let mut path = std::path::PathBuf::from(env!("CARGO_MANIFEST_DIR"));
    path.push("target/debug/tq");
    path
}

fn run_tq(args: &[&str], config_dir: &std::path::Path) -> std::process::Output {
    Command::new(tq_binary())
        .args(args)
        .env("TQ_CONFIG_DIR", config_dir)
        .output()
        .expect("Failed to run tq binary")
}

#[test]
fn test_profile_add_accepts_logmech_flag() {
    let dir = TempDir::new().unwrap();
    let output = run_tq(
        &["profile", "add", "dev", "--host", "myhost", "--logmech", "LDAP"],
        dir.path(),
    );
    assert!(output.status.success(), "Expected exit 0, got: {:?}\nstderr: {}",
        output.status,
        String::from_utf8_lossy(&output.stderr));

    let config = std::fs::read_to_string(dir.path().join("config.toml")).unwrap();
    assert!(config.contains("logmech = \"LDAP\""),
        "Config should contain logmech = \"LDAP\", got:\n{}", config);
}

#[test]
fn test_profile_add_accepts_password_file_flag() {
    let dir = TempDir::new().unwrap();
    let output = run_tq(
        &["profile", "add", "dev", "--host", "myhost", "--password-file", "/tmp/pw"],
        dir.path(),
    );
    assert!(output.status.success());

    let config = std::fs::read_to_string(dir.path().join("config.toml")).unwrap();
    assert!(config.contains("password_file"));
}

#[test]
fn test_profile_add_rejects_old_auth_flag() {
    let dir = TempDir::new().unwrap();
    let output = run_tq(
        &["profile", "add", "dev", "--host", "myhost", "--auth", "LDAP"],
        dir.path(),
    );
    assert!(!output.status.success(),
        "Expected non-zero exit when using deprecated --auth flag");
}

#[test]
fn test_profile_add_rejects_old_pass_file_flag() {
    let dir = TempDir::new().unwrap();
    let output = run_tq(
        &["profile", "add", "dev", "--host", "myhost", "--pass-file", "/tmp/pw"],
        dir.path(),
    );
    assert!(!output.status.success(),
        "Expected non-zero exit when using deprecated --pass-file flag");
}

#[test]
fn test_no_clap_conflict_global_and_profile_logmech() {
    let dir = TempDir::new().unwrap();
    let output = run_tq(
        &["--logmech", "TD2", "profile", "add", "dev", "--host", "myhost", "--logmech", "LDAP"],
        dir.path(),
    );
    assert!(output.status.success(),
        "Should not have clap conflict when both global and profile use --logmech.\nstderr: {}",
        String::from_utf8_lossy(&output.stderr));
}
```

## Pass Criteria

- Scenarios 1, 2, 5, 6 exit with code 0
- Scenarios 3, 4 exit with non-zero code
- Config file contains expected values after successful operations
- No panic or "error: The argument was provided more than once" clap messages
