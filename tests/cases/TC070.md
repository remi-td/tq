# Test Case TC070: Batch Mode - Comprehensive Error Handling

## Purpose

Verify that all batch mode error conditions are handled gracefully with clear, actionable error messages and correct exit codes.

## Scope

**Testing:**
- File I/O errors (not found, permissions, empty)
- Input source conflicts (multiple sources)
- SQL execution errors
- Connection failures
- Error message quality and clarity
- Exit code correctness
- Stream separation (errors on stderr)

**Not Testing:**
- Success cases (covered in TC066-TC069)
- Interactive mode errors (different context)

## Prerequisites

- tq binary built in release mode
- Valid TQ_LOGON configured
- Live Teradata database connection (for some tests)
- Write access to /tmp for test files

## Test Procedure

### Category 1: File I/O Errors

#### Test 1.1: File Not Found

```bash
./target/release/tq query --file /tmp/nonexistent_file.sql
```

**Expected outcome:**
- Exit code: 2 (usage error)
- stderr contains:
  ```
  Error: File not found

  Could not read file: /tmp/nonexistent_file.sql
  Reason: No such file or directory

  Check:
    - File path is correct (relative or absolute)
    - File exists and is readable
    - Current directory: /path/to/current/dir
  ```
- stdout: empty
- Error is actionable and helpful

#### Test 1.2: Permission Denied

```bash
cat > /tmp/no_read_perm.sql <<'EOF'
SELECT 1;
EOF
chmod 000 /tmp/no_read_perm.sql

./target/release/tq query --file /tmp/no_read_perm.sql
```

**Expected outcome:**
- Exit code: 2 (usage error)
- stderr contains:
  ```
  Error: Cannot read file

  Could not read file: /tmp/no_read_perm.sql
  Reason: Permission denied

  Check:
    - File has read permissions
    - User has access to file
  ```
- stdout: empty

**Cleanup:**
```bash
chmod 644 /tmp/no_read_perm.sql
rm /tmp/no_read_perm.sql
```

#### Test 1.3: Empty File

```bash
touch /tmp/empty.sql
./target/release/tq query --file /tmp/empty.sql
```

**Expected outcome:**
- Exit code: 2 (usage error)
- stderr contains:
  ```
  Error: Empty query

  File '/tmp/empty.sql' contains no SQL statements.

  Provide at least one SQL statement.
  ```
- stdout: empty

**Cleanup:**
```bash
rm /tmp/empty.sql
```

#### Test 1.4: File is Directory

```bash
mkdir -p /tmp/test_dir
./target/release/tq query --file /tmp/test_dir
```

**Expected outcome:**
- Exit code: 2 (usage error)
- stderr contains:
  ```
  Error: Invalid file

  Path is a directory, not a file: /tmp/test_dir

  Provide a path to a SQL file.
  ```
- stdout: empty

**Cleanup:**
```bash
rmdir /tmp/test_dir
```

### Category 2: Input Source Conflicts

#### Test 2.1: Multiple Input Sources (argument + stdin)

```bash
echo "SELECT 1" | ./target/release/tq query "SELECT 2"
```

**Expected outcome:**
- Exit code: 2 (usage error)
- stderr contains:
  ```
  Error: Multiple input sources provided

  You specified both a query argument and piped stdin.
  Only one input source is allowed.

  Use one of:
    - Query argument: tq query "SELECT ..."
    - File input: tq query --file script.sql
    - stdin: echo "SELECT ..." | tq query
  ```
- stdout: empty

#### Test 2.2: Multiple Input Sources (argument + file)

```bash
cat > /tmp/test.sql <<'EOF'
SELECT 1;
EOF

./target/release/tq query "SELECT 2" --file /tmp/test.sql
```

**Expected outcome:**
- Exit code: 2 (usage error)
- stderr contains:
  ```
  Error: Multiple input sources provided

  You specified both a query argument and --file flag.
  Only one input source is allowed.

  Remove either the query argument or the --file flag.
  ```
- stdout: empty

**Cleanup:**
```bash
rm /tmp/test.sql
```

#### Test 2.3: Multiple Input Sources (file + stdin)

```bash
cat > /tmp/test.sql <<'EOF'
SELECT 1;
EOF

echo "SELECT 2" | ./target/release/tq query --file /tmp/test.sql
```

**Expected outcome:**
- Exit code: 2 (usage error)
- stderr contains:
  ```
  Error: Multiple input sources provided

  You specified both --file flag and piped stdin.
  Only one input source is allowed.

  Remove either the --file flag or stdin input.
  ```
- stdout: empty

**Cleanup:**
```bash
rm /tmp/test.sql
```

### Category 3: SQL Execution Errors

#### Test 3.1: SQL Syntax Error (single statement)

```bash
echo "INVALID SQL SYNTAX" | ./target/release/tq query
```

**Expected outcome:**
- Exit code: 1 (runtime error)
- stderr contains Teradata error message:
  ```
  Error: SQL syntax error

  Expected something like a 'SELECT' keyword but found 'INVALID'.

  Error Code: 3706
  Session ID: [session-id]

  Failed statement:
    INVALID SQL SYNTAX
  ```
- stdout: empty
- No credential leaks in error

#### Test 3.2: Table Not Found

```bash
echo "SELECT * FROM nonexistent_table_xyz" | ./target/release/tq query
```

**Expected outcome:**
- Exit code: 1 (runtime error)
- stderr contains:
  ```
  Error: Table not found

  Object 'nonexistent_table_xyz' does not exist.

  Error Code: 3807
  Session ID: [session-id]

  Check:
    - Table name is spelled correctly
    - Table exists in current database
    - User has SELECT permission on table
  ```
- stdout: empty

#### Test 3.3: Permission Denied

```bash
# This test requires a table the user doesn't have permission to access
# Adjust table name as needed for test environment
echo "SELECT * FROM restricted_table" | ./target/release/tq query
```

**Expected outcome (if permission denied):**
- Exit code: 1 (runtime error)
- stderr contains:
  ```
  Error: Permission denied

  User '[username]' does not have SELECT privilege on 'restricted_table'.

  Error Code: 3523
  Session ID: [session-id]

  Contact your DBA to grant access.
  ```
- stdout: empty

#### Test 3.4: SQL Error in Multiple Statements

```bash
cat > /tmp/error_multi.sql <<'EOF'
SELECT 1 AS stmt1;
SELECT 2 AS stmt2;
INVALID SQL;
SELECT 4 AS stmt4;
EOF

./target/release/tq query --file /tmp/error_multi.sql
```

**Expected outcome:**
- Exit code: 1 (runtime error)
- Statements 1-2 execute successfully
- Statement 3 fails
- Statements 4+ NOT executed (fail-fast)
- stderr contains:
  ```
  Error: SQL syntax error in statement 3

  Expected something like a 'SELECT' keyword but found 'INVALID'.

  Error Code: 3706
  Session ID: [session-id]

  Failed statement:
    INVALID SQL;

  Statements executed: 1-2
  Statements failed: 3 (stopped here)
  Statements remaining: 4
  ```
- stdout contains results from statements 1-2

**Cleanup:**
```bash
rm /tmp/error_multi.sql
```

### Category 4: Connection Errors

#### Test 4.1: Connection Failure (bad credentials)

```bash
echo "SELECT 1" | ./target/release/tq query -l baduser:badpass@localhost:1025/dbc
```

**Expected outcome:**
- Exit code: 1 (runtime error)
- stderr contains:
  ```
  Error: Authentication failed

  Could not connect to Teradata database.
  Reason: Invalid username or password

  Check:
    - Username and password are correct
    - User account is active
    - Authentication mechanism is appropriate
  ```
- stdout: empty
- No password in error message (security)

#### Test 4.2: Connection Failure (bad host)

```bash
echo "SELECT 1" | ./target/release/tq query -l user:pass@nonexistent.host:1025/dbc
```

**Expected outcome:**
- Exit code: 1 (runtime error)
- stderr contains:
  ```
  Error: Connection failed

  Could not connect to Teradata database at 'nonexistent.host:1025'.
  Reason: Host not found or unreachable

  Check:
    - Hostname is correct
    - Port is correct (usually 1025)
    - Network connectivity
    - Firewall settings
  ```
- stdout: empty

### Category 5: No Input Provided

#### Test 5.1: No Input (TTY)

```bash
./target/release/tq query
# (assuming stdin is a TTY, not piped)
```

**Expected outcome:**
- Exit code: 2 (usage error)
- stderr contains:
  ```
  Error: No query provided

  Use 'tq query "SELECT ..."' or pipe SQL via stdin.

  Examples:
    tq query "SELECT 1"
    tq query --file script.sql
    echo "SELECT 1" | tq query
  ```
- stdout: empty

#### Test 5.2: Empty stdin

```bash
echo "" | ./target/release/tq query
```

**Expected outcome:**
- Exit code: 2 (usage error)
- stderr contains:
  ```
  Error: Empty query

  Provide SQL via argument, file, or stdin.
  ```
- stdout: empty

### Verification

**Critical Checks:**

1. **Exit Codes:**
   - [ ] Usage errors: exit code 2
   - [ ] Runtime errors: exit code 1
   - [ ] Success: exit code 0

2. **Error Messages:**
   - [ ] Clear and specific
   - [ ] Actionable suggestions
   - [ ] No credential leaks
   - [ ] Proper capitalization and grammar

3. **Stream Separation:**
   - [ ] Errors always on stderr
   - [ ] Data always on stdout
   - [ ] No mixing of streams

4. **Error Context:**
   - [ ] File path shown (when relevant)
   - [ ] Statement number shown (multiple statements)
   - [ ] Error code included (SQL errors)
   - [ ] Helpful suggestions provided

| Error Type | Exit Code | Stream | Key Message Elements |
|------------|-----------|--------|---------------------|
| File not found | 2 | stderr | Path, reason, suggestions |
| Permission denied | 2 | stderr | Path, reason, fix steps |
| Empty file | 2 | stderr | File path, requirement |
| Multiple inputs | 2 | stderr | What conflicts, how to fix |
| SQL syntax error | 1 | stderr | Error code, statement, location |
| Table not found | 1 | stderr | Table name, suggestions |
| Permission denied | 1 | stderr | Object, user, DBA contact |
| Connection failure | 1 | stderr | Reason, troubleshooting steps |
| No input | 2 | stderr | Usage examples |

## Pass/Fail Criteria

**PASS:**
- All error types handled gracefully
- Exit codes correct for all scenarios
- Error messages clear and actionable
- Errors always on stderr, never stdout
- No credential leaks in any error
- Stream separation correct
- Context appropriate to error type
- Suggestions helpful

**FAIL:**
- Any error crashes the tool
- Exit codes incorrect
- Error messages unclear or missing
- Errors mixed with data on stdout
- Credentials exposed in errors
- Missing context or suggestions
- Unhelpful or confusing messages

## Notes

**Exit Code Standards (from error-handling.md):**

| Exit Code | Meaning | Example |
|-----------|---------|---------|
| 0 | Success | Query executed successfully |
| 1 | Runtime error | SQL error, connection failure |
| 2 | Usage error | Invalid arguments, file not found |
| 130 | Interrupted | User pressed Ctrl-C |

**Error Message Quality Guidelines:**
1. Start with "Error: [Category]"
2. Explain what went wrong (specific)
3. Explain why (if known)
4. Suggest how to fix (actionable)
5. Never leak credentials

**Security Check:**
- grep error messages for password patterns
- Ensure connection strings sanitized in errors
- No secrets in stack traces or logs
