# Test Case TC066: Batch Mode - stdin Input with echo

## Purpose

Verify that tq can execute SQL queries piped from stdin using the echo command, enabling simple shell integration and one-liner usage.

## Scope

**Testing:**
- stdin detection (non-TTY input)
- SQL execution from piped input
- Output format control in batch mode
- Exit code correctness
- Stream separation (stdout/stderr)

**Not Testing:**
- File input (covered in TC067)
- Multiple statements (covered in TC069)
- Heredoc input (covered in TC068)

## Prerequisites

- tq binary built in release mode
- Valid TQ_LOGON configured in .env or environment
- Live Teradata database connection

## Test Procedure

### Setup

```bash
# Ensure database is accessible
./target/release/tq ping
```

### Execution Steps

#### Step 1: Simple query with echo (table format)

```bash
echo "SELECT 1 AS test_value" | ./target/release/tq query
```

**Expected outcome:**
- Exit code: 0
- stdout contains formatted table with value 1
- stderr: empty
- Table format rendered correctly
- No TTY-specific features (no colors, no paging)

#### Step 2: Query with JSON format

```bash
echo "SELECT 1 AS col1, 'test' AS col2" | ./target/release/tq query --format json
```

**Expected outcome:**
- Exit code: 0
- stdout contains valid JSON array:
  ```json
  [{"col1":1,"col2":"test"}]
  ```
- JSON is parseable with jq
- stderr: empty

#### Step 3: Query with CSV format

```bash
echo "SELECT 1 AS id, 'Alice' AS name" | ./target/release/tq query --format csv
```

**Expected outcome:**
- Exit code: 0
- stdout contains CSV with header:
  ```csv
  id,name
  1,Alice
  ```
- RFC 4180 compliant
- stderr: empty

#### Step 4: Multi-line SQL (single statement)

```bash
echo "SELECT employee_id, salary
FROM DBC.EmployeesV
WHERE salary > 50000
SAMPLE 5" | ./target/release/tq query
```

**Expected outcome:**
- Exit code: 0
- Multi-line SQL parsed correctly
- Results returned
- stderr: empty

#### Step 5: Empty input

```bash
echo "" | ./target/release/tq query
```

**Expected outcome:**
- Exit code: 2 (usage error)
- stderr contains clear error message:
  ```
  Error: Empty query

  Provide SQL via argument, file, or stdin.
  ```
- stdout: empty

#### Step 6: Whitespace-only input

```bash
echo "   " | ./target/release/tq query
```

**Expected outcome:**
- Exit code: 2 (usage error)
- stderr contains error about empty query
- stdout: empty

#### Step 7: Invalid SQL

```bash
echo "INVALID SQL SYNTAX" | ./target/release/tq query
```

**Expected outcome:**
- Exit code: 1 (runtime error)
- stderr contains Teradata SQL error message
- Error message is clear and actionable
- No credential leaks in error output
- stdout: empty

### Verification

**Critical Checks:**

1. **stdin Detection:**
   - [ ] tq correctly detects piped input
   - [ ] Reads entire stdin until EOF
   - [ ] No prompt or interactive behavior

2. **Output Correctness:**
   - [ ] All formats work correctly (table, JSON, CSV)
   - [ ] Output goes to stdout only
   - [ ] No batch mode artifacts (timing, session info)

3. **Error Handling:**
   - [ ] Empty input rejected with clear error
   - [ ] SQL errors reported on stderr
   - [ ] Exit codes correct for all scenarios

4. **Stream Separation:**
   - [ ] Data always on stdout
   - [ ] Errors always on stderr
   - [ ] No mixing of streams

## Expected Results

### Success Case (Simple Query)

```bash
$ echo "SELECT 1 AS test_value" | tq query
┌────────────┐
│ test_value │
├────────────┤
│ 1          │
└────────────┘
```

### Success Case (JSON)

```bash
$ echo "SELECT 1 AS col1" | tq query --format json
[{"col1":1}]
```

### Error Case (Empty Input)

```bash
$ echo "" | tq query
Error: Empty query

Provide SQL via argument, file, or stdin.

$ echo $?
2
```

### Error Case (SQL Error)

```bash
$ echo "INVALID SQL" | tq query
Error: SQL syntax error

[Teradata error details]

$ echo $?
1
```

## Pass/Fail Criteria

**PASS:**
- stdin input works with echo command
- All output formats function correctly
- Empty input rejected with clear error
- SQL errors reported properly
- Exit codes correct (0 for success, 1 for SQL error, 2 for usage error)
- stdout/stderr separation correct
- No TTY-specific features in batch mode

**FAIL:**
- stdin not detected or not read
- Output goes to wrong stream
- Empty input causes crash or hang
- Errors not reported clearly
- Exit codes incorrect
- Batch mode shows interactive features (colors, paging)

## Notes

**stdin Detection Method:**
- Use `atty::is(atty::Stream::Stdin)` to detect piped input
- When stdin is not a TTY, read until EOF
- Treat as batch mode (no interactive features)

**Batch Mode Behavior (from batch-mode.md section 6.2.4):**
> "Automatically detected (stdin is not a TTY)
> Supports multi-statement execution
> Ideal for shell scripts and pipelines
> Works with pipes, redirects, and heredocs"

**Performance Expectation:**
- Minimal overhead vs direct query argument
- Connection time dominates (100-200ms)
- stdin reading should be <10ms
