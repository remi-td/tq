# Test Case TC081: Regression Test - Batch Mode Features Still Work (Sprint 10)

## Purpose

Verify that Sprint 10 batch mode features still work correctly after Sprint 11 fixes. Ensure we didn't break batch mode while fixing REPL bugs.

This is a REGRESSION TEST - ensuring Sprint 10 functionality intact.

## Scope

**Testing:**
- Batch mode execution (non-interactive)
- stdin input processing
- File input processing
- Exit code correctness
- Error handling in batch mode
- All Sprint 10 features functional

**Not Testing:**
- REPL features (other TCs)
- New Sprint 11 features

## Prerequisites

- tq binary with Sprint 11 fixes
- Teradata connection available
- Test SQL files
- Sprint 10 passed all batch mode tests

## Test Procedure

### Setup

```bash
# Create test SQL files
echo "SELECT 1 AS test_col;" > test1.sql
echo "SELECT DatabaseName FROM DBC.DatabasesV LIMIT 5;" > test2.sql
echo "INVALID SQL SYNTAX;" > test_error.sql
```

### Execution Steps

**Step 1: Test batch mode with command argument**

```bash
./target/release/tq query "SELECT 1 AS test;"
```

**Expected outcome:**
- Executes successfully
- Shows result table
- Exit code 0

**Step 2: Test batch mode with file input**

```bash
./target/release/tq query --file test1.sql
```

**Expected outcome:**
- Reads and executes file
- Shows result
- Exit code 0

**Step 3: Test batch mode with stdin**

```bash
echo "SELECT 2 AS value;" | ./target/release/tq query
```

**Expected outcome:**
- Reads from stdin
- Executes query
- Shows result
- Exit code 0

**Step 4: Test exit code on error**

```bash
./target/release/tq query "INVALID SQL;"
echo "Exit code: $?"
```

**Expected outcome:**
- Shows error message on stderr
- Exit code != 0 (non-zero)
- Proper error handling

**Step 5: Test multiple format outputs**

```bash
./target/release/tq query "SELECT 1 AS col1, 2 AS col2;" --format json
./target/release/tq query "SELECT 1 AS col1, 2 AS col2;" --format csv
./target/release/tq query "SELECT 1 AS col1, 2 AS col2;" --format table
```

**Expected outcome:**
- JSON format produces valid JSON
- CSV format produces valid CSV
- Table format produces table
- All formats work correctly

**Step 6: Test batch mode with connection string**

```bash
./target/release/tq query --connection "$TQ_LOGON" "SELECT 1 AS test;"
```

**Expected outcome:**
- Connection override works
- Query executes
- Exit code 0

**Step 7: Test piped output**

```bash
./target/release/tq query "SELECT DatabaseName FROM DBC.DatabasesV LIMIT 5;" | grep -i "dbc"
```

**Expected outcome:**
- Pipe works correctly
- Output parseable
- grep finds matches

### Verification

**Batch Mode Checklist:**

- [ ] Command argument execution works
- [ ] File input works
- [ ] stdin input works
- [ ] Exit codes correct (0 success, non-zero error)
- [ ] Error messages on stderr
- [ ] Data output on stdout
- [ ] All formats work (json, csv, table)
- [ ] Connection override works
- [ ] Piping works

**Regression Check:**

Compare to Sprint 10 test results:
- [ ] All Sprint 10 tests still pass
- [ ] No new failures introduced
- [ ] Performance similar
- [ ] Behavior unchanged

### Cleanup

```bash
rm -f test1.sql test2.sql test_error.sql
```
