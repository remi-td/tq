# TC-042-003: Comment Blocks Between Statements (Bug #30)

**Test ID:** TC-042-003
**Feature:** SQL Parser - Comment-Aware Statement Splitting
**Priority:** P0 - Critical
**Test Type:** Unit
**Sprint:** 42
**Created:** 2026-03-21
**Requirement References:** REQ-PARSE-003, REQ-PARSE-008, REQ-PARSE-009, REQ-PARSE-010, REQ-PARSE-011, REQ-PARSE-012, REQ-PARSE-013, REQ-PARSE-014, AC-4, AC-5, AC-6, AC-11
**GitHub Issue:** #30 - SQL comment blocks cause parser misalignment

---

## Objective

Verify that the new parser correctly handles line comments (`-- ...`) and block comments (`/* ... */`) in all positions: within a statement, at the end of a line, between statements, and spanning multiple lines. Verify that comment content is stripped from the statement text (per REQ-PARSE-009), that semicolons inside comments are not treated as statement terminators, and that unterminated block comments produce a proper parse error.

## Background

Bug #30 describes a failure where comments between statements contaminate the next statement. For example:

```sql
SELECT 1;
-- This comment sits between statements
SELECT 2;
```

With the naive `split(';')` parser, this was handled accidentally (the comment text ended up as part of `SELECT 2`'s prefix). But more complex cases like:

```sql
SELECT 1; -- inline comment; this semicolon must be ignored
SELECT 2;
```

would incorrectly split into THREE statements instead of two.

The new parser must:
1. Ignore semicolons inside comments
2. Strip comment content from statement text
3. Not let comment-only segments count as statements

## Test Cases

All tests are unit tests in `src/sql/parser.rs` `#[cfg(test)]` module.

### Line Comment Tests

#### TS42-U11: Line comment content is stripped from statement

```rust
#[test]
fn test_line_comment_stripped_from_statement() {
    // REQ-PARSE-009: line comment is stripped before statement assembly
    // The newline ending the comment is preserved as whitespace
    let sql = "SELECT 1 -- this is a comment\n;";
    let statements = parse_statements(sql).expect("parse should succeed");
    assert_eq!(statements.len(), 1);
    assert!(
        !statements[0].sql.contains("-- this is a comment"),
        "line comment must be stripped from statement SQL text"
    );
    assert!(statements[0].sql.contains("SELECT 1"));
}
```

**Expected Result:** 1 statement; the `-- this is a comment` part is absent from the `sql` field.

---

#### TS42-U12: Semicolon inside line comment is NOT a statement terminator

```rust
#[test]
fn test_line_comment_semicolon_not_terminator() {
    // REQ-PARSE-008: semicolons inside -- comments are not terminators
    // The spec example: SELECT 1 -- use ';' to end; ok
    // followed by the actual terminator on the next line
    let sql = "SELECT 1 -- inline; semicolon; inside comment\n;\nSELECT 2;";
    let statements = parse_statements(sql).expect("parse should succeed");
    assert_eq!(
        statements.len(), 2,
        "semicolons in line comments must not split statements; expected 2, got {}",
        statements.len()
    );
    assert!(statements[0].sql.contains("SELECT 1"));
    assert!(statements[1].sql.contains("SELECT 2"));
}
```

**Expected Result:** 2 statements (not 4).

#### TS42-U19: Line-comment-only segment between statements is discarded

```rust
#[test]
fn test_line_comment_only_between_statements() {
    // REQ-PARSE-003: comment-only segments after stripping are empty, so discarded
    // AC-6: comments between statements do not contaminate adjacent statements
    let sql = "SELECT 1;\n-- just a comment\nSELECT 2;";

    assert_eq!(statements.len(), 2);
    assert!(statements[0].sql.contains("SELECT 1"));
    assert!(statements[1].sql.contains("SELECT 2"));
    // The comment text must not appear in either statement
    assert!(
        !statements[0].sql.contains("just a comment"),
        "comment must not contaminate first statement"
    );
    assert!(
        !statements[1].sql.contains("just a comment"),
        "comment must not contaminate second statement"
    );
}
```

**Expected Result:** 2 clean statements; no comment text in either.

#### TS42-U17: Unterminated block comment produces error

```rust
#[test]
fn test_unterminated_block_comment_error() {
    // REQ-PARSE-013: EOF inside block comment is a parse error
    let sql = "SELECT 1;\n/* unterminated block comment";
    let result = parse_statements(sql);

    );
}
```

**Expected Result:** `Err(...)` with line 2 mentioned.

### Between-Statement Comment Tests

#### TS42-U18: Comment between statements does not contaminate either

```rust
#[test]
fn test_comment_between_statements_no_contamination() {
    // AC-6: comments between statements must not contaminate adjacent statements
    // This is the core of bug #30
    let sql = "SELECT 1;\n/* comment between statements */\nSELECT 2;";
    let statements = parse_statements(sql).expect("parse should succeed");
    assert_eq!(statements.len(), 2);
    // First statement: only SELECT 1
    assert!(statements[0].sql.contains("SELECT 1"));
    assert!(
        !statements[0].sql.contains("comment between"),
        "first statement must not contain block comment"
    );
    // Second statement: only SELECT 2
    assert!(statements[1].sql.contains("SELECT 2"));
    assert!(
        !statements[1].sql.contains("comment between"),
        "second statement must not contain block comment"
    );
}
```

**Expected Result:** 2 clean statements; comment text absent from both.

## Acceptance Criteria

- [x] Line comments (`--`) are stripped from statement text (AC-4, REQ-PARSE-009)
- [x] Block comments (`/* */`) are stripped from statement text (AC-5, REQ-PARSE-010)
- [x] Semicolons inside line comments are NOT statement terminators (REQ-PARSE-008)
- [x] Semicolons inside block comments are NOT statement terminators (REQ-PARSE-010)
- [x] Block comments may span multiple lines (REQ-PARSE-011)
- [x] Nested block comments are not supported (first `*/` closes) (REQ-PARSE-012)
- [x] Unterminated block comments produce a parse error (REQ-PARSE-013)
- [x] Comments between statements do not contaminate adjacent statements (AC-6)
- [x] Comment-only segments are discarded (not counted as statements) (REQ-PARSE-003)
- [x] Line numbers remain accurate through all comment types (AC-8, REQ-PARSE-014)

## Execution Notes

Run with: `cargo test --lib sql::parser::tests::test_block_comment`
Or: `cargo test --lib sql::parser::tests::test_line_comment`

All tests are **no-database** unit tests.

Note: Tests TS42-U17 and TS42-U17b require `parse_statements()` to return a `Result`. If the architect chooses a different API for error reporting, the assertion forms must be adapted. The behavioral requirement (unterminated block comment = error with correct line number) remains invariant.

Note on comment stripping vs. preservation: The existing tests `test_parse_preserves_comments` and `test_parse_multiline_comment` in `src/sql/parser.rs` assert that comments ARE preserved in output. These tests conflict with REQ-PARSE-009 and must be updated by the architect to assert that comment-stripped SQL is the new expected behavior. The test cases in this document reflect the NEW specified behavior (comments stripped).
