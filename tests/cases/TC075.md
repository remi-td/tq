# Test Case TC075: Tab Completion - Error Handling When Metadata Unavailable

## Purpose

Verify that tab completion gracefully handles error conditions (permission denied, connection lost, timeout) and shows helpful error messages instead of crashing or showing garbage.

## Scope

**Testing:**
- Permission denied to DBC.TablesV
- Permission denied to DBC.ColumnsV
- Metadata query timeout
- Connection lost during completion
- Empty database (no tables)
- Helpful error messages shown

**Not Testing:**
- Happy path completion (other TCs)
- Performance under normal conditions

## Prerequisites

- tq REPL connected to Teradata
- Ability to test permission scenarios (or simulate)
- Test database that can be manipulated
- Network control for timeout testing (optional)

## Test Procedure

### Setup

```bash
./target/release/tq repl
tq> /ping  # Verify baseline connection
```

### Execution Steps

**Step 1: Test completion with no SELECT on DBC.TablesV**

*Note: This may require DBA to revoke permissions temporarily, or test with restricted user account*

```sql
tq> SELECT * FROM <TAB>
```

**Expected outcome:**
- Shows error message: "Cannot load table list (permission denied)"
- Suggests: "Contact DBA to grant SELECT on DBC.TablesV"
- Does NOT crash
- REPL remains usable
- Can still type table name manually

**Step 2: Test completion with empty database**

```sql
# Connect to empty database (or create one for testing)
tq> /logon user:pass@host:1025/empty_test_db
tq> SELECT * FROM <TAB>
```

**Expected outcome:**
- Shows message: "(No tables found in current database)"
- Does NOT show keywords
- Does NOT crash
- Graceful degradation

**Step 3: Test completion on non-existent table**

```sql
tq> SELECT * FROM nonexistent_table WHERE <TAB>
```

**Expected outcome:**
- Shows error: "Table 'nonexistent_table' not found"
- Suggests: "Check spelling or use /list tables"
- Cannot provide column completion
- Does NOT crash

**Step 4: Test timeout scenario (simulated or real)**

*If metadata query takes >500ms:*

```sql
tq> SELECT * FROM <TAB>
```

**Expected outcome:**
- Shows "Loading tables..." initially
- If timeout occurs: "Table list query timed out"
- Suggests: "Database may be slow. Try again or type manually."
- REPL recovers, doesn't hang forever

**Step 5: Test connection lost during completion**

*Simulate by network interruption or database shutdown*

```sql
tq> SELECT * FROM <TAB>
# While loading, disconnect network/database
```

**Expected outcome:**
- Shows error: "Connection lost. Cannot retrieve table list."
- Suggests: "Use /ping to check connection or /reconnect"
- REPL detects connection problem
- User informed of state

**Step 6: Verify REPL remains usable after errors**

After any error from Steps 1-5:

```sql
tq> /ping
tq> SELECT 1 AS test;
tq> /help
```

**Expected outcome:**
- REPL fully functional
- Errors don't corrupt state
- Can continue working
- Completion error doesn't break other features

### Verification

**Error Handling Checklist:**

- [ ] Errors show helpful messages (not stack traces)
- [ ] Errors suggest corrective actions
- [ ] No crashes on permission denied
- [ ] No crashes on timeout
- [ ] No crashes on connection loss
- [ ] REPL recovers gracefully
- [ ] Can continue working after error

**Message Quality Check:**

- [ ] Error messages are user-friendly
- [ ] Technical details included where helpful
- [ ] Suggestions are actionable
- [ ] Tone is professional, not blaming

### Cleanup

```bash
tq> /quit
```

## Expected Results

**Step 1 Output (Permission Denied):**

```
tq> SELECT * FROM <TAB>

Warning: Cannot load table list (permission denied to DBC.TablesV)
Tab completion for tables unavailable.

Suggestion: Contact DBA to grant SELECT on DBC.TablesV
```

**Step 2 Output (Empty Database):**

```
tq> SELECT * FROM <TAB>

(No tables found in current database 'empty_test_db')
```

**Step 3 Output (Table Not Found):**

```
tq> SELECT * FROM nonexistent_table WHERE <TAB>

Error: Table 'nonexistent_table' not found
Cannot provide column completion.

Suggestions:
  - Check spelling: /list tables non%
  - List all tables: /list tables
  - Use qualified name: database.table_name
```

**Step 4 Output (Timeout):**

```
tq> SELECT * FROM <TAB>

Loading tables...
Warning: Table list query timed out after 500ms
Tab completion for tables unavailable.

Suggestion: Database may be slow. Try again or continue typing manually.
```

**Step 5 Output (Connection Lost):**

```
tq> SELECT * FROM <TAB>

Loading tables...
Error: Connection lost. Cannot retrieve table list.

Use /ping to check connection or /reconnect to restore.
```

## Anti-Pattern (What Should NOT Happen)

**INCORRECT Behavior:**

```
tq> SELECT * FROM <TAB>

thread 'main' panicked at 'called `Result::unwrap()` on an `Err` value: PermissionDenied'
[Stack trace...]
[REPL crashes]
```

OR

```
tq> SELECT * FROM <TAB>

[Hangs forever, no feedback]
[User must Ctrl-C to kill]
```

OR

```
tq> SELECT * FROM <TAB>

(SQL keyword)  (SQL keyword)  (SQL keyword)  [Garbage fallback]
```

## Pass/Fail Criteria

**PASS:**
- Permission denied shows helpful error
- Empty database handled gracefully
- Nonexistent table shows error with suggestions
- Timeout doesn't hang REPL forever
- Connection loss detected and reported
- Error messages are actionable
- REPL remains usable after any error
- No crashes, panics, or hangs

**FAIL:**
- REPL crashes on any error condition
- Hangs forever without feedback
- Stack traces shown to user
- Cryptic error messages
- No suggestions provided
- REPL corrupted after error
- Shows garbage (keywords) as fallback

## Notes

**Error Handling Philosophy:**

Good error handling:
1. Never crash (catch all errors)
2. Explain what happened (clear message)
3. Explain why (technical detail if helpful)
4. Suggest how to fix (actionable steps)
5. Recover gracefully (REPL still works)

**Why This Test Matters:**

Completion runs user-triggered queries to DBC views:
- Permissions may be denied
- Database may be slow/unavailable
- Network may be unreliable
- Edge cases will happen in production

Robust error handling:
- Preserves user trust
- Prevents frustration
- Guides users to solutions
- Maintains tool reliability

**Testing Challenges:**

Some scenarios hard to test without infrastructure:
- Permission denial requires DBA or test account
- Timeout requires slow database or network throttling
- Connection loss requires network control

If can't test all scenarios:
- Review code for error handling
- Test what's possible
- Document untested scenarios
- Plan for staging environment testing

**Implementation Requirements:**

Every metadata query should:
```rust
match query_metadata() {
    Ok(data) => show_completions(data),
    Err(PermissionDenied) => show_permission_error(),
    Err(Timeout) => show_timeout_error(),
    Err(ConnectionLost) => show_connection_error(),
    Err(e) => show_generic_error(e),
}
```

Never:
```rust
let data = query_metadata().unwrap(); // DON'T DO THIS
```
