## Purpose

Verify end-to-end that the identifier quoting fix propagates correctly through the full command dispatch paths. Unit tests (TC-046-001, TC-046-002) validate the pure functions in isolation. This test validates that the call sites in `metacommands.rs` and `commands/sample.rs` correctly use the fixed `quote_identifier()` so that real Teradata queries succeed.

## Acceptance Criteria Coverage

- **AC-1**: `/sample dbc.tables;` works correctly in REPL
- **AC-2**: `/sample dbc.tables` (no semicolon) works correctly
- **AC-3**: `/peek dbc.tables;` works correctly
- **AC-4**: `tq sample dbc.tables` works in batch mode
- **AC-5**: Case-insensitive names work: `dbc.TablesV`, `DBC.TABLESV`, `dbc.tablesv`

## Prerequisites

- Teradata database accessible
- `TQ_LOGON` environment variable set (e.g., `user:pass@host:1025/DBC`)
- `tq` binary compiled (`cargo build`)

## Test Procedure

### Test Implementation (in `tests/bug35_sample_integration.rs` or `tests/integration_tests.rs`)

```rust
use std::process::Command;

fn tq_bin() -> std::path::PathBuf {
    let mut path = std::env::current_exe().expect("current exe path");
    path.pop(); // remove test binary name
    path.pop(); // remove "deps"
    path.push("tq");
    path
}

fn logon() -> String {
    std::env::var("TQ_LOGON").expect("TQ_LOGON must be set for integration tests")
}

// TC-046-003-A: tq sample dbc.tables (batch mode, lowercase)
#[test]
#[ignore]
fn test_sample_dbc_tables_batch_lowercase() {
    let output = Command::new(tq_bin())
        .args(["-l", &logon(), "sample", "dbc.tables"])
        .output()
        .expect("Failed to execute tq");

    let stdout = String::from_utf8_lossy(&output.stdout);
    let stderr = String::from_utf8_lossy(&output.stderr);

    assert!(
        output.status.success(),
        "tq sample dbc.tables failed\nstdout: {}\nstderr: {}",
        stdout, stderr
    );
    // Output should contain rows (at least a header line)
    assert!(
        !stdout.trim().is_empty(),
        "Expected output rows but got empty stdout"
    );
    // Must NOT contain "Table 's' does not exist" (the pre-fix bug error)
    assert!(
        !stderr.contains("does not exist"),
        "Got 'does not exist' error — fix not applied\nstderr: {}",
        stderr
    );
}
```

## Pass/Fail Criteria

**PASS if:**
- All 4 tests exit with status 0
- stdout is non-empty (rows returned)
- stderr does not contain "does not exist" or "Table 's'"

**FAIL if:**
- Any command exits non-zero
- stderr contains "does not exist" — the bug is not fixed in the call site
- stdout is empty — connection or query issue

**BLOCKED if:**
- `TQ_LOGON` is not set or database is unreachable — tests cannot run

## Notes

- These tests are marked `#[ignore]` and will NOT run in the standard `cargo test` invocation
- They require a live Teradata connection to DBC database
- `DBC.Tables` and `DBC.TablesV` are standard Teradata system views that always exist with SELECT access
- The REPL-mode tests (AC-1, AC-2 for REPL) are not implemented here because they require PTY simulation. The batch-mode tests (AC-4) are the primary coverage. AC-1 and AC-2 are validated implicitly: the REPL and batch paths both use `quote_table_reference()` which calls `quote_identifier()`.
