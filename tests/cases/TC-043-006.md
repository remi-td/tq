# TC-043-006: Config Preservation - Add, Edit, Delete Preserve Unrelated Content

**Test ID:** TC-043-006
**Feature:** Profile Management - config file preservation (all operations)
**Priority:** P0 - Critical
**Test Type:** Integration (CLI process) + Unit
**Sprint:** 43
**Created:** 2026-03-21
**Requirement References:** AC-7

---

## Objective

Verify that profile add, edit, and delete operations correctly preserve the TOML config file's unrelated content: profiles not being operated on, and the `[defaults]` section. This is the highest-risk behavior in Sprint 43 - a TOML write that loses existing data is silent data corruption.

---

## Background

The config file typically contains multiple sections:
```toml
[defaults]
logmech = "TD2"
format = "table"

[profiles.dev]
host = "dev.example.com"
port = 1025

[profiles.prod]
host = "prod.example.com"
database = "proddb"
```

Any write operation (add, edit, delete) must produce a file where all unrelated sections are bit-for-bit identical to the pre-operation state, or at minimum semantically equivalent (same keys and values, allowing TOML re-serialization differences in whitespace/order).

---

## Test Environment

Temporary directory via `TQ_CONFIG_DIR` environment variable. No database required.

A shared helper to write a known config:
```rust
fn write_test_config(dir: &std::path::Path) {

    std::fs::write(dir.join("config.toml"), config.trim_start()).unwrap();
```

## Test Cases

### TS43-P-C01: Add profile preserves existing profiles (AC-7)

**Precondition:** Config file contains profiles `dev` and `prod`.

**Command:**
```
tq profile add staging --host staging.example.com
```

**Expected Results:**
- Exit code: 0
- `staging` profile added
- `dev` profile UNCHANGED (host, port preserved)
- `prod` profile UNCHANGED (host, database preserved)

```rust
#[test]
fn test_profile_add_preserves_existing_profiles() {
    let tmp = tempfile::TempDir::new().unwrap();
    write_test_config(tmp.path());

    let output = std::process::Command::new(env!("CARGO_BIN_EXE_tq"))
        .args(["profile", "add", "staging", "--host", "staging.example.com"])
        .env("TQ_CONFIG_DIR", tmp.path())
        .output().unwrap();

    assert!(output.status.success(), "add must succeed, stderr: {}", String::from_utf8_lossy(&output.stderr));

    let contents = std::fs::read_to_string(tmp.path().join("config.toml")).unwrap();

    // New profile
    assert!(contents.contains("staging.example.com"), "staging profile must be added");

    // Existing profiles preserved
    assert!(contents.contains("dev.example.com"),  "dev host must be preserved");
    assert!(contents.contains("1025"),              "dev port must be preserved");
    assert!(contents.contains("prod.example.com"), "prod host must be preserved");
    assert!(contents.contains("proddb"),            "prod database must be preserved");
}
```

### TS43-P-C07: Unit test - round-trip TOML preserves all sections (AC-7)

**Location:** `src/commands/profile.rs` or `src/config.rs` `#[cfg(test)]` module

This validates the underlying read-modify-write function without invoking the full CLI.

```rust
#[test]
fn test_config_round_trip_preserves_all_sections() {
    let original_toml = r#"
[defaults]
logmech = "TD2"
format = "table"

[profiles.dev]
host = "dev.example.com"
port = 1025

[profiles.prod]
host = "prod.example.com"
database = "proddb"
"#.trim_start();

    // Simulate: parse the config, add a new profile, re-serialize
    let mut config = parse_config(original_toml).expect("must parse");
    let new_profile = ProfileConfig {
        host: "staging.example.com".to_string(),
        port: None,
        database: None,
        user: None,
        logmech: None,
        password_file: None,
    };
    config.add_profile("staging".to_string(), new_profile).expect("must add");
    let serialized = serialize_config(&config);

    // Parse the result and verify all original content survived
    let reparsed = parse_config(&serialized).expect("must re-parse");

    // defaults preserved
    let defaults = reparsed.defaults.as_ref().expect("defaults section must survive");
    assert_eq!(defaults.get("logmech").and_then(|v| v.as_str()), Some("TD2"), "logmech default preserved");
    assert_eq!(defaults.get("format").and_then(|v| v.as_str()), Some("table"), "format default preserved");

    // dev profile preserved
    let dev = reparsed.profiles.get("dev").expect("dev profile must survive");
    assert_eq!(dev.host, "dev.example.com", "dev host preserved");
    assert_eq!(dev.port, Some(1025), "dev port preserved");

    // prod profile preserved
    let prod = reparsed.profiles.get("prod").expect("prod profile must survive");
    assert_eq!(prod.host, "prod.example.com", "prod host preserved");
    assert_eq!(prod.database, Some("proddb".to_string()), "prod database preserved");

    // new profile added
    let staging = reparsed.profiles.get("staging").expect("staging profile must exist");
    assert_eq!(staging.host, "staging.example.com", "staging host correct");
}
```

**Note:** Adjust type names and method signatures to match the architect's implementation. The key assertions are that `[defaults]` and unrelated profiles survive the round-trip.

### TS43-P-C08: TOML known-risk - comment preservation note

**Test Type:** Documentation / awareness (not executable)

The `toml` crate's serialization does NOT preserve comments. If the user's config file has comments:
```toml
# Production database
[profiles.prod]
host = "prod.example.com"
```

After an add/edit/delete operation, the comment `# Production database` may be lost because TOML round-trip serialization doesn't preserve comments.

**This is an ACCEPTED limitation** per Sprint 43 planning (Risk 1: "accept that write operations may reformat the file").

**Validation:** Verify that the sprint planning and documentation explicitly state this limitation. Check `docs/specifications/configuration.md` for a note about comment-stripping behavior.

**Test (manual):**
1. Create a config with comments
2. Run `tq profile add newprofile --host h`
3. Verify behavior matches the documented specification (either comments preserved or documented as lost)
