## Purpose

Validate that `tq locks` works as a batch mode CLI command:
- CLI argument dispatch is wired correctly
- `--format` flag works for table, csv, and json output
- Exit codes are correct
- "No locks" case produces clean output (not an error)

Three tests run without a database. Two tests require a live database (marked `#[ignore]`).

## Acceptance Criteria Coverage

- **AC-4**: `tq locks` batch mode command with table/csv/json output formats

## Prerequisites

- `tq` binary built
- Live Teradata database configured in `.env` for `#[ignore]` tests

## Test Procedure

**Location:** `tests/integration_locks.rs`

```rust
//! Integration tests for tq locks batch mode command

use std::process::Command;

fn tq_bin() -> std::path::PathBuf {
    assert_cmd::cargo::cargo_bin!("tq")
}

fn logon_string() -> String {
    dotenvy::dotenv().ok();
    std::env::var("TQ_LOGON").expect("TQ_LOGON must be set for live database tests")
}

// ============================================================================
// Tests that do NOT require a database (CLI wiring validation)
// ============================================================================

#[test]
fn test_locks_subcommand_exists_in_help() {
    let output = Command::new(tq_bin())
        .arg("--help")
        .output()
        .expect("Failed to execute tq --help");

    let stdout = String::from_utf8_lossy(&output.stdout);
    let stderr = String::from_utf8_lossy(&output.stderr);
    let all_output = format!("{}{}", stdout, stderr);

    assert!(
        all_output.contains("locks"),
        "tq --help must list 'locks' subcommand. Got: {}",
        all_output
    );
}

#[test]
fn test_locks_help_subcommand_succeeds() {
    let output = Command::new(tq_bin())
        .args(&["locks", "--help"])
        .output()
        .expect("Failed to execute tq locks --help");

    let stdout = String::from_utf8_lossy(&output.stdout);
    let stderr = String::from_utf8_lossy(&output.stderr);
    let all_output = format!("{}{}", stdout, stderr);

    assert!(
        all_output.contains("locks") || output.status.success(),
        "tq locks --help must display help text. Got: {}",
        all_output
    );
}

#[test]
fn test_locks_without_logon_exits_nonzero() {
    let output = Command::new(tq_bin())
        .arg("locks")
        .env_remove("TQ_LOGON")
        .output()
        .expect("Failed to execute tq locks");

    assert!(
        !output.status.success(),
        "tq locks without credentials must exit non-zero"
    );
}

// ============================================================================
// Tests that require a live database (marked #[ignore])
// ============================================================================

#[test]
#[ignore] // Requires live database: cargo test --test integration_locks -- --ignored
fn test_locks_no_locks_or_table_output() {
    // In test environment there may be no active locks.
    // The command should succeed and show either:
    // (a) A table with lock data if locks exist
    // (b) A "no active locks" message if no locks
    let logon = logon_string();

    let output = Command::new(tq_bin())
        .args(&["locks", "--logon", &logon])
        .output()
        .expect("Failed to execute tq locks");

    let stdout = String::from_utf8_lossy(&output.stdout);
    let stderr = String::from_utf8_lossy(&output.stderr);

    assert!(
        output.status.success(),
        "tq locks should succeed with valid credentials. stderr: {}",
        stderr
    );

    // Must produce some output: either lock data or "no locks" message
    assert!(
        !stdout.is_empty() || !stderr.is_empty(),
        "tq locks must produce output"
    );
}

#[test]
#[ignore] // Requires live database: cargo test --test integration_locks -- --ignored
fn test_locks_csv_format() {
    let logon = logon_string();

    let output = Command::new(tq_bin())
        .args(&["locks", "--logon", &logon, "--format", "csv"])
        .output()
        .expect("Failed to execute tq locks --format csv");

    let stdout = String::from_utf8_lossy(&output.stdout);

    assert!(
        output.status.success(),
        "tq locks --format csv must succeed"
    );

    // If there is CSV output, it must have a comma-separated header
    if !stdout.trim().is_empty() {
        let lines: Vec<&str> = stdout.lines().collect();
        if !lines.is_empty() {
            // If any CSV lines exist, they should be comma-separated
            // (Note: empty result may produce only a header line)
            let first_line = lines[0];
            if first_line.contains(',') {
                // Has CSV content - validate structure
                assert!(
                    first_line.len() > 0,
                    "CSV first line must not be empty"
                );
            }
        }
    }
}

#[test]
#[ignore] // Requires live database: cargo test --test integration_locks -- --ignored
fn test_locks_json_format() {
    let logon = logon_string();

    let output = Command::new(tq_bin())
        .args(&["locks", "--logon", &logon, "--format", "json"])
        .output()
        .expect("Failed to execute tq locks --format json");

    let stdout = String::from_utf8_lossy(&output.stdout);

    assert!(
        output.status.success(),
        "tq locks --format json must succeed"
    );

    // JSON output must be parseable
    if !stdout.trim().is_empty() {
        let parsed: Result<serde_json::Value, _> = serde_json::from_str(&stdout);
        assert!(
            parsed.is_ok(),
            "tq locks --format json must produce valid JSON. Got: {}",
            stdout
        );

        // Must be a JSON array (even if empty)
        let json = parsed.unwrap();
        assert!(
            json.is_array(),
            "Locks JSON must be an array. Got: {:?}",
            json
        );
    }
}
```

## Expected Results

### Without Database (3 tests):
- `tq --help` mentions "locks"
- `tq locks --help` displays usage text
- `tq locks` without credentials exits non-zero

### With Live Database (2 tests, `#[ignore]`):
- `tq locks` exits 0 with either lock data or "no locks" message
- `tq locks --format csv` produces comma-separated output
- `tq locks --format json` produces valid JSON array

## Pass/Fail Criteria

**PASS if:**
- All 3 no-DB tests pass (CLI wiring correct)
- Live-DB: `tq locks` exits 0 (no crash when no locks exist)
- Live-DB: CSV format produces valid comma-separated output
- Live-DB: JSON format produces valid JSON array (may be empty array `[]`)

**FAIL if:**
- `locks` not found in CLI help
- `tq locks` with valid credentials exits non-zero (crashes on no locks)
- JSON output is invalid JSON
- CSV output is malformed

## Notes

- Run no-DB tests: `cargo test --test integration_locks`
- Run live-DB tests: `cargo test --test integration_locks -- --ignored`
- The empty-result case is the most likely state in CI (no active locks)
- Empty JSON array `[]` is valid output for no-locks state
