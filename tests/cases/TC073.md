# Test Case TC073: Tab Completion - Column Name Completion After SELECT/WHERE

## Purpose

Verify that tab completion shows column names (not SQL keywords) when the context is a column position like SELECT clause or WHERE clause.

Ensures column completion context detection survived Sprint 10 changes.

## Scope

**Testing:**
- Column completion after SELECT keyword
- Column completion after WHERE keyword
- Column completion after comma in SELECT list
- Context detection extracts table from FROM clause
- Shows actual column names, not keywords

**Not Testing:**
- Multi-table JOINs (complexity TC)
- Subqueries/CTEs (out of scope)
- ORDER BY/GROUP BY (similar contexts)

## Prerequisites

- tq REPL connected to Teradata
- Test table available with known columns
- Recommended: DBC.TablesV (well-known schema)
- User has SELECT on DBC.ColumnsV

## Test Procedure

### Setup

```bash
./target/release/tq repl

# Verify connection
tq> /ping

# Identify test table columns
tq> /describe DBC.TablesV
# Note: Should show columns like DatabaseName, TableName, TableKind, etc.
```

### Execution Steps

**Step 1: Test SELECT clause completion with full table context**

```sql
tq> SELECT <TAB> FROM DBC.TablesV
```

**Expected outcome:**
- Shows column names from DBC.TablesV
- Examples: DatabaseName, TableName, TableKind, CreatorName
- **CRITICAL:** Does NOT show SQL keywords (SELECT, INSERT, etc.)
- **CRITICAL:** Shows actual column names

**Step 2: Test SELECT with partial column prefix**

```sql
tq> SELECT Table<TAB> FROM DBC.TablesV
```

**Expected outcome:**
- Filters to columns starting with "Table"
- Should show: TableName, TableKind
- Prefix matching works
- Not keywords

**Step 3: Test multi-column completion (after comma)**

```sql
tq> SELECT DatabaseName, <TAB> FROM DBC.TablesV
```

**Expected outcome:**
- Shows remaining columns
- TableName, TableKind, CreatorName, etc.
- Context preserved across comma

**Step 4: Test WHERE clause completion**

```sql
tq> SELECT * FROM DBC.TablesV WHERE <TAB>
```

**Expected outcome:**
- Shows column names suitable for filtering
- Same columns as SELECT (DatabaseName, TableName, etc.)
- Context detection works for WHERE

**Step 5: Test WHERE with partial prefix**

```sql
tq> SELECT * FROM DBC.TablesV WHERE Database<TAB>
```

**Expected outcome:**
- Auto-completes to "DatabaseName" (if unique)
- OR shows: DatabaseName (if multiple matches with "Database")

**Step 6: Test with simple table (not qualified)**

```sql
# First create simple context (assuming "employees" exists)
tq> SELECT <TAB> FROM employees
```

**Expected outcome:**
- Shows columns from employees table
- Examples: employee_id, first_name, last_name
- Unqualified table names work

**Step 7: Test completion without FROM clause (should gracefully fail)**

```sql
tq> SELECT <TAB>
```

**Expected outcome:**
- Shows message: "Cannot determine table context"
- OR shows generic keywords (acceptable fallback)
- Does NOT crash or hang
- Helpful message if possible

### Verification

**Visual Inspection:**

- [ ] Column names visible in completion list
- [ ] Column names semantically match table
- [ ] NO SQL keywords in column position
- [ ] Type hints shown (optional but nice)

**Functional Validation:**

Complete a column name and verify query works:
```sql
tq> SELECT DatabaseName FROM DBC.TablesV LIMIT 5;
# Should execute successfully
```

**Cross-reference Check:**

Compare completion to actual columns:
```sql
tq> SELECT ColumnName FROM DBC.ColumnsV
    WHERE DatabaseName = 'DBC'
    AND TableName = 'TablesV'
    ORDER BY ColumnName;
```

Completion list should match this query result.

### Cleanup

```bash
tq> /quit
```

## Expected Results

**Step 1 Output:**

```
tq> SELECT <TAB> FROM DBC.TablesV

Columns in DBC.TablesV:
  DatabaseName (VARCHAR)    TableName (VARCHAR)    TableKind (CHAR)
  CreatorName (VARCHAR)     OwnerName (VARCHAR)    ProtectionType (CHAR)
  [10 more columns...]
```

OR (simpler format):

```
tq> SELECT <TAB> FROM DBC.TablesV
DatabaseName    TableName    TableKind    CreatorName    OwnerName
```

**Step 2 Output:**

```
tq> SELECT Table<TAB> FROM DBC.TablesV
TableName    TableKind
```

**Step 4 Output:**

```
tq> SELECT * FROM DBC.TablesV WHERE <TAB>
DatabaseName    TableName    TableKind    CreatorName    [etc...]
```

**Step 7 Output (graceful degradation):**

```
tq> SELECT <TAB>
(Cannot determine table context. Complete table name first.)
```

OR shows generic SQL keywords as fallback (acceptable).

## Anti-Pattern (What Should NOT Happen)

**INCORRECT Output (Bug Behavior):**

```
tq> SELECT <TAB> FROM DBC.TablesV
SELECT    INSERT    UPDATE    DELETE    CREATE    DROP    ALTER
(SQL keyword)  (SQL keyword)  (SQL keyword)  (SQL keyword)
```

This would indicate column completion is broken - showing keywords instead of columns.

## Pass/Fail Criteria

**PASS:**
- SELECT completion shows column names from table in FROM
- WHERE completion shows column names
- Partial prefix filters columns correctly
- Multi-column (after comma) works
- Context parsing extracts table from FROM clause
- No SQL keywords shown in column position
- Graceful degradation without FROM clause

**FAIL:**
- Shows SQL keywords in column position
- Shows "(SQL keyword)" repeated
- Empty completion when columns exist
- Context detection broken (wrong table's columns)
- Crashes or hangs without FROM clause
- Cannot complete any real column name

## Notes

**Context Detection Requirements:**

For column completion to work, parser must:
1. Identify we're in a column position (after SELECT, WHERE, etc.)
2. Extract table name from FROM clause
3. Query DBC.ColumnsV for that table
4. Show those columns

If any step fails → Should show helpful error, not garbage.

**Why This Test is Critical:**

Column completion is a primary use case:
- Users forget column names frequently
- DBC views have 20+ columns (hard to remember)
- Completion significantly speeds query writing

Bug 2 may have broken this by:
- Context detection failing
- Falling back to keyword completion inappropriately
- Not querying DBC.ColumnsV at all

**Edge Cases:**

- Multiple tables (JOINs): May show "(Multiple tables, use alias)" - acceptable
- Subquery: May not detect table - acceptable limitation
- Complex FROM: May fail - document limitation

**Performance Note:**

- First column completion: <300ms (metadata query)
- Cached: <50ms
- Should show "Loading columns..." if slow
